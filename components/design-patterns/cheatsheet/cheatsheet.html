CheatSheet de Patrones de Diseño

Los Patrones de Diseño son soluciones probadas, reutilizables y estandarizadas a problemas comunes que surgen al diseñar arquitecturas de software orientadas a objetos. No son fragmentos de código listos para copiar y pegar, sino guías conceptuales y plantillas sobre cómo organizar clases, interfaces y sus relaciones.

1. Clasificación Rápida: Los 23 Patrones del Gang of Four (GoF)

Publicados en 1994 por Erich Gamma, Richard Helm, Ralph Johnson y John Vlissides, se dividen en tres familias según su propósito:

A. Patrones Creacionales (Mecanismos de creación de objetos)

Patrón Propósito Principal ¿Cuándo usarlo?
Singleton Garantiza una única instancia global en memoria y un punto de acceso centralizado. Pools de conexiones, gestores de caché, logs o configuración compartida.
Factory Method Define una interfaz para crear objetos, delegando la instanciación concreta en subclases o métodos de fábrica. Cuando el código cliente no debe acoplarse a clases concretas (ej. notificaciones por Email, SMS o Push).
Abstract Factory Proporciona una interfaz para crear familias completas de objetos relacionados sin especificar sus clases concretas. Sistemas multiplataforma o temas visuales (ej. Botón y Ventana para Windows vs Mac).
Builder Separa la construcción paso a paso de un objeto complejo de su representación final. Objetos con muchos atributos opcionales o constructores telescópicos con más de 4 parámetros.
Prototype Crea nuevos objetos clonando una instancia existente en lugar de crearlos desde cero con new. Cuando la creación de un objeto nuevo es computacionalmente costosa o compleja.

B. Patrones Estructurales (Composición y relación entre clases)

Patrón Propósito Principal ¿Cuándo usarlo?
Adapter Convierte la interfaz de una clase en otra interfaz que el cliente espera, permitiendo cooperar a clases incompatibles. Integrar librerías externas o sistemas legacy con firmas de métodos incompatibles.
Bridge Desacopla una abstracción de su implementación para que ambas puedan variar de forma independiente. Evitar explosiones combinatorias de subclases (ej. Formas geométricas vs Motores de renderizado).
Composite Compone objetos en estructuras de árbol para representar jerarquías de parte-todo, tratando elementos individuales y compuestos por igual. Estructuras de carpetas/archivos, menús gráficos multinivel o listas de tareas anidadas.
Decorator Añade responsabilidades y comportamientos adicionales a un objeto de forma dinámica sin usar herencia. Flujos de E/S en Java (BufferedInputStream(FileInputStream)) o filtros de compresión/cifrado.
Facade Proporciona una interfaz unificada y simplificada frente a un subsistema complejo de clases. Simplificar el uso de subsistemas complejos (ej. compras online que coordinan inventario, pago y envíos).
Flyweight Reduce el consumo de memoria compartiendo eficientemente partes comunes de estado entre miles de objetos similares. Sistemas con millones de objetos pequeños (ej. caracteres en un procesador de texto, partículas o árboles en videojuegos).
Proxy Proporciona un sustituto o intermediario que controla el acceso a otro objeto (seguridad, carga diferida o caché). Lazy loading de imágenes pesadas, proxys transaccionales de Spring o proxys de seguridad.

C. Patrones de Comportamiento (Algoritmos y asignación de responsabilidades)

Patrón Propósito Principal ¿Cuándo usarlo?
Chain of Responsibility Pasa una petición a lo largo de una cadena de manejadores hasta que uno de ellos la procesa. Filtros de seguridad (Spring Security filter chain), validadores secuenciales o pipelines de peticiones HTTP.
Command Encapsula una petición como un objeto, permitiendo parametrizar clientes, encolar operaciones y soportar deshacer (undo). Sistemas transaccionales, botones de interfaz gráfica con historial o colas de tareas asíncronas.
Interpreter Define una representación gramatical y un intérprete para evaluar oraciones en un lenguaje específico. Evaluadores de expresiones matemáticas, motores de reglas de negocio o lenguajes DSL sencillos.
Iterator Proporciona una forma de acceder secuencialmente a los elementos de una colección sin exponer su estructura interna. Recorrer colecciones complejas (listas, árboles, grafos) con la interfaz estándar java.util.Iterator.
Mediator Define un objeto que encapsula cómo interactúa un conjunto de objetos, evitando que se comuniquen directamente. Torres de control, formularios de diálogo donde el cambio en un campo afecta a otros campos.
Memento Captura y externaliza el estado interno de un objeto para poder restaurarlo más tarde sin violar el encapsulamiento. Historial de deshacer (Ctrl+Z) en editores de texto, puntos de guardado o snapshots de estado.
Observer Define una dependencia uno-a-muchos: cuando un objeto cambia de estado, todos sus suscriptores son notificados automáticamente. Arquitecturas reactivas, listeners de eventos UI o sistemas de suscripción y publicación de noticias.
State Permite a un objeto alterar su comportamiento cuando su estado interno cambia, simulando un cambio de clase. Máquinas de estados finitos (ej. pedidos con estados Creado, Pagado, Enviado, Cancelado).
Strategy Define una familia de algoritmos, los encapsula en clases intercambiables y los hace sustituibles en tiempo de ejecución. Algoritmos de cálculo de impuestos, métodos de pago intercambiables o estrategias de compresión.
Template Method Define el esqueleto de un algoritmo en una clase base y permite a las subclases redefinir ciertos pasos sin cambiar su estructura. Pipelines de procesamiento de archivos (CSV, XML, JSON) donde la apertura y cierre son idénticos pero el parseo varía.
Visitor Permite añadir nuevas operaciones a una jerarquía de clases existente sin modificar dichas clases. Generación de reportes o exportación (XML, JSON, PDF) sobre nodos de un árbol AST o elementos de factura.

2. Patrones Arquitectónicos Java EE y Empresariales

Patrón Empresarial Capa de Aplicación Propósito y Responsabilidad
Data Access Object (DAO) Persistencia / Datos Aísla la capa de negocio de los detalles de la base de datos (SQL, JDBC, JPA).
Transfer Object (DTO) Presentación / Negocio Transporta datos estructurados entre capas o a través de la red reduciendo llamadas remotas.
MVC (Model-View-Controller) Presentación / Web Separa el modelo de datos, la interfaz visual (vista) y la lógica de control del flujo HTTP.
Front Controller Presentación / Web Punto centralizado de entrada que intercepta todas las peticiones (como DispatcherServlet en Spring MVC).
Intercepting Filter Presentación / Web Aplica filtros de pre/postprocesamiento antes de invocar el controlador (autenticación, compresión, logging).
Business Delegate Negocio / Clientes Desacopla a los clientes de la capa de presentación de la complejidad de los servicios de negocio remotos.
Service Locator Negocio / Servicios Centraliza la búsqueda y caché de servicios y recursos JNDI/EJB en aplicaciones distribuidas.
