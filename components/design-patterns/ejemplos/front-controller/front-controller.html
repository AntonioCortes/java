Patrón Front Controller

El patrón Front Controller (Controlador Frontal) es un patrón de la arquitectura Java EE que define un único punto de entrada centralizado para recibir todas las peticiones web de una aplicación, encargándose de las tareas comunes y de despachar cada petición al controlador o vista adecuada.

Analogía del Mundo Real

Piensa en la Recepción Central de un gran hospital o un hotel. Cuando llegas por la puerta principal, no vas abriendo puertas al azar buscando al médico: siempre pasas primero por el mostrador de Recepción (el ControladorFrontal). El recepcionista registra tu llegada, verifica tu tarjeta sanitaria y te indica a qué consulta exacta debes dirigirte (Despachador).

Propósito

Evitar que cada vista o página web tenga que gestionar por su cuenta la seguridad, el rastreo de peticiones y la navegación, centralizando todo ese control en una única puerta de entrada.

Caso de Uso Real: El DespachadorServlet de Spring MVC

Contexto: Una aplicación educativa tiene múltiples pantallas (VistaInicio, VistaEstudiante). Antes de mostrar cualquier pantalla hay que registrar la URL solicitada y comprobar que el usuario está autenticado.

El Problema (Sin Front Controller): Si el navegador llama directamente a cada vista por separado, es muy fácil olvidar poner el chequeo de seguridad en alguna página nueva, dejando agujeros de seguridad.

La Solución (Con Front Controller): Todas las peticiones pasan obligatoriamente por ControladorFrontal.procesarPeticion(url). Este método registra la petición, comprueba esUsuarioAutenticado() y delega en Despachador para mostrar la vista solicitada.

Implementación en Java


// 1. Vistas destino
class VistaInicio {
    public void mostrar() {
        System.out.println("🏠 [VistaInicio] Renderizando Página Principal del Portal.");
    }
}

class VistaEstudiante {
    public void mostrar() {
        System.out.println("🎓 [VistaEstudiante] Renderizando Expediente Académico del Estudiante.");
    }
}

// 2. Despachador: Enruta hacia la vista correspondiente
class Despachador {
    private VistaInicio homeView = new VistaInicio();
    private VistaEstudiante studentView = new VistaEstudiante();

    public void despachar(String request) {
        if (request.equalsIgnoreCase("STUDENT")) {
            studentView.mostrar();
        } else {
            homeView.mostrar();
        }
    }
}

// 3. Front Controller: Único punto de entrada para TODAS las peticiones
class ControladorFrontal {
    private Despachador dispatcher;

    public ControladorFrontal() {
        this.dispatcher = new Despachador();
    }

    private void registrarPeticion(String request) {
        System.out.println("📌 [ControladorFrontal] Petición recibida en el punto central: " + request);
    }

    private boolean esUsuarioAutenticado() {
        System.out.println("✅ [ControladorFrontal] Usuario autenticado correctamente.");
        return true;
    }

    public void procesarPeticion(String request) {
        // 1. Tareas centralizadas comunes a toda petición
        registrarPeticion(request);

        // 2. Control de seguridad centralizado antes de despachar
        if (esUsuarioAutenticado()) {
            dispatcher.despachar(request);
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. El corazón de Spring Boot Web:

    Cuando trabajas con Spring Boot y creas clases con @RestController o @Controller, por delante de todas ellas existe un único Servlet maestro llamado DespachadorServlet que implementa exactamente este patrón Front Controller.

  • 2. Imposible saltarse los controles:

    Al existir una única puerta de entrada (procesarPeticion), ninguna vista puede ser invocada sin haber pasado antes por registrarPeticion() e esUsuarioAutenticado().

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        ControladorFrontal frontController = new ControladorFrontal();

        System.out.println("--- Navegador solicita /home ---");
        frontController.procesarPeticion("HOME");

        System.out.println("\n--- Navegador solicita /student ---");
        frontController.procesarPeticion("STUDENT");
    }
}
Todas las peticiones del cliente entran siempre por el ControladorFrontal

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: En cualquier aplicación web o API REST donde quieras centralizar el enrutamiento de URLs, el manejo global de errores y la seguridad (en frameworks modernos como Spring MVC o JSF ya viene integrado de serie).
  • Cuándo evitarlo: En sitios puramente estáticos de archivos HTML donde no existe lógica de servidor común.
