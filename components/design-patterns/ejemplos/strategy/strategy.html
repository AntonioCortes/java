Patrón Strategy

El patrón Strategy (Estrategia) es un patrón de comportamiento que permite definir una familia de algoritmos, colocar cada uno de ellos en una clase separada y hacer que sus objetos sean intercambiables en tiempo de ejecución.

Analogía del Mundo Real

Piensa en Google Maps cuando calculas una ruta al aeropuerto. El objetivo final siempre es el mismo ("llegar del punto A al punto B"), pero tú puedes elegir distintas Estrategias de ruta pulsando un icono: ir en Coche, en Transporte Público, en Bicicleta o Caminando. El mapa (el Contexto) cambia instantáneamente el algoritmo de cálculo según la estrategia que selecciones.

Propósito

Extraer distintos algoritmos que resuelven la misma tarea fuera de la clase principal, eliminando bloques if-else o switch y permitiendo cambiar el algoritmo al vuelo mediante composición.

Caso de Uso Real: Pasarela de Pagos en un Carrito de Compra

Contexto: Una tienda online (CarritoCompra) permite al usuario pagar su compra eligiendo entre Tarjeta de Crédito (PagoTarjetaCredito) o PayPal (PagoPayPal).

El Problema (Sin Strategy): Si dentro de CarritoCompra.procesarCompra() pones if (type.equals("CARD")) { ... } else if (type.equals("PAYPAL")) { ... }, violas el Principio Abierto/Cerrado (OCP): cada vez que quieras añadir Bizum o Apple Pay tendrás que abrir y modificar la clase del carrito.

La Solución (Con Strategy): Definimos la interfaz EstrategiaPago con el método pagar(int amount). Cada método de pago es una clase independiente que implementa esa interfaz. El carrito solo tiene el método setEstrategiaPago() y delega el cobro llamando a estrategiaPago.pagar(amount).

Rol en el Patrón Clase / Interfaz en el Ejemplo Responsabilidad
Strategy (Interfaz) EstrategiaPago Declara el método común (pagar(int amount)) para todos los algoritmos de pago soportados.
Concrete Strategies PagoTarjetaCredito, PagoPayPal Implementan cada algoritmo específico de pago con sus propios datos (número de tarjeta o email de cuenta).
Context (Contexto) CarritoCompra Guarda una referencia a una EstrategiaPago y permite cambiarla en cualquier momento con setEstrategiaPago().

Implementación en Java


// 1. Interfaz Strategy: contrato común para cualquier algoritmo de pago
interface EstrategiaPago {
    void pagar(int amount);
}

// 2. Estrategia Concreta A: Pago con Tarjeta de Crédito
class PagoTarjetaCredito implements EstrategiaPago {
    private String cardNumber;

    public PagoTarjetaCredito(String cardNumber) {
        this.cardNumber = cardNumber;
    }

    @Override
    public void pagar(int amount) {
        System.out.println("💳 Pagando " + amount + "€ con Tarjeta de Crédito terminada en: " + cardNumber);
    }
}

// 3. Estrategia Concreta B: Pago con PayPal
class PagoPayPal implements EstrategiaPago {
    private String email;

    public PagoPayPal(String email) {
        this.email = email;
    }

    @Override
    public void pagar(int amount) {
        System.out.println("🅿️ Pagando " + amount + "€ mediante cuenta PayPal: " + email);
    }
}

// 4. Contexto: El Carrito de Compra que delega el cobro en la estrategia elegida
class CarritoCompra {
    private EstrategiaPago estrategiaPago;

    // Permite asignar o cambiar la estrategia en tiempo de ejecución
    public void setEstrategiaPago(EstrategiaPago estrategiaPago) {
        this.estrategiaPago = estrategiaPago;
    }

    public void procesarCompra(int amount) {
        if (estrategiaPago == null) {
            System.out.println("⚠️ Por favor, seleccione un método de pago antes de continuar.");
        } else {
            estrategiaPago.pagar(amount);
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Composición sobre Herencia:

    CarritoCompra no hereda de ninguna pasarela de pago; contiene un atributo private EstrategiaPago. Eso es lo que permite que el mismo carrito pague primero con PayPal y dos líneas más abajo cambie a Tarjeta sin crear otro carrito.

  • 2. Ejemplo en el propio JDK de Java:

    Collections.sort(lista, comparator) es un ejemplo clásico de Strategy: la lista es el contexto y el Comparator que le pasas por parámetro es la estrategia de ordenación (ordenar por precio, por nombre o por fecha).

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        CarritoCompra cart = new CarritoCompra();

        // El usuario selecciona pagar con PayPal su primer pedido
        cart.setEstrategiaPago(new PagoPayPal("cliente@ejemplo.com"));
        cart.procesarCompra(120);

        // El usuario cambia de opinión y selecciona pagar con Tarjeta el segundo pedido
        cart.setEstrategiaPago(new PagoTarjetaCredito("****-****-****-4589"));
        cart.procesarCompra(250);
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando tengas distintas variantes de un mismo algoritmo (cálculo de impuestos por país, algoritmos de compresión ZIP/RAR, métodos de pago o descuentos) y quieras poder intercambiarlos en tiempo de ejecución sin usar condicionales switch.
  • Cuándo evitarlo: Si solo tienes un par de algoritmos muy breves que casi nunca cambian (en Java 8+ a menudo puedes pasar directamente una expresión lambda).
