Patrón Abstract Factory

El patrón Abstract Factory (Fábrica Abstracta) es un patrón creacional que permite producir familias de objetos relacionados entre sí sin especificar sus clases concretas. Si Factory Method es una fábrica de un único tipo de producto, Abstract Factory es una "fábrica de fábricas" que garantiza que todos los objetos creados combinen entre sí.

Analogía del Mundo Real

Imagina que vas a comprar un conjunto de muebles para tu salón: una Silla y una Mesa de Centro. Existen distintas familias de estilo: estilo Moderno y estilo Victoriano. No quieres que por error te entreguen una silla moderna minimalista combinada con una mesa victoriana barroca. Al elegir el catálogo de la "Fábrica Moderna", te aseguras de que tanto la silla como la mesa que te entreguen pertenezcan a la misma familia visual.

Propósito

Proporcionar una interfaz para crear familias de productos relacionados o dependientes, garantizando la compatibilidad entre los productos de una misma familia y ocultando las clases concretas al código cliente.

Caso de Uso Real: Toolkit de Interfaz Gráfica Multiplataforma (Windows vs Mac)

Contexto: Estás desarrollando una aplicación de escritorio que debe ejecutarse tanto en Windows como en macOS. Tu ventana principal contiene un botón (Boton) y una casilla de verificación (CasillaVerificacion).

El Problema (Sin Abstract Factory): Si instancias los controles manualmente con condicionales dispersos por toda la aplicación, es muy fácil cometer el error de mezclar un BotonWindows con un CasillaMac, provocando una interfaz incoherente y llenando el código de if (os.equals("WIN")).

La Solución (Con Abstract Factory): Defines la interfaz FabricaGUI con los métodos crearBoton() y createCasillaVerificacion(). Al arrancar el programa, compruebas el sistema operativo una sola vez e inyectas FabricaWindows o FabricaMac en la clase Aplicacion. A partir de ese instante, todos los controles creados serán 100% coherentes con ese sistema operativo.

Implementación en Java


// 1. Interfaces de los Productos Abstractos
interface Boton {
    void pintar();
}

interface CasillaVerificacion {
    void pintar();
}

// 2. Familia de Productos Concretos: WINDOWS
class BotonWindows implements Boton {
    @Override
    public void pintar() {
        System.out.println("Renderizando Botón con estilo clásico de Windows.");
    }
}

class CasillaWindows implements CasillaVerificacion {
    @Override
    public void pintar() {
        System.out.println("Renderizando CasillaVerificacion cuadrado de Windows.");
    }
}

// 3. Familia de Productos Concretos: MAC
class BotonMac implements Boton {
    @Override
    public void pintar() {
        System.out.println("Renderizando Botón redondeado estilo macOS.");
    }
}

class CasillaMac implements CasillaVerificacion {
    @Override
    public void pintar() {
        System.out.println("Renderizando CasillaVerificacion minimalista estilo macOS.");
    }
}

// 4. Interfaz Abstract Factory
interface FabricaGUI {
    Button crearBoton();
    CasillaVerificacion createCasillaVerificacion();
}

// 5. Fábricas Concretas (una por cada familia)
class FabricaWindows implements FabricaGUI {
    @Override
    public Button crearBoton() {
        return new BotonWindows();
    }
    @Override
    public CasillaVerificacion createCasillaVerificacion() {
        return new CasillaWindows();
    }
}

class FabricaMac implements FabricaGUI {
    @Override
    public Button crearBoton() {
        return new BotonMac();
    }
    @Override
    public CasillaVerificacion createCasillaVerificacion() {
        return new CasillaMac();
    }
}

// 6. Cliente: trabaja exclusivamente con las interfaces abstractas
class Aplicacion {
    private Boton boton;
    private CasillaVerificacion casilla;

    public Aplicacion(FabricaGUI fabrica) {
        this.boton = fabrica.crearBoton();
        this.checkbox = factory.createCasillaVerificacion();
    }

    public void pintar() {
        boton.pintar();
        casilla.pintar();
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Garantía de consistencia entre familias:

    Observa que FabricaWindows solo puede devolver BotonWindows y CasillaWindows. Es imposible que Aplicacion mezcle por accidente un botón de Windows con un checkbox de Mac porque ambos provienen del mismo objeto factory.

  • 2. Principio Abierto/Cerrado (OCP) para nuevas familias:

    Si mañana queremos dar soporte a Linux, solo tenemos que crear LinuxButton, LinuxCasillaVerificacion y LinuxFactory. ¡No hay que tocar ni una sola línea de la clase Aplicacion!

Ejemplo de Uso


public class Main {
    // Método auxiliar que selecciona la fábrica una única vez al inicio
    private static Application configureApplication(String osName) {
        FabricaGUI fabrica;
        if (osName.equalsIgnoreCase("MAC")) {
            fabrica = new FabricaMac();
        } else {
            fabrica = new FabricaWindows();
        }
        return new Aplicacion(fabrica);
    }

    public static void main(String[] args) {
        System.out.println("--- Arrancando aplicación en entorno Windows ---");
        Aplicacion appWin = configureApplication("WIN");
        appWin.pintar();

        System.out.println("\n--- Arrancando aplicación en entorno macOS ---");
        Aplicacion appMac = configureApplication("MAC");
        appMac.pintar();
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando tu sistema deba trabajar con múltiples familias de productos relacionados (temas visuales claro/oscuro, conectores de distintas nubes AWS/Azure/GCP) y quieras asegurar que los objetos de una familia siempre se usen juntos.
  • Cuándo evitarlo: Si frecuentemente necesitas añadir nuevos tipos de productos a la familia (por ejemplo, añadir createSlider()), ya que eso te obligará a modificar la interfaz FabricaGUI y todas sus subclases.
