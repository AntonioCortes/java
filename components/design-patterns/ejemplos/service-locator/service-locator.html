Patrón Service Locator

El patrón Service Locator (Localizador de Servicios) es un patrón de la arquitectura Java EE que centraliza la búsqueda de servicios o recursos costosos (como conexiones JNDI, colas de mensajería o microservicios) y guarda sus referencias en una caché en memoria para no tener que buscarlos una y otra vez.

Analogía del Mundo Real

Piensa en la agenda de contactos rápidos de tu teléfono móvil. La primera vez que necesitas llamar al fontanero, tienes que buscar su número en las Páginas Amarillas o en Google (una búsqueda lenta: ContextoInicial.buscar()). Una vez que lo encuentras, lo guardas en los "Contactos Favoritos" de tu móvil (la Caché del Service Locator). La próxima vez que lo necesites, lo obtienes al instante sin volver a buscar en la guía telefónica.

Propósito

Abstraer la complejidad de los directorios de nombres (como JNDI o registros de servicios) y mejorar drásticamente el rendimiento evitando búsquedas de red repetitivas.

Caso de Uso Real: Localización y Caché de Servicios Empresariales

Contexto: En un servidor de aplicaciones empresarial, localizar un servicio por su nombre (PaymentService o MessagingService) a través de ContextoInicial.buscar() tarda varios milisegundos porque consulta un directorio en red.

El Problema (Sin Service Locator): Si cada petición de usuario ejecuta new ContextoInicial().buscar("PaymentService"), el servidor perderá la mayor parte del tiempo haciendo búsquedas repetidas del mismo servicio.

La Solución (Con Service Locator): El cliente pide el servicio a LocalizadorServicios.obtenerServicio("PaymentService"). El localizador mira primero en su CacheServicios: si aún no está, hace el lookup costoso una sola vez y lo guarda en caché; en todas las llamadas siguientes lo devuelve inmediatamente desde la memoria RAM.

Implementación en Java


import java.util.HashMap;
import java.util.Map;

// 1. Interfaz común para los servicios
interface Servicio {
    String getNombre();
    void ejecutar();
}

// 2. Servicios Concretos
class PaymentService implements Servicio {
    public String getNombre() { return "PaymentService"; }
    public void ejecutar() { System.out.println("💳 Ejecutando PaymentService..."); }
}

class EmailService implements Servicio {
    public String getNombre() { return "EmailService"; }
    public void ejecutar() { System.out.println("✉️ Ejecutando EmailService..."); }
}

// 3. ContextoInicial: Simula el directorio JNDI (operación lenta/costosa)
class ContextoInicial {
    public Object buscar(String jndiName) {
        System.out.println("🔍 [JNDI Lookup Costoso] Buscando y creando '" + jndiName + "' en el directorio de red...");
        if (jndiName.equalsIgnoreCase("PaymentService")) {
            return new PaymentService();
        } else if (jndiName.equalsIgnoreCase("EmailService")) {
            return new EmailService();
        }
        return null;
    }
}

// 4. CacheServicios: Almacena en memoria los servicios ya encontrados
class CacheServicios {
    private Map<String, Service> services = new HashMap<>();

    public Servicio obtenerServicio(String serviceName) {
        Servicio s = services.get(serviceName.toUpperCase());
        if (s != null) {
            System.out.println("⚡ [CACHÉ HIT] Devolviendo '" + serviceName + "' directamente desde memoria.");
        }
        return s;
    }

    public void agregarServicio(Servicio newService) {
        services.put(newService.getNombre().toUpperCase(), newService);
    }
}

// 5. Service Locator: Fachada estática de localización
class LocalizadorServicios {
    private static CacheServicios cache = new CacheServicios();

    public static Servicio obtenerServicio(String jndiName) {
        // Paso 1: Comprobar si ya está en la caché
        Servicio service = cache.obtenerServicio(jndiName);
        if (service != null) {
            return service;
        }

        // Paso 2: Si no está, hacer lookup en ContextoInicial y guardarlo en caché
        ContextoInicial context = new ContextoInicial();
        Service newService = (Service) context.buscar(jndiName);
        cache.agregarServicio(newService);
        return newService;
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Observa la diferencia entre la 1ª y la 2ª llamada:

    La primera vez que pides "PaymentService", se ejecuta el costoso ContextoInicial.buscar(). La segunda vez que lo pides, CacheServicios lo intercepta y lo entrega al instante sin tocar la red.

  • 2. Service Locator vs Inyección de Dependencias (Spring):

    En el patrón Service Locator, la clase pide activamente su dependencia (LocalizadorServicios.obtenerServicio(...)). Con Inyección de Dependencias (@Autowired en Spring), el contenedor de Spring busca en su registro interno y te inyecta el objeto automáticamente por constructor.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        System.out.println("--- 1ª Petición de PaymentService ---");
        Servicio service = LocalizadorServicios.obtenerServicio("PaymentService");
        service.ejecutar();

        System.out.println("\n--- 2ª Petición de PaymentService (ya está en caché) ---");
        service = LocalizadorServicios.obtenerServicio("PaymentService");
        service.ejecutar();

        System.out.println("\n--- 1ª Petición de EmailService ---");
        service = LocalizadorServicios.obtenerServicio("EmailService");
        service.ejecutar();
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando trabajes con registros JNDI, descubrimiento de servicios dinámicos o sistemas de plugins donde el servicio a cargar se decide por nombre en tiempo de ejecución.
  • Cuándo evitarlo: Si usas un framework moderno como Spring Boot o Jakarta CDI, prefiere siempre la Inyección de Dependencias por constructor en lugar de llamar manualmente a un Service Locator estático, ya que la inyección por constructor facilita mucho los tests unitarios.
