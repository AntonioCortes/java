Patrón Adapter

El patrón Adapter (Adaptador o Envoltorio/Wrapper) es un patrón estructural que permite que dos clases con interfaces incompatibles puedan trabajar juntas sin tener que modificar su código interno.

Analogía del Mundo Real

Piensa en cuando viajas del Reino Unido o Estados Unidos a España: el enchufe de tu cargador tiene clavijas planas, pero la toma de corriente de la pared tiene agujeros redondos. No desmontas la pared del hotel ni cortas el cable de tu portátil: colocas un adaptador de corriente en medio que recibe tus clavijas planas por un lado y se conecta a los agujeros redondos por el otro.

Propósito

Convertir la interfaz de una clase existente (generalmente de una librería externa o código legado que no podemos cambiar) en otra interfaz que el código cliente espera utilizar.

Caso de Uso Real: Reproductor Multimedia integrando una Librería de Terceros

Contexto: Tu aplicación tiene un reproductor de música (ReproductorAudio) que implementa la interfaz estándar ReproductorMultimedia con el método reproducir(tipoAudio, nombreArchivo). Inicialmente solo sabe reproducir archivos mp3.

El Problema (Sin Adapter): Quieres añadir soporte para formatos mp4 y vlc usando una librería externa (ReproductorAvanzado). Sin embargo, esa librería no tiene el método reproducir(type, file), sino dos métodos completamente distintos: reproducirVlc(file) y reproducirMp4(file). Sus interfaces son incompatibles.

La Solución (Con Adapter): Creamos la clase AdaptadorMultimedia que implementa la interfaz que nuestro sistema espera (ReproductorMultimedia) y guarda dentro una instancia de ReproductorAvanzado. Cuando alguien llama a reproducir("mp4", "video.mp4") sobre el adaptador, este traduce la llamada invocando reproductorAvanzado.reproducirMp4("video.mp4").

Implementación en Java


// 1. Target: Interfaz estándar que nuestra aplicación espera utilizar
interface ReproductorMultimedia {
    void reproducir(String tipoAudio, String nombreArchivo);
}

// 2. Adaptee: Clase de una librería externa con métodos distintos (incompatibles)
class ReproductorAvanzado {
    public void reproducirVlc(String nombreArchivo) {
        System.out.println("[Librería Externa VLC] Reproduciendo archivo VLC: " + nombreArchivo);
    }

    public void reproducirMp4(String nombreArchivo) {
        System.out.println("[Librería Externa MP4] Reproduciendo vídeo MP4: " + nombreArchivo);
    }
}

// 3. Adapter: Implementa la interfaz esperada (ReproductorMultimedia) y traduce hacia el Adaptee
class AdaptadorMultimedia implements ReproductorMultimedia {
    private ReproductorAvanzado advancedMusicPlayer;

    public AdaptadorMultimedia() {
        this.advancedMusicPlayer = new ReproductorAvanzado();
    }

    @Override
    public void reproducir(String tipoAudio, String nombreArchivo) {
        // Traducción de la llamada estándar al método específico de la librería
        if (tipoAudio.equalsIgnoreCase("vlc")) {
            advancedMusicPlayer.reproducirVlc(nombreArchivo);
        } else if (tipoAudio.equalsIgnoreCase("mp4")) {
            advancedMusicPlayer.reproducirMp4(nombreArchivo);
        }
    }
}

// 4. Reproductor principal de nuestra aplicación
class ReproductorAudio implements ReproductorMultimedia {
    private AdaptadorMultimedia adaptador = new AdaptadorMultimedia();

    @Override
    public void reproducir(String tipoAudio, String nombreArchivo) {
        // Formato soportado de forma nativa
        if (tipoAudio.equalsIgnoreCase("mp3")) {
            System.out.println("[Nativo MP3] Reproduciendo canción MP3: " + nombreArchivo);
        }
        // Formatos delegados al Adaptador
        else if (tipoAudio.equalsIgnoreCase("vlc") || tipoAudio.equalsIgnoreCase("mp4")) {
            adaptador.reproducir(tipoAudio, nombreArchivo);
        } else {
            System.out.println("[Error] Formato no soportado: " + tipoAudio);
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Composición sobre Herencia:

    AdaptadorMultimedia guarda un atributo private ReproductorAvanzado (composición) a la vez que implementa ReproductorMultimedia. Gracias a eso, puede actuar como "puente traductor" entre ambos mundos.

  • 2. Código externo intacto:

    En ningún momento hemos tenido que abrir ni modificar el archivo de ReproductorAvanzado (que podría venir compilado dentro de un archivo .jar de terceros).

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        ReproductorAudio player = new ReproductorAudio();

        player.reproducir("mp3", "cancion_rock.mp3");
        player.reproducir("mp4", "tutorial_java.mp4");
        player.reproducir("vlc", "pelicula_hd.vlc");
        player.reproducir("avi", "antiguo.avi");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando necesitas integrar una librería de terceros, un SDK bancario o un sistema legado cuya interfaz no coincide con las interfaces de tu dominio.
  • Cuándo evitarlo: Si eres dueño de ambas clases y puedes refactorizar directamente sus métodos para que coincidan sin necesidad de una clase intermediaria.
