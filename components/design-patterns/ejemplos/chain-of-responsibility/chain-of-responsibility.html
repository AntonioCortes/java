Patrón Chain of Responsibility

El patrón Chain of Responsibility (Cadena de Responsabilidad) es un patrón de comportamiento que permite pasar una solicitud a lo largo de una cadena de manejadores (eslabones). Al recibir una solicitud, cada eslabón decide si puede resolverla él mismo o si debe pasársela al siguiente eslabón de la cadena.

Analogía del Mundo Real

Piensa en cuando llamas al Soporte Técnico de tu compañía de Internet. Primero te atiende un Bot automático (Nivel 1): si solo quieres reiniciar el router, lo resuelve él. Si el problema es más complejo, te pasa con un Operador Técnico (Nivel 2). Y si es una avería grave en la centralita de tu calle, el operador escala el ticket a un Ingeniero de Red (Nivel 3).

Propósito

Desacoplar al emisor de una petición de sus posibles receptores, evitando escribir clases gigantes llenas de if / else if / else anidados y permitiendo añadir, quitar o reordenar eslabones dinámicamente.

Caso de Uso Real: Escalado de Tickets de Soporte o Filtros de Seguridad

Contexto: Un sistema de atención de incidencias recibe tickets clasificados por nivel de gravedad (1 = Básico, 2 = Intermedio, 3 = Crítico).

El Problema (Sin Chain of Responsibility): Tener un único método con un gran bloque if (level == 1) ... else if (level == 2) ... obliga a modificar esa misma clase cada vez que cambia una regla o se añade un cuarto nivel de soporte.

La Solución (Con Chain of Responsibility): Creamos la clase base ManejadorSoporte que guarda una referencia al siguiente eslabón (siguiente). Enlazamos Bot -> Técnico -> Ingeniero. El cliente siempre entrega el ticket al primer eslabón y la cadena se encarga de hacerlo avanzar hasta quien corresponda.

Implementación en Java


// 1. Manejador Abstracto: contiene el puntero al siguiente eslabón (siguiente)
abstract class ManejadorSoporte {
    protected ManejadorSoporte siguiente;

    public void setSiguiente(ManejadorSoporte siguiente) {
        this.siguiente = siguiente;
    }

    public abstract void procesarIncidencia(int severityLevel, String issue);
}

// 2. Eslabón 1: Bot Automático (resuelve nivel 1)
class ManejadorBotNivel1 extends ManejadorSoporte {
    @Override
    public void procesarIncidencia(int severityLevel, String issue) {
        if (severityLevel == 1) {
            System.out.println("[Nivel 1 - Bot] Resuelto automáticamente: " + issue);
        } else if (siguiente != null) {
            System.out.println("[Nivel 1 - Bot] No puedo resolverlo, escalando a Nivel 2...");
            siguiente.procesarIncidencia(severityLevel, issue);
        }
    }
}

// 3. Eslabón 2: Técnico de Soporte (resuelve nivel 2)
class ManejadorTecnicoNivel2 extends ManejadorSoporte {
    @Override
    public void procesarIncidencia(int severityLevel, String issue) {
        if (severityLevel == 2) {
            System.out.println("[Nivel 2 - Técnico] Resuelto por operador humano: " + issue);
        } else if (siguiente != null) {
            System.out.println("[Nivel 2 - Técnico] Requiere ingeniería, escalando a Nivel 3...");
            siguiente.procesarIncidencia(severityLevel, issue);
        }
    }
}

// 4. Eslabón 3: Ingeniero de Sistemas (resuelve nivel 3 o superior)
class ManejadorIngenieroNivel3 extends ManejadorSoporte {
    @Override
    public void procesarIncidencia(int severityLevel, String issue) {
        System.out.println("[Nivel 3 - Ingeniero Senior] Incidencia crítica resuelta: " + issue);
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Una lista enlazada de objetos:

    Cada ManejadorSoporte tiene dentro un campo protected ManejadorSoporte siguiente. Es exactamente igual que los vagones de un tren: cada vagón solo conoce al vagón que lleva enganchado justo detrás.

  • 2. Dos variantes posibles:

    En este ejemplo (Soporte Técnico), uno solo de los eslabones resuelve la petición y corta la cadena. En otros escenarios (como los filtros de seguridad de Spring Security), cada eslabón valida su parte y todos llaman a siguiente si la petición es válida.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // 1. Instanciamos los eslabones
        ManejadorSoporte bot = new ManejadorBotNivel1();
        ManejadorSoporte tech = new ManejadorTecnicoNivel2();
        ManejadorSoporte engineer = new ManejadorIngenieroNivel3();

        // 2. Los enganchamos formando la cadena: Bot -> Técnico -> Ingeniero
        bot.setSiguiente(tech);
        tech.setSiguiente(engineer);

        // 3. Enviamos todas las peticiones siempre al inicio de la cadena (bot)
        System.out.println("--- Ticket A (Nivel 1) ---");
        bot.procesarIncidencia(1, "Olvidé mi contraseña");

        System.out.println("\n--- Ticket B (Nivel 2) ---");
        bot.procesarIncidencia(2, "Mi router parpadea en rojo");

        System.out.println("\n--- Ticket C (Nivel 3) ---");
        bot.procesarIncidencia(3, "Caída total del servidor de base de datos");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando tu programa deba procesar peticiones a través de varios filtros o niveles de validación (autenticación, autorización, rate-limiting, logging) o cuando el conjunto y orden de manejadores deba poder cambiar dinámicamente.
  • Cuándo evitarlo: Si cada petición tiene siempre un único receptor fijo y conocido de antemano.
