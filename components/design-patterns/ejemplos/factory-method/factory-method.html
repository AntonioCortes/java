Patrón Factory Method (Método Fábrica)

El patrón Factory Method (Método Fábrica) es un patrón creacional de diseño que define una interfaz o método para crear un objeto, pero delega en las subclases o en una factoría especializada la decisión de qué clase concreta instanciar, desacoplando el código cliente del operador new y de las implementaciones concretas.

Analogía del Mundo Real: Agencia de Envíos y Logística

Imagina una empresa de mensajería urgente:

  • Cuando un usuario acude al mostrador para enviar un paquete, solo solicita el servicio: "Quiero enviar este paquete a su destino".
  • El cliente no necesita saber si la empresa utilizará un camión diésel, un avión de carga o un buque portacontenedores; tampoco necesita comprar ni mantener el vehículo.
  • El departamento de logística interna (la Factoría) evalúa el destino y la urgencia y proporciona el Transporte adecuado. Para el cliente, todos los transportes cumplen el mismo contrato: entregar(paquete).

Propósito

Separar la lógica de creación de objetos de la lógica de negocio que los utiliza. El cliente trabaja exclusivamente contra una interfaz o abstracción común (ej. Notificacion), mientras que la factoría centraliza las reglas de instanciación, facilitando añadir nuevos tipos de objetos sin modificar el código existente (Principio Open/Closed).

Caso de Uso Real: Sistema de Notificaciones Multicanal en PetShop

Contexto: En la plataforma PetShop, cuando se confirma la adopción o cita médica de una mascota, el sistema debe alertar al usuario a través de su canal preferido: Correo Electrónico (NotificacionEmail), SMS (NotificacionSMS) o Alerta Push (NotificacionPush).

El Problema (Sin Factory Method): Si cada servicio de la aplicación instancia manualmente new NotificacionEmail() o new NotificacionSMS() mediante bloques if-else dispersos, añadir un nuevo canal (como WhatsApp) obligará a modificar y retestear decenas de clases en toda la aplicación.

La Solución (Con Factory Method): Centralizar la instanciación en FabricaNotificaciones, devolviendo siempre el contrato Notificacion. El cliente invoca notificarUsuario(mensaje) con total transparencia.

Implementación en Java


// 1. Interfaz común del Producto
public interface Notificacion {
    void notificarUsuario(String mensaje);
}

// 2. Productos Concretos
public class NotificacionEmail implements Notificacion {
    @Override
    public void notificarUsuario(String mensaje) {
        System.out.println("✉️ [EMAIL] Enviando correo electrónico a la bandeja de entrada: " + mensaje);
    }
}

public class NotificacionSMS implements Notificacion {
    @Override
    public void notificarUsuario(String mensaje) {
        System.out.println("📱 [SMS] Transmitiendo SMS a la red móvil: " + mensaje);
    }
}

public class NotificacionPush implements Notificacion {
    @Override
    public void notificarUsuario(String mensaje) {
        System.out.println("🔔 [PUSH] Emitiendo notificación push al dispositivo móvil: " + mensaje);
    }
}

// 3. Creador / Factoría (Factory Method Parametrizado)
public class FabricaNotificaciones {
    public Notificacion crearNotificacion(String canal) {
        if (canal == null || canal.isBlank()) {
            throw new IllegalArgumentException("El canal de notificación no puede ser nulo o vacío.");
        }
        switch (canal.toUpperCase()) {
            case "EMAIL":
                return new NotificacionEmail();
            case "SMS":
                return new NotificacionSMS();
            case "PUSH":
                return new NotificacionPush();
            default:
                throw new IllegalArgumentException("Canal de mensajería no soportado: " + canal);
        }
    }
}
Implementación completa y limpia del patrón Factory Method en Java

Diferencia Clave: Simple Factory vs Factory Method Clásico (GoF)

  • Simple Factory (La más habitual en la práctica): Una clase estática o utilitaria con un método crearNotificacion(tipo) que contiene el switch de instanciación. Es compacta y directa para el 90% de los casos.
  • Factory Method Clásico (Gang of Four): La clase creadora es abstracta (abstract class CreadorNotificacion) con el método abstracto abstract Notificacion crear(). Cada canal tiene su propio creador concreto (CreadorEmail, CreadorSMS). Permite añadir canales sin modificar siquiera el switch de la factoría principal.

Ejemplo de Uso y Trazas de Consola


public class Main {
    public static void main(String[] args) {
        FabricaNotificaciones fabrica = new FabricaNotificaciones();

        // El cliente solicita notificaciones indicando el canal sin usar operadores 'new' directos
        System.out.println("1. Alerta de confirmación de cita médica:");
        Notificacion alertaEmail = fabrica.crearNotificacion("EMAIL");
        alertaEmail.notificarUsuario("Tu cita para vacunación de 'Max' está confirmada para el viernes.");

        System.out.println("\n2. Código de autenticación de dos factores (2FA):");
        Notificacion alertaSMS = fabrica.crearNotificacion("SMS");
        alertaSMS.notificarUsuario("Tu código temporal de acceso es: 749-102.");

        System.out.println("\n3. Aviso de entrega a domicilio:");
        Notificacion alertaPush = fabrica.crearNotificacion("PUSH");
        alertaPush.notificarUsuario("El transportista está a 5 minutos de tu domicilio.");
    }
}

Antipatrón: Acoplamiento extremo que rompe el principio de sustitución y dificulta los tests

¿Cuándo usarlo y cuándo NO usarlo?

Cuándo SÍ Usar Factory Method Cuándo NO Usarlo
Cuando no se conoce con antelación el tipo exacto de objeto que se necesitará hasta el momento de ejecución (depende de parámetros del usuario, cabeceras o base de datos). Cuando el sistema solo cuenta con una clase concreta fija y nunca existirá variación polimórfica (crear una interfaz y factoría para una sola clase es sobreingeniería).
Para desacoplar el cliente de librerías externas o frameworks propietarios. En clases de datos simples (POJOs, DTOs o records inmutables) donde un constructor o Builder es mucho más natural.
Cuando se requiera facilitar la extensión de una librería permitiendo a otros programadores introducir nuevos productos. Si la creación del objeto involucra familias completas de productos relacionados que deben combinar entre sí (en tal caso se debe usar Abstract Factory).
