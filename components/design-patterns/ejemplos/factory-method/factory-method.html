Patrón Factory Method

El patrón Factory Method (Método Fábrica) es un patrón creacional que centraliza la creación de objetos a través de un método especializado, devolviendo los objetos bajo una interfaz común en lugar de acoplar el código cliente a clases concretas con new.

Analogía del Mundo Real

Piensa en una empresa de logística y mensajería. Cuando contratas un envío en el mostrador, tú solo pides "enviar este paquete" (notificarUsuario). No vas tú mismo al garaje a comprar un camión, un barco o una furgoneta. El departamento de despacho (la Fábrica) decide internamente qué medio de transporte concreto preparar según el destino, pero para ti todos cumplen exactamente el mismo contrato: entregar el paquete.

Propósito

Separar el código que usa los objetos del código que los construye. El cliente trabaja únicamente con una interfaz abstracta (por ejemplo, Notificacion) y delega en la fábrica la decisión de qué clase concreta instanciar.

Caso de Uso Real: Sistema de Notificaciones Multicanal

Contexto: Una aplicación bancaria necesita enviar alertas a los clientes por distintos canales según sus preferencias: Email, SMS o Notificaciones Push móviles.

El Problema (Sin Factory Method): Si repartes sentencias new NotificacionEmail() y new NotificacionSMS() por decenas de clases de tu aplicación, tu lógica de negocio queda fuertemente acoplada a esas clases concretas. Si mañana cambias el constructor de NotificacionSMS o añades un canal de WhatsApp, tendrás que modificar código en toda la aplicación.

La Solución (Con Factory Method): Creas una interfaz Notificacion con el método notificarUsuario(), y una clase FabricaNotificaciones cuyo método crearNotificacion(canal) encapsula el switch y los operadores new. El resto de la aplicación solo conoce la interfaz Notificacion.

Implementación en Java


// 1. Interfaz Producto: contrato común para cualquier tipo de notificación
interface Notificacion {
    void notificarUsuario(String mensaje);
}

// 2. Productos Concretos: cada uno implementa el envío a su manera
class NotificacionEmail implements Notificacion {
    @Override
    public void notificarUsuario(String mensaje) {
        System.out.println("[EMAIL] Enviando correo electrónico: " + mensaje);
    }
}

class NotificacionSMS implements Notificacion {
    @Override
    public void notificarUsuario(String mensaje) {
        System.out.println("[SMS] Enviando mensaje de texto: " + mensaje);
    }
}

class NotificacionPush implements Notificacion {
    @Override
    public void notificarUsuario(String mensaje) {
        System.out.println("[PUSH] Enviando alerta móvil: " + mensaje);
    }
}

// 3. Clase Fábrica: único lugar donde se hace 'new' de los productos
class FabricaNotificaciones {
    public Notification crearNotificacion(String channel) {
        if (canal == null || canal.isEmpty()) {
            throw new IllegalArgumentException("El canal no puede estar vacío");
        }
        switch (canal.toUpperCase()) {
            case "EMAIL":
                return new NotificacionEmail();
            case "SMS":
                return new NotificacionSMS();
            case "PUSH":
                return new NotificacionPush();
            default:
                throw new IllegalArgumentException("Canal desconocido: " + canal);
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Programar hacia una interfaz, no hacia una implementación:

    Fíjate en el tipo de retorno de crearNotificacion(String channel): devuelve Notificacion (la interfaz), no NotificacionEmail. Gracias al polimorfismo, el cliente puede guardar cualquier notificación en una variable de tipo Notificacion y llamar a notificarUsuario() con total transparencia.

  • 2. Principio de Responsabilidad Única (SRP):

    Hemos sacado la lógica de decisión y construcción fuera del código de negocio y la hemos concentrado en FabricaNotificaciones. Si mañana hay que añadir un cuarto canal (NotificacionSlack), solo añadimos la nueva clase y un case "SLACK" en la fábrica.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        FabricaNotificaciones fabrica = new FabricaNotificaciones();

        // El cliente pide objetos por su identificador lógico, sin usar 'new NotificacionEmail()'
        Notificacion alerta1 = fabrica.crearNotificacion("EMAIL");
        alerta1.notificarUsuario("Tu factura de octubre ya está disponible.");

        Notificacion alerta2 = fabrica.crearNotificacion("SMS");
        alerta2.notificarUsuario("Código de verificación: 849201");

        Notificacion alerta3 = fabrica.crearNotificacion("PUSH");
        alerta3.notificarUsuario("Has recibido una transferencia de 50,00 EUR.");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando no sabes de antemano qué tipo exacto de objeto necesitarás crear hasta el momento de ejecución (por ejemplo, según un parámetro del usuario, un archivo de configuración o un evento entrante).
  • Cuándo evitarlo: Si tu aplicación solo tiene una clase concreta y nunca va a variar, crear una interfaz y una fábrica añadirá complejidad innecesaria.
