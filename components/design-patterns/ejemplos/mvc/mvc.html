Patrón Model View Controller (MVC)

El patrón Model-View-Controller (MVC) es el patrón arquitectónico más famoso del desarrollo de software interactivo. Divide una aplicación en tres componentes con responsabilidades estrictamente separadas: el Modelo (los datos y reglas de negocio), la Vista (la pantalla que ve el usuario) y el Controlador (el cerebro coordinador que recibe las órdenes del usuario).

Analogía del Mundo Real

Piensa en una tienda de ropa: el almacén con las prendas y sus precios reales es el Modelo. El escaparate de cristal donde se exhiben los maniquíes a la calle es la Vista. Y el dependiente que atiende al cliente, busca la talla en el almacén y actualiza el escaparate es el Controlador.

Propósito

Separar la lógica de datos de la interfaz visual para que puedas cambiar por completo el diseño de la pantalla sin romper las reglas de negocio, o reutilizar los mismos datos en una web, una app móvil o un PDF.

Caso de Uso Real: Gestión de Perfil de Usuario en una Aplicación Web

Contexto: Tienes los datos de un cliente (ModeloUsuario), una pantalla que muestra su ficha (VistaUsuario) y un controlador que procesa los cambios cuando el usuario actualiza su email (ControladorUsuario).

El Problema (Sin MVC): Si mezclas consultas de datos, validaciones y generación de HTML en una sola clase gigante, cualquier cambio estético puede borrar por accidente una validación de negocio, y es imposible hacer tests unitarios limpios.

La Solución (Con MVC):
1. ModeloUsuario guarda los datos (username, email) y no sabe nada de pantallas ni de HTML.
2. VistaUsuario solo sabe imprimir los datos en pantalla.
3. ControladorUsuario recibe la petición del usuario, actualiza el ModeloUsuario y le pide a VistaUsuario que vuelva a pintar la pantalla actualizada.

Model (Modelo) ModeloUsuario Representa el estado de los datos y las reglas de negocio. Es 100% independiente de cómo se muestre en pantalla.
View (Vista) VistaUsuario Se encarga exclusivamente de presentar la información al usuario de forma legible.
Controller (Controlador) ControladorUsuario Actúa como intermediario: recibe las entradas del usuario, modifica el ModeloUsuario y refresca la VistaUsuario.

Implementación en Java


// 1. MODELO (Model): Contiene los datos y estado del negocio
class ModeloUsuario {
    private String username;
    private String email;

    public ModeloUsuario(String username, String email) {
        this.username = username;
        this.email = email;
    }

    public String getNombreUsuario() { return username; }
    public String getEmail() { return email; }

    public void setEmail(String email) {
        this.email = email;
    }
}

// 2. VISTA (View): Solo se encarga de mostrar los datos por pantalla
class VistaUsuario {
    public void mostrarDetallesUsuario(String username, String email) {
        System.out.println("🖥️ [VISTA - Ficha de Usuario]");
        System.out.println("   👤 Nombre : " + username);
        System.out.println("   ✉️ Email  : " + email);
    }
}

// 3. CONTROLADOR (Controller): Coordina las peticiones entre Modelo y Vista
class ControladorUsuario {
    private ModeloUsuario model;
    private VistaUsuario view;

    public ControladorUsuario(ModeloUsuario model, VistaUsuario view) {
        this.model = model;
        this.view = view;
    }

    public void actualizarEmail(String newEmail) {
        System.out.println(">> [CONTROLADOR] Recibida petición para cambiar email a: " + newEmail);
        model.setEmail(newEmail);
    }

    public void actualizarVista() {
        view.mostrarDetallesUsuario(model.getNombreUsuario(), model.getEmail());
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Por qué ModeloUsuario no tiene un atributo VistaUsuario?

    Porque el Modelo debe ser reutilizable en cualquier sitio. Si mañana quieres mostrar ese mismo ModeloUsuario en una aplicación de móvil o exportarlo a Excel, puedes hacerlo sin tocar ni una coma de ModeloUsuario.

  • 2. Trabajo en equipo sin pisarse:

    Un diseñador frontend puede estar editando la Vista mientras un desarrollador backend programa el Modelo y el Controlador en paralelo.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // 1. Inicializamos el Modelo, la Vista y el Controlador
        ModeloUsuario model = new ModeloUsuario("antonio_java", "antonio.antiguo@correo.es");
        VistaUsuario view = new VistaUsuario();
        ControladorUsuario controller = new ControladorUsuario(model, view);

        // 2. Mostramos la pantalla inicial
        System.out.println("--- Estado Inicial ---");
        controller.actualizarVista();

        // 3. El usuario interactúa con el Controlador para actualizar su correo
        System.out.println("\n--- Usuario actualiza su correo ---");
        controller.actualizarEmail("antonio.nuevo@empresa.com");

        // 4. El Controlador refresca la Vista con los nuevos datos del Modelo
        controller.actualizarVista();
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Como arquitectura base de prácticamente cualquier aplicación web o de escritorio con interfaz de usuario (Spring MVC, Jakarta MVC, Ruby on Rails, ASP.NET MVC).
  • Cuándo evitarlo: En pequeños scripts de consola o demonios de procesamiento por lotes que no tienen interfaz de usuario.
