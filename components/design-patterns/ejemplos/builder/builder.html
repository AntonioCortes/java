Patrón Builder

El patrón Builder (Constructor) es un patrón creacional que permite construir objetos complejos paso a paso. En lugar de obligar al programador a usar un constructor gigante lleno de parámetros confusos, proporciona métodos claros y encadenables para configurar solo las piezas deseadas.

Analogía del Mundo Real

Piensa en pedir una pizza personalizada en una pizzería. En lugar de rellenar una tabla con 25 casillas donde tienes que escribir "sin anchoas, sin piña, sin aceitunas, sin jalapeños...", simplemente vas eligiendo paso a paso lo que sí quieres: primero eliges el tipo de masa, luego la salsa, después el ingrediente principal y finalmente dices "¡al horno!" (construir()).

Propósito

Separar la construcción de un objeto complejo de su representación final, evitando el anti-patrón conocido como Telescoping Constructor (tener múltiples constructores con 6, 8 o 10 parámetros donde muchos se pasan como null).

Caso de Uso Real: Configuración de Pedidos o Consultas con Parámetros Opcionales

Contexto: Tienes una clase Pizza (o una petición HTTP, o una consulta SQL) donde algunos atributos son habituales y otros son completamente opcionales (masa, salsa, ingrediente extra, borde relleno de queso).

El Problema (Sin Builder): Llamar a new Pizza("Fina", "Tomate", null, true, false, "Orégano") es ilegible. Si te equivocas en el orden de dos String seguidos, el compilador no te avisará y habrás puesto la salsa donde iba la masa.

La Solución (Con Builder): Creas la clase ConstructorPizza con métodos descriptivos (conMasa("Fina"), conSalsa("Tomate")). Cada método configura un paso y devuelve el propio Builder (return this), permitiendo encadenar llamadas de forma autoexplicativa hasta invocar construir().

Implementación en Java


// 1. Producto final que queremos construir
class Pizza {
    private String masa;
    private String salsa;
    private String ingrediente;

    public void setMasa(String masa) { this.masa = masa; }
    public void setSalsa(String salsa) { this.salsa = salsa; }
    public void setIngrediente(String ingrediente) { this.ingrediente = ingrediente; }

    @Override
    public String toString() {
        return "Pizza [masa=" + masa + ", salsa=" + salsa + ", ingrediente=" + ingrediente + "]";
    }
}

// 2. Clase Builder: construye la Pizza paso a paso
class ConstructorPizza {
    private Pizza pizza;

    public ConstructorPizza() {
        this.pizza = new Pizza();
    }

    // Cada método configura una parte y devuelve 'this' para poder encadenar llamadas
    public ConstructorPizza conMasa(String masa) {
        pizza.setMasa(masa);
        return this;
    }

    public ConstructorPizza conSalsa(String salsa) {
        pizza.setSalsa(salsa);
        return this;
    }

    public ConstructorPizza conIngrediente(String ingrediente) {
        pizza.setIngrediente(ingrediente);
        return this;
    }

    // Paso final: valida si es necesario y devuelve el objeto construido
    public Pizza construir() {
        return this.pizza;
    }
}
Implementación del patrón Builder con métodos encadenables

Análisis Paso a Paso para Principiantes

  • 1. ¿Cuál es el truco del encadenamiento (return this)?

    Fíjate en que conMasa() no devuelve void, sino ConstructorPizza, y su última línea es return this;. Eso significa: "devuélveme a mí mismo (el Builder) para que en la misma línea puedas seguir llamando a otro método mío como .conSalsa()". Esta técnica se llama Fluent Interface (Interfaz Fluida).

  • 2. Parámetros opcionales sin pasar null:

    Si un cliente quiere una pizza solo con masa gruesa (focaccia), simplemente llama a new ConstructorPizza().conMasa("Gruesa").construir(). No tiene que preocuparse por los demás atributos.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // Construcción completa paso a paso
        Pizza pepperoniPizza = new ConstructorPizza()
                .conMasa("Fina y crujiente")
                .conSalsa("Tomate natural")
                .conIngrediente("Pepperoni y Mozzarella")
                .construir();

        System.out.println("Pedido 1: " + pepperoniPizza);

        // Construcción parcial omitiendo pasos opcionales (sin pasar 'null')
        Pizza focaccia = new ConstructorPizza()
                .conMasa("Gruesa artesanal")
                .conIngrediente("Romero y aceite de oliva")
                .construir();

        System.out.println("Pedido 2: " + focaccia);
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando una clase tenga más de 3 o 4 parámetros en su constructor, especialmente si varios de ellos son opcionales o del mismo tipo de dato (String, boolean), o cuando quieras construir objetos inmutables paso a paso (muy común con la anotación @Builder de Lombok).
  • Cuándo evitarlo: En objetos muy simples de 1 o 2 atributos obligatorios donde un constructor normal es directo y claro.
