Patrón Interpreter

El patrón Interpreter (Intérprete) es un patrón de comportamiento que define una representación en clases para la gramática de un lenguaje sencillo, permitiendo evaluar o interpretar expresiones escritas en ese lenguaje.

Analogía del Mundo Real

Piensa en leer una partitura musical o evaluar un filtro de búsqueda como ("Java" Y "Spring"). Cada símbolo básico (una palabra clave o una nota musical) es una expresión terminal, y los conectores (Y, O) combinan dos expresiones para producir un resultado final verdadero o falso.

Propósito

Representar cada regla gramatical (palabras clave, operadores AND, OR, sumas, restas) como una clase que implementa un método común interpretar(contexto), formando un árbol de expresiones (Árbol de Sintaxis Abstracta o AST).

Caso de Uso Real: Motor de Reglas de Filtrado de Currículums (RRHH)

Contexto: Un portal de empleo necesita evaluar automáticamente si la descripción de un candidato cumple ciertas reglas lógicas configurables, como por ejemplo: "Conoce Java O C#" o "Es Senior Y sabe SQL".

El Problema (Sin Interpreter): Si intentas programar todas las combinaciones posibles de búsqueda con métodos fijos, cada vez que RRHH quiera una regla nueva tendrás que programar un método nuevo.

La Solución (Con Interpreter): Creamos ExpresionTerminal (comprueba si una palabra aparece en el texto), ExpresionO (evalúa expr1 || expr2) y ExpresionY (evalúa expr1 && expr2). Combinando objetos de estas 3 clases podemos construir cualquier regla lógica imaginable.

Implementación en Java


// 1. Interfaz Expresión Abstracta
interface Expresion {
    boolean interpretar(String context);
}

// 2. Expresión Terminal (Hoja): busca una palabra clave en el texto
class ExpresionTerminal implements Expresion {
    private String palabraClave;

    public ExpresionTerminal(String palabraClave) {
        this.palabraClave = palabraClave;
    }

    @Override
    public boolean interpretar(String context) {
        return context.contains(palabraClave);
    }
}

// 3. Expresión No-Terminal OR: devuelve true si cualquiera de las dos se cumple
class ExpresionO implements Expresion {
    private Expresion expr1;
    private Expresion expr2;

    public ExpresionO(Expresion expr1, Expresion expr2) {
        this.expr1 = expr1;
        this.expr2 = expr2;
    }

    @Override
    public boolean interpretar(String context) {
        return expr1.interpretar(context) || expr2.interpretar(context);
    }
}

// 4. Expresión No-Terminal AND: devuelve true solo si ambas se cumplen
class ExpresionY implements Expresion {
    private Expresion expr1;
    private Expresion expr2;

    public ExpresionY(Expresion expr1, Expresion expr2) {
        this.expr1 = expr1;
        this.expr2 = expr2;
    }

    @Override
    public boolean interpretar(String context) {
        return expr1.interpretar(context) && expr2.interpretar(context);
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Relación con el patrón Composite:

    Si observas el diagrama, la estructura es un árbol idéntico al patrón Composite: ExpresionTerminal son las hojas y ExpresionY/ExpresionO son los nodos compuestos. La diferencia es que el propósito aquí es evaluar reglas de un lenguaje.

  • 2. Evaluación recursiva:

    Al llamar a regla.interpretar("Candidato con Java y SQL") en la raíz del árbol, cada nodo evalúa a sus hijos hasta llegar a las palabras individuales y combina los booleanos de vuelta hacia arriba.

Ejemplo de Uso


public class Main {
    // Regla 1: El candidato debe saber "Java" O "Python"
    public static Expresion buildDeveloperRule() {
        Expresion java = new ExpresionTerminal("Java");
        Expresion python = new ExpresionTerminal("Python");
        return new ExpresionO(java, python);
    }

    // Regla 2: El candidato debe saber "Java" Y "Spring"
    public static Expresion buildSpringSpecialistRule() {
        Expresion java = new ExpresionTerminal("Java");
        Expresion spring = new ExpresionTerminal("Spring");
        return new ExpresionY(java, spring);
    }

    public static void main(String[] args) {
        Expresion isDeveloper = buildDeveloperRule();
        Expresion isSpringSpecialist = buildSpringSpecialistRule();

        String cv1 = "Ingeniero con experiencia en Python y Docker";
        String cv2 = "Desarrollador Backend experto en Java y Spring Boot";

        System.out.println("CV 1: \"" + cv1 + "\"");
        System.out.println("  ¿Cumple regla Desarrollador (Java OR Python)?: " + isDeveloper.interpretar(cv1));
        System.out.println("  ¿Cumple regla Especialista (Java AND Spring)?: " + isSpringSpecialist.interpretar(cv1));

        System.out.println("\nCV 2: \"" + cv2 + "\"");
        System.out.println("  ¿Cumple regla Especialista (Java AND Spring)?: " + isSpringSpecialist.interpretar(cv2));
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Para evaluar reglas de negocio sencillas, filtros de búsqueda, expresiones matemáticas básicas o motores de promociones.
  • Cuándo evitarlo: Si la gramática tiene decenas de reglas complejas (como un lenguaje de programación completo o SQL avanzado), ya que el número de clases crecería demasiado; en esos casos se utilizan generadores de parsers como ANTLR.
