Patrón Proxy

El patrón Proxy (Sustituto o Apoderado) es un patrón estructural que proporciona un objeto representante que controla el acceso a otro objeto real. Al implementar exactamente la misma interfaz que el objeto real, el Proxy puede interceptar las llamadas para realizar tareas antes o después (como carga perezosa, caché, control de permisos o registro de logs).

Analogía del Mundo Real

Piensa en una tarjeta de débito bancaria. La tarjeta es un Proxy de tu dinero en efectivo guardado en la cámara acorazada del banco (el Objeto Real). Para el comerciante, cobrar con tarjeta o cobrar en efectivo cumple la misma interfaz ("pagar"), pero la tarjeta intercepta la operación, verifica si tienes saldo o permisos y solo mueve el dinero real cuando se confirma la compra.

Propósito

Actuar como intermediario transparente del objeto real para gestionar su ciclo de vida o proteger su acceso. Sus variantes más famosas son: Virtual Proxy (carga diferida / Lazy Loading), Protection Proxy (control de permisos) y Caching Proxy (guardar respuestas en caché).

Caso de Uso Real: Carga Diferida (Lazy Loading) de Imágenes Pesadas

Contexto: Un catálogo tiene 500 fotografías en alta resolución (ImagenReal). Cargar cada foto desde el disco duro o desde internet tarda mucho tiempo y consume mucha memoria.

El Problema (Sin Proxy): Si al abrir la pantalla instancias las 500 ImagenReal de golpe, la aplicación se quedará congelada cargando fotos que el usuario quizá ni siquiera llegue a mirar.

La Solución (Con Virtual Proxy): La lista carga 500 objetos ImagenProxy ultraligeros que implementan la interfaz Imagen pero aún no han leído el disco. Solo cuando el usuario hace clic en una foto y se invoca mostrar(), el ImagenProxy instancia por primera vez a ImagenReal y además la guarda en memoria por si vuelve a mostrarse.

Implementación en Java


// 1. Interfaz común para el Objeto Real y para el Proxy
interface Imagen {
    void mostrar();
}

// 2. Objeto Real: pesado de instanciar porque carga el archivo en su constructor
class ImagenReal implements Imagen {
    private String nombreArchivo;

    public ImagenReal(String nombreArchivo) {
        this.nombreArchivo = nombreArchivo;
        cargarDesdeDisco(nombreArchivo);
    }

    private void cargarDesdeDisco(String nombreArchivo) {
        System.out.println(">> [DISCO] Cargando archivo pesado de 25MB: " + nombreArchivo + "...");
    }

    @Override
    public void mostrar() {
        System.out.println("🖼 Mostrando en pantalla la imagen: " + nombreArchivo);
    }
}

// 3. Proxy: objeto ligero que retrasa la creación de ImagenReal hasta que sea indispensable
class ImagenProxy implements Imagen {
    private ImagenReal imagenReal;
    private String nombreArchivo;

    public ImagenProxy(String nombreArchivo) {
        this.nombreArchivo = nombreArchivo;
    }

    @Override
    public void mostrar() {
        // Lazy Loading: solo creamos ImagenReal la primera vez que alguien pide verla
        if (imagenReal == null) {
            imagenReal = new ImagenReal(nombreArchivo);
        } else {
            System.out.println(">> [CACHÉ PROXY] La imagen ya estaba en memoria, evitando lectura de disco.");
        }
        imagenReal.mostrar();
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Por qué Spring Boot e Hibernate usan tanto el patrón Proxy?

    En Hibernate/JPA, cuando tienes una relación FetchType.LAZY, Hibernate te entrega un Proxy en vez de hacer un SELECT inmediato a la base de datos. Y en Spring, anotaciones como @Transactional o @Cacheable funcionan creando un Proxy alrededor de tu @Service que abre la transacción antes de llamar a tu método y hace commit al terminar.

  • 2. Diferencia entre Decorator y Proxy:

    Aunque su estructura UML se parece mucho, en Decorator el cliente envuelve manualmente los objetos para sumar funcionalidades (leche + azúcar), mientras que el Proxy controla el acceso y suele gestionar él mismo la creación del objeto real sin que el cliente tenga que instanciarlo.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        System.out.println("1. Creando el ImagenProxy...");
        Image image = new ImagenProxy("paisaje_8k.jpg");
        System.out.println("Proxy creado al instante (aún no se ha tocado el disco duro).\n");

        System.out.println("2. Primera llamada a image.mostrar():");
        image.mostrar();

        System.out.println("\n3. Segunda llamada a image.mostrar():");
        image.mostrar();
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando tengas objetos muy pesados que no siempre se llegan a utilizar (Lazy Loading), cuando necesites comprobar permisos antes de ejecutar un método sensible, o para medir tiempos de ejecución y guardar logs sin ensuciar la clase de negocio.
  • Cuándo evitarlo: Si el objeto original es ligero, rápido y no requiere control de acceso ni caché.
