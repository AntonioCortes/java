Patrón Template Method

El patrón Template Method (Método Plantilla) es un patrón de comportamiento que define el esqueleto fijo de un algoritmo en una clase padre abstracta, pero deja que las subclases personalicen ciertos pasos concretos sin poder alterar el orden general de la receta.

Analogía del Mundo Real

Piensa en la construcción de viviendas en una urbanización. El arquitecto jefe fija el orden inalterable de la obra (el Método Plantilla): 1. Cimientos -> 2. Estructura -> 3. Fontanería -> 4. Pintura y Acabados. Ningún constructor puede pintar antes de poner los cimientos, pero cada subcontratista puede personalizar cómo se hace el paso 4 (unos pintan en blanco y ponen suelo de madera, otros pintan en beige y ponen cerámica).

Propósito

Evitar la duplicación de código cuando varias clases comparten exactamente la misma secuencia de pasos de un algoritmo, diferenciándose únicamente en cómo se implementan algunos de esos pasos.

Caso de Uso Real: Ciclo de Partida en un Motor de Videojuegos

Contexto: Estás programando un motor deportivo para distintos juegos (Ajedrez y Futbol). En todos los deportes, una partida siempre sigue el mismo orden obligatorio: 1. Inicializar campo y equipos (inicializar()) $\rightarrow$ 2. Empezar el partido (iniciarJuego()) $\rightarrow$ 3. Finalizar y mostrar marcador (finalizarJuego()).

El Problema (Sin Template Method): Si cada deporte programa su propio método jugar() por libre, duplicarás la estructura de control y algún programador podría olvidarse de llamar a inicializar() antes de iniciarJuego().

La Solución (Con Template Method): En la clase abstracta Juego creamos el método public final void jugar() que llama en orden a inicializar(), iniciarJuego() y finalizarJuego(). Al ser final, ninguna subclase puede alterar el orden, solo rellenar qué ocurre en cada paso.

Implementación en Java


// 1. Clase Abstracta que contiene el Método Plantilla
abstract class Juego {
    // Pasos abstractos que cada subclase personalizará
    protected abstract void inicializar();
    protected abstract void iniciarJuego();
    protected abstract void finalizarJuego();

    // MÉTODO PLANTILLA: es 'final' para que ninguna subclase pueda cambiar el orden de los pasos
    public final void jugar() {
        inicializar();
        iniciarJuego();
        finalizarJuego();
    }
}

// 2. Subclase Concreta A: Ajedrez
class Ajedrez extends Juego {
    @Override
    protected void inicializar() {
        System.out.println("[Ajedrez] Preparando bateadores y campo ovalado.");
    }

    @Override
    protected void iniciarJuego() {
        System.out.println("[Ajedrez] ¡Comienza el partido de Ajedrez!");
    }

    @Override
    protected void finalizarJuego() {
        System.out.println("[Ajedrez] Partido de Ajedrez finalizado. Mostrando puntuación.");
    }
}

// 3. Subclase Concreta B: Fútbol
class Futbol extends Juego {
    @Override
    protected void inicializar() {
        System.out.println("[Fútbol] Colocando porterías, balón en el centro y 11 jugadores por equipo.");
    }

    @Override
    protected void iniciarJuego() {
        System.out.println("[Fútbol] ¡Pitido inicial del árbitro! Rueda el balón.");
    }

    @Override
    protected void finalizarJuego() {
        System.out.println("[Fútbol] Minuto 90: Final del partido de Fútbol.");
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Por qué el método jugar() lleva la palabra clave final?

    En Java, un método marcado como final no puede ser sobrescrito (@Override) por ninguna clase hija. Así protegemos la "receta" para que nadie pueda por error llamar a finalizarJuego() antes de inicializar().

  • 2. El "Principio de Hollywood" (No nos llames, nosotros te llamaremos):

    El cliente solo llama a game.jugar() en la clase padre, y es la clase padre quien va llamando automáticamente a los métodos de las clases hijas en el momento oportuno.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        System.out.println("--- Ejecutando plantilla con Ajedrez ---");
        Juego game = new Ajedrez();
        game.jugar();

        System.out.println("\n--- Ejecutando la misma plantilla con Fútbol ---");
        game = new Futbol();
        game.jugar();
    }
}
El método plantilla garantiza siempre la misma secuencia de ejecución

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando varias clases tengan algoritmos casi idénticos paso a paso (como importar archivos PDF/CSV/XML donde abrir, validar, procesar y cerrar siempre siguen el mismo orden).
  • Cuándo evitarlo: Si el orden de los pasos cambia radicalmente entre una clase y otra; en ese caso es preferible usar el patrón Strategy (basado en composición en vez de herencia).
