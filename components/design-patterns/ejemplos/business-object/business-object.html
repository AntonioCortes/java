Patrón Business Object

El patrón Business Object (Objeto de Negocio) es un patrón de la capa de negocio de Java EE que propone diseñar clases de dominio que contengan tanto los datos como las reglas de negocio, validaciones y cálculos propios de ese concepto empresarial.

Analogía del Mundo Real

Piensa en una Caja Fuerte inteligente con bloqueo de seguridad frente a una simple caja de cartón abierta. En una caja de cartón (un objeto solo con getters y setters), cualquiera puede meter un saldo negativo o sacar dinero cuando está cerrada. En cambio, la Caja Fuerte (Business Object) guarda el dinero en su interior y tiene sus propios mecanismos internos que impiden retirar más dinero del que hay o modificar una factura que ya ha sido pagada.

Propósito

Evitar el anti-patrón del Modelo de Dominio Anémico (clases que solo tienen atributos, getters y setters sin ninguna lógica), asegurando una alta cohesión al colocar las reglas de negocio justo al lado de los datos que protegen.

Caso de Uso Real: Facturación con Reglas de Integridad (Factura y LineaFactura)

Contexto: En un sistema contable, una factura (Factura) contiene líneas de detalle (LineaFactura) y debe cumplir reglas estrictas: ninguna línea puede tener precio o cantidad negativa, y una vez que la factura se marca como pagada, está prohibido añadirle líneas nuevas.

El Problema (Con Modelo Anémico): Si Factura tiene un public void setItems(...) libre y los cálculos del total e IVA están dispersos en 5 controladores distintos, tarde o temprano alguien modificará una factura ya pagada o calculará mal el IVA en una pantalla.

La Solución (Con Business Object): Factura encapsula su lista de líneas y ofrece métodos de negocio ricos: agregarLinea(item) (que comprueba si ya está pagada), calcularSubtotal(), calcularTotalConImpuestos(iva) y marcarComoPagada().

Implementación en Java


import java.util.ArrayList;
import java.util.List;

// 1. Business Object de Línea de Factura (valida sus propios datos y calcula su subtotal)
class LineaFactura {
    private final String productName;
    private final int quantity;
    private final double unitPrice;

    public LineaFactura(String productName, int quantity, double unitPrice) {
        if (quantity <= 0 || unitPrice < 0) {
            throw new IllegalArgumentException("La cantidad y el precio deben ser positivos.");
        }
        this.productName = productName;
        this.quantity = quantity;
        this.unitPrice = unitPrice;
    }

    public double calcularTotalLinea() {
        return quantity * unitPrice;
    }

    public String getProductName() { return productName; }
}

// 2. Business Object Principal: Factura con comportamiento y reglas de negocio ricas
class Factura {
    private final String invoiceNumber;
    private final List<LineaFactura> items = new ArrayList<>();
    private boolean paid = false;

    public Factura(String invoiceNumber) {
        this.invoiceNumber = invoiceNumber;
    }

    // Regla de negocio 1: No se pueden añadir conceptos a una factura ya pagada
    public void agregarLinea(LineaFactura item) {
        if (paid) {
            throw new IllegalStateException("Error: No se puede modificar la factura " + invoiceNumber + " porque ya está PAGADA.");
        }
        items.add(item);
        System.out.println("➕ Añadido a factura " + invoiceNumber + ": " + item.getProductName() + " (" + item.calcularTotalLinea() + " EUR)");
    }

    // Comportamiento de negocio 2: Cálculo del subtotal
    public double calcularSubtotal() {
        double sum = 0;
        for (LineaFactura item : items) {
            sum += item.calcularTotalLinea();
        }
        return sum;
    }

    // Comportamiento de negocio 3: Cálculo del total con impuestos (IVA)
    public double calcularTotalConImpuestos(double taxPercentage) {
        double subtotal = calcularSubtotal();
        return subtotal + (subtotal * (taxPercentage / 100.0));
    }

    public void marcarComoPagada() {
        this.paid = true;
        System.out.println("✅ Factura " + invoiceNumber + " marcada oficialmente como PAGADA.");
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Qué es una "Invariante de Negocio"?

    Es una regla que siempre debe cumplirse para que el objeto sea válido (por ejemplo: "una factura pagada no se puede alterar"). Al poner el chequeo if (paid) throw ... dentro de Factura.agregarLinea(), es imposible que ningún programador se salte esa regla en ninguna parte del programa.

  • 2. Business Object vs DTO (Transfer Object):

    Un DTO es solo una caja tonta sin lógica para transportar datos por la red (JSON). Un Business Object vive en el corazón de tu servidor y contiene la inteligencia de tu negocio (base de Domain-Driven Design).

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        Factura factura = new Factura("FAC-2026-001");

        // Añadimos conceptos a la factura abierta
        factura.agregarLinea(new LineaFactura("Licencia Servidor Anual", 1, 500.0));
        factura.agregarLinea(new LineaFactura("Soporte Técnico 24/7", 2, 100.0));

        System.out.println("Subtotal sin IVA : " + factura.calcularSubtotal() + " EUR");
        System.out.println("Total con 21% IVA: " + factura.calcularTotalConImpuestos(21.0) + " EUR\n");

        // Pagamos la factura
        factura.marcarComoPagada();

        // Intentamos añadir un concepto después de pagada (el Business Object se protege solo)
        try {
            factura.agregarLinea(new LineaFactura("Teclado Extra", 1, 50.0));
        } catch (IllegalStateException e) {
            System.out.println("🛡️ [Regla de Negocio Activada] " + e.getMessage());
        }
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Siempre que modeles conceptos centrales de tu negocio (Cuentas bancarias, Pedidos, Facturas, Pólizas, Reservas) que tengan reglas de validación y cálculos propios.
  • Cuándo evitarlo: En catálogos meramente informativos de solo lectura donde no existen reglas de negocio ni transiciones de estado.
