Patrón Application Service

El patrón Application Service (Servicio de Aplicación) es un patrón de la capa de negocio de Java EE (y pieza central de Domain-Driven Design y Arquitectura Hexagonal) que orquesta los pasos de un caso de uso de la aplicación, manteniéndose 100% independiente de si quien lo llama es una API REST, una pantalla web o una tarea automática.

Analogía del Mundo Real

Piensa en un Director de Orquesta (ApplicationService). El director no toca el violín ni el piano por sí mismo (esos son los objetos de dominio y los componentes de infraestructura), pero tiene la partitura completa de la obra y va indicando en qué orden exacto entra cada músico para que la pieza suene coordinada.

Propósito

Coordinar objetos de dominio (Business Objects), repositorios de datos y servicios de infraestructura (como encriptación o envío de emails) para completar un caso de uso, pudiendo ser reutilizado desde cualquier canal de entrada.

Caso de Uso Real: Caso de Uso "Registrar Nuevo Usuario"

Contexto: Dar de alta a un usuario en tu plataforma requiere: 1) encriptar su contraseña, 2) crear la entidad User, 3) guardarla en RepositorioUsuarios y 4) enviarle un correo de bienvenida con ServicioEmail. Además, los usuarios pueden registrarse tanto desde la Web (UserRestController) como mediante una importación masiva nocturna (BatchImportJob).

El Problema (Sin Application Service): Si metes esos 4 pasos dentro del controlador REST, cuando tengas que programar el proceso nocturno de importación por lotes tendrás que copiar y pegar toda la lógica.

La Solución (Con Application Service): Creamos ServicioAplicacionUsuario.registrarUsuario(...). Tanto el controlador REST como el proceso por lotes llaman a este mismo servicio de aplicación.

Implementación en Java


// 1.Componentes especializados de dominio e infraestructura
class EncriptadorContrasena {
    public String hashPassword(String rawPassword) {
        return "BCRYPT_HASH(" + rawPassword + ")";
    }
}

class RepositorioUsuarios {
    public void save(String username, String email, String passwordHash) {
        System.out.println("   💾 [RepositorioUsuarios] Usuario guardado en BD: " + username + " | Hash: " + passwordHash);
    }
}

class WelcomeServicioEmail {
    public void enviarBienvenidaEmail(String email) {
        System.out.println("   ✉️ [WelcomeServicioEmail] Correo de bienvenida enviado a: " + email);
    }
}

// 2. Application Service: Director de orquesta del caso de uso
class ServicioAplicacionUsuario {
    private EncriptadorContrasena encryptor = new EncriptadorContrasena();
    private RepositorioUsuarios repository = new RepositorioUsuarios();
    private WelcomeServicioEmail emailService = new WelcomeServicioEmail();

    public void registrarUsuario(String username, String email, String rawPassword) {
        System.out.println("⚙️ [ServicioAplicacionUsuario] Ejecutando caso de uso: Registrar Usuario '" + username + "'");

        // Paso 1: Encriptar contraseña
        String hashed = encryptor.hashPassword(rawPassword);

        // Paso 2: Persistir en base de datos
        repository.save(username, email, hashed);

        // Paso 3: Enviar notificación de bienvenida
        emailService.enviarBienvenidaEmail(email);
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Independencia total de la Interfaz de Usuario:

    ServicioAplicacionUsuario no devuelve páginas HTML ni códigos de estado HTTP 200/404. Recibe datos de negocio y ejecuta el flujo del caso de uso, por lo que sirve igual para una API REST, una interfaz gráfica de escritorio, un consumidor de RabbitMQ/Kafka o un test unitario.

  • 2. Orquestación vs Lógica de Dominio:

    Un buen Application Service es delgado: coordina el orden de los pasos ("encripta $\rightarrow$ guarda $\rightarrow$ envía email"), delegando los cálculos de negocio puros en las entidades o Business Objects.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        ServicioAplicacionUsuario appService = new ServicioAplicacionUsuario();

        System.out.println("--- Canal 1: Registro desde el Formulario Web (REST Controller) ---");
        appService.registrarUsuario("elena_web", "elena@correo.com", "Secreto123");

        System.out.println("\n--- Canal 2: Alta desde Proceso Nocturno de Importación (Batch Job) ---");
        appService.registrarUsuario("marco_batch", "marco@empresa.com", "TempPass99");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: En la capa de servicios (@Service) de cualquier aplicación empresarial para representar cada caso de uso del sistema.
  • Cuándo evitarlo: Evita meter toda la matemática y reglas de validación de las entidades dentro del Application Service dejando a las entidades vacías (anti-patrón conocido como Modelo de Dominio Anémico).
