Patrón Flyweight

El patrón Flyweight (Peso Mosca) es un patrón estructural diseñado para ahorrar memoria RAM cuando necesitamos crear una cantidad masiva de objetos similares, compartiendo los datos pesados comunes entre todos ellos en lugar de duplicarlos en cada objeto.

Analogía del Mundo Real

Imagina un documento de procesador de textos con 500.000 letras. Si cada letra individual de la página guardara en memoria todo el dibujo vectorial de su tipografía Arial, el documento ocuparía gigabytes de RAM. En lugar de eso, el programa guarda el dibujo de la letra 'A' una única vez en memoria (estado compartido) y en la página solo anota en qué fila y columna aparece cada 'A' (estado único).

Propósito

Dividir los datos de un objeto en dos partes: el Estado Intrínseco (datos pesados, idénticos e inmutables que se comparten entre miles de objetos) y el Estado Extrínseco (datos ligeros y únicos de cada instancia, como sus coordenadas X e Y).

Caso de Uso Real: Renderizado de un Bosque en un Videojuego

Contexto: En un videojuego de mundo abierto necesitas dibujar un bosque con 1.000.000 de árboles (Pinos y Robles). Cada especie tiene una textura 4K y un modelo 3D muy pesado.

El Problema (Sin Flyweight): Si creas 1.000.000 de objetos Arbol y cada uno guarda su propia copia de la textura y la malla 3D en memoria, la tarjeta gráfica y la RAM se agotarán en pocos segundos (OutOfMemoryError).

La Solución (Con Flyweight): Extraemos los datos pesados (nombre de especie, color, textura) a la clase compartida TipoArbol (el Flyweight), gestionada por una caché FabricaArboles. Así solo existen 2 objetos TipoArbol en memoria ("Pino" y "Roble"), y el millón de objetos Arbol solo ocupa unos pocos bytes guardando sus coordenadas (x, y) y un puntero al TipoArbol compartido.

Implementación en Java


import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

// 1. Flyweight: Estado Intrínseco (pesado, inmutable y compartido)
class TipoArbol {
    private final String name;
    private final String color;
    private final String heavyTextureData;

    public TipoArbol(String name, String color, String heavyTextureData) {
        this.name = name;
        this.color = color;
        this.heavyTextureData = heavyTextureData;
        System.out.println(">> [MEMORIA] Cargando textura 3D pesada una sola vez para especie: " + name);
    }

    public void dibujar(int x, int y) {
        System.out.println("Dibujando " + name + " (" + color + ") en coordenadas (" + x + ", " + y + ")");
    }
}

// 2. Flyweight Factory: Caché que garantiza que no se dupliquen los TipoArbol
class FabricaArboles {
    private static final Map<String, TipoArbol> tiposArbol = new HashMap<>();

    public static TipoArbol getTipoArbol(String name, String color, String texture) {
        TipoArbol result = tiposArbol.get(name);
        if (result == null) {
            result = new TipoArbol(name, color, texture);
            tiposArbol.put(name, result);
        }
        return result;
    }

    public static int getTotalSharedTypes() {
        return tiposArbol.size();
    }
}

// 3. Contexto: Estado Extrínseco (ligero, único para cada árbol plantado)
class Arbol {
    private int x;
    private int y;
    private TipoArbol type; // Referencia al Flyweight compartido

    public Tree(int x, int y, TipoArbol type) {
        this.x = x;
        this.y = y;
        this.type = type;
    }

    public void dibujar() {
        type.dibujar(x, y);
    }
}

// 4. Cliente contenedor: El Bosque
class Bosque {
    private List<Tree> trees = new ArrayList<>();

    public void plantarArbol(int x, int y, String name, String color, String texture) {
        TipoArbol type = FabricaArboles.getTipoArbol(name, color, texture);
        Tree tree = new Arbol(x, y, type);
        trees.add(tree);
    }

    public void pintarBosque() {
        for (Tree tree : trees) {
            tree.dibujar();
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Inmutabilidad del Flyweight (final):

    Como miles de objetos Arbol apuntan al mismo objeto TipoArbol ("Pino"), los atributos de TipoArbol deben ser final (inmutables). Si un árbol pudiera cambiar el color dentro de TipoArbol, ¡todos los pinos del bosque cambiarían de color a la vez!

  • 2. Ejemplo en el propio JDK de Java:

    String.intern() y Integer.valueOf(int) (que reutiliza en caché los enteros entre -128 y 127) aplican exactamente el patrón Flyweight.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        Bosque bosque = new Bosque();

        // Plantamos 5 árboles, pero solo de 2 especies ("Pino" y "Roble")
        bosque.plantarArbol(10, 20, "Pino", "Verde Oscuro", "Textura_Pino_4K.png");
        bosque.plantarArbol(15, 25, "Pino", "Verde Oscuro", "Textura_Pino_4K.png");
        bosque.plantarArbol(50, 80, "Roble", "Verde Claro", "Textura_Roble_4K.png");
        bosque.plantarArbol(70, 90, "Pino", "Verde Oscuro", "Textura_Pino_4K.png");
        bosque.plantarArbol(85, 95, "Roble", "Verde Claro", "Textura_Roble_4K.png");

        System.out.println("\n--- Renderizando el bosque ---");
        bosque.pintarBosque();

        System.out.println("\nTotal de árboles plantados: 5");
        System.out.println("Total de objetos pesados TipoArbol en memoria: " + FabricaArboles.getTotalSharedTypes());
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Únicamente cuando tu aplicación deba mantener en RAM decenas de miles o millones de objetos que comparten gran parte de su estado pesado.
  • Cuándo evitarlo: Si tienes pocos objetos en memoria o si ningún objeto comparte datos repetidos con los demás.
