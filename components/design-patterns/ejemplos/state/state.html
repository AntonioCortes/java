Patrón State

El patrón State (Estado) es un patrón de comportamiento que permite a un objeto cambiar su comportamiento automáticamente cuando su estado interno cambia, hasta el punto de parecer que el objeto ha cambiado de clase.

Analogía del Mundo Real

Piensa en el botón principal de tu teléfono móvil. Cuando el teléfono está en estado Desbloqueado, pulsar el botón te lleva a la pantalla de inicio. Cuando está en estado Bloqueado, pulsar ese mismo botón solo enciende la pantalla de PIN. Y cuando está en estado Sin Batería, pulsar el botón muestra el icono de enchufar el cargador. El botón es el mismo, pero su comportamiento depende del Estado actual del teléfono.

Propósito

Sustituir grandes bloques condicionales (switch (estado) o if (estado == PAGADO)) repartidos por toda una clase, extrayendo la lógica de cada estado a su propia clase independiente.

Caso de Uso Real: Ciclo de Vida de un Pedido de Tienda Online

Contexto: Un pedido (ContextoPedido) pasa secuencialmente por tres estados: 1. Pendiente de Pago (EstadoPendientePago) $\rightarrow$ 2. Pagado (EstadoPagado) $\rightarrow$ 3. Enviado (EstadoEnviado).

El Problema (Sin State): Si controlas el estado con un String o boolean y llenas cada método de if (state.equals("PENDING")) ... else if (state.equals("PAID")) ..., añadir un nuevo estado ("En Aduanas") obliga a modificar todos los métodos de la clase Order.

La Solución (Con State): Creamos la interfaz EstadoPedido y una clase por cada estado. El pedido (ContextoPedido) guarda una referencia estadoActual y delega en ella las acciones y la transición hacia el siguiente estado.

Implementación en Java


// 1. Interfaz State
interface EstadoPedido {
    void siguiente(ContextoPedido context);
    void mostrarEstado();
}

// 2. Contexto: El Pedido cuyo comportamiento varía según su estado actual
class ContextoPedido {
    private EstadoPedido estadoActual;

    public ContextoPedido() {
        // Todo pedido nace en estado "Pendiente de Pago"
        this.estadoActual = new EstadoPendientePago();
    }

    public void setEstado(EstadoPedido state) {
        this.estadoActual = state;
    }

    public void avanzarPaso() {
        estadoActual.siguiente(this);
    }

    public void mostrarEstado() {
        estadoActual.mostrarEstado();
    }
}

// 3. Estados Concretos
class EstadoPendientePago implements EstadoPedido {
    @Override
    public void siguiente(ContextoPedido context) {
        System.out.println(">> Procesando cobro... Transicionando a estado PAGADO.");
        context.setEstado(new EstadoPagado());
    }

    @Override
    public void mostrarEstado() {
        System.out.println("🛒 Estado actual: [PENDIENTE DE PAGO] - Esperando confirmación bancaria.");
    }
}

class EstadoPagado implements EstadoPedido {
    @Override
    public void siguiente(ContextoPedido context) {
        System.out.println(">> Preparando paquete en almacén... Transicionando a estado ENVIADO.");
        context.setEstado(new EstadoEnviado());
    }

    @Override
    public void mostrarEstado() {
        System.out.println("💳 Estado actual: [PAGADO] - El pedido está listo para salir del almacén.");
    }
}

class EstadoEnviado implements EstadoPedido {
    @Override
    public void siguiente(ContextoPedido context) {
        System.out.println(">> Aviso: El pedido ya ha sido enviado, no hay más estados siguientes.");
    }

    @Override
    public void mostrarEstado() {
        System.out.println("🚚 Estado actual: [ENVIADO] - El paquete va en camino al cliente.");
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Cero sentencias if o switch:

    Fíjate en la clase ContextoPedido: no tiene ni un solo if. Simplemente ejecuta estadoActual.mostrarEstado() y estadoActual.siguiente(this).

  • 2. Diferencia entre State y Strategy:

    En Strategy, el cliente elige desde fuera qué algoritmo quiere usar (ej. pagar con PayPal o Tarjeta) y las estrategias no se conocen entre sí. En State, los propios estados transicionan automáticamente de uno a otro (de EstadoPendientePago a EstadoPagado) siguiendo un ciclo de vida.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        ContextoPedido pedido = new ContextoPedido();

        // Estado 1: recién creado
        pedido.mostrarEstado();

        // Avanzamos al Estado 2 (Pagado)
        pedido.avanzarPaso();
        pedido.mostrarEstado();

        // Avanzamos al Estado 3 (Enviado)
        pedido.avanzarPaso();
        pedido.mostrarEstado();

        // Intentamos avanzar más allá del último estado
        pedido.avanzarPaso();
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando tengas un objeto que se comporte como una máquina de estados finitos (pedidos, trámites administrativos, conexiones TCP, reproductores multimedia) y sus métodos estén llenos de condicionales según el estado actual.
  • Cuándo evitarlo: Si el objeto solo tiene 2 estados muy simples que rara vez cambian.
