Patrón Service to Worker

El patrón Service to Worker es un patrón de la capa de presentación de Java EE en el que un controlador (el Worker) recibe la petición, coordina e invoca múltiples servicios de negocio pesados, prepara un modelo de datos completo y finalmente despacha a una vista pasiva para que solo pinte el resultado.

Analogía del Mundo Real

Piensa en un Chef Ejecutivo en la cocina de un restaurante (el Worker Controller) y el Camarero que lleva el plato a la mesa (la Vista pasiva). Antes de que el plato salga del pase de cocina, el Chef pide la carne a la parrilla, la guarnición a la estación de verduras y la salsa al salsero, emplata todo listo y solo entonces se lo entrega al camarero para que lo sirva en la mesa sin tener que cocinar nada.

Propósito

Asegurar una separación estricta donde todo el trabajo pesado de negocio y acceso a datos ocurra antes de empezar a renderizar la vista HTML, manteniendo la vista 100% pasiva y limpia.

Caso de Uso Real: Procesamiento Completo de un Pedido antes de Mostrar el Recibo

Contexto: Un cliente pulsa "Comprar ahora". Antes de mostrarle la pantalla de confirmación (VistaConfirmacion), el sistema debe comprobar y reservar el stock en ServicioInventario y procesar el cobro bancario en ServicioPagos.

El Problema (Sin Service to Worker): Si muestras primero la vista y desde mitad del HTML intentas cobrar la tarjeta o consultar el stock, si el cobro falla a mitad de página el usuario verá una pantalla rota e inconsistente.

La Solución (Con Service to Worker): El controlador ControladorTrabajadorPedido ejecuta primero las llamadas a ServicioInventario y ServicioPagos. Cuando todo ha terminado con éxito, empaqueta el recibo y se lo entrega listo a VistaConfirmacion.

Rol en el Patrón Clase en el Ejemplo Responsabilidad
Worker Controller ControladorTrabajadorPedido Recibe la petición, invoca a los servicios de negocio, construye el modelo de respuesta y selecciona la vista final.
Business Services ServicioInventario, ServicioPagos Ejecutan la lógica de negocio real (reservar unidades en almacén y realizar el cargo financiero).
Passive View (Vista Pasiva) VistaConfirmacion Recibe los datos ya calculados y se limita a pintarlos en pantalla sin ejecutar ninguna lógica de negocio.

Implementación en Java


// 1. Servicios de Negocio (Capa de Servicios)
class ServicioInventario {
    public boolean reservarStock(String product, int quantity) {
        System.out.println("📦 [ServicioInventario] Reservando " + quantity + " unidad(es) de: " + product);
        return true;
    }
}

class ServicioPagos {
    public String processPayment(double amount) {
        System.out.println("💳 [ServicioPagos] Cobrando " + amount + " EUR en la pasarela bancaria...");
        return "TXN-994810"; // Devuelve el código de recibo bancario
    }
}

// 2. Vista Pasiva (Solo pinta los datos que el controlador ya le entrega listos)
class VistaConfirmacion {
    public void renderizar(String product, double total, String transactionId) {
        System.out.println("🖥️ [VistaConfirmacion - HTML] ¡Compra completada!");
        System.out.println("   Producto : " + product);
        System.out.println("   Importe  : " + total + " EUR");
        System.out.println("   Recibo Nº: " + transactionId);
    }
}

// 3. Worker Controller: hace todo el trabajo pesado ANTES de llamar a la vista
class ControladorTrabajadorPedido {
    private ServicioInventario inventoryService = new ServicioInventario();
    private ServicioPagos paymentService = new ServicioPagos();
    private VistaConfirmacion confirmationView = new VistaConfirmacion();

    public void handleCheckoutRequest(String product, int quantity, double price) {
        System.out.println(">> [ControladorTrabajadorPedido] Iniciando procesamiento pesado de la petición...");

        // Paso 1 y 2: Orquestar la lógica de negocio
        boolean stockOk = inventoryService.reservarStock(product, quantity);
        if (stockOk) {
            String txId = paymentService.processPayment(price * quantity);

            // Paso 3: Con todos los datos listos, despachamos a la vista pasiva
            confirmationView.renderizar(product, price * quantity, txId);
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. La base de los @Controller de Spring MVC:

    En Spring MVC, cuando un método anotado con @PostMapping("/checkout") llama a varios @Service, mete los resultados en model.addAttribute(...) y al final devuelve "confirmation", estás aplicando exactamente el patrón Service to Worker.

  • 2. Vistas "tontas" (Passive Views):

    VistaConfirmacion no tiene ninguna referencia a ServicioInventario ni a ServicioPagos; solo recibe tipos simples o DTOs ya listos para mostrar.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        ControladorTrabajadorPedido workerController = new ControladorTrabajadorPedido();

        // El usuario envía el formulario de compra
        workerController.handleCheckoutRequest("Monitor Ultrawide 34\"", 2, 350.00);
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: En casi cualquier operación web empresarial que requiera consultar o modificar datos de negocio antes de mostrar la página resultante.
  • Cuándo evitarlo: Si solo necesitas redirigir a una página estática de ayuda sin tocar ningún servicio de negocio (usa entonces Dispatcher View).
