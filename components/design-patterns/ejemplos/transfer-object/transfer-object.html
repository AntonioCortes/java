Patrón Transfer Object (DTO)

El patrón Transfer Object, universalmente conocido como DTO (Data Transfer Object), es un patrón de la arquitectura Java EE que consiste en empaquetar únicamente los datos que necesita el cliente dentro de un objeto simple y serializable para enviarlos a través de la red en una sola llamada, sin exponer las entidades internas de la base de datos.

Analogía del Mundo Real

Piensa en pedir comida a domicilio. El restaurante no te manda por correo primero el pan, en otro viaje la carne, en otro viaje las patatas, ni tampoco te envía su libro de recetas secreto ni la sartén de hierro de la cocina (la Entidad JPA interna). El restaurante mete solo los alimentos que has pedido dentro de una caja de cartón para llevar (el DTO) y el repartidor te la entrega en un único viaje.

Propósito

Cumplir dos objetivos críticos en aplicaciones web y microservicios:
1. Seguridad y Desacoplamiento: Evitar exponer al exterior campos sensibles de la base de datos (como hashContrasena o el salario interno) que existen en la entidad @Entity.
2. Rendimiento de Red: Agrupar todos los atributos necesarios en un solo viaje HTTP/JSON.

Caso de Uso Real: Respuesta de Perfil de Usuario en una API REST

Contexto: En tu base de datos tienes la tabla de usuarios mapeada en la clase EntidadUsuario, que contiene id, nombreUsuario, email, hashContrasena y salarioInterno. El navegador web necesita mostrar el perfil público del usuario.

El Problema (Sin DTO): Si devuelves el objeto EntidadUsuario directamente en el controlador REST, se convertirá entero a JSON y cualquier persona que abra las herramientas de desarrollador del navegador (F12) verá el hash de la contraseña y el salario privado del empleado.

La Solución (Con DTO): Creamos la clase UsuarioDTO que solo contiene nombreUsuario y email. El servicio copia únicamente esos dos campos seguros desde EntidadUsuario hacia UsuarioDTO y envía el DTO al cliente.

Implementación en Java


import java.io.Serializable;

// 1. Entidad Interna de Base de Datos (Contiene datos sensibles que NO deben salir al exterior)
class EntidadUsuario {
    private Long id;
    private String nombreUsuario;
    private String email;
    private String hashContrasena;   // 🔒 Dato confidencial
    private double salarioInterno; // 🔒 Dato confidencial

    public EntidadUsuario(Long id, String nombreUsuario, String email, String hashContrasena, double salarioInterno) {
        this.id = id;
        this.nombreUsuario = nombreUsuario;
        this.email = email;
        this.hashContrasena = hashContrasena;
        this.salarioInterno = salarioInterno;
    }

    public String getUsername() { return nombreUsuario; }
    public String getEmail() { return email; }
}

// 2. Transfer Object (DTO): Objeto plano diseñado específicamente para viajar al cliente
class UsuarioDTO implements Serializable {
    private String nombreUsuario;
    private String email;

    public UsuarioDTO(String nombreUsuario, String email) {
        this.nombreUsuario = nombreUsuario;
        this.email = email;
    }

    public String getUsername() { return nombreUsuario; }
    public String getEmail() { return email; }

    @Override
    public String toString() {
        return "UsuarioDTO JSON { \"nombreUsuario\": \"" + nombreUsuario + "\", \"email\": \"" + email + "\" }";
    }
}

// 3. Servicio de Backend que transforma la Entidad en DTO antes de enviarla por red
class ServicioUsuarios {
    public UsuarioDTO obtenerPerfil(Long userId) {
        // Simulamos la lectura completa desde la Base de Datos
        EntidadUsuario entityFromDb = new EntidadUsuario(
                userId, "carlos_dev", "carlos@empresa.es", "$2a$10$xyzSecretHash", 48000.0
        );

        System.out.println("🔒 [ServicioUsuarios] Entidad leída de BD (ocultando hashContrasena y salario).");
        System.out.println("📦 [ServicioUsuarios] Empaquetando solo datos públicos en UsuarioDTO...");

        // Mapeamos a DTO
        return new UsuarioDTO(entityFromDb.getUsername(), entityFromDb.getEmail());
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Desacoplamiento entre la Base de Datos y el Frontend:

    Si mañana renombras una columna en tu tabla SQL o divides EntidadUsuario en dos tablas, la aplicación móvil y el frontend web no se romperán porque tú sigues devolviéndoles el mismo UsuarioDTO.

  • 2. En Java moderno (Java 16+):

    Hoy en día los DTOs inmutables suelen declararse en una sola línea usando record UsuarioDTO(String nombreUsuario, String email) {}.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        ServicioUsuarios backendService = new ServicioUsuarios();

        // El cliente solicita el perfil en una única llamada y recibe el DTO limpio
        UsuarioDTO responseDto = backendService.obtenerPerfil(10L);

        System.out.println("\n🌐 [Cliente Frontend] Respuesta recibida en 1 llamada de red:");
        System.out.println("   " + responseDto);
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Siempre en las entradas (@RequestBody) y salidas (ResponseEntity) de tus controladores REST o en la comunicación entre microservicios.
  • Cuándo evitarlo: No hace falta convertir a DTO para pasar datos entre dos métodos privados internos dentro de la misma clase de negocio.
