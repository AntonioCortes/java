Patrón Composite

El patrón Composite (Compuesto) es un patrón estructural que permite componer objetos en estructuras de árbol (jerarquías parte-todo) y trabajar con esas estructuras como si fueran objetos individuales.

Analogía del Mundo Real

Piensa en el sistema de carpetas y archivos de tu ordenador. Una carpeta puede contener archivos sueltos (foto.jpg), pero también puede contener otras carpetas que a su vez tienen más archivos dentro. Cuando haces clic derecho y pides ver las propiedades o mostrar el contenido, tanto un archivo individual como una carpeta entera responden a la misma operación.

Propósito

Permitir que el código cliente trate exactamente igual a un objeto simple (una Hoja) que a un grupo complejo de objetos (un Compuesto), gracias a que ambos implementan la misma interfaz común.

Caso de Uso Real: Explorador de Archivos y Directorios

Contexto: Quieres representar un árbol de directorios donde cada directorio puede contener tanto archivos simples (Archivo) como subdirectorios (Directorio), y necesitas imprimir toda la estructura o calcular su tamaño.

El Problema (Sin Composite): Si Archivo y Directorio no comparten una interfaz común, el cliente tendría que escribir bucles anidados llenos de comprobaciones if (elemento instanceof Directory) para saber cómo recorrer cada nivel.

La Solución (Con Composite): Creamos la interfaz ComponenteSistemaArchivos con el método mostrarDetalles(). Tanto Archivo (Hoja) como Directorio (Compuesto) la implementan. Cuando llamas a mostrarDetalles() sobre un Directorio, este se imprime a sí mismo y recorre su lista de hijos llamando recursivamente a mostrarDetalles() en cada uno.

Diagrama de Clases y Participantes

Rol en el Patrón Clase / Interfaz en el Ejemplo Responsabilidad
Component (Componente) ComponenteSistemaArchivos Declara la interfaz común tanto para objetos simples (archivos) como para contenedores (directorios).
Leaf (Hoja) Archivo Representa un elemento individual que no tiene hijos; realiza el trabajo directo.
Composite (Compuesto) Directorio Almacena una lista de hijos de tipo ComponenteSistemaArchivos (que pueden ser hojas u otros compuestos) y les delega las operaciones.

Implementación en Java


import java.util.ArrayList;
import java.util.List;

// 1. Componente: Interfaz común para hojas y compuestos
interface ComponenteSistemaArchivos {
    void mostrarDetalles(String indent);
}

// 2. Hoja (Leaf): Objeto individual que no puede contener a otros
class Archivo implements ComponenteSistemaArchivos {
    private String name;
    private int tamanoKb;

    public File(String name, int tamanoKb) {
        this.name = name;
        this.tamanoKb = tamanoKb;
    }

    @Override
    public void mostrarDetalles(String indent) {
        System.out.println(indent + "📄 Archivo: " + name + " (" + tamanoKb + " KB)");
    }
}

// 3. Compuesto (Composite): Puede contener tanto Archivos como otros Directorios
class Directorio implements ComponenteSistemaArchivos {
    private String name;
    // ¡Clave del patrón!: la lista es de la interfaz ComponenteSistemaArchivos
    private List<ComponenteSistemaArchivos> hijos = new ArrayList<>();

    public Directory(String name) {
        this.name = name;
    }

    public void agregar(ComponenteSistemaArchivos component) {
        hijos.agregar(component);
    }

    @Override
    public void mostrarDetalles(String indent) {
        System.out.println(indent + "📁 Directorio: " + name);
        // Delegación recursiva a todos sus hijos
        for (ComponenteSistemaArchivos child : hijos) {
            child.mostrarDetalles(indent + "   ");
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Por qué Directorio guarda List<ComponenteSistemaArchivos>?

    Si guardase List<File>, una carpeta solo podría tener archivos sueltos y nunca subcarpetas. Al guardar la interfaz ComponenteSistemaArchivos, una carpeta puede contener archivos, subcarpetas, sub-subcarpetas, etc., hasta cualquier profundidad.

  • 2. Magia recursiva sin if/else:

    El cliente solo llama a raiz.mostrarDetalles("") una vez en la carpeta raíz y toda la jerarquía en árbol se recorre sola gracias al polimorfismo.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // Creamos archivos individuales (Hojas)
        File cv = new Archivo("curriculum.pdf", 450);
        File foto = new Archivo("vacaciones.png", 2100);
        File codigo = new Archivo("Main.java", 12);

        // Creamos subdirectorios (Compuestos)
        Directorio docs = new Directorio("Documentos");
        docs.agregar(cv);

        Directorio proyectos = new Directorio("Proyectos");
        proyectos.agregar(codigo);

        // Creamos el directorio raíz y metemos tanto archivos como subdirectorios
        Directorio raiz = new Directorio("MiUsuario");
        raiz.agregar(docs);
        raiz.agregar(proyectos);
        raiz.agregar(foto);

        // Mostramos todo el árbol con una única llamada
        raiz.mostrarDetalles("");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Siempre que tu modelo de negocio tenga una estructura jerárquica en forma de árbol (menús con submenús, organigramas de departamentos y empleados, componentes visuales contenedores en HTML/Swing, carpetas y archivos).
  • Cuándo evitarlo: Cuando los objetos simples y los contenedores sean tan distintos funcionalmente que forzar una interfaz común deje muchos métodos vacíos o sin sentido en las hojas.
