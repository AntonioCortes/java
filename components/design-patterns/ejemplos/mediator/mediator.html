Patrón Mediator

El patrón Mediator (Mediador) es un patrón de comportamiento que reduce las dependencias caóticas entre muchos objetos. En lugar de que todos los objetos hablen directamente entre sí (todos contra todos), los fuerza a comunicarse únicamente a través de un objeto mediador central.

Analogía del Mundo Real

Piensa en los pilotos de avión acercándose a un aeropuerto y la Torre de Control. Si los 30 pilotos en vuelo tuvieran que llamarse por radio unos a otros directamente para acordar quién aterriza primero, sería un caos absoluto y peligroso. En su lugar, ningún piloto habla con otro piloto: todos hablan exclusivamente con la Torre de Control (el Mediador), y es la torre quien coordina y transmite los avisos.

Propósito

Transformar una red de dependencias "muchos a muchos" (en malla) en una estructura simple en estrella donde cada componente (llamado Colleague o Colega) solo conoce al Mediator.

Caso de Uso Real: Sala de Chat Grupal

Contexto: Tienes múltiples usuarios (UsuarioChat) conectados a una sala de chat grupal. Cuando un usuario envía un mensaje, debe llegar a todos los demás participantes de la sala.

El Problema (Sin Mediator): Si cada objeto Usuario tuviera que guardar una lista de referencias directas a todos los demás usuarios del chat, cada vez que alguien entrara o saliera habría que actualizar las listas de todos los usuarios conectados.

La Solución (Con Mediator): Creamos la interfaz MediadorChat y su implementación SalaChat. Cada Usuario solo guarda una referencia a su MediadorChat. Cuando Ana escribe un mensaje, se lo entrega a SalaChat, y la sala se encarga de reenviarlo al resto de participantes.

Implementación en Java


import java.util.ArrayList;
import java.util.List;

// 1. Interfaz Mediador
interface MediadorChat {
    void enviarMensaje(String msg, Usuario emisor);
    void registrarUsuario(Usuario usuario);
}

// 2. Mediador Concreto: la Sala de Chat que coordina a todos
class SalaChat implements MediadorChat {
    private List<User> users = new ArrayList<>();

    @Override
    public void registrarUsuario(Usuario usuario) {
        this.users.add(user);
    }

    @Override
    public void enviarMensaje(String msg, Usuario emisor) {
        for (Usuario u : this.users) {
            // El mediador reenvía el mensaje a todos excepto al propio emisor
            if (u != sender) {
                u.recibir(msg, sender.name);
            }
        }
    }
}

// 3. Componente / Colega Abstracto
abstract class Usuario {
    protected MediadorChat mediator;
    protected String name;

    public User(MediadorChat mediator, String name) {
        this.mediator = mediator;
        this.name = name;
    }

    public abstract void enviar(String msg);
    public abstract void recibir(String msg, String from);
}

// 4. Colega Concreto
class UsuarioChat extends Usuario {
    public UsuarioChat(MediadorChat mediator, String name) {
        super(mediator, name);
    }

    @Override
    public void enviar(String msg) {
        System.out.println("📤 [" + this.name + " envía]: " + msg);
        mediator.enviarMensaje(msg, this);
    }

    @Override
    public void recibir(String msg, String from) {
        System.out.println("   📥 [" + this.name + " recibe de " + from + "]: " + msg);
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Desacoplamiento total entre compañeros:

    Observa la clase UsuarioChat: no tiene ningún atributo List<User> ni conoce a ningún otro usuario. Solo llama a mediator.enviarMensaje(msg, this).

  • 2. Diferencia entre Mediator y Observer:

    En Observer, un sujeto publica eventos de forma unidireccional a sus suscriptores. En Mediator, el objetivo es eliminar las conexiones cruzadas multidireccionales entre muchos compañeros centralizando las reglas de coordinación en un único punto.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // 1. Creamos el Mediador central (la sala de chat)
        MediadorChat salaGeneral = new SalaChat();

        // 2. Creamos los usuarios vinculados al mediador
        Usuario ana = new UsuarioChat(salaGeneral, "Ana");
        Usuario luis = new UsuarioChat(salaGeneral, "Luis");
        Usuario marta = new UsuarioChat(salaGeneral, "Marta");

        // 3. Los registramos en la sala
        salaGeneral.registrarUsuario(ana);
        salaGeneral.registrarUsuario(luis);
        salaGeneral.registrarUsuario(marta);

        // 4. Ana envía un mensaje y el mediador lo reparte a Luis y Marta
        ana.enviar("¡Hola equipo! ¿A qué hora es la reunión?");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando tengas muchos componentes que interactúan entre sí (como los campos de un formulario complejo donde marcar un checkbox habilita un desplegable y oculta un botón, o un sistema de chat/tráfico).
  • Cuándo evitarlo: Ten cuidado de no meter demasiada lógica distinta en un único Mediador hasta convertirlo en un "Objeto Dios" difícil de mantener.
