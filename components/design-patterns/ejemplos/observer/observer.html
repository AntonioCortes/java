Patrón Observer

El patrón Observer (Observador o Publicador-Suscriptor) es un patrón de comportamiento que define un mecanismo de suscripción uno-a-muchos para que, cuando un objeto cambie de estado, notifique automáticamente a todos los objetos que están suscritos a él.

Analogía del Mundo Real

Piensa en suscribirte a un canal de YouTube y activar la campanita (🔔). En lugar de que tú tengas que entrar cada 5 minutos al canal para comprobar si hay un vídeo nuevo ("¿ya subió vídeo?, ¿y ahora?, ¿y ahora?"), simplemente te apuntas a su lista de suscriptores. En el instante en que el creador sube un vídeo, YouTube recorre la lista y os envía una notificación automática a todos.

Propósito

Evitar el coste de comprobar continuamente cambios de estado (polling) y desacoplar al objeto que produce el evento (el Subject) de los múltiples objetos que reaccionan a él (los Observers).

Caso de Uso Real: Notificaciones de un Canal de YouTube a sus Suscriptores

Contexto: Un canal (CanalYoutube) publica vídeos periódicamente y miles de usuarios (Suscriptor) quieren enterarse al instante, pudiendo suscribirse o darse de baja en cualquier momento.

El Problema (Sin Observer): Si el canal tuviera referencias fijas a usuarios concretos, no se podrían añadir ni quitar suscriptores dinámicamente en tiempo de ejecución ni añadir otros tipos de observadores (como un bot de Twitter o un sistema de estadísticas).

La Solución (Con Observer): El canal implementa Sujeto y mantiene una lista dinámica List<Observer>. Cuando se llama a subirVideo(), el canal recorre su lista e invoca observer.actualizar(titulo) en cada suscriptor.

Implementación en Java


import java.util.ArrayList;
import java.util.List;

// 1. Interfaz Observador (Suscriptor)
interface Observador {
    void actualizar(String videoTitle);
}

// 2. Interfaz Sujeto (Publicador)
interface Sujeto {
    void suscribir(Observador observer);
    void desuscribir(Observador observer);
    void notificarObservadores(String videoTitle);
}

// 3. Sujeto Concreto: Canal de YouTube
class CanalYoutube implements Sujeto {
    private List<Observer> suscribirrs = new ArrayList<>();
    private String channelName;

    public CanalYoutube(String channelName) {
        this.channelName = channelName;
    }

    @Override
    public void suscribir(Observador observer) {
        suscribirrs.add(observer);
    }

    @Override
    public void desuscribir(Observador observer) {
        suscribirrs.remove(observer);
    }

    @Override
    public void notificarObservadores(String videoTitle) {
        for (Observador observer : suscribirrs) {
            observer.actualizar(videoTitle);
        }
    }

    public void subirVideo(String title) {
        System.out.println("🎬 [" + channelName + "] Ha subido un nuevo vídeo: \"" + title + "\"");
        notificarObservadores(title);
    }
}

// 4. Observador Concreto: Usuario Suscriptor
class Suscriptor implements Observador {
    private String name;

    public Subscriber(String name) {
        this.name = name;
    }

    @Override
    public void actualizar(String videoTitle) {
        System.out.println("   🔔 Notificación para " + name + ": ¡Nuevo vídeo disponible -> " + videoTitle + "!");
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Inversión de Dependencias y Bajo Acoplamiento:

    CanalYoutube no sabe si quien lo escucha es una persona (Suscriptor), una app móvil o un bot de Discord. Solo sabe que todos los elementos de su lista implementan la interfaz Observador y tienen el método actualizar().

  • 2. Suscripción dinámica en tiempo de ejecución:

    En cualquier momento del programa un objeto puede suscribirse con suscribir() o borrarse con desuscribir() sin detener ni modificar el canal.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        CanalYoutube channel = new CanalYoutube("JavaMasterClass");

        Subscriber alice = new Suscriptor("Alice");
        Subscriber bob = new Suscriptor("Bob");

        // Alice y Bob se suscriben al canal
        channel.suscribir(alice);
        channel.suscribir(bob);

        // El canal sube su primer vídeo (ambos reciben aviso)
        channel.subirVideo("Patrón Observador explicado desde cero");

        System.out.println("\n--- Bob desactiva las notificaciones (desuscribir) ---\n");
        channel.desuscribir(bob);

        // El canal sube un segundo vídeo (solo Alice recibe aviso)
        channel.subirVideo("Patrón Singleton en profundidad");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando un cambio en un objeto requiera actualizar a otros objetos sin saber cuántos habrá o cuáles serán (eventos de interfaz gráfica como ActionListener, arquitecturas orientadas a eventos, programación reactiva/RxJava).
  • Cuándo evitarlo: Recuerda siempre dar de baja (desuscribir) a los observadores que ya no se usen para evitar fugas de memoria (memory leaks por referencias retenidas en la lista).
