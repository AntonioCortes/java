Patrón Dispatcher View

El patrón Dispatcher View (Vista con Despachador) es un patrón de la capa de presentación de Java EE que combina un controlador frontal ligero con un despachador cuya misión principal es elegir y mostrar inmediatamente la vista adecuada, realizando un trabajo previo de negocio mínimo o nulo antes de pasar el control a la vista.

Analogía del Mundo Real

Piensa en el conserje de un edificio de oficinas cuando alguien pregunta: "¿Dónde está el salón de actos?". El conserje no te hace una entrevista ni rellena veinte formularios: simplemente mira tu acreditación de un vistazo ("¿eres empleado o visitante?") y te dirige inmediatamente a la sala correspondiente.

Propósito

Gestionar de forma rápida y directa la navegación hacia páginas o vistas que requieren una validación muy ligera antes de renderizarse.

Caso de Uso Real: Enrutamiento Directo de Pantallas según el Rol del Usuario

Contexto: Cuando un usuario accede al panel de control (/panel), si su rol es ADMIN debe ver la pantalla de administración (VistaPanelAdmin), y si es USER debe ver la portada de usuario (VistaInicioUsuario).

El Problema (Sin Dispatcher View): Si dejas que el usuario navegue directamente a archivos JSP/HTML sueltos o metes redirecciones dentro del HTML, pierdes el control centralizado de qué vista corresponde a cada caso.

La Solución (Con Dispatcher View): El controlador DespachadorVistasServlet recibe la petición, comprueba ligeramente el parámetro/rol y despacha (hace forward) directamente a la vista elegida.

Implementación en Java


// 1. Vistas Destino
class VistaPanelAdmin {
    public void render(String username) {
        System.out.println("🛠️ [VistaPanelAdmin] Bienvenido Administrador " + username + ". Mostrando consola de servidores.");
    }
}

class VistaInicioUsuario {
    public void render(String username) {
        System.out.println("🏠 [VistaInicioUsuario] Hola " + username + ". Mostrando tu resumen personal.");
    }
}

// 2. Controlador Dispatcher View: validación mínima y despacho inmediato a la vista
class DespachadorVistasServlet {
    private VistaPanelAdmin adminView = new VistaPanelAdmin();
    private VistaInicioUsuario userView = new VistaInicioUsuario();

    public void manejarPeticion(String username, String role) {
        System.out.println(">> [Dispatcher] Evaluando ruta rápida para usuario: " + username + " (Rol: " + role + ")");

        // Selección directa de la vista (sin orquestación pesada de servicios de negocio)
        if ("ADMIN".equalsIgnoreCase(role)) {
            adminView.render(username);
        } else {
            userView.render(username);
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Diferencia clave entre Dispatcher View y Service to Worker:

    Esta es una pregunta clásica de examen y arquitectura en Java EE: en Dispatcher View, el controlador hace un trabajo previo mínimo y pasa rápido a la vista. En Service to Worker, el controlador primero llama a varios servicios pesados de negocio (inventario, banco, base de datos), construye un modelo de datos complejo y solo al final llama a la vista.

  • 2. En Spring MVC:

    Equivale a un ViewControllerRegistry (registry.addViewController("/login").setViewName("login")) o un método de controlador que simplemente devuelve el nombre de la plantilla sin llamar a servicios de base de datos.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        DespachadorVistasServlet dispatcher = new DespachadorVistasServlet();

        System.out.println("--- Petición 1: Accede una administradora ---");
        dispatcher.manejarPeticion("Laura", "ADMIN");

        System.out.println("\n--- Petición 2: Accede un usuario estándar ---");
        dispatcher.manejarPeticion("Carlos", "USER");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Para pantallas informativas, páginas de login/ayuda o redirecciones condicionales sencillas donde no hay que ejecutar transacciones de negocio previas.
  • Cuándo evitarlo: Cuando antes de pintar la pantalla necesites validar stock, cobrar con tarjeta o cruzar datos de varios microservicios; en ese caso debes usar Service to Worker.
