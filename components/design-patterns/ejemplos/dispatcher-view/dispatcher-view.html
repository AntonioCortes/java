Patrón Dispatcher View

El patrón Dispatcher View (Vista con Despachador) es un patrón de diseño de la capa de presentación de Java EE que combina un controlador frontal ligero con un despachador cuya misión exclusiva es elegir y mostrar inmediatamente la vista adecuada, realizando un trabajo previo de negocio mínimo o nulo antes de transferir el control a la vista.

Analogía del Mundo Real: El Conserje del Edificio de Oficinas

Piensa en el conserje de un edificio corporativo cuando alguien pregunta: "¿Dónde está el salón de actos?":

  • El conserje (Dispatcher View) no te somete a un interrogatorio ni te pide rellenar veinte formularios contables: simplemente mira tu acreditación de un vistazo ("¿eres empleado o visitante?") y te indica con el dedo inmediatamente la puerta del salón correspondiente.
  • En cambio, el departamento de recursos humanos (Service to Worker) no te deja pasar directamente a la sala: primero te sienta en una oficina, consulta tu historial en la base de datos, llama a tres directores, firma una autorización de seguridad y solo cuando todo está orquestado te acompaña a la sala.

Propósito

Centralizar y agilizar el enrutamiento y la selección de vistas cuando la petición no requiere una orquestación pesada de transacciones ni llamadas complejas a servicios de negocio antes de renderizar la pantalla.

Caso de Uso Real: Enrutamiento Rápido de Pantallas según el Rol del Usuario

Contexto: En la tienda de mascotas PetShop, cuando un usuario autenticado accede a la ruta genérica /dashboard, si su rol es ADMIN debe ver inmediatamente el panel de monitorización de servidores (VistaPanelAdmin), mientras que si es CLIENTE debe visualizar su resumen de compras y citas veterinarias (VistaInicioCliente).

El Problema (Sin Dispatcher View): Si dejas que el cliente front-end navegue directamente a plantillas HTML/JSP sueltas o incluyes lógica de redirección dispersa dentro de las propias vistas, pierdes el control centralizado de seguridad y navegación, duplicando código condicional en cada página.

La Solución (Con Dispatcher View): Un despachador centralizado (DespachadorVistasServlet) intercepta la petición, verifica de forma ligera los atributos de sesión o cabeceras y delega (hace forward) directamente a la vista correspondiente sin bloquear el hilo con cálculos pesados.

Implementación en Java


// 1. Contrato e implementaciones de las Vistas Destino
interface Vista {
    void render(String usuario);
}

class VistaPanelAdmin implements Vista {
    @Override
    public void render(String usuario) {
        System.out.println("🛠️ [VistaPanelAdmin] Administrador '" + usuario + "'. Mostrando consola de telemetría y catálogo general.");
    }
}

class VistaInicioCliente implements Vista {
    @Override
    public void render(String usuario) {
        System.out.println("🐾 [VistaInicioCliente] Hola '" + usuario + "'. Mostrando tus mascotas registradas y citas pendientes.");
    }
}

class VistaAccesoDenegado implements Vista {
    @Override
    public void render(String usuario) {
        System.out.println("⛔ [VistaAccesoDenegado] Usuario '" + usuario + "' no autenticado. Redirigiendo a pantalla de login.");
    }
}

// 2. Controlador Dispatcher View: despacho estático o condicional inmediato
class DespachadorVistasServlet {
    private final Vista adminView = new VistaPanelAdmin();
    private final Vista clientView = new VistaInicioCliente();
    private final Vista errorView = new VistaAccesoDenegado();

    public void despachar(String usuario, String rol) {
        System.out.println(">> [Dispatcher] Enrutando petición para usuario: " + usuario + " (Rol: " + rol + ")");

        // Despacho directo a la vista adecuada sin orquestación de servicios pesados
        if (usuario == null || usuario.isBlank()) {
            errorView.render("Anónimo");
        } else if ("ADMIN".equalsIgnoreCase(rol)) {
            adminView.render(usuario);
        } else {
            clientView.render(usuario);
        }
    }
}

Ejemplo de Uso y Trazas de Consola


public class Main {
    public static void main(String[] args) {
        DespachadorVistasServlet dispatcher = new DespachadorVistasServlet();

        System.out.println("--- Caso 1: Petición de Administrador ---");
        dispatcher.despachar("Laura_Admin", "ADMIN");

        System.out.println("\n--- Caso 2: Petición de Cliente Habitual ---");
        dispatcher.despachar("Carlos_Gomez", "CLIENTE");

        System.out.println("\n--- Caso 3: Petición sin Identificar ---");
        dispatcher.despachar("", "NONE");
    }
}

Comparativa: Dispatcher View vs Service to Worker vs Front Controller

Patrón Momento del Procesamiento de Negocio Complejidad Caso Típico en Spring MVC
Dispatcher View Nulo o mínimo antes de la vista. La vista puede obtener datos diferidos a través de View Helpers. Baja ViewControllerRegistry.addViewController("/faq").setViewName("faq") o páginas de bienvenida/estáticas.
Service to Worker Intenso antes de la vista. El controlador coordina servicios, valida stock, llama pasarelas de pago y puebla el modelo antes de renderizar. Alta Endpoints @PostMapping("/checkout") o procesos transaccionales complejos con PetService.
Front Controller Punto de entrada único que centraliza seguridad, internacionalización y logging antes de delegar en cualquier despachador o worker. Media/Alta El DispatcherServlet nativo de Spring MVC que intercepta /*.

// ANTIPATRÓN: El despachador asume responsabilidades de facturación y persistencia
public class BrokenDispatcherServlet {

    public void manejarPeticion(HttpServletRequest req) {
        // ERROR GRAVE: Si la petición requiere cobrar con tarjeta y descontar stock,

        stockRepository.descontar(req.getParameter("productoId"));
        // ...
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: En páginas informativas, dashboards de bienvenida, enrutamiento basado en roles simples, pantallas de login o cuando la vista solo requiere datos que pueden ser recuperados de forma perezosa por un View Helper.
  • Cuándo evitarlo: En cualquier flujo donde se requiera persistencia de datos, pagos, validaciones complejas de negocio o transformaciones de modelos; en tales casos se debe implementar Service to Worker.
