Patrón Application Controller

El patrón Application Controller (Controlador de Aplicación) es un patrón de la capa de presentación de Java EE que centraliza la lógica de flujo de navegación entre pantallas (como en un asistente o Wizard paso a paso) y la invocación de comandos de negocio.

Analogía del Mundo Real

Piensa en un asistente de instalación de un programa ("Siguiente > Siguiente > Finalizar"). La ventana de "Aceptar Licencia" no decide por su cuenta cuál es la siguiente ventana; le pregunta al motor del asistente (ControladorAplicacion). Si el usuario eligió "Instalación Rápida", el motor salta directamente a la barra de progreso; si eligió "Instalación Personalizada", el motor muestra primero la pantalla de selección de carpetas.

Propósito

Sacar las reglas de "¿a qué pantalla hay que ir después?" fuera de las vistas y de los controladores individuales, concentrando todo el mapa de navegación en una única clase fácil de mantener.

Caso de Uso Real: Asistente de Compra (Checkout Wizard) en E-Commerce

Contexto: Un proceso de compra pasa por varias pantallas: CART (Carrito) $\rightarrow$ SHIPPING (Dirección de envío) $\rightarrow$ PAYMENT (Pago) $\rightarrow$ SUCCESS (Confirmación). Además, si el producto es un libro digital (E-Book), debe saltarse la pantalla de dirección de envío e ir directo al pago.

El Problema (Sin Application Controller): Si cada pantalla tiene if internos apuntando al nombre de la siguiente pantalla, reordenar los pasos o añadir una condición nueva obliga a buscar y cambiar código en todas las pantallas.

La Solución (Con Application Controller): Creamos ControladorAplicacion con el método obtenerSiguienteVista(currentView, action) que actúa como el mapa central de navegación de toda la aplicación.

Implementación en Java


// 1. Application Controller: Máquina de estados que centraliza el mapa de navegación
class ControladorAplicacion {

    public String obtenerSiguienteVista(String currentView, String action) {
        if (currentView.equals("CART") && action.equals("CHECKOUT_FISICO")) {
            return "SHIPPING_VIEW"; // Producto físico requiere dirección de envío
        }
        if (currentView.equals("CART") && action.equals("CHECKOUT_DIGITAL")) {
            return "PAYMENT_VIEW";  // Producto digital salta directamente al pago
        }
        if (currentView.equals("SHIPPING_VIEW") && action.equals("ADDRESS_OK")) {
            return "PAYMENT_VIEW";
        }
        if (currentView.equals("PAYMENT_VIEW") && action.equals("PAY_SUCCESS")) {
            return "SUCCESS_VIEW";
        }
        return "ERROR_VIEW";
    }

    public void renderView(String viewName) {
        System.out.println("🖥️ [Navegación] Mostrando pantalla al usuario: >> " + viewName + " <<");
    }
}

// 2. Front Controller que se apoya en el Application Controller
class CheckoutControladorFrontal {
    private ControladorAplicacion appController = new ControladorAplicacion();

    public String processStep(String currentView, String userAction) {
        System.out.println("➡️ Usuario en [" + currentView + "] ejecuta acción: " + userAction);
        String nextView = appController.obtenerSiguienteVista(currentView, userAction);
        appController.renderView(nextView);
        return nextView;
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Diferencia entre Front Controller y Application Controller:

    El Front Controller es el portero que recibe la petición HTTP y verifica la seguridad general. El Application Controller es el navegador GPS que sabe qué pantalla toca mostrar después dentro de un flujo multipaso complejo.

  • 2. Fácil mantenimiento del flujo:

    Observa cómo en obtenerSiguienteVista() se ve de un solo vistazo todo el recorrido de compra, tanto para productos físicos como para digitales (Spring Web Flow utiliza exactamente este patrón).

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        CheckoutControladorFrontal controller = new CheckoutControladorFrontal();

        System.out.println("--- Caso 1: Compra de un producto FÍSICO (3 pasos) ---");
        String step = "CART";
        step = controller.processStep(step, "CHECKOUT_FISICO");
        step = controller.processStep(step, "ADDRESS_OK");
        controller.processStep(step, "PAY_SUCCESS");

        System.out.println("\n--- Caso 2: Compra de un E-Book DIGITAL (salta el envío) ---");
        String stepDigital = "CART";
        stepDigital = controller.processStep(stepDigital, "CHECKOUT_DIGITAL");
        controller.processStep(stepDigital, "PAY_SUCCESS");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: En asistentes multipaso (wizards de contratación de seguros, procesos de checkout, encuestas condicionales) donde la siguiente pantalla depende del estado y de las respuestas previas.
  • Cuándo evitarlo: En APIs REST sin estado o páginas con navegación libre donde cada enlace apunta siempre a un recurso fijo.
