Patrón Composite Entity

El patrón Composite Entity (Entidad Compuesta) es un patrón de persistencia de Java EE (y precursor directo del concepto de Aggregate Root en JPA/Hibernate y DDD) que modela un grafo de objetos estrechamente relacionados como una única entidad padre de grano grueso, gestionando automáticamente el ciclo de vida en base de datos de todos sus objetos hijos dependientes.

Analogía del Mundo Real

Piensa en un Libro y sus Capítulos/Páginas. Una página suelta no se vende ni se cataloga por separado en una biblioteca: existe únicamente como parte del Libro al que pertenece. Cuando la biblioteca registra o da de baja el Libro (la Entidad Raíz), automáticamente quedan registrados o dados de baja todos sus capítulos y páginas internas (los Objetos Dependientes).

Propósito

Simplificar la persistencia de estructuras maestro-detalle: en lugar de obligar al programador a hacer save() o delete() manualmente sobre la tabla padre y luego sobre cada una de las tablas hijas, se persiste únicamente la entidad raíz (EntidadPedido) y sus hijos se guardan o borran en cascada.

Caso de Uso Real: Persistencia en Cascada de un Pedido con Dirección y Líneas (JPA)

Contexto: Un pedido (EntidadPedido) está compuesto por una dirección de entrega (DireccionEnvio) y varias líneas de pedido (LineaPedido). Ninguna línea de pedido ni dirección tiene sentido en la base de datos si el pedido padre no existe.

El Problema (Sin Composite Entity): Si tratas cada tabla como una entidad independiente desconectada, al guardar o borrar un pedido tienes que acordarte de insertar o borrar manualmente todas sus líneas y su dirección; un descuido dejará registros huérfanos o errores de clave foránea.

La Solución (Con Composite Entity): EntidadPedido actúa como el objeto de grano grueso (Coarse-Grained Object) que encapsula a DireccionEnvio y List<LineaPedido>. Al pedir al repositorio guardar EntidadPedido, todo el árbol se persiste en cascada como una unidad atómica.

Implementación en Java


import java.util.ArrayList;
import java.util.List;

// 1. Objeto Dependiente 1: Dirección de Envío
class DireccionEnvio {
    private String street;
    private String city;

    public DireccionEnvio(String street, String city) {
        this.street = street;
        this.city = city;
    }

    @Override
    public String toString() { return street + " (" + city + ")"; }
}

// 2. Objeto Dependiente 2: Línea de Pedido
class LineaPedido {
    private String product;
    private double price;

    public LineaPedido(String product, double price) {
        this.product = product;
        this.price = price;
    }

    @Override
    public String toString() { return product + " [" + price + " EUR]"; }
}

// 3. Coarse-Grained Object (Entidad Compuesta Raíz): En JPA lleva @OneToMany(cascade = CascadeType.ALL)
class EntidadPedido {
    private Long id;
    private String customerName;
    private DireccionEnvio address;
    private List<LineaPedido> lines = new ArrayList<>();

    public EntidadPedido(Long id, String customerName) {
        this.id = id;
        this.customerName = customerName;
    }

    public void setDireccion(String street, String city) {
        this.address = new DireccionEnvio(street, city);
    }

    public void agregarLinea(String product, double price) {
        this.lines.add(new LineaPedido(product, price));
    }

    public Long getId() { return id; }
    public String getCustomerName() { return customerName; }
    public DireccionEnvio getAddress() { return address; }
    public List<LineaPedido> getLines() { return lines; }
}

// 4. Gestor de Persistencia (Simulación de EntityManager / JpaRepository con Cascada)
class EntidadPedidoManager {
    public void saveCompositeEntity(EntidadPedido order) {
        System.out.println("💾 [JPA Cascade] Guardando Entidad Raíz EntidadPedido ID=" + order.getId() + " (" + order.getCustomerName() + ")");
        System.out.println("   ↳ [Cascade INSERT] Guardando DireccionEnvio dependiente: " + order.getAddress());
        for (LineaPedido line : order.getLines()) {
            System.out.println("   ↳ [Cascade INSERT] Guardando LineaPedido dependiente: " + line);
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Equivalencia directa en Hibernate / Spring Data JPA:

    Cada vez que en una entidad JPA escribes @OneToMany(cascade = CascadeType.ALL, orphanRemoval = true) sobre una lista de líneas de factura o de pedido, estás aplicando el patrón Composite Entity.

  • 2. Un solo repositorio para todo el grupo:

    Gracias a este patrón, no necesitas crear un LineaPedidoRepository ni un DireccionEnvioRepository: todo se guarda y se lee a través del repositorio del padre (OrderRepository).

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // 1. Construimos la Entidad Compuesta y sus objetos dependientes a través de la raíz
        EntidadPedido pedido = new EntidadPedido(501L, "María Fernández");
        pedido.setDireccion("Calle Mayor 14", "Madrid");
        pedido.agregarLinea("Ratón Inalámbrico", 29.90);
        pedido.agregarLinea("Alfombrilla XL", 15.00);

        // 2. Persistimos ÚNICAMENTE la raíz y todo el grafo se guarda en cascada
        EntidadPedidoManager entityManager = new EntidadPedidoManager();
        entityManager.saveCompositeEntity(pedido);
    }
}
Una sola llamada persiste la entidad padre junto con todos sus hijos

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: En relaciones padre-hijo de composición fuerte donde los hijos no tienen vida propia fuera del padre (Pedido y Líneas de Pedido, Factura y Conceptos, Cuestionario y Preguntas).
  • Cuándo evitarlo: Nunca pongas CascadeType.ALL hacia entidades maestras compartidas por muchos registros (por ejemplo, de Order hacia Product o Customer), porque al borrar un pedido ¡borrarías también al cliente o al producto del catálogo!
