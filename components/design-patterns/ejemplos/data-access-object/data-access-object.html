Patrón Data Access Object (DAO)

El patrón Data Access Object (DAO) es uno de los patrones estructurales y de integración más importantes de Java EE. Su objetivo es aislar por completo la lógica de negocio de los detalles técnicos de la base de datos mediante una interfaz intermedia.

Analogía del Mundo Real

Piensa en un Bibliotecario en el mostrador de préstamos. Cuando tú (la Lógica de Negocio) pides el libro con código 101 (buscarPorId(101)), no entras tú mismo al sótano ni necesitas saber si los libros están ordenados en estanterías de madera, en cajas fuertes automatizadas o en formato digital. Tú hablas con el Bibliotecario (la interfaz UsuarioDAO), y él sabe cómo ir al almacén concreto a buscarlo o guardarlo.

Propósito

Lograr que tus servicios de negocio no contengan ni una sola línea de SQL, JDBC, JPA ni MongoDB. La capa de negocio solo invoca métodos limpios de una interfaz (guardar(user), buscarPorId(id)), permitiendo cambiar de motor de base de datos o usar una base de datos en memoria para tests sin tocar el negocio.

Caso de Uso Real: Cambio Transparente entre Base de Datos SQL y Memoria

Contexto: Tu servicio de usuarios (ServicioUsuarios) necesita guardar y consultar usuarios. En producción trabajas contra MySQL (UsuarioDAOMySQL), pero en los tests automáticos quieres guardar en un HashMap en memoria RAM (UsuarioDAOMemoria) para que los tests tarden milisegundos.

El Problema (Sin DAO): Si metes sentencias SELECT * FROM users directamente dentro de ServicioUsuarios, es imposible ejecutar ServicioUsuarios sin tener un servidor MySQL real encendido, y migrar mañana a PostgreSQL o MongoDB obligaría a reescribir la lógica de negocio.

La Solución (Con DAO): Creamos la interfaz UsuarioDAO. ServicioUsuarios recibe cualquier implementación de UsuarioDAO por su constructor y trabaja siempre igual.

Implementación en Java


import java.util.HashMap;
import java.util.Map;

// 1. Modelo de datos (Usuario)
class Usuario {
    private int id;
    private String name;

    public User(int id, String name) {
        this.id = id;
        this.name = name;
    }

    public int getId() { return id; }
    public String getName() { return name; }
}

// 2. Interfaz DAO: Contrato de persistencia 100% agnóstico de la tecnología de BD
interface UsuarioDAO {
    void guardar(Usuario user);
    Usuario buscarPorId(int id);
}

// 3. Implementación Concreta A: Base de Datos Relacional MySQL
class UsuarioDAOMySQL implements UsuarioDAO {
    @Override
    public void guardar(Usuario user) {
        System.out.println("🐬 [MySQL DAO] Ejecutando SQL: INSERT INTO users VALUES (" + user.getId() + ", '" + user.getName() + "')");
    }

    @Override
    public Usuario buscarPorId(int id) {
        System.out.println("🐬 [MySQL DAO] Ejecutando SQL: SELECT * FROM users WHERE id = " + id);
        return new Usuario(id, "Usuario_Desde_MySQL");
    }
}

// 4. Implementación Concreta B: Base de Datos en Memoria (ideal para Tests Unitarios)
class UsuarioDAOMemoria implements UsuarioDAO {
    private Map<Integer, User> memoryDb = new HashMap<>();

    @Override
    public void guardar(Usuario user) {
        System.out.println("⚡ [InMemory DAO] Guardando usuario en HashMap en RAM: " + user.getName());
        memoryDb.put(user.getId(), user);
    }

    @Override
    public Usuario buscarPorId(int id) {
        System.out.println("⚡ [InMemory DAO] Buscando usuario ID=" + id + " en RAM...");
        return memoryDb.get(id);
    }
}

// 5. Servicio de Negocio: ¡No sabe si está usando MySQL o Memoria!
class ServicioUsuarios {
    private UsuarioDAO userDao;

    public ServicioUsuarios(UsuarioDAO userDao) {
        this.userDao = userDao;
    }

    public void registerAndVerify(int id, String name) {
        userDao.guardar(new Usuario(id, name));
        Usuario found = userDao.buscarPorId(id);
        System.out.println("✅ [ServicioUsuarios] Usuario verificado correctamente: " + found.getName());
    }
}
Implementación completa del patrón DAO con dos motores intercambiables

Análisis Paso a Paso para Principiantes

  • 1. Inversión de Dependencias (La 'D' de SOLID):

    ServicioUsuarios no hace new UsuarioDAOMySQL(), sino que recibe la interfaz UsuarioDAO por su constructor. Por eso podemos cambiar de MySQL a Memoria sin cambiar ni una línea de ServicioUsuarios.

  • 2. Relación con @Repository de Spring Data:

    En Spring Boot, las interfaces que extienden JpaRepository<User, Long> son una evolución directa del patrón DAO donde Spring genera automáticamente la clase Impl por ti en tiempo de ejecución.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        System.out.println("--- Escenario 1: Ejecutando ServicioUsuarios en Producción (MySQL) ---");
        ServicioUsuarios prodService = new ServicioUsuarios(new UsuarioDAOMySQL());
        prodService.registerAndVerify(1, "Lucía");

        System.out.println("\n--- Escenario 2: Ejecutando el MISMO ServicioUsuarios en Tests (En Memoria) ---");
        ServicioUsuarios testService = new ServicioUsuarios(new UsuarioDAOMemoria());
        testService.registerAndVerify(2, "Roberto");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: En toda aplicación que acceda a bases de datos, archivos o almacenamiento externo para mantener la lógica de negocio limpia y testeable.
  • Cuándo evitarlo: Nunca expongas objetos técnicos de la base de datos (como un ResultSet de JDBC) en el tipo de retorno de la interfaz DAO, ya que romperías la abstracción.
