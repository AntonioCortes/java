Patrón Iterator

El patrón Iterator (Iterador) es un patrón de comportamiento que permite recorrer todos los elementos de una colección de forma secuencial (uno tras otro) sin exponer cómo están almacenados por dentro (ya sea un array, una lista enlazada, un árbol o un grafo).

Analogía del Mundo Real

Piensa en el botón "Siguiente canción" (⏭) de Spotify o el botón "Canal +" de tu televisor. Cuando pulsas "Siguiente", no necesitas saber en qué posición de memoria ni en qué estructura de base de datos está guardada la lista de reproducción: el reproductor lleva la cuenta de por qué canción vas (index), sabe si queda alguna más (tieneSiguiente()) y te entrega la siguiente (siguiente()).

Propósito

Extraer la responsabilidad de recorrer una estructura de datos hacia un objeto dedicado llamado Iterador, permitiendo recorrer cualquier colección con un bucle uniforme while (it.tieneSiguiente()) sin acoplar el cliente a la estructura interna de la colección.

Caso de Uso Real: Recorrido Uniforme de un Repositorio de Datos

Contexto: Tienes una clase RepositorioNombres que almacena internamente los nombres de los empleados en un array privado String[].

El Problema (Sin Iterator): Si expones el array interno directamente al exterior, el cliente se acopla a que es un array. Si el mes que viene decides cambiar el array interno por un TreeSet o una consulta paginada, romperás todos los bucles de tu aplicación.

La Solución (Con Iterator): RepositorioNombres oculta su array privado y ofrece el método obtenerIterador(), que devuelve un objeto Iterador con dos métodos universales: tieneSiguiente() (¿queda algún elemento?) y siguiente() (dame el siguiente y avanza una posición).

Implementación en Java


// 1. Interfaz Iterator: contrato universal de recorrido
interface Iterador {
    boolean tieneSiguiente();
    Object siguiente();
}

// 2. Interfaz Container (Colección iterable)
interface Contenedor {
    Iterador obtenerIterador();
}

// 3. Colección Concreta: oculta su estructura interna (array privado)
class RepositorioNombres implements Contenedor {
    private String[] names = {"Ana", "Carlos", "Elena", "David"};

    @Override
    public Iterador obtenerIterador() {
        return new IteradorNombres();
    }

    // 4. Iterador Concreto (como clase interna para acceder a 'names' sin exponerlo fuera)
    private class IteradorNombres implements Iterador {
        private int index = 0;

        @Override
        public boolean tieneSiguiente() {
            return index < names.length;
        }

        @Override
        public Object siguiente() {
            if (this.tieneSiguiente()) {
                return names[index++];
            }
            return null;
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Encapsulación total de la estructura de datos:

    El atributo private String[] names es privado. La clase Main no sabe si dentro de RepositorioNombres hay un array, una lista enlazada o un árbol binario; solo usa tieneSiguiente() y siguiente().

  • 2. Múltiples recorridos independientes a la vez:

    Como el contador int index vive dentro de cada objeto IteradorNombres y no en el repositorio, puedes pedir dos iteradores al mismo tiempo y cada uno llevará su propia cuenta sin estorbar al otro.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        RepositorioNombres repository = new RepositorioNombres();

        // Pedimos un iterador a la colección
        Iterator it = repository.obtenerIterador();

        System.out.println("--- Recorriendo el repositorio con Iterator ---");
        while (it.tieneSiguiente()) {
            String name = (String) it.siguiente();
            System.out.println("Empleado encontrado: " + name);
        }
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando diseñes una estructura de datos personalizada (como un grafo, un árbol o un catálogo paginado) y quieras ofrecer una forma estándar de recorrerla sin exponer sus punteros internos. De hecho, el bucle for (String s : lista) de Java usa internamente java.util.Iterator.
  • Cuándo evitarlo: Si ya estás usando una colección estándar de Java (ArrayList, HashSet), usa directamente el Iterador que ya trae incluido el JDK en lugar de programar el tuyo propio.
