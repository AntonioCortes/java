Patrón Intercepting Filter

El patrón Intercepting Filter (Filtro Interceptor) es un patrón de la capa de presentación de Java EE que permite interceptar y manipular una petición web antes de que llegue al controlador destino (pre-procesamiento) y/o antes de que la respuesta regrese al usuario (post-procesamiento), encadenando filtros enchufables.

Analogía del Mundo Real

Piensa en los controles de seguridad de un aeropuerto antes de subir al avión (el recurso destino). Todo pasajero pasa por una fila secuencial de filtros independientes: primero el control de billete (FiltroAutenticacion), segundo el arco detector de metales (FiltroAuditoria) y tercero el control de equipaje (FiltroCompresion). El capitán del avión no tiene que revisar tu pasaporte en la puerta de la cabina porque los filtros ya lo hicieron antes.

Propósito

Extraer tareas transversales repetitivas (autenticación JWT/sesión, registro de auditoría, cabeceras CORS, compresión GZIP) fuera de los controladores de negocio para no violar el principio DRY (Don't Repeat Yourself).

Caso de Uso Real: Tubería de Filtros HTTP en una Aplicación Web

Contexto: Tienes 50 endpoints REST y quieres que en todos ellos se compruebe la autenticación del usuario y se registre un log de acceso antes de ejecutar la lógica del controlador (ControladorDestino).

El Problema (Sin Intercepting Filter): Si copias y pegas las líneas de autenticación y logging al principio de los 50 controladores, el día que cambies el sistema de seguridad tendrás que editar 50 clases.

La Solución (Con Intercepting Filter): Creamos filtros independientes (FiltroAutenticacion, FiltroAuditoria) que implementan la interfaz Filtro, y una clase CadenaFiltros que los ejecuta en orden uno tras otro antes de invocar finalmente a ControladorDestino.

Target (Destino) ControladorDestino El controlador final que procesa la petición de negocio una vez superados todos los filtros.

Implementación en Java


import java.util.ArrayList;
import java.util.List;

// 1. Interfaz Filter
interface Filtro {
    void ejecutar(String request);
}

// 2. Filtros Concretos
class FiltroAutenticacion implements Filtro {
    @Override
    public void ejecutar(String request) {
        System.out.println("🔒 [Filtro 1 - FiltroAutenticacion] Verificando token de seguridad para: " + request);
    }
}

class FiltroAuditoria implements Filtro {
    @Override
    public void ejecutar(String request) {
        System.out.println("📝 [Filtro 2 - FiltroAuditoria] Registrando petición en auditoría: " + request);
    }
}

// 3. Recurso Destino (Controlador de negocio limpio)
class ControladorDestino {
    public void ejecutar(String request) {
        System.out.println("🎯 [ControladorDestino] Ejecutando lógica de negocio principal para: " + request);
    }
}

// 4. Cadena de Filtros (CadenaFiltros): recorre los filtros y finalmente llama al Target
class CadenaFiltros {
    private List<Filter> filters = new ArrayList<>();
    private ControladorDestino target;

    public void agregarFiltro(Filtro filter) {
        filters.add(filter);
    }

    public void setTarget(ControladorDestino target) {
        this.target = target;
    }

    public void ejecutar(String request) {
        for (Filtro filter : filters) {
            filter.ejecutar(request);
        }
        target.ejecutar(request);
    }
}

// 5. Gestor de Filtros (GestorFiltros)
class GestorFiltros {
    private CadenaFiltros filterChain;

    public GestorFiltros(ControladorDestino target) {
        filterChain = new CadenaFiltros();
        filterChain.setTarget(target);
    }

    public void agregarFiltro(Filtro filter) {
        filterChain.agregarFiltro(filter);
    }

    public void filtrarPeticion(String request) {
        filterChain.ejecutar(request);
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Uso real en Jakarta EE y Spring Security:

    La interfaz estándar jakarta.servlet.Filter (con su método doFilter(req, res, chain)) y toda la arquitectura de seguridad de Spring Security (SecurityCadenaFiltros) son implementaciones directas de este patrón.

  • 2. Filtros "enchufables" sin tocar el negocio:

    Puedes añadir un tercer filtro (FiltroCompresion) llamando a filterManager.agregarFiltro(...) sin cambiar ni una línea de ControladorDestino.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // Configuramos el gestor apuntando al controlador destino
        GestorFiltros filterManager = new GestorFiltros(new ControladorDestino());

        // Enchufamos los filtros en el orden deseado
        filterManager.agregarFiltro(new FiltroAutenticacion());
        filterManager.agregarFiltro(new FiltroAuditoria());

        // Simulamos la llegada de una petición HTTP del cliente
        System.out.println("--- Petición entrante del navegador ---");
        filterManager.filtrarPeticion("GET /api/v1/facturas/2026");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Para cualquier validación o transformación transversal que aplique a múltiples URLs (autenticación, CORS, cabeceras de seguridad, compresión, medición de tiempos).
  • Cuándo evitarlo: Nunca metas reglas de negocio específicas de una pantalla concreta (como calcular el descuento de un carrito) dentro de un filtro global.
