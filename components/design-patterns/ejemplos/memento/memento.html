Patrón Memento

El patrón Memento (Recuerdo o Instantánea) es un patrón de comportamiento que permite guardar y restaurar el estado previo de un objeto (como un punto de guardado o un Ctrl+Z) sin romper su encapsulamiento ni exponer sus atributos privados al exterior.

Analogía del Mundo Real

Piensa en los puntos de guardado (Save Points) de un videojuego. Antes de enfrentarte al jefe final, guardas la partida. El juego empaqueta tu vida actual, nivel y monedas en una "cápsula sellada" (el Memento) y la almacena en la tarjeta de memoria (el CareTaker). Si pierdes la batalla, cargas esa cápsula y tu personaje vuelve exactamente al estado que tenía antes.

Propósito

Permitir que el propio objeto dueño de los datos (llamado Originator) cree una "fotografía" inmutable de su estado (Memento) para que un guardián externo (CareTaker) la custodie en un historial sin poder alterar su contenido.

Caso de Uso Real: Función Deshacer (Ctrl+Z) en un Editor de Texto

Contexto: Un usuario escribe frases en un editor de texto (EditorTexto) y quiere poder volver a versiones anteriores del documento en cualquier momento.

El Problema (Sin Memento): Si una clase externa intenta hacer copias manuales de todos los atributos del editor desde fuera, necesitaría que todos los campos internos del editor fueran public, rompiendo el principio de encapsulamiento.

La Solución (Con Memento): El propio EditorTexto tiene el método guardarEnMemento() que devuelve un objeto inmutable Memento, y el método restaurarDesdeMemento(m) que restaura su texto a partir de esa instantánea. La clase Historial solo guarda una lista de instantáneas.

Implementación en Java


import java.util.ArrayList;
import java.util.List;

// 1. Memento: Instantánea inmutable del estado en un momento dado
class Memento {
    private final String state;

    public Memento(String state) {
        this.state = state;
    }

    public String getEstado() {
        return state;
    }
}

// 2. Originator: El Editor de Texto que crea y restaura sus propias instantáneas
class EditorTexto {
    private String state;

    public void setEstado(String state) {
        System.out.println("[Editor] Escribiendo texto: \"" + state + "\"");
        this.state = state;
    }

    public String getEstado() {
        return state;
    }

    // Crea una fotografía inmutable del estado actual
    public Memento guardarEnMemento() {
        System.out.println("💾 [Guardado] Creando instantánea Memento...");
        return new Memento(this.state);
    }

    // Restaura el estado interno a partir de un Memento previo
    public void restaurarDesdeMemento(Memento memento) {
        this.state = memento.getEstado();
        System.out.println("⏪ [Restaurado] Volviendo al estado: \"" + this.state + "\"");
    }
}

// 3. CareTaker (Guardián): Gestiona el historial de instantáneas
class Historial {
    private List<Memento> mementoList = new ArrayList<>();

    public void guardar(Memento state) {
        mementoList.add(state);
    }

    public Memento obtener(int index) {
        return mementoList.get(index);
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Por qué Memento no tiene método setEstado()?

    Porque una fotografía del pasado nunca debe alterarse. Al declarar private final String state sin ningún setter, garantizamos que nadie en el programa pueda corromper un punto de guardado antiguo.

  • 2. Separación de responsabilidades entre EditorTexto y Historial:

    EditorTexto solo se preocupa del estado actual, mientras que Historial se encarga de almacenar la pila o lista de versiones pasadas.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        EditorTexto editor = new EditorTexto();
        Historial historial = new Historial();

        // Versión 1: escribimos y guardamos instantánea
        editor.setEstado("Versión 1: Hola Mundo");
        historial.guardar(editor.guardarEnMemento());

        // Versión 2: escribimos y guardamos instantánea
        editor.setEstado("Versión 2: Hola Mundo en Java");
        historial.guardar(editor.guardarEnMemento());

        // Versión 3: cometemos un error y NO guardamos
        editor.setEstado("Versión 3: Texto borrado por accidente #@!");
        System.out.println("Estado actual antes de deshacer: \"" + editor.getEstado() + "\"\n");

        // Deshacer (Ctrl+Z): restauramos la versión guardada en el índice 1
        editor.restaurarDesdeMemento(historial.obtener(1));

        // Deshacer otra vez: restauramos la primera versión (índice 0)
        editor.restaurarDesdeMemento(historial.obtener(0));
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando necesites implementar operaciones de Deshacer/Rehacer (Undo/Redo), puntos de control (checkpoints) o rollback en memoria preservando el encapsulamiento del objeto.
  • Cuándo evitarlo: Si el objeto contiene cientos de megabytes de datos (por ejemplo, un vídeo o imagen en crudo) y se crean instantáneas cada segundo, ya que llenaría rápidamente la memoria RAM.
