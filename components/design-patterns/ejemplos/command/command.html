Patrón Command

El patrón Command (Comando u Orden) es un patrón de comportamiento que convierte una solicitud o acción en un objeto independiente. Esto permite pasar acciones como parámetros, ponerlas en una cola de tareas, registrarlas en un historial o deshacerlas (Undo).

Analogía del Mundo Real

Piensa en hacer un pedido en un restaurante. Tú (el Cliente) le dices lo que quieres al Camarero (el Invocador). El camarero escribe tu pedido en una Comanda de papel (el objeto Comando) y la coloca en la barra de la cocina. Más tarde, el Cocinero (el Receptor) lee esa comanda y prepara el plato. El camarero no necesita saber cocinar; solo sabe entregar comandas.

Propósito

Desacoplar por completo el objeto que dispara una acción (como un botón de una interfaz o un mando domótico) del objeto que realmente sabe cómo ejecutarla (una bombilla inteligente, un motor o un documento de texto).

Caso de Uso Real: Mando Programable de Domótica (Smart Home)

Contexto: Tienes un botón inteligente en la pared (ControlRemoto) que puede configurarse desde el móvil para encender la luz del salón, apagarla o abrir la puerta del garaje.

El Problema (Sin Command): Si dentro de la clase ControlRemoto escribes directamente luz.encender(), ese botón queda atado para siempre a encender esa bombilla y no sirve para ninguna otra acción sin reprogramar la clase del mando.

La Solución (Con Command): Creamos la interfaz Comando con un único método ejecutar(). El mando (ControlRemoto) solo guarda un objeto Comando y al pulsar el botón llama a command.ejecutar(). Así puedes asignarle un ComandoEncenderLuz o un ComandoApagarLuz en cualquier momento.

Implementación en Java


// 1. Interfaz Command
interface Comando {
    void ejecutar();
}

// 2. Receptor (Receiver): quien realiza el trabajo físico o de negocio real
class Luz {
    public void encender() {
        System.out.println("💡 [Luz del Salón] Bombilla ENCENDIDA");
    }

    public void apagar() {
        System.out.println("🌑 [Luz del Salón] Bombilla APAGADA");
    }
}

// 3. Comandos Concretos: empaquetan una acción sobre el Receptor
class ComandoEncenderLuz implements Comando {
    private Luz luz;

    public ComandoEncenderLuz(Luz luz) {
        this.luz = luz;
    }

    @Override
    public void ejecutar() {
        luz.encender();
    }
}

class ComandoApagarLuz implements Comando {
    private Luz luz;

    public ComandoApagarLuz(Luz luz) {
        this.luz = luz;
    }

    @Override
    public void ejecutar() {
        luz.apagar();
    }
}

// 4. Invocador (Invoker): el botón o mando que dispara el comando asignado
class ControlRemoto {
    private Comando comando;

    public void setComando(Comando comando) {
        this.comando = comando;
    }

    public void pulsarBoton() {
        System.out.println(">> Usuario pulsa el botón del mando...");
        comando.ejecutar();
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Por qué no llamar a luz.encender() directamente?

    Porque si el botón llama a luz.encender(), el botón solo sirve para luces. En cambio, como el botón solo llama a command.ejecutar(), puedes usar exactamente la misma clase ControlRemoto para encender luces, abrir persianas, enviar un correo o deshacer texto en un editor.

  • 2. Historial y Cola de Tareas:

    Como cada orden (ComandoEncenderLuz) es un objeto normal de Java, puedes meter todas las órdenes ejecutadas en una lista List<Command> historial para repetirlas (macros) o deshacerlas.

public class Main {
    public static void main(String[] args) {
        // Creamos el receptor real (la bombilla) y el invocador (el mando)
        Luz salonLuz = new Luz();

        remote.setComando(turnOn);

        // Reprogramamos el mismo botón con el comando de apagar y lo pulsamos
        remote.setComando(turnOff);
        remote.pulsarBoton();
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando necesites botones/menús configurables, colas de trabajos en segundo plano (como Runnable en Java, que es literalmente un patrón Command) o sistemas con historial de Deshacer/Rehacer (Undo/Redo).
  • Cuándo evitarlo: En llamadas directas entre servicios donde no necesitas encolar, parametrizar ni deshacer la operación.
