Patrón Transfer Object Assembler

El patrón Transfer Object Assembler (Ensamblador de DTOs) es un patrón de la arquitectura Java EE y de microservicios que recolecta datos procedentes de múltiples servicios, microservicios o DAOs distintos y los combina en un único DTO compuesto hecho a la medida de una pantalla concreta.

Analogía del Mundo Real

Piensa en las cestas de Navidad. Los productos vienen de fábricas completamente distintas: el jamón viene de Salamanca, el turrón de Alicante y el vino de La Rioja. En lugar de que el comprador tenga que hacer tres pedidos a tres fábricas distintas, una empresa ensambladora (Transfer Object Assembler) pide cada producto a su fabricante y los mete todos juntos en una única cesta lista para regalar (PanelCompuestoDTO).

Propósito

Evitar que el cliente (una app móvil o un navegador web) tenga que realizar 3, 4 o 5 llamadas HTTP separadas a distintos microservicios para poder pintar una sola pantalla como un Panel de Control (Dashboard).

Caso de Uso Real: Construcción del Dashboard Inicial en una Arquitectura de Microservicios

Contexto: Cuando el usuario abre la app de una tienda, la pantalla de inicio necesita mostrar tres cosas a la vez: 1) su nombre completo (que vive en MicroservicioUsuarios), 2) sus últimos pedidos (que viven en MicroservicioPedidos) y 3) cuántas notificaciones sin leer tiene (que viven en MicroservicioNotificaciones).

El Problema (Sin Transfer Object Assembler): Si el teléfono móvil con cobertura 4G inestable tiene que hacer 3 peticiones REST distintas a 3 microservicios, la pantalla irá apareciendo a trozos llenándose de iconos de carga (spinners).

La Solución (Con Transfer Object Assembler): Creamos en el servidor la clase EnsambladorPanel. El móvil hace una única llamada, el Assembler consulta rápidamente por la red interna de alta velocidad a los 3 microservicios y devuelve un solo objeto PanelCompuestoDTO con toda la información unificada.

Implementación en Java


import java.util.Arrays;
import java.util.List;

// 1. Fuentes de datos independientes (Microservicios / Servicios de Dominio)
class MicroservicioUsuarios {
    public String fetchUserName(Long userId) {
        System.out.println("   🔹 [MicroservicioUsuarios] Obteniendo perfil del usuario ID=" + userId);
        return "Antonio Cortés";
    }
}

class MicroservicioPedidos {
    public List<String> fetchRecentOrders(Long userId) {
        System.out.println("   🔹 [MicroservicioPedidos] Obteniendo últimos pedidos del usuario ID=" + userId);
        return Arrays.asList("Pedido #101 (Teclado)", "Pedido #102 (Monitor)");
    }
}

class MicroservicioNotificaciones {
    public int fetchUnreadCount(Long userId) {
        System.out.println("   🔹 [MicroservicioNotificaciones] Contando alertas no leídas del usuario ID=" + userId);
        return 3;
    }
}

// 2. DTO Compuesto Final (diseñado a medida de la pantalla de Dashboard)
class PanelCompuestoDTO {
    private String userName;
    private List<String> recentOrders;
    private int unreadAlerts;

    public PanelCompuestoDTO(String userName, List<String> recentOrders, int unreadAlerts) {
        this.userName = userName;
        this.recentOrders = recentOrders;
        this.unreadAlerts = unreadAlerts;
    }

    @Override
    public String toString() {
        return "PanelCompuestoDTO {\n"
                + "   usuario: '" + userName + "',\n"
                + "   ultimosPedidos: " + recentOrders + ",\n"
                + "   alertasSinLeer: " + unreadAlerts + "\n}";
    }
}

// 3. Transfer Object Assembler: Recolecta de los 3 microservicios y ensambla el DTO único
class EnsambladorPanel {
    private MicroservicioUsuarios userService = new MicroservicioUsuarios();
    private MicroservicioPedidos orderService = new MicroservicioPedidos();
    private MicroservicioNotificaciones notifService = new MicroservicioNotificaciones();

    public PanelCompuestoDTO ensamblarPanel(Long userId) {
        System.out.println("⚙️ [EnsambladorPanel] Recolectando datos de múltiples microservicios...");
        String name = userService.fetchUserName(userId);
        List<String> orders = orderService.fetchRecentOrders(userId);
        int alerts = notifService.fetchUnreadCount(userId);

        System.out.println("📦 [EnsambladorPanel] Ensamblando respuesta única PanelCompuestoDTO.");
        return new PanelCompuestoDTO(name, orders, alerts);
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Su nombre en arquitecturas modernas de Microservicios:

    En el mundo actual de microservicios y Cloud, este mismo patrón también se conoce como Aggregator Microservice o BFF (Backend For Frontend): un servicio intermedio que agrega las respuestas de varios microservicios para entregárselas ya unificadas a la app móvil.

  • 2. Diferencia entre Transfer Object (DTO) y Transfer Object Assembler:

    Un DTO simple transporta los datos de una entidad. El Transfer Object Assembler es la clase constructora que junta datos de muchas fuentes distintas para fabricar un DTO compuesto.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        EnsambladorPanel assembler = new EnsambladorPanel();

        // El cliente móvil pide el Dashboard completo en 1 sola llamada
        PanelCompuestoDTO dashboard = assembler.ensamblarPanel(77L);

        System.out.println("\n📱 [App Móvil] Pintando pantalla completa de una sola vez:");
        System.out.println(dashboard);
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: En pantallas tipo Dashboard, resúmenes de cuenta o fichas de detalle que necesitan cruzar información procedente de varios microservicios o múltiples tablas sin relación directa.
  • Cuándo evitarlo: En pantallas CRUD simples que solo consultan una única tabla o servicio.
