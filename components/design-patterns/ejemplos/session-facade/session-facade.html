Patrón Session Facade

El patrón Session Facade (Fachada de Sesión) es un patrón de la capa de negocio de Java EE que proporciona un único servicio de grano grueso y transaccional frente a múltiples objetos o servicios internos de negocio, evitando que el cliente tenga que hacer muchas llamadas remotas individuales.

Analogía del Mundo Real

Piensa en una transferencia bancaria entre dos cuentas. Desde la app de tu móvil tú solo pulsas un botón: "Transferir 100€" (una única llamada al Session Facade). Dentro del banco, esa fachada abre una transacción segura, resta 100€ de tu cuenta, suma 100€ a la cuenta destino y registra el apunte contable. Si el último paso falla, la fachada deshace (rollback) todos los pasos anteriores automáticamente.

Propósito

Resolver dos grandes problemas de las aplicaciones distribuidas: 1) reducir el tráfico de red (hacer 1 llamada remota en lugar de 4 llamadas pequeñas), y 2) agrupar todas las operaciones internas dentro de una única transacción atómica (todo o nada).

Caso de Uso Real: Formalización de un Pedido en una Sola Transacción

Contexto: Completar un pedido (realizarPedido) requiere coordinar tres componentes internos: reservar el artículo en ServicioInventario, cobrar el importe en ServicioPagos y programar el envío en ServicioEnvios.

El Problema (Sin Session Facade): Si la aplicación móvil llama por red primero a Inventario, luego a Pagos y luego a Envíos por separado, además de tardar el triple por la latencia de red, si la llamada a Envíos falla el cliente ya habrá pagado y el stock quedará bloqueado sin forma fácil de deshacerlo desde el móvil.

La Solución (Con Session Facade): Exponemos FachadaSesionPedido.realizarPedido(). El cliente hace una sola llamada remota y la fachada ejecuta las tres operaciones dentro de una misma frontera transaccional en el servidor.

Implementación en Java


// 1. Componentes internos de negocio (Grano Fino)
class ServicioInventario {
    public void reserveItem(String item) {
        System.out.println("   1️⃣ [Inventario] Stock reservado para: " + item);
    }
}

class ServicioPagos {
    public void chargeCustomer(double amount) {
        System.out.println("   2️⃣ [Pagos] Cargo realizado por importe de: " + amount + " EUR");
    }
}

class ServicioEnvios {
    public void scheduleDelivery(String item) {
        System.out.println("   3️⃣ [Envíos] Orden de transporte generada para: " + item);
    }
}

// 2. Session Facade: Interfaz de grano grueso y frontera transaccional
class FachadaSesionPedido {
    private ServicioInventario inventory = new ServicioInventario();
    private ServicioPagos payment = new ServicioPagos();
    private ServicioEnvios shipping = new ServicioEnvios();

    // En EJB sería @Stateless y en Spring sería @Service + @Transactional
    public void realizarPedido(String item, double amount) {
        System.out.println("🔒 [SessionFacade] >> INICIANDO TRANSACCIÓN ATÓMICA EN SERVIDOR <<");
        try {
            inventory.reserveItem(item);
            payment.chargeCustomer(amount);
            shipping.scheduleDelivery(item);
            System.out.println("✅ [SessionFacade] >> COMMIT: Pedido completado con éxito en 1 sola llamada <<");
        } catch (Exception e) {
            System.out.println("❌ [SessionFacade] >> ROLLBACK: Deshaciendo cambios por error <<");
        }
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Qué significa "Grano Grueso" (Coarse-Grained) vs "Grano Fino" (Fine-Grained)?

    Llamar por red a 5 métodos pequeñitos (checkStock(), decrementStock(), validateCard(), chargeCard(), createShipment()) es una API de grano fino (lenta en red). Agrupar todo en un único método remoto realizarPedido() es una API de grano grueso.

  • 2. Relación con @Transactional de Spring:

    En aplicaciones empresariales modernas con Spring Boot, una clase @Service cuyo método público está anotado con @Transactional y coordina varios repositorios/componentes cumple exactamente el rol de un Session Facade.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        FachadaSesionPedido orderFacade = new FachadaSesionPedido();

        // El cliente remoto solo hace UNA llamada para ejecutar toda la operación
        System.out.println("--- Cliente solicita formalizar compra ---");
        orderFacade.realizarPedido("Auriculares Bluetooth Pro", 199.95);
    }
}
El cliente realiza una única invocación remota a la fachada de sesión

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Siempre que una operación de negocio involucre modificar varias tablas o subsistemas que deban confirmarse o deshacerse juntos bajo una misma transacción.
  • Cuándo evitarlo: Si la operación es una consulta simple de un único dato sin lógica transaccional ni coordinación de múltiples componentes.
