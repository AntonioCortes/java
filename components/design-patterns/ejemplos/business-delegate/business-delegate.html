Patrón Business Delegate

El patrón Business Delegate (Delegado de Negocio) es un patrón de la arquitectura Java EE que coloca una clase intermediaria local en la capa de presentación para ocultar toda la complejidad de localizar y comunicarse con servicios de negocio remotos (como microservicios, EJBs o servicios SOAP/REST).

Analogía del Mundo Real

Piensa en un Agente de Viajes o un Abogado Representante. Si quieres reservar un viaje internacional complejo, tú no llamas personalmente en inglés a la aerolínea, luego en francés al hotel y luego a la aseguradora gestionando los errores de línea telefónica: tú hablas en tu idioma con tu Agente local (el DelegadoNegocio) y él se encarga de localizar a cada proveedor remoto, reintentar la llamada si comunica y darte una respuesta limpia.

Propósito

Desacoplar la capa de presentación (controladores web/vistas) de los detalles de red, protocolos de comunicación, búsqueda de servicios (Service Lookup) y excepciones de infraestructura remota.

Caso de Uso Real: Cliente Web invocando Microservicios de Envío y Facturación

Contexto: Tu capa de presentación (ClientePresentacion) necesita ejecutar operaciones tanto en el servicio remoto de Envíos (MicroservicioEnvios) como en el de Facturación (MicroservicioFacturacion).

El Problema (Sin Business Delegate): Si la pantalla o controlador web tiene que buscar direcciones de red, configurar clientes HTTP/RMI y capturar RemoteException directamente, cualquier cambio en la ubicación de los microservicios obligará a modificar la capa de presentación.

La Solución (Con Business Delegate): ClientePresentacion solo habla con la clase local DelegadoNegocio. Internamente, DelegadoNegocio pide al LocalizadorServicios la referencia del servicio remoto adecuado y ejecuta procesar().

Implementación en Java


// 1. Interfaz común de los Servicios de Negocio Remotos
interface ServicioNegocio {
    void procesar();
}

// 2. Servicios de Negocio Concretos (Simulación de Microservicios / EJBs remotos)
class MicroservicioEnvios implements ServicioNegocio {
    @Override
    public void procesar() {
        System.out.println("🚚 [Microservicio Remoto Envíos] Generando etiqueta logística y orden de reparto.");
    }
}

class MicroservicioFacturacion implements ServicioNegocio {
    @Override
    public void procesar() {
        System.out.println("🧾 [Microservicio Remoto Facturación] Emitiendo factura electrónica firmada.");
    }
}

// 3. Buscador de Servicios (Lookup Service)
class LocalizadorServicios {
    public ServicioNegocio obtenerServicio(String serviceType) {
        if (serviceType.equalsIgnoreCase("SHIPPING")) {
            return new MicroservicioEnvios();
        } else {
            return new MicroservicioFacturacion();
        }
    }
}

// 4. Business Delegate: Intermediario local que usa la capa de presentación
class DelegadoNegocio {
    private LocalizadorServicios locator = new LocalizadorServicios();
    private ServicioNegocio businessService;
    private String serviceType;

    public void setTipoServicio(String serviceType) {
        this.serviceType = serviceType;
    }

    public void ejecutarTarea() {
        System.out.println(">> [DelegadoNegocio] Localizando e invocando servicio remoto: " + serviceType);
        businessService = locator.obtenerServicio(serviceType);
        businessService.procesar();
    }
}

// 5. Cliente de la Capa de Presentación
class ClientePresentacion {
    private DelegadoNegocio businessDelegate;

    public ClientePresentacion(DelegadoNegocio businessDelegate) {
        this.businessDelegate = businessDelegate;
    }

    public void realizarTrabajo() {
        businessDelegate.ejecutarTarea();
    }
}

Análisis Paso a Paso para Principiantes

  • 1. Equivalente moderno en Spring Cloud (OpenFeign):

    En arquitecturas modernas de microservicios con Spring Boot, un cliente declarativo como Spring Cloud OpenFeign (@FeignClient) actúa como un Business Delegate: tu código llama a un método Java normal y el delegado oculta el descubrimiento en Eureka, la llamada HTTP y la traducción de errores.

  • 2. Traducción de Excepciones:

    Si el servidor remoto se cae y lanza una excepción técnica de red (SocketTimeoutException), el DelegadoNegocio la captura y la convierte en una excepción de negocio comprensible para la interfaz.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        DelegadoNegocio delegate = new DelegadoNegocio();
        ClientePresentacion client = new ClientePresentacion(delegate);

        // 1. La capa de presentación solicita ejecutar Facturación
        delegate.setTipoServicio("BILLING");
        client.realizarTrabajo();

        System.out.println();

        // 2. La capa de presentación solicita ejecutar Envíos
        delegate.setTipoServicio("SHIPPING");
        client.realizarTrabajo();
    }
}
La capa de presentación interactúa únicamente con el DelegadoNegocio

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando la capa de presentación o un microservicio cliente deba comunicarse con servicios remotos cuya ubicación, protocolo o disponibilidad pueda variar.
  • Cuándo evitarlo: En aplicaciones monolíticas sencillas donde los servicios son simples clases locales en memoria inyectadas directamente con @Autowired.
