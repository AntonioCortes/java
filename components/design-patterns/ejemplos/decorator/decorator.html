Patrón Decorator

El patrón Decorator (Decorador) es un patrón estructural que permite añadir funcionalidades o responsabilidades extra a un objeto de forma dinámica en tiempo de ejecución, colocándolo dentro de objetos "envoltorio" especiales sin modificar la clase original.

Analogía del Mundo Real

Piensa en vestirse cuando hace frío o en las muñecas rusas (Matrioshkas). Tú eres el objeto base (CafeSimple). Si tienes frío, te pones un jersey encima (primer decorador). Si además llueve, te pones un chubasquero encima del jersey (segundo decorador). Sigues siendo una persona, pero cada capa que te envuelve te añade una propiedad nueva (abrigo, impermeabilidad) y puedes quitártelas o combinarlas al vuelo.

Propósito

Ofrecer una alternativa flexible a la herencia para ampliar la funcionalidad de un objeto, evitando crear decenas de subclases para cada posible combinación de características.

Caso de Uso Real: Sistema de Cafetería (Personalización de Bebidas)

Contexto: Una cafetería vende café simple y permite añadir suplementos combinables: Leche (+0.50€), Azúcar (+0.20€), Chocolate, Nata, etc.

El Problema (Con Herencia clásica): Si intentas crear una subclase por cada combinación posible (CafeConLeche, CafeConAzucar, CafeConLecheYAzucar, CafeConDobleLecheYChocolate...), tendrás una explosión combinatoria inmanejable.

La Solución (Con Decorator): Tanto el café base (CafeSimple) como los envoltorios de ingredientes (DecoradorLeche, DecoradorAzucar) implementan la misma interfaz Cafe. Cada decorador guarda dentro un objeto Cafe, le pide su precio/descripción y le suma el suyo propio: new DecoradorAzucar(new DecoradorLeche(new CafeSimple())).

Component (Interfaz) Cafe Define las operaciones comunes (obtenerDescripcion() y obtenerCosto()) para el objeto base y sus envoltorios.
Concrete Component CafeSimple El objeto base sobre el que se irán añadiendo capas de decoración.
Base Decorator DecoradorCafe Clase abstracta que implementa Cafe y guarda una referencia protected Coffee cafeEnvuelto al objeto envuelto.
Concrete Decorators DecoradorLeche, DecoradorAzucar Llaman al objeto envuelto (super.obtenerCosto()) y le suman su coste y descripción adicional.

Implementación en Java


// 1. Interfaz Componente
interface Cafe {
    String obtenerDescripcion();
    double obtenerCosto();
}

// 2. Componente Concreto: el objeto base sin extras
class CafeSimple implements Cafe {
    @Override
    public String obtenerDescripcion() {
        return "Café Simple";
    }

    @Override
    public double obtenerCosto() {
        return 1.0;
    }
}

// 3. Decorador Base: implementa Coffee y además TIENE un Coffee dentro
abstract class DecoradorCafe implements Cafe {
    protected Cafe cafeEnvuelto;

    public DecoradorCafe(Cafe cafe) {
        this.cafeEnvuelto = cafe;
    }

    @Override
    public String obtenerDescripcion() {
        return cafeEnvuelto.obtenerDescripcion();
    }

    @Override
    public double obtenerCosto() {
        return cafeEnvuelto.obtenerCosto();
    }
}

// 4. Decoradores Concretos: añaden comportamiento antes o después de delegar
class DecoradorLeche extends DecoradorCafe {
    public DecoradorLeche(Cafe cafe) {
        super(cafe);
    }

    @Override
    public String obtenerDescripcion() {
        return super.obtenerDescripcion() + ", con Leche";
    }

    @Override
    public double obtenerCosto() {
        return super.obtenerCosto() + 0.5;
    }
}

class DecoradorAzucar extends DecoradorCafe {
    public DecoradorAzucar(Cafe cafe) {
        super(cafe);
    }

    @Override
    public String obtenerDescripcion() {
        return super.obtenerDescripcion() + ", con Azúcar";
    }

    @Override
    public double obtenerCosto() {
        return super.obtenerCosto() + 0.2;
    }
}

Análisis Paso a Paso para Principiantes

  • 1. El secreto del patrón: "Es un" y "Tiene un" a la vez:

    DecoradorCafe implementa Cafe (para que puedas seguir envolviéndolo dentro de otro decorador más) y a la vez tiene un atributo Cafe (para saber a quién tiene envuelto por dentro y pedirle su precio base).

  • 2. Cómo se calcula el precio en cadena:

    Cuando llamas a obtenerCosto() en la capa exterior (DecoradorAzucar), este pide el precio a DecoradorLeche, que a su vez se lo pide a CafeSimple (1.0€). Al volver hacia afuera se suma: 1.0 + 0.5 + 0.2 = 1.7€.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // 1. Empezamos con un café simple
        Coffee myCoffee = new CafeSimple();
        System.out.println(myCoffee.obtenerDescripcion() + " -> " + myCoffee.obtenerCosto() + "€");

        // 2. Lo envolvemos dinámicamente con Leche
        myCoffee = new DecoradorLeche(myCoffee);
        System.out.println(myCoffee.obtenerDescripcion() + " -> " + myCoffee.obtenerCosto() + "€");

        // 3. Lo volvemos a envolver con Azúcar
        myCoffee = new DecoradorAzucar(myCoffee);
        System.out.println(myCoffee.obtenerDescripcion() + " -> " + myCoffee.obtenerCosto() + "€");
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando necesitas añadir o combinar comportamientos opcionales en tiempo de ejecución (como los flujos de entrada/salida de Java: new BufferedReader(new FileReader("datos.txt")), o añadir compresión y cifrado a un flujo de datos).
  • Cuándo evitarlo: Si el orden en que se envuelven los decoradores es crítico y propenso a errores por parte del cliente, o si solo necesitas añadir un método fijo a una clase.
