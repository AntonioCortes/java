Patrón Visitor

El patrón Visitor (Visitante) es un patrón de comportamiento que permite separar las operaciones o algoritmos de la estructura de objetos sobre la que operan. Gracias a esto, puedes añadir nuevas operaciones a toda una familia de clases sin tener que modificar esas clases.

Analogía del Mundo Real

Piensa en un Inspector de Sanidad o un Tasador de Seguros (el Visitor) que visita distintos tipos de locales comerciales: un Restaurante, una Farmacia y una Panadería (los Elements). Cada local simplemente le abre la puerta (aceptar(visitor)), y el inspector aplica un protocolo distinto según si está visitando un restaurante (visitar(Restaurante)) o una farmacia (visitar(Farmacia)). Si mañana viene un Inspector de Incendios, los locales no cambian su estructura: simplemente reciben a un nuevo visitante.

Propósito

Mantener limpias las clases de datos o de dominio sacando fuera de ellas las operaciones secundarias (como exportar a XML, mostrar diagnósticos por pantalla o calcular presupuestos) hacia clases Visitor dedicadas.

Caso de Uso Real: Diagnóstico y Visualización de Componentes de Hardware

Contexto: Tienes clases que representan las piezas de un ordenador (Teclado, Monitor, Mouse). Quieres añadir distintas operaciones sobre ellas (mostrar su estado en pantalla, exportar inventario a JSON, comprobar consumo eléctrico) sin ensuciar las clases de hardware cada vez.

El Problema (Sin Visitor): Cada vez que se te ocurra un nuevo informe o exportación tendrías que abrir las clases Teclado, Monitor y Mouse para añadirles un método nuevo, violando el Principio de Responsabilidad Única.

La Solución (Con Visitor): Las piezas de hardware implementan PiezaOrdenador con un único método sencillo: aceptar(visitor) { visitor.visitar(this); }. Toda la operación vive agrupada en la clase VisitanteMostrarPieza.

Implementación en Java


// 1. Interfaz Elemento: cualquier pieza que puede recibir a un Visitor
interface PiezaOrdenador {
    void aceptar(VisitantePieza visitor);
}

// 2. Elementos Concretos: Teclado y Monitor
class Teclado implements PiezaOrdenador {
    @Override
    public void aceptar(VisitantePieza visitor) {
        // Double Dispatch: le pasa 'this' (de tipo Teclado) al visitante
        visitor.visitar(this);
    }
}

class Monitor implements PiezaOrdenador {
    @Override
    public void aceptar(VisitantePieza visitor) {
        // Double Dispatch: le pasa 'this' (de tipo Monitor) al visitante
        visitor.visitar(this);
    }
}

// 3. Interfaz Visitor: un método visitar() para cada clase concreta de elemento
interface VisitantePieza {
    void visitar(Teclado keyboard);
    void visitar(Monitor monitor);
}

// 4. Visitor Concreto: Operación de visualización y diagnóstico
class VisitanteMostrarPieza implements VisitantePieza {
    @Override
    public void visitar(Teclado keyboard) {
        System.out.println("⌨️ [Visitor] Inspeccionando Teclado mecánico USB: OK.");
    }

    @Override
    public void visitar(Monitor monitor) {
        System.out.println("🖥️ [Visitor] Inspeccionando Monitor 4K HDMI: OK.");
    }
}

Análisis Paso a Paso para Principiantes

  • 1. ¿Qué significa "Double Dispatch" (Doble Despacho)?

    Es el corazón del patrón y consta de 2 saltos: primero el cliente llama a part.aceptar(visitor), y dentro de ese método la pieza llama de vuelta a visitor.visitar(this). Como dentro de Teclado la palabra this es de tipo Teclado, Java elige automáticamente el método visitar(Teclado) sin necesidad de hacer instanceof ni castings.

  • 2. Añadir nuevas operaciones es facilísimo:

    Si mañana quieres calcular el precio total o exportar a XML, solo creas otra clase PriceCalculatorVisitor implements VisitantePieza sin tocar Teclado ni Monitor.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        PiezaOrdenador[] parts = new PiezaOrdenador[] {
            new Teclado(),
            new Monitor()
        };

        // Creamos el visitante con la operación que queremos ejecutar hoy
        VisitantePieza displayVisitor = new VisitanteMostrarPieza();

        System.out.println("--- Pasando el Visitor por todas las piezas del equipo ---");
        for (PiezaOrdenador part : parts) {
            part.aceptar(displayVisitor);
        }
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando las clases de tu estructura de datos cambian muy pocas veces, pero necesitas añadir frecuentemente nuevas operaciones sobre ellas (compiladores que recorren árboles de sintaxis AST, exportadores de documentos).
  • Cuándo evitarlo: Si añades nuevas clases de elementos todo el tiempo (ej. añadir Webcam, Printer, Microphone cada semana), porque cada clase nueva obliga a añadir un método visitar() en la interfaz Visitor y en todos sus visitantes.
