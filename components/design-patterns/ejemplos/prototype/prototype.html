Patrón Prototype

El patrón Prototype (Prototipo) es un patrón creacional que permite crear nuevos objetos clonando una instancia ya existente (el prototipo), sin que el código cliente tenga que conocer ni depender de sus clases concretas.

Analogía del Mundo Real

Piensa en la división celular (mitosis) o en usar una fotocopiadora para duplicar un documento complejo ya redactado y sellado. En lugar de volver a redactar las 50 páginas desde cero cada vez que necesitas una copia, tomas el documento original (el prototipo) y pulsas el botón "Copiar" (clonar()), obteniendo un objeto idéntico e independiente al instante.

Propósito

Evitar el coste de crear e inicializar un objeto complejo desde cero (por ejemplo, cuando su creación inicial requiere consultas a base de datos o cálculos pesados) y permitir duplicar objetos polimórficamente sin acoplarse a sus clases concretas.

Caso de Uso Real: Duplicación de Figuras en un Editor Gráfico o Enemigos en un Videojuego

Contexto: En un editor de diseño (o un motor de videojuegos), el usuario tiene en pantalla figuras geométricas (Circulo, Rectangulo) ya configuradas con coordenadas, colores y dimensiones específicas, y pulsa Ctrl+D (Duplicar).

El Problema (Sin Prototype): Si el código del editor intenta copiar una figura desde fuera, primero tendría que averiguar qué clase exacta es (if (shape instanceof Circulo)), crear una instancia vacía y copiar campo por campo. Además, si algunos campos son private, ni siquiera podrá leerlos desde fuera.

La Solución (Con Prototype): La clase base Figura define el método clonar(). Como un objeto sí tiene acceso a sus propios atributos privados, cada subclase (Circulo, Rectangulo) sabe exactamente cómo copiarse a sí misma llamando a su constructor de copia: new Circulo(this).

Implementación en Java


// 1. Prototipo Abstracto
abstract class Figura {
    public int x;
    public int y;
    public String color;

    public Shape() {}

    // Constructor de copia: copia los atributos de la clase padre
    public Shape(Figura origen) {
        if (origen != null) {
            this.x = origen.x;
            this.y = origen.y;
            this.color = origen.color;
        }
    }

    // Método de clonación que cada subclase implementará
    public abstract Figura clonar();
}

// 2. Prototipo Concreto A: Círculo
class Circulo extends Figura {
    public int radio;

    public Circulo() {}

    // Constructor de copia del Círculo
    public Circulo(Circulo origen) {
        super(origen); // Copia x, y, color usando el constructor del padre
        if (origen != null) {
            this.radio = origen.radio;
        }
    }

    @Override
    public Figura clonar() {
        return new Circulo(this);
    }

    @Override
    public String toString() {
        return "Circulo [x=" + x + ", y=" + y + ", color=" + color + ", radio=" + radio + "]";
    }
}

// 3. Prototipo Concreto B: Rectángulo
class Rectangulo extends Figura {
    public int ancho;
    public int alto;

    public Rectangulo() {}

    // Constructor de copia del Rectángulo
    public Rectangulo(Rectangulo origen) {
        super(origen);
        if (origen != null) {
            this.ancho = origen.ancho;
            this.alto = origen.alto;
        }
    }

    @Override
    public Figura clonar() {
        return new Rectangulo(this);
    }

    @Override
    public String toString() {
        return "Rectangulo [x=" + x + ", y=" + y + ", color=" + color + ", w=" + ancho + ", h=" + alto + "]";
    }
}
Implementación del patrón Prototype mediante constructores de copia

Análisis Paso a Paso para Principiantes

  • 1. ¿Qué es el "Constructor de Copia" (public Circulo(Circulo origen))?

    Es un constructor que recibe como parámetro otro objeto de su misma clase y copia todos sus atributos al nuevo objeto (this.radio = origen.radio). Es mucho más limpio y seguro que el antiguo Object.clonar() nativo de Java.

  • 2. Objetos independientes en memoria:

    Al hacer Figura copia = original.clonar(), se crea un objeto nuevo en otra dirección de memoria (original != copia), pero con los mismos datos iniciales. Si después cambiamos el color de la copia, el original no se ve afectado.

Ejemplo de Uso


public class Main {
    public static void main(String[] args) {
        // 1. Creamos y configuramos un Círculo prototipo
        Circulo circuloOriginal = new Circulo();
        circuloOriginal.x = 10;
        circuloOriginal.y = 20;
        circuloOriginal.radio = 15;
        circuloOriginal.color = "Rojo";

        // 2. Lo clonamos sin acoplarnos a su proceso de configuración
        Figura circuloClonado = circuloOriginal.clonar();
        circuloClonado.color = "Azul"; // Modificamos solo el clon

        System.out.println("Original: " + circuloOriginal);
        System.out.println("Clonado : " + circuloClonado);
        System.out.println("¿Son distintos objetos en memoria?: " + (circuloOriginal != circuloClonado));
    }
}

¿Cuándo usarlo y cuándo NO usarlo?

  • Cuándo usarlo: Cuando crear un objeto desde cero sea muy costoso (requiera leer archivos, red o base de datos) o cuando necesites duplicar objetos complejos sin acoplar tu código a sus clases concretas.
  • Cuándo evitarlo: En objetos muy simples sin estado costoso de inicializar, o cuando los objetos tengan referencias circulares complejas que dificulten la copia profunda (deep copy).
