Constructor

En Java, la definición y el mantenimiento de constructores resulta tedioso cuando una clase cambia de atributos con frecuencia. Además, frameworks como JPA/Hibernate o librerías de serialización como Jackson exigen la presencia de un constructor vacío, mientras que los tests o la inyección de dependencias en Spring Boot requieren constructores parametrizados.

Project Lombok proporciona tres anotaciones a nivel de clase para automatizar por completo la generación de constructores en tiempo de compilación: @NoArgsConstructor, @AllArgsConstructor y @RequiredArgsConstructor. En todas ellas los atributos estáticos (static) se ignoran automáticamente, ya que pertenecen a la clase y no a la instancia.

Anotaciones de generación de constructores

  • @NoArgsConstructor: Esta anotación pertenece a la librería Project Lombok, se encuentra dentro del paquete lombok.NoArgsConstructor y se coloca sobre la definición de la clase para generar automáticamente un constructor sin parámetros (constructor vacío).
    Si la clase contiene campos declarados como final que no han sido inicializados en su declaración, el compilador mostrará un error porque un constructor vacío no podría inicializarlos. Para resolver este caso (muy habitual en entidades JPA o clases inmutables deserializadas por Jackson), permite usar el parámetro force = true, que inicializa todos los campos final a su valor por defecto (null para objetos, 0 para números y false para booleanos).
  • @AllArgsConstructor: Esta anotación pertenece a la librería Project Lombok, se encuentra dentro del paquete lombok.AllArgsConstructor y se coloca sobre la clase para generar un constructor con un parámetro por cada atributo no estático de la clase.
    El orden de los parámetros en el constructor generado sigue estrictamente el orden en que los atributos han sido declarados de arriba a abajo dentro de la clase. Si algún atributo está anotado con @NonNull, Lombok incluye automáticamente una validación explícita de nulidad al inicio del constructor para ese parámetro.
  • @RequiredArgsConstructor: Esta anotación pertenece a la librería Project Lombok, se encuentra dentro del paquete lombok.RequiredArgsConstructor y genera un constructor que incluye únicamente un parámetro por cada atributo que requiera un tratamiento especial de inicialización (atributos obligatorios):
    • Atributos declarados como final que no hayan sido inicializados en el momento de su declaración.
    • Atributos marcados con la anotación @NonNull (lombok.NonNull) que no hayan sido inicializados en su declaración (incluyendo además una comprobación de nulidad que lanza un NullPointerException si se recibe null).
    Si la clase no tiene ningún atributo final ni @NonNull sin inicializar, @RequiredArgsConstructor generará un constructor sin argumentos equivalente a @NoArgsConstructor.

Parámetros de configuración de los constructores

Las tres anotaciones anteriores comparten una serie de parámetros opcionales que permiten personalizar la visibilidad, la forma de invocación y las anotaciones del constructor generado:

  • access: Permite definir el modificador de acceso (visibilidad) del constructor generado mediante el enumerado lombok.AccessLevel. Por defecto su valor es AccessLevel.PUBLIC. Sus posibles valores son:
    • AccessLevel.PUBLIC: El constructor generado será public (valor por defecto).
    • AccessLevel.PROTECTED: El constructor generado será protected (muy útil en clases base o entidades JPA donde no se quiere permitir la instanciación directa desde fuera del paquete).
    • AccessLevel.PACKAGE: El constructor tendrá visibilidad de paquete (package-private, sin palabra clave de modificador).
    • AccessLevel.PRIVATE: El constructor generado será private (habitual en clases de utilidades o cuando se combina con métodos factoría estáticos).
    • AccessLevel.NONE: Desactiva la generación manual del constructor.
  • staticName: Recibe un String con el nombre de un método factoría estático. Al especificar este parámetro (por ejemplo, @RequiredArgsConstructor(staticName = "of")), Lombok convierte el constructor generado en private y crea en su lugar un método estático público con el nombre indicado que invoca internamente a dicho constructor privado.
  • force (exclusivo de @NoArgsConstructor): Recibe un booleano (por defecto false). Cuando se establece a @NoArgsConstructor(force = true), fuerza la inicialización de todos los campos final no inicializados con sus valores por defecto (0, false o null) y evita errores de compilación cuando los atributos están marcados con @NonNull.
  • onConstructor_: Permite añadir anotaciones adicionales directamente sobre el constructor generado (por ejemplo, @AllArgsConstructor(onConstructor_ = @Autowired) en versiones antiguas de Spring).

Interacción con @NonNull

La anotación @NonNull pertenece a Project Lombok y se encuentra en el paquete lombok.NonNull. Cuando se coloca sobre un atributo de la clase y se utiliza junto con @RequiredArgsConstructor o @AllArgsConstructor, produce dos efectos:

  • Hace que dicho atributo sea considerado obligatorio por @RequiredArgsConstructor aunque no sea final.
  • Genera al principio del constructor una comprobación explícita de nulidad (if (campo == null) throw new NullPointerException("campo is marked non-null but is null");) antes de asignar el valor al atributo.

Ejemplo comparativo: Vanilla Java vs Lombok

A continuación se muestra cómo se traduce una clase Pet que combina las tres anotaciones de constructor, un método factoría estático y campos obligatorios:

Con Lombok:


import lombok.AccessLevel;
import lombok.AllArgsConstructor;
import lombok.NoArgsConstructor;
import lombok.NonNull;
import lombok.RequiredArgsConstructor;

@NoArgsConstructor(force = true, access = AccessLevel.PROTECTED)
@RequiredArgsConstructor(staticName = "of")
@AllArgsConstructor
public class Pet {

    private final Integer id;

    @NonNull
    private String name;

    private Short age;
}

Código equivalente en Vanilla Java que Lombok genera automáticamente:


public class Pet {

    private final Integer id;
    private String name;
    private Short age;

    // Generado por @NoArgsConstructor(force = true, access = AccessLevel.PROTECTED)
    protected Pet() {
        this.id = null;
    }

    // Constructor privado generado por @RequiredArgsConstructor(staticName = "of")
    private Pet(final Integer id, final String name) {
        if (name == null) {
            throw new NullPointerException("name is marked non-null but is null");
        }
        this.id = id;
        this.name = name;
    }

    // Método factoría estático generado por staticName = "of"
    public static Pet of(final Integer id, final String name) {
        return new Pet(id, name);
    }

    // Generado por @AllArgsConstructor
    public Pet(final Integer id, final String name, final Short age) {
        if (name == null) {
            throw new NullPointerException("name is marked non-null but is null");
        }
        this.id = id;
        this.name = name;
        this.age = age;
    }
}

Inyección de dependencias en Spring Boot con @RequiredArgsConstructor

En aplicaciones con Spring Boot, la práctica recomendada por el equipo de Spring es realizar la inyección de dependencias por constructor en lugar de utilizar @Autowired directamente sobre los atributos de la clase. Esto presenta grandes ventajas de diseño:

  • Inmutabilidad: Permite declarar todas las dependencias (servicios, repositorios, mappers) como atributos private final, garantizando que no puedan ser reasignadas una vez construido el componente.
  • Seguridad frente a nulos: Evita que el bean pueda instanciarse en un estado incompleto con dependencias en null.
  • Facilidad para pruebas unitarias (Testing): Permite instanciar el servicio o controlador directamente con new PetService(...) en los tests de JUnit y Mockito sin necesidad de levantar el contexto de Spring ni usar reflexión.

Dado que a partir de Spring Framework 4.3 no es necesario anotar el constructor con @Autowired cuando la clase tiene un único constructor, combinar atributos private final con @RequiredArgsConstructor se ha convertido en el estándar de facto para inyectar dependencias en controladores y servicios de Spring Boot:


import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import java.util.Optional;

@Service
@RequiredArgsConstructor
public class PetService {

    // Al ser final y no estar inicializados, @RequiredArgsConstructor
    // crea el constructor PetService(PetRepository, ModelMapper)
    // y Spring Boot inyecta ambos beans automáticamente.
    private final PetRepository petRepository;
    private final ModelMapper mapper;

    public Optional<Pet> findById(final Integer id) {
        return petRepository.findById(id);
    }
}

¿Cuándo usar cada constructor de Lombok y cuándo NO usarlo?

  • Cuándo usar @RequiredArgsConstructor: En todos los @Service, @RestController y @Component de Spring Boot cuyos atributos inyectados sean private final.
  • Cuándo usar @NoArgsConstructor y @AllArgsConstructor: En entidades JPA (que exigen un constructor sin parámetros por especificación) y en clases que usen @Builder junto con serialización JSON (Jackson).
  • Cuándo NO usar @AllArgsConstructor: En clases con muchos atributos del mismo tipo (por ejemplo, cuatro campos String seguidos: firstName, lastName, email, phone). Si alguien reordena los atributos en la clase, el orden de los parámetros de @AllArgsConstructor cambiará silenciosamente sin dar error de compilación, intercambiando los datos por error. En esos casos es mucho más seguro usar @Builder.

Contraejemplo: Peligro de reordenar campos con @AllArgsConstructor


// CONTRAEJEMPLO (PELIGROSO): Si mañana alguien mueve 'breed' antes de 'name',
// todas las llamadas new Pet("Joe", "Bulldog") asignarán la raza como nombre sin dar error de compilación
@AllArgsConstructor
public class Pet {
    private String name;
    private String breed;
}

// EJEMPLO (SEGURO): Usar @Builder evita depender del orden posicional de los atributos
@Builder
public class SafePet {
    private String name;
    private String breed;
}
