ToString

En Java, todas las clases heredan de java.lang.Object, cuya implementación por defecto del método toString() devuelve únicamente el nombre de la clase seguido de la arroba (@) y el código hash en hexadecimal (por ejemplo, Pet@15db9742). Sobrescribir manualmente toString() para mostrar el estado real del objeto en trazas de log o depuración resulta repetitivo y propenso a quedar desactualizado cuando se añaden nuevos campos a la clase.

Anotación @ToString

  • @ToString: Esta anotación pertenece a la librería Project Lombok, se encuentra dentro del paquete lombok.ToString y se coloca sobre la definición de una clase para generar automáticamente una implementación del método public String toString().
    Comportamiento por defecto:
    • Imprime el nombre de la clase seguido entre paréntesis de cada atributo no estático en pares nombreCampo=valor separados por comas: Pet(id=1, name=Joe, age=3).
    • Ignora todos los atributos estáticos (static), ya que no forman parte del estado particular de la instancia.
    • Si la clase dispone de un método getter para un atributo, Lombok invoca al método getter (this.getName()) en lugar de acceder directamente al atributo privado.
    • Si un atributo es un array, utiliza Arrays.deepToString() o Arrays.toString() para imprimir el contenido real del array en lugar de su dirección de memoria.

Parámetros de configuración y anotaciones internas de @ToString

El comportamiento de @ToString se puede ajustar mediante sus parámetros a nivel de clase y sus anotaciones internas a nivel de atributo o método:

  • includeFieldNames: Recibe un booleano (por defecto true). Si se establece a @ToString(includeFieldNames = false), omite el nombre de los campos e imprime únicamente sus valores separados por comas: Pet(1, Joe, 3).
  • callSuper: Recibe un booleano (por defecto false). Cuando se configura como @ToString(callSuper = true) en una clase hija, incluye el resultado de llamar a super.toString() como primer elemento de la cadena generada.
  • doNotUseGetters: Recibe un booleano (por defecto false). Si se establece a true, Lombok accederá siempre directamente a los atributos (this.name) aunque existan métodos getter en la clase.
  • onlyExplicitlyIncluded: Recibe un booleano (por defecto false). Si es true, Lombok no incluirá ningún atributo por defecto, sino únicamente aquellos que estén marcados explícitamente con @ToString.Include.
  • @ToString.Exclude: Se coloca sobre un atributo concreto para excluirlo de la cadena generada por toString(). Es fundamental para ocultar datos sensibles (contraseñas, tokens) o para evitar bucles infinitos (StackOverflowError) en relaciones bidireccionales de entidades JPA/Hibernate.
  • @ToString.Include: Se coloca sobre un atributo o sobre un método sin parámetros para incluir su valor en el toString() (muy útil junto con onlyExplicitlyIncluded = true). Acepta los parámetros:
    • name: Cambia el nombre que se muestra para ese campo en el texto resultante.
    • rank: Entero (por defecto 0) que altera el orden de impresión; los campos con mayor rank se imprimen primero.

Ejemplo comparativo: Vanilla Java vs Con Lombok

En el siguiente ejemplo de la clase ToStringExample se aprecia cómo Lombok ignora automáticamente la constante estática STATIC_VAR, excluye el atributo id anotado con @ToString.Exclude, invoca el getter getName(), formatea el array tags con Arrays.deepToString() e incluye la llamada a la clase padre en la subclase Square mediante callSuper = true:

Vanilla Java:


import java.util.Arrays;

public class ToStringExample {
    private static final int STATIC_VAR = 10;
    private String name;
    private Shape shape = new Square(5, 10);
    private String[] tags;
    private int id;

    public String getName() {
        return this.name;
    }

    public static class Square extends Shape {
        private final int width, height;

        public Square(int width, int height) {
            this.width = width;
            this.height = height;
        }

        @Override
        public String toString() {
            return "Square(super=" + super.toString() + ", width=" + this.width + ", height=" + this.height + ")";
        }
    }

    @Override
    public String toString() {
        return "ToStringExample(name=" + this.getName() + ", shape=" + this.shape + ", tags=" + Arrays.deepToString(this.tags) + ")";
    }
}

Con Lombok:


import lombok.ToString;

@ToString
public class ToStringExample {

    private static final int STATIC_VAR = 10;
    private String name;
    private Shape shape = new Square(5, 10);
    private String[] tags;
    @ToString.Exclude private int id;

    public String getName() {
        return this.name;
    }

    @ToString(callSuper = true, includeFieldNames = true)
    public static class Square extends Shape {

        private final int width, height;

        public Square(int width, int height) {
            this.width = width;
            this.height = height;
        }
    }
}

Anotación complementaria: @EqualsAndHashCode

Estrechamente relacionada con @ToString se encuentra la anotación @EqualsAndHashCode, que pertenece a Project Lombok y se ubica en el paquete lombok.EqualsAndHashCode. Su función es generar conjuntamente los métodos equals(Object) y hashCode() cumpliendo todas las reglas del contrato de igualdad en Java:

  • Por defecto utiliza todos los atributos no estáticos y no transitorios (transient) de la clase para comparar dos instancias y calcular su código hash.
  • Dispone de las mismas anotaciones internas de filtrado que @ToString:
    • @EqualsAndHashCode.Exclude: Excluye un campo del cálculo de igualdad y hash.
    • @EqualsAndHashCode.Include: Incluye explícitamente un campo o método (habitual cuando se configura @EqualsAndHashCode(onlyExplicitlyIncluded = true) para comparar entidades únicamente por su clave primaria id).
    • callSuper: Permite incluir el resultado de super.equals() y super.hashCode() cuando la clase extiende de otra clase con estado propio.

import lombok.EqualsAndHashCode;
import lombok.ToString;

@ToString
@EqualsAndHashCode(onlyExplicitlyIncluded = true)
public class Pet {

    // Dos instancias de Pet se considerarán iguales si tienen el mismo id
    @EqualsAndHashCode.Include
    private Integer id;

    private String name;

    // Se excluye la imagen en bytes del toString() para no saturar los logs
    @ToString.Exclude
    private byte[] picture;
}

¿Cuándo usar @ToString y cuándo NO usarlo (o excluir campos)?

  • Cuándo usarlo: En DTOs, objetos de dominio y respuestas para facilitar la depuración y la lectura de logs.
  • Cuándo NO usarlo sin @ToString.Exclude:
    • Datos confidenciales (Contraseñas, Tokens, Tarjetas, DNI): Si se incluye un campo password en el toString(), quedará expuesto en texto plano en los ficheros de log del servidor, incumpliendo normativas de seguridad.
    • Arrays binarios pesados (byte[]): Imágenes o ficheros en memoria generarán líneas de log de miles de caracteres.
    • Relaciones bidireccionales o perezosas (FetchType.LAZY) en JPA: Provocan bucles infinitos (StackOverflowError) o consultas SQL adicionales no deseadas.

Ejemplo y Contraejemplo: Seguridad y Recursión en @ToString


// CONTRAEJEMPLO (INCORRECTO): Expone la contraseña en los logs y provoca StackOverflowError con Owner
@ToString
public class UserAccount {
    private String username;
    private String password; // ¡Peligro! Se imprimirá en los logs al hacer log.info("User: {}", user)
    private Owner owner;     // Si Owner también imprime UserAccount, revienta la pila de llamadas
}

// EJEMPLO (CORRECTO): Exclusión explícita de campos sensibles y relaciones circulares
@ToString
public class SafeUserAccount {
    private String username;

    @ToString.Exclude
    private String password;

    @ToString.Exclude
    private Owner owner;
}
