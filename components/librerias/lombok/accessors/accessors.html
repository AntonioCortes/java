Accessors

Por defecto, cuando utilizamos @Getter, @Setter o @Data, Lombok genera los métodos de lectura y escritura siguiendo estrictamente el estándar tradicional de JavaBeans: los métodos llevan los prefijos get/is y set, y los setters devuelven void. Sin embargo, en el diseño de APIs modernas, DTOs y entidades es muy común preferir un estilo de invocación encadenado o fluido.

Para personalizar este comportamiento existe la anotación @Accessors.

Anotación @Accessors

  • @Accessors: Esta anotación pertenece al módulo experimental de Project Lombok, se encuentra dentro del paquete lombok.experimental.Accessors y sirve para configurar cómo Lombok genera y nombra los métodos getter y setter.
    Importante: Por sí sola, @Accessors no genera ningún método; únicamente modifica el comportamiento de las anotaciones @Getter, @Setter o @Data que estén presentes en la misma clase o atributo.
    Se puede colocar tanto a nivel de clase (afectando a todos los campos de la clase) como sobre un atributo concreto (sobrescribiendo la configuración de la clase para ese campo específico).

Parámetros de configuración de @Accessors

La anotación @Accessors dispone de cuatro opciones configurables que pueden combinarse entre sí:

  • chain: Recibe un valor booleano (por defecto false, salvo que se active fluent = true). Cuando se configura como @Accessors(chain = true), todos los métodos setter generados dejan de devolver void y pasan a devolver this (la propia instancia del objeto). Esto permite encadenar múltiples llamadas a setters en una sola sentencia: new PetDTO().setId(1).setName("Joe").setAge((short) 2). Es una de las opciones más utilizadas en DTOs y modelos de dominio en Spring Boot.
  • fluent: Recibe un valor booleano (por defecto false). Cuando se configura como @Accessors(fluent = true), los métodos getter y setter se generan sin los prefijos get, is ni set, utilizando como nombre del método exactamente el mismo nombre del atributo (por ejemplo, el getter es pet.name() y el setter es pet.name("Joe")). Además, activar fluent = true activa implícitamente chain = true a menos que se indique explícitamente chain = false.
  • prefix: Recibe una lista de cadenas de texto (por defecto vacía {}). Sirve para trabajar con convenciones de nomenclatura en las que los nombres de los atributos privados empiezan por un prefijo identificativo (como f, p, m_ o _). Al indicar @Accessors(prefix = {"p", "m_"}), Lombok omite dichos prefijos al construir el nombre de los getters y setters (por ejemplo, el atributo private String pName; generará getName() y setName() en lugar de getPName()).
  • makeFinal: Recibe un valor booleano (por defecto false). Si se establece a @Accessors(makeFinal = true), los métodos getter y setter generados incluirán el modificador final en su firma para impedir que las subclases puedan sobrescribirlos.

Ejemplos prácticos de uso

1. Encadenamiento de setters con @Accessors(chain = true)

En la capa de DTOs (como PetDTO o PetPatchDTO) es muy habitual combinar @Data con @Accessors(chain = true). De esta forma se mantienen los nombres estándar getNombre() y setNombre() (necesarios para que librerías como Jackson o ModelMapper funcionen sin configuraciones adicionales), pero se gana la comodidad de instanciar y poblar el objeto encadenando llamadas:

Con Lombok:


import lombok.Data;
import lombok.experimental.Accessors;

@Data
@Accessors(chain = true)
public class PetDTO {
    private Integer id;
    private String name;
    private Short age;
}

Código equivalente en Vanilla Java para los getters y setters generados:


public class PetDTO {
    private Integer id;
    private String name;
    private Short age;

    public Integer getId() {
        return this.id;
    }

    public PetDTO setId(Integer id) {
        this.id = id;
        return this;
    }

    public String getName() {
        return this.name;
    }

    public PetDTO setName(String name) {
        this.name = name;
        return this;
    }

    public Short getAge() {
        return this.age;
    }

    public PetDTO setAge(Short age) {
        this.age = age;
        return this;
    }
}

Uso del encadenamiento al instanciar el DTO:


PetDTO petDTO = new PetDTO()
        .setId(1)
        .setName("Joe")
        .setAge((short) 3);

2. Estilo fluido sin prefijos con @Accessors(fluent = true)

Cuando se utiliza @Accessors(fluent = true), tanto la asignación como la lectura de propiedades se realizan invocando métodos con el nombre exacto del atributo:


import lombok.Getter;
import lombok.Setter;
import lombok.experimental.Accessors;

@Getter
@Setter
@Accessors(fluent = true)
public class PetFilter {
    private String name;
    private Short minAge;
}

// Uso de los métodos generados con fluent = true:
PetFilter filter = new PetFilter()
        .name("Joe")
        .minAge((short) 1);

String searchedName = filter.name();

3. Eliminación de prefijos de atributos con @Accessors(prefix = ...)

Si el estándar de codificación del proyecto exige que los atributos de clase lleven un prefijo como p o m_, el parámetro prefix evita que esos prefijos se filtren a la firma pública de los métodos get y set:


import lombok.Getter;
import lombok.Setter;
import lombok.experimental.Accessors;

@Getter
@Setter
@Accessors(prefix = {"p", "m_"})
public class PetEntity {

    // Genera getId() y setId(Integer id)
    private Integer m_id;

    // Genera getName() y setName(String name)
    private String pName;
}

¿Cuándo usar @Accessors y cuándo NO usarlo?

  • Cuándo usar @Accessors(chain = true): Muy recomendable en DTOs, Entidades y objetos de configuración porque mantiene los nombres estándar getX() y setX() (siendo 100% compatible con Jackson, ModelMapper, Hibernate y Spring) mientras permite encadenar asignaciones fluidamente.
  • Cuándo NO usar @Accessors(fluent = true): Nunca debe usarse en clases que dependan del estándar JavaBeans (como DTOs serializados por Jackson sin anotaciones extras, formularios de Spring MVC, beans mapeados por ModelMapper o entidades JPA con acceso por propiedades), ya que estas librerías buscan métodos que empiecen estrictamente por get y set.

Ejemplo y Contraejemplo: fluent = true frente a chain = true en DTOs

Contraejemplo (Mala práctica): Usar fluent = true en un DTO de un Controlador REST

Al activar fluent = true, el método generado se llama name() en lugar de getName(). Cuando el controlador devuelva este DTO, Jackson no encontrará ningún getter estándar y devolverá un JSON vacío o lanzará una excepción InvalidDefinitionException: No serializer found:


// CONTRAEJEMPLO (INCORRECTO): Jackson y ModelMapper no reconocerán los getters ni setters sin prefijo get/set
@Data
@Accessors(fluent = true)
public class PetDTO {
    private Integer id;
    private String name;
}

Ejemplo (Buena práctica): Usar chain = true en DTOs

Con chain = true se conservan los nombres estándar getId() / setId() requeridos por todos los frameworks del ecosistema Spring y además se pueden encadenar las llamadas en una sola línea:


// EJEMPLO (CORRECTO): 100% compatible con Jackson y ModelMapper y permite encadenar setters
@Data
@Accessors(chain = true)
public class PetDTO {
    private Integer id;
    private String name;
}

PetDTO dto = new PetDTO().setId(1).setName("Joe");
