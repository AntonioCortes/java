Anotación @Builder

Esta anotación permite aplicar el patrón de diseño creacional "Builder" a una clase sin tener que escribir todo el código auxiliar manualmente. También puede ser usada sobre constructores específicos o sobre métodos estáticos para trabajar con clases inmutables y métodos factoría.

¿Qué es y cómo funciona @Builder?

  • @Builder: Esta anotación pertenece a la librería Project Lombok y se encuentra dentro del paquete lombok.Builder. Al colocarla sobre una clase (por ejemplo, Customer o Pet), Lombok genera automáticamente en tiempo de compilación:
    • Una clase interna estática llamada NombreClaseBuilder (ej. CustomerBuilder) con los mismos atributos que la clase principal.
    • Un método estático público builder() en la clase principal que devuelve una nueva instancia de ese builder.
    • Un método fluido (sin prefijo, que devuelve el propio builder) por cada atributo para asignar su valor encadenando llamadas.
    • Un método build() que invoca al constructor de la clase principal pasándole los valores configurados y devuelve la instancia final creada.
    • Una implementación de toString() dentro de la propia clase Builder.
    • Un constructor con todos los argumentos de visibilidad de paquete (package-private) en la clase principal (siempre que no se haya definido otro constructor explícito).

Dónde se puede aplicar @Builder

  • A nivel de clase: El builder incluirá todos los atributos de instancia no estáticos (excepto los campos final que ya estén inicializados en su declaración).
  • A nivel de constructor: Si solo queremos que el Builder exponga un subconjunto concreto de atributos o ejecute lógica personalizada al construir el objeto, podemos escribir un constructor manual y anotar únicamente ese constructor con @Builder.
  • A nivel de método estático: Si se coloca @Builder sobre un método static, Lombok creará un Builder cuyos campos coinciden exactamente con los parámetros de entrada de ese método, y al llamar a build() se ejecutará dicho método estático devolviendo su tipo de retorno.

Ejemplo básico:

En el siguiente ejemplo se anota la clase Customer con @Builder y se instancia un objeto de forma fluida indicando únicamente los atributos deseados sin importar el orden:


import lombok.Builder;

@Builder
public class Customer {
    private Integer id;
    private String firstName;
    private String lastName;
    private String email;
}

Customer customer = Customer.builder()
        .firstName("Luffy")
        .lastName("Monkey")
        .email("luffy_d_monkey@grandline.com")
        .build();

Atributos y parámetros de @Builder

La anotación @Builder admite varios parámetros para personalizar los nombres de los métodos y el comportamiento del constructor fluido:

  • builderMethodName: Define el nombre del método estático inicial que crea la instancia del builder. Su valor predefinido es "builder".
  • buildMethodName: Define el nombre del método final que construye y devuelve el objeto. Su valor predefinido es "build".
  • builderClassName: Permite cambiar el nombre de la clase interna estática generada (por defecto es NombreClaseBuilder).
  • toBuilder: Recibe un booleano (por defecto false). Cuando se activa como @Builder(toBuilder = true), Lombok añade un método de instancia llamado toBuilder() en la clase principal. Al invocarlo sobre un objeto ya existente, crea un nuevo builder precargado con todos los valores actuales de ese objeto, permitiendo modificar solo uno o dos campos y generar una copia actualizada (muy útil con objetos inmutables).
  • setterPrefix: Recibe un String (por defecto vacío ""). Permite añadir un prefijo a los métodos de asignación del builder (por ejemplo, @Builder(setterPrefix = "with") generará métodos como .withFirstName("Luffy")).
  • access: Permite restringir la visibilidad de la clase builder y del método builder() utilizando el enumerado lombok.AccessLevel (por defecto AccessLevel.PUBLIC).

Ejemplo personalizando el atributo builderMethodName:


import lombok.Builder;

@Builder(builderMethodName = "buildingTheThing")
public class Customer {
    private Integer id;
    private String firstName;
    private String lastName;
    private String email;
}

Customer customer = Customer.buildingTheThing()
        .firstName("Luffy")
        .lastName("Monkey")
        .email("luffy_d_monkey@grandline.com")
        .build();

Anotaciones complementarias de @Builder

1. @Builder.Default (Valores por defecto)

  • @Builder.Default: Cuando inicializamos un atributo directamente en su declaración (por ejemplo, private boolean active = true;), si la clase está anotada con @Builder y no asignamos ese campo al construir el objeto, el valor inicial se perderá y tomará false o null (porque el builder interno tiene sus propios atributos sin inicializar que luego pasa al constructor de todos los argumentos).
    Para conservar la expresión de inicialización por defecto cuando no se especifica el valor en el builder, es obligatorio anotar el atributo con @Builder.Default.

import lombok.Builder;
import lombok.Getter;
import lombok.ToString;
import java.time.LocalDate;

@Getter
@ToString
@Builder(toBuilder = true)
public class Pet {

    private Integer id;
    private String name;

    // Sin @Builder.Default, si no se llama a .vaccinated(...) valdría false
    @Builder.Default
    private boolean vaccinated = true;

    // Se evalúa LocalDate.now() cada vez que se construye un Pet sin indicar registrationDate
    @Builder.Default
    private LocalDate registrationDate = LocalDate.now();
}

// Uso de @Builder.Default y toBuilder = true:
Pet pet1 = Pet.builder()
        .id(1)
        .name("Joe")
        .build(); // vaccinated es true y registrationDate es la fecha de hoy

// Creamos una copia modificando únicamente el nombre a partir de pet1:
Pet pet2 = pet1.toBuilder()
        .id(2)
        .name("Max")
        .build();

2. @Singular (Colecciones inmutables elemento a elemento)

  • @Singular: Esta anotación pertenece a Project Lombok, se encuentra en el paquete lombok.Singular y se coloca sobre atributos de tipo colección o mapa (List, Set, Iterable, Map) dentro de una clase o constructor con @Builder.
    Al anotar por ejemplo @Singular private List<String> vaccines;, Lombok singulariza automáticamente el nombre en inglés (o permite indicarlo por parámetro como @Singular("vacuna")) y genera tres métodos en el builder:
    • Un método en singular (.vaccine("Rabia")) para añadir elementos sueltos uno a uno sin tener que instanciar una lista previa.
    • Un método en plural (.vaccines(List.of(...))) para añadir toda una colección de golpe.
    • Un método de limpieza (.clearVaccines()) para vaciar los elementos acumulados en el builder.
    Además, la colección resultante tras llamar a .build() es inmutable y nunca es null (si no se añade ningún elemento, devuelve una colección vacía inmutable).

import lombok.Builder;
import lombok.Getter;
import lombok.Singular;
import lombok.ToString;
import java.util.List;

@Getter
@ToString
@Builder
public class PetHealthCard {

    private Integer petId;

    @Singular
    private List<String> vaccines;
}

// Añadimos vacunas individualmente sin crear un ArrayList manualmente:
PetHealthCard card = PetHealthCard.builder()
        .petId(1)
        .vaccine("Rabia")
        .vaccine("Parvovirus")
        .vaccine("Moquillo")
        .build();

3. @SuperBuilder (Soporte para herencia)

  • @SuperBuilder: Esta anotación pertenece al módulo experimental de Project Lombok y se encuentra en el paquete lombok.experimental.SuperBuilder.
    La anotación estándar @Builder solo contempla los atributos de la propia clase y no incluye los atributos heredados de una superclase. Cuando existe una jerarquía de herencia (por ejemplo, una clase hija Pet que extiende de una clase padre Animal), se debe anotar tanto la clase padre como la clase hija con @SuperBuilder. De este modo, el builder generado para la clase hija permitirá encadenar indistintamente los atributos del padre y los de la hija.

import lombok.Getter;
import lombok.ToString;
import lombok.experimental.SuperBuilder;

@Getter
@ToString
@SuperBuilder
public class Animal {
    private String species;
    private Short age;
}

@Getter
@ToString(callSuper = true)
@SuperBuilder
public class Pet extends Animal {
    private Integer id;
    private String name;
}

// El builder de Pet permite asignar atributos tanto de Animal como de Pet:
Pet pet = Pet.builder()
        .id(1)
        .name("Joe")
        .species("Canis lupus familiaris")
        .age((short) 4)
        .build();

¿Cuándo usar @Builder y cuándo NO usarlo?

  • Cuándo usarlo: En clases con muchos atributos (3 o más), especialmente cuando varios son opcionales o del mismo tipo, y en la creación de datos de prueba (Test Fixtures) en tests unitarios e integración.
  • Cuándo NO usarlo:
    • En clases con solo 1 o 2 atributos obligatorios donde un constructor normal o un método estático of(id, name) es mucho más directo y ligero.
    • En jerarquías de clases con herencia usando @Builder simple: si la clase hereda de otra, usar @Builder ocultará los campos del padre o dará conflicto de firmas; en ese caso debe usarse siempre @SuperBuilder.

Ejemplo y Contraejemplo: Valores iniciales con @Builder


// CONTRAEJEMPLO (INCORRECTO): Olvidar @Builder.Default hace que 'active' valga false y 'tags' sea null
@Builder
public class BadPet {
    private String name;
    private boolean active = true; // ¡Lombok ignora este '= true' al usar Pet.builder().name("Joe").build()!
    private List<String> tags = new ArrayList<>(); // ¡Valdrá null al construir con el builder!
}

// EJEMPLO (CORRECTO): Uso de @Builder.Default para conservar los valores por defecto
@Builder
public class GoodPet {
    private String name;

    @Builder.Default
    private boolean active = true;

    @Builder.Default
    private List<String> tags = new ArrayList<>();
}
