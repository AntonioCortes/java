Getter y Setter

En Java, el principio de encapsulación aconseja declarar los atributos de una clase como privados (private) y exponer su lectura y modificación a través de métodos públicos conocidos como Getters y Setters. Con las anotaciones @Getter y @Setter, Project Lombok genera automáticamente estos métodos en tiempo de compilación siguiendo la convención estándar de JavaBeans.

Anotaciones @Getter y @Setter

  • @Getter: Esta anotación pertenece a la librería Project Lombok, se encuentra dentro del paquete lombok.Getter y sirve para generar automáticamente el método de lectura (getter) de un atributo. Por defecto el método generado es public, devuelve el mismo tipo de dato que el atributo y su nombre se forma con el prefijo get seguido del nombre del atributo en PascalCase (por ejemplo, para private String name; genera public String getName()).
  • @Setter: Esta anotación pertenece a la librería Project Lombok, se encuentra dentro del paquete lombok.Setter y sirve para generar automáticamente el método de escritura (setter) de un atributo no final. Por defecto el método generado es public, devuelve void, recibe un parámetro del mismo tipo y nombre que el atributo, y su nombre se forma con el prefijo set seguido del nombre del atributo en PascalCase (por ejemplo, para private int age; genera public void setAge(int age)). Si el atributo está marcado con @NonNull, el setter generado incluirá también una validación contra valores nulos.

Dónde se aplican y comportamiento con booleanos

  • A nivel de atributo: Si se coloca @Getter o @Setter sobre un atributo concreto, Lombok solo generará el método correspondiente para ese atributo.
  • A nivel de clase: Si se coloca @Getter sobre la declaración de la clase, Lombok generará los métodos getter para todos los atributos no estáticos de esa clase. De igual modo, si se coloca @Setter sobre la clase, generará los métodos setter para todos los atributos no estáticos y no finales (no final).
  • Comportamiento con tipos booleanos (boolean vs Boolean):
    • Si el atributo es de tipo primitivo boolean (por ejemplo, private boolean vaccinated;), el método getter generado utiliza el prefijo is en lugar de get: public boolean isVaccinated().
    • Si el atributo es de tipo envoltorio java.lang.Boolean (por ejemplo, private Boolean vaccinated;), al tratarse de un objeto que puede ser null, Lombok genera el prefijo estándar get: public Boolean getVaccinated().

Parámetros y opciones de configuración

  • value (AccessLevel): Permite cambiar el nivel de visibilidad del método getter o setter generado utilizando el enumerado lombok.AccessLevel. Sus valores posibles son:
    • AccessLevel.PUBLIC: El método generado es public (comportamiento por defecto si no se indica nada).
    • AccessLevel.PROTECTED: El método generado es protected, accesible únicamente desde la misma clase, subclases o clases del mismo paquete.
    • AccessLevel.PACKAGE: El método se genera sin modificador explícito (package-private), accesible solo dentro del mismo paquete.
    • AccessLevel.PRIVATE: El método generado es private, accesible únicamente dentro de la propia clase.
    • AccessLevel.NONE: Desactiva la generación del getter o setter para ese atributo. Es especialmente útil cuando hemos anotado toda la clase con @Getter, @Setter o @Data pero queremos impedir que se genere el getter o el setter de un atributo específico.
  • lazy (exclusivo de @Getter): Recibe un booleano (por defecto false). Al establecer @Getter(lazy = true) sobre un atributo private final cuya inicialización sea costosa (por ejemplo, un cálculo matemático pesado o la carga de un archivo grande en memoria), Lombok no calcula el valor al instanciar la clase, sino la primera vez que se invoca el método getter. A partir de esa primera llamada, el resultado queda almacenado en caché utilizando bloqueo de doble comprobación (Double-Checked Locking con AtomicReference), siendo completamente seguro en entornos multihilo (thread-safe).
  • onMethod_: Permite añadir una o varias anotaciones directamente sobre el método getter o setter que Lombok va a generar (por ejemplo, @Getter(onMethod_ = @JsonIgnore)).
  • onParam_ (exclusivo de @Setter): Permite añadir anotaciones sobre el parámetro de entrada del método setter generado.

Ejemplo comparativo a nivel de atributo

En el siguiente ejemplo se observa cómo se reducen las líneas de código de la clase GetterSetterExample al sustituir los métodos manuales por las anotaciones @Getter y @Setter, incluyendo la personalización del nivel de acceso AccessLevel.PROTECTED en el setter del atributo name:

Vanilla Java:


public class GetterSetterExample {

    private int age = 10;

    private String name;

    @Override
    public String toString() {
        return String.format("%s (age: %d)", name, age);
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }

    protected void setName(String name) {
        this.name = name;
    }
}

Con Lombok:


import lombok.AccessLevel;
import lombok.Getter;
import lombok.Setter;

public class GetterSetterExample {

    @Getter @Setter private int age = 10;

    @Setter(AccessLevel.PROTECTED) private String name;

    @Override
    public String toString() {
        return String.format("%s (age: %d)", name, age);
    }
}

Ejemplo a nivel de clase y exclusión con AccessLevel.NONE

Cuando una clase tiene muchos atributos, es mucho más limpio colocar @Getter y @Setter sobre la cabecera de la clase y utilizar AccessLevel.NONE únicamente en aquellos campos cuyo acceso queramos restringir (por ejemplo, impedir que el identificador id se modifique con un setter o que un código interno se exponga mediante un getter):


import lombok.AccessLevel;
import lombok.Getter;
import lombok.Setter;

@Getter
@Setter
public class Pet {

    // Tendrá getId(), pero NO tendrá setId()
    @Setter(AccessLevel.NONE)
    private Integer id;

    // Tendrá getName() y setName()
    private String name;

    // Tendrá getAge() y setAge()
    private Short age;

    // Al ser boolean primitivo, tendrá isVaccinated() y setVaccinated()
    private boolean vaccinated;

    // No tendrá ni getInternalToken() ni setInternalToken()
    @Getter(AccessLevel.NONE)
    @Setter(AccessLevel.NONE)
    private String internalToken;
}

Ejemplo de inicialización perezosa con @Getter(lazy = true)

Si una clase posee un atributo private final que requiere ejecutar un método costoso para obtener su valor pero no siempre se va a consultar, podemos anotarlo con @Getter(lazy = true). Lombok ocultará el atributo dentro de un contenedor atómico y solo ejecutará el método loadMedicalHistory() la primera vez que alguien llame a getMedicalHistory():


import lombok.Getter;
import java.util.List;

public class PetMedicalRecord {

    @Getter(lazy = true)
    private final List<String> medicalHistory = loadMedicalHistory();

    private List<String> loadMedicalHistory() {
        // Simulación de una consulta pesada o cálculo costoso
        return List.of("Vacuna rabia - 2022", "Desparasitación - 2023", "Revisión anual - 2024");
    }
}

¿Cuándo usar @Getter / @Setter y cuándo NO usarlos?

  • Cuándo usarlos: En prácticamente cualquier entidad JPA, DTO o modelo de datos donde se necesite exponer la lectura o escritura de propiedades sin lógica adicional.
  • Cuándo NO usar @Setter indiscriminadamente:
    • En objetos que deban ser inmutables (donde ningún estado debe cambiar tras el constructor).
    • En campos cuyo cambio requiera mantener invariantes de negocio o validaciones cruzadas (por ejemplo, no permitir cambiar el saldo de una cuenta con setBalance(), sino mediante un método de negocio withdraw(amount)).
    • Sobre colecciones en entidades JPA si reemplazar la lista entera rompe el seguimiento de orphanRemoval = true de Hibernate.

Ejemplo y Contraejemplo: Modificación de colecciones con orphanRemoval en Hibernate


// CONTRAEJEMPLO (INCORRECTO): Reemplazar la lista con un setter generado por @Setter
// hace que Hibernate pierda la referencia a su PersistentBag y lance HibernateException
@Getter
@Setter
@Entity
public class Owner {
    @Id
    private Integer id;

    @OneToMany(mappedBy = "owner", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Pet> pets = new ArrayList<>();
}

// EJEMPLO (CORRECTO): Desactivar el setter en la colección y limpiar/añadir elementos sobre la instancia existente
@Getter
@Setter
@Entity
public class SafeOwner {
    @Id
    private Integer id;

    @Setter(AccessLevel.NONE)
    @OneToMany(mappedBy = "owner", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Pet> pets = new ArrayList<>();

    public void updatePets(List<Pet> newPets) {
        this.pets.clear();
        if (newPets != null) {
            this.pets.addAll(newPets);
        }
    }
}
