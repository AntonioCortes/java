Construcción y Configuración de Requests en Apache HttpClient

Para realizar una llamada HTTP con Apache HttpClient, primero es necesario construir un objeto que represente la petición (implementación de la interfaz HttpUriRequest), configurar su URL, sus parámetros de consulta (query params), sus cabeceras HTTP, su cuerpo (si aplica) y sus tiempos máximos de espera (timeouts).

1. Clases de Métodos HTTP

En el paquete org.apache.http.client.methods.* existe una clase específica para cada verbo del protocolo HTTP. Todas ellas reciben en su constructor la URL de destino (como String o como objeto java.net.URI):

Clase Java Verbo HTTP ¿Admite Body (setEntity)? Propósito habitual
HttpGet GET No Consultar y recuperar un recurso o listado de recursos pasando filtros en la URL.
HttpPost POST Sí Crear un nuevo recurso enviando un JSON, un formulario o un archivo en el cuerpo.
HttpPut PUT Sí Reemplazar por completo un recurso existente identificado en la ruta.
HttpPatch PATCH Sí Modificar parcialmente algunos campos de un recurso existente.
HttpDelete DELETE No Eliminar un recurso identificado por su ruta.
HttpHead / HttpOptions HEAD / OPTIONS No Obtener únicamente las cabeceras de un recurso o consultar los métodos permitidos por el servidor.
Clases de petición disponibles en el paquete org.apache.http.client.methods

2. Construcción de URLs y Query Params con URIBuilder

Para evitar errores de codificación de caracteres especiales (espacios, tildes, símbolos &) al concatenar parámetros manualmente en un String, Apache HttpClient incluye la clase URIBuilder en el paquete org.apache.http.client.utils.URIBuilder.

Permite construir la URL de forma fluida y segura añadiendo todos los parámetros de búsqueda con addParameter(clave, valor) o setParameter(clave, valor):


import java.net.URI;
import org.apache.http.client.methods.HttpGet;
import org.apache.http.client.utils.URIBuilder;

// Construye de forma segura: http://localhost:8080/petshop/pet/all?age=4&name=Joe
URI uri = new URIBuilder()
		.setScheme("http")
		.setHost("localhost")
		.setPort(8080)
		.setPath("/petshop/pet/all")
		.addParameter("age", "4")
		.addParameter("name", "Joe")
		.build();

HttpGet httpGet = new HttpGet(uri);

3. Configuración de Cabeceras HTTP (Headers)

Las cabeceras permiten indicar al servidor en qué formato se envía el cuerpo (Content-Type), qué formato de respuesta se espera (Accept), credenciales de seguridad (Authorization) o metadatos personalizados. Se recomienda utilizar las constantes estándar de la clase org.apache.http.HttpHeaders:

  • request.addHeader(nombre, valor): Añade una nueva cabecera a la petición (si ya existía una con ese nombre, conserva ambas).
  • request.setHeader(nombre, valor): Establece el valor de la cabecera sobrescribiendo cualquier valor previo que tuviera esa misma clave.

import org.apache.http.HttpHeaders;
import org.apache.http.client.methods.HttpGet;

HttpGet request = new HttpGet("http://localhost:8080/petshop/pet/15");

request.setHeader(HttpHeaders.ACCEPT, "application/json");
request.setHeader(HttpHeaders.CONTENT_TYPE, "application/json");
request.setHeader(HttpHeaders.USER_AGENT, "PetShop-Client/1.0");
request.setHeader("X-Request-ID", "98a7bc-1234");

4. Envío de Datos en el Cuerpo de la Petición (HttpEntity)

Las clases que heredan de HttpEntityEnclosingRequestBase (es decir: HttpPost, HttpPut y HttpPatch) disponen del método setEntity(HttpEntity entity) para adjuntar datos en el cuerpo de la llamada:

  • StringEntity (Paquete org.apache.http.entity.StringEntity): Se utiliza para enviar cadenas de texto como JSON o XML. Es importante especificar siempre el tipo de contenido (ContentType.APPLICATION_JSON, que ya establece la codificación UTF-8 y la cabecera Content-Type: application/json; charset=UTF-8): 

import org.apache.http.client.methods.HttpPost;
import org.apache.http.entity.ContentType;
import org.apache.http.entity.StringEntity;

HttpPost postRequest = new HttpPost("http://localhost:8080/petshop/pet");

String jsonBody = "{\"petId\": 10, \"petName\": \"Rocky\", \"age\": 3}";
StringEntity entity = new StringEntity(jsonBody, ContentType.APPLICATION_JSON);

postRequest.setEntity(entity);
  • UrlEncodedFormEntity (Paquete org.apache.http.client.entity.UrlEncodedFormEntity): Simula el envío de un formulario HTML tradicional (application/x-www-form-urlencoded) a partir de una lista de pares clave-valor representados con NameValuePair y BasicNameValuePair (paquete org.apache.http.message.BasicNameValuePair).
  • MultipartEntityBuilder (Paquete org.apache.http.entity.mime.MultipartEntityBuilder de la dependencia httpmime): Permite construir peticiones multipart/form-data combinando campos de texto (addTextBody) y archivos binarios o imágenes (addBinaryBody).

5. Configuración de Timeouts y Redirecciones con RequestConfig

En cualquier entorno de producción es crítico configurar tiempos máximos de espera (timeouts) para evitar que los hilos de nuestra aplicación queden bloqueados indefinidamente si el servidor externo tarda en responder. Esto se realiza mediante la clase RequestConfig ubicada en el paquete org.apache.http.client.config.RequestConfig:

  • setConnectTimeout(int ms): Tiempo máximo (en milisegundos) permitido para establecer el handshake TCP inicial con el servidor remoto. Si se supera, lanza ConnectTimeoutException.
  • setConnectionRequestTimeout(int ms): Tiempo máximo esperando a que el pool interno de conexiones (ConnectionManager) nos asigne una conexión libre cuando todas están ocupadas.
  • setSocketTimeout(int ms): Tiempo máximo de inactividad esperando la llegada de paquetes de datos una vez establecida la conexión (tiempo que tarda el servidor remoto en procesar y devolver la respuesta). Si se supera, lanza SocketTimeoutException.
  • setRedirectsEnabled(boolean): Activa o desactiva el seguimiento automático de redirecciones HTTP (códigos 301, 302, 307).

import org.apache.http.client.config.RequestConfig;
import org.apache.http.client.methods.HttpGet;

// Configurar timeouts de 5 segundos (5000 ms)
RequestConfig requestConfig = RequestConfig.custom()
		.setConnectTimeout(5000)
		.setConnectionRequestTimeout(5000)
		.setSocketTimeout(5000)
		.setRedirectsEnabled(true)
		.build();

HttpGet request = new HttpGet("http://localhost:8080/petshop/pet/15");
request.setConfig(requestConfig);

¿Cuándo usar cada tipo de petición y de entidad y cuándo NO usarlos?

  • HttpGet / HttpDelete: Para consultar o eliminar. No enviar cuerpo en un GET: muchos servidores lo ignoran.
  • HttpPost / HttpPut / HttpPatch: Para crear, reemplazar o modificar parcialmente. No usar POST para consultas que no modifican datos.
  • StringEntity: Para JSON o XML. No olvidar el ContentType, o el servidor puede rechazar la petición con un 415.
  • UrlEncodedFormEntity: Para formularios clásicos. No usarla para enviar JSON.
  • RequestConfig: Siempre en producción. No dejar los timeouts por defecto (infinitos en socketTimeout de HttpClient 4.x).

Ejemplo y Contraejemplo al Construir una Petición HTTP

Contraejemplo (Mala práctica): Concatenar parámetros en la URL a mano y no definir Timeouts

Si concatenamos directamente parámetros de búsqueda en el String de la URL (por ejemplo, un nombre con espacios como "San Bernardo" o caracteres especiales) sin usar URIBuilder, el constructor de HttpGet lanzará una excepción IllegalArgumentException: Illegal character in query. Además, si no configuramos un RequestConfig con timeouts, una caída del servidor externo bloqueará los hilos de nuestra aplicación indefinidamente:


// CONTRAEJEMPLO (INCORRECTO): El espacio en blanco en 'San Bernardo' rompe la URI y no hay timeouts configurados
String breed = "San Bernardo";
HttpGet badRequest = new HttpGet("http://localhost:8080/petshop/pet/search?breed=" + breed); // ¡Lanza IllegalArgumentException!

Ejemplo (Buena práctica): Construir la URI con URIBuilder y aplicar RequestConfig

Con URIBuilder los espacios y caracteres especiales se codifican automáticamente en formato URL (San+Bernardo o San%20Bernardo) y RequestConfig protege el hilo frente a bloqueos de red:


// EJEMPLO (CORRECTO): Codificación segura de parámetros con URIBuilder y protección con RequestConfig
URI safeUri = new URIBuilder("http://localhost:8080/petshop/pet/search")
		.addParameter("breed", "San Bernardo")
		.build();

RequestConfig config = RequestConfig.custom()
		.setConnectTimeout(3000)
		.setSocketTimeout(5000)
		.build();

HttpGet goodRequest = new HttpGet(safeUri);
goodRequest.setConfig(config);
