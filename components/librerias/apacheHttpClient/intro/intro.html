Apache HttpClient - Introducción y Configuración

Apache HttpClient (parte del proyecto Apache HttpComponents) es una de las librerías más robustas, completas y utilizadas en Java para actuar como cliente HTTP y consumir servicios web o APIs REST externas desde una aplicación backend.

A diferencia de la clase básica HttpURLConnection de versiones antiguas del JDK, Apache HttpClient proporciona gestión automática de pools de conexiones persistentes (Keep-Alive), configuración granular de timeouts, redirecciones automáticas, manejo de cookies, soporte de proxies, subida de archivos multipart y distintos esquemas de autenticación (Basic, Digest, NTLM, Bearer Token).

Dependencias necesarias

Existen dos ramas principales de la librería en los repositorios de Maven:

  • Rama clásica 4.x (org.apache.httpcomponents:httpclient): Es la versión más extendida en proyectos empresariales (con paquetes bajo org.apache.http.*).
  • Rama moderna 5.x (org.apache.httpcomponents.client5:httpclient5): Evolución con soporte nativo para HTTP/2 y programación reactiva/asíncrona (con paquetes bajo org.apache.hc.client5.*).

Dependencia en Maven (pom.xml):


<!-- Versión clásica original -->
<dependency>
    <groupId>org.apache.httpcomponents</groupId>
    <artifactId>httpclient</artifactId>
    <version>4.1.1</version>
</dependency>

<!-- Versión 4.5.x estable recomendada (incluye CloseableHttpClient y HttpClients) -->
<dependency>
    <groupId>org.apache.httpcomponents</groupId>
    <artifactId>httpclient</artifactId>
    <version>4.5.14</version>
</dependency>

<!-- Opcional: Para envío de formularios con ficheros (MultipartEntityBuilder) -->
<dependency>
    <groupId>org.apache.httpcomponents</groupId>
    <artifactId>httpmime</artifactId>
    <version>4.5.14</version>
</dependency>

Equivalente en Gradle (build.gradle):


dependencies {
    implementation 'org.apache.httpcomponents:httpclient:4.5.14'
    implementation 'org.apache.httpcomponents:httpmime:4.5.14'
}

Clases e Interfaces Principales de Apache HttpClient

  • CloseableHttpClient: Clase abstracta ubicada en el paquete org.apache.http.impl.client.CloseableHttpClient. Es el motor principal encargado de ejecutar las peticiones HTTP mediante su método execute(). Implementa la interfaz AutoCloseable de Java, lo que permite cerrarlo automáticamente dentro de un bloque try-with-resources. Es un objeto thread-safe.
  • HttpClients y HttpClientBuilder: Clases de factoría ubicadas en org.apache.http.impl.client.HttpClients y org.apache.http.impl.client.HttpClientBuilder. Permiten instanciar un cliente HTTP con la configuración por defecto o personalizada:
    • HttpClients.createDefault(): Crea un CloseableHttpClient con pool de conexiones estándar y gestión de redirecciones y cookies por defecto.
    • HttpClients.custom(): Devuelve un HttpClientBuilder para configurar timeouts por defecto, credenciales de proxy, certificados SSL o tamaño del pool de conexiones antes de llamar a .build().
  • CloseableHttpResponse: Interfaz ubicada en el paquete org.apache.http.client.methods.CloseableHttpResponse. Representa la respuesta devuelta por el servidor tras ejecutar una petición. Es fundamental cerrarla siempre (con try-with-resources) o usar un ResponseHandler para que el socket subyacente se libere y vuelva al pool de conexiones.

    Sus métodos más utilizados son:

    • getStatusLine(): Devuelve un objeto StatusLine del que se obtiene el código numérico HTTP con getStatusCode() (ej. 200, 201, 404) y la frase descriptiva con getReasonPhrase() (ej. "OK").
    • getEntity(): Devuelve el cuerpo (payload) de la respuesta encapsulado en un objeto HttpEntity (o null si la respuesta no tiene cuerpo, como en un 204 No Content).
    • getAllHeaders() / getFirstHeader(String name): Permiten inspeccionar las cabeceras HTTP devueltas por el servidor.
  • HttpEntity: Interfaz ubicada en el paquete org.apache.http.HttpEntity. Representa el contenido de un mensaje HTTP tanto al enviar datos en el body de una petición (POST, PUT, PATCH) como al recibir datos en la respuesta.
  • EntityUtils: Clase de utilidades estáticas ubicada en el paquete org.apache.http.util.EntityUtils. Facilita la lectura y el consumo seguro del flujo de bytes de un HttpEntity:
    • EntityUtils.toString(HttpEntity entity, Charset defaultCharset): Lee todo el flujo de la respuesta y lo convierte en un String (por ejemplo con StandardCharsets.UTF_8 para obtener el JSON devuelto por el servidor).
    • EntityUtils.toByteArray(HttpEntity entity): Lee el cuerpo de la respuesta y lo devuelve como byte[] (útil al descargar imágenes o archivos PDF).
    • EntityUtils.consume(HttpEntity entity): Asegura que el stream de la entidad se haya leído hasta el final y se cierre para liberar la conexión inmediatamente.

Flujo Básico de Ejecución y Gestión de Recursos

El ciclo de vida estándar de una llamada con Apache HttpClient sigue siempre estos cuatro pasos dentro de un bloque try-with-resources para evitar fugas de conexiones:


import java.nio.charset.StandardCharsets;
import org.apache.http.HttpEntity;
import org.apache.http.client.methods.CloseableHttpResponse;
import org.apache.http.client.methods.HttpGet;
import org.apache.http.impl.client.CloseableHttpClient;
import org.apache.http.impl.client.HttpClients;
import org.apache.http.util.EntityUtils;

// 1. Crear el cliente HTTP
try (CloseableHttpClient httpClient = HttpClients.createDefault()) 
{
	// 2. Definir el método y la URL de la petición
	HttpGet request = new HttpGet("http://localhost:8080/petshop/pet/15");

	// 3. Ejecutar la petición y obtener la respuesta (también dentro de try-with-resources)
	try (CloseableHttpResponse response = httpClient.execute(request)) 
	{
		// 4. Comprobar el código de estado HTTP y consumir el cuerpo con EntityUtils
		int statusCode = response.getStatusLine().getStatusCode();
		System.out.println("Código HTTP: " + statusCode);

		HttpEntity entity = response.getEntity();
		if (entity != null) 
		{
			String responseBody = EntityUtils.toString(entity, StandardCharsets.UTF_8);
			System.out.println("Respuesta JSON: " + responseBody);
		}
	}
}

¿Cuándo usar Apache HttpClient y cuándo NO usarlo?

Escenario ¿Cuándo SÍ usarlo? (Recomendado) ¿Cuándo NO usarlo? (Desaconsejado / Alternativas)
Control de bajo nivel HTTP y Pools de Conexiones Cuando se requiere configurar al milímetro pools de conexiones con PoolingHttpClientConnectionManager, proxies corporativos, certificados SSL mutuos (mTLS), cookies, reintentos automáticos o formularios multipart complejos. En microservicios con Spring Cloud donde se quiere invocar otro microservicio declarando simplemente una interfaz Java anotada: ahí es mucho más limpio usar Spring Cloud OpenFeign (que por debajo puede usar Apache HttpClient como motor) o RestTemplate / WebClient / RestClient.
Proyectos sin dependencias externas En proyectos Java 8 o aplicaciones empresariales que ya incluyen Apache HttpComponents en su stack. En aplicaciones ligeras con Java 11+ que solo necesitan hacer un par de llamadas HTTP sencillas sin añadir librerías externas al pom.xml: se puede usar el cliente nativo java.net.http.HttpClient del JDK.
Cuándo elegir Apache HttpClient frente a otros clientes HTTP del ecosistema Java

Ejemplo y Contraejemplo: Gestión de Recursos y Fugas de Conexiones

Contraejemplo (Mala práctica): No cerrar CloseableHttpResponse ni consumir el HttpEntity

Uno de los fallos más graves en producción con Apache HttpClient es ejecutar una petición sin cerrar el CloseableHttpResponse ni consumir su HttpEntity. Esto mantiene el socket TCP bloqueado permanentemente hasta agotar el pool de conexiones, provocando que las siguientes peticiones se queden colgadas indefinidamente lanzando ConnectionPoolTimeoutException:


// CONTRAEJEMPLO (INCORRECTO): Fuga de memoria y de sockets por no cerrar la respuesta ni el cliente
public int checkServerStatusBad() throws Exception 
{
	CloseableHttpClient client = HttpClients.createDefault();
	CloseableHttpResponse response = client.execute(new HttpGet("http://localhost:8080/petshop/pet/15"));

	// ¡Error! Nos quedamos solo con el statusCode y salimos del método sin cerrar 'response' ni consumir el body.
	// La conexión queda bloqueada y nunca vuelve a estar disponible en el pool.
	return response.getStatusLine().getStatusCode();
}

Ejemplo (Buena práctica): Uso de try-with-resources o ResponseHandler

Al envolver la respuesta en un bloque try-with-resources y consumir la entidad con EntityUtils, Java garantiza que el flujo y la conexión se liberen siempre, incluso si ocurre una excepción:


// EJEMPLO (CORRECTO): Cierre automático garantizado mediante try-with-resources y EntityUtils.consume()
public int checkServerStatusGood(CloseableHttpClient sharedClient) throws Exception 
{
	HttpGet request = new HttpGet("http://localhost:8080/petshop/pet/15");
	try (CloseableHttpResponse response = sharedClient.execute(request)) 
	{
		EntityUtils.consume(response.getEntity());
		return response.getStatusLine().getStatusCode();
	}
}
