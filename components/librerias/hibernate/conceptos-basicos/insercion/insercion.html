Inserción de Entidades en Hibernate y JPA

Para insertar un nuevo registro en la base de datos utilizando Hibernate, primero se instancia el objeto entidad en memoria (estado Transient), se abre una sesión y una transacción activa, se pasa el objeto al contexto de persistencia mediante persist() o save() (pasando a estado Persistent), y finalmente se confirma la transacción con commit() para que Hibernate ejecute el INSERT INTO en la base de datos.

Existen dos formas de realizar este proceso: utilizando la interfaz estándar de JPA (EntityManager) o utilizando la API nativa de Hibernate (Session).

1. Inserción mediante el estándar JPA (EntityManager)

Cuando se trabaja a través de la especificación estándar JPA (paquete javax.persistence.* o jakarta.persistence.*), se utiliza la clase Persistence para levantar la factoría a partir del archivo META-INF/persistence.xml y se emplea el método entityManager.persist(entidad):


EntityManagerFactory emfactory = Persistence.createEntityManagerFactory("Hibernate");

EntityManager entitymanager = emfactory.createEntityManager();
entitymanager.getTransaction().begin();

Author author = new Author();

entitymanager.persist(author);
entitymanager.getTransaction().commit();

entitymanager.close();
emfactory.close();

Explicación paso a paso del fragmento anterior:

  • Persistence.createEntityManagerFactory("Hibernate"): Busca en el archivo persistence.xml la unidad de persistencia llamada "Hibernate" y construye la factoría de conexiones.
  • emfactory.createEntityManager(): Abre un nuevo contexto de persistencia (equivalente a una sesión).
  • entitymanager.getTransaction().begin(): Inicia una transacción de base de datos. En JPA todas las operaciones de escritura (inserción, modificación o borrado) requieren obligatoriamente una transacción activa.
  • entitymanager.persist(author): Registra la instancia author dentro del contexto de persistencia para que sea insertada.
  • entitymanager.getTransaction().commit(): Vuelca los cambios pendientes (flush), ejecuta la sentencia SQL INSERT y confirma la transacción en la base de datos.
  • close(): Libera la conexión y cierra los recursos.

2. Todo el proceso con la API nativa de Hibernate (SessionFactory y Session)

Cuando se utiliza directamente la API nativa de Hibernate sin intermediarios, el flujo completo consta de: definir el archivo XML de configuración (hibernate.cfg.xml), mapear la clase entidad, construir el singleton SessionFactory y abrir una Session para guardar el objeto.

Paso 1: Creación del archivo de configuración (hibernate.cfg.xml)

El archivo hibernate.cfg.xml se ubica en la raíz de recursos (src/main/resources/) y define los parámetros de conexión JDBC, el dialecto SQL, el comportamiento de creación de tablas (hbm2ddl.auto) y las clases de entidad registradas mediante la etiqueta <mapping>:


<?xml version="1.0" encoding="utf-8"?>
<!DOCTYPE hibernate-configuration PUBLIC 
"-//Hibernate/Hibernate Configuration DTD 3.0//EN" 
"http://hibernate.sourceforge.net/hibernate-configuration-3.0.dtd">
<hibernate-configuration>
    <session-factory>
        <property name="hibernate.connection.driver_class">com.mysql.jdbc.Driver</property>
        <property name="hibernate.connection.url">jdbc:mysql://localhost:3306/hibernatedemo</property>
        <property name="hibernate.connection.password">password</property>
        <property name="hibernate.connection.username">root</property>
        <property name="hibernate.dialect">org.hibernate.dialect.MySQLDialect</property>
        <property name="show_sql">true</property>
        <property name="hbm2ddl.auto">create</property>
        <mapping class="hibernate.test.dto.EmployeeEntity"></mapping>
    </session-factory>
</hibernate-configuration>

Paso 2: Definición de la Entidad mapeada (EmployeeEntity)

La clase indicada en <mapping class="..."> se anota con las anotaciones de persistencia (@Entity, @Table, @Id, @GeneratedValue y @Column) para vincular cada atributo con su columna en la tabla:


package hibernate.test.dto;

import java.io.Serializable;
import javax.persistence.Column;
import javax.persistence.Entity;
import javax.persistence.GeneratedValue;
import javax.persistence.GenerationType;
import javax.persistence.Id;
import javax.persistence.Table;
import lombok.Data;

@Data
@Entity
@Table(name = "EMPLOYEE")
public class EmployeeEntity implements Serializable 
{
    private static final long serialVersionUID = 1L;

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "ID", unique = true, nullable = false)
    private Integer employeeId;

    @Column(name = "EMAIL", unique = true, nullable = false, length = 100)
    private String email;

    @Column(name = "FIRST_NAME", nullable = false, length = 100)
    private String firstName;

    @Column(name = "LAST_NAME", nullable = false, length = 100)
    private String lastName;
}

Paso 3: Creación de una SessionFactory (HibernateUtil)

Como crear la instancia de SessionFactory es una operación muy costosa, se encapsula en una clase de utilidad (HibernateUtil) siguiendo el patrón Singleton para inicializarla una única vez al cargar la clase en memoria y reutilizarla durante toda la ejecución de la aplicación:


public class HibernateUtil 
{
    private static final SessionFactory sessionFactory = buildSessionFactory();
        
    private static SessionFactory buildSessionFactory() 
    {
        try
        {
            // Create the SessionFactory from hibernate.cfg.xml
            return new AnnotationConfiguration().configure(new File("hibernate.cgf.xml")).buildSessionFactory();
        }
        catch (Throwable ex) {
            // Make sure you log the exception, as it might be swallowed
            System.err.println("Initial SessionFactory creation failed." + ex);
            throw new ExceptionInInitializerError(ex);
        }
    }
    
    public static SessionFactory getSessionFactory() {
        return sessionFactory;
    }
    
    public static void shutdown() {
        // Close caches and connection pools
        getSessionFactory().close();
    }
}

Nota sobre versiones modernas de Hibernate (Hibernate 4.3 / 5 / 6): La clase AnnotationConfiguration se fusionó dentro de org.hibernate.cfg.Configuration, por lo que en versiones actuales basta con invocar new Configuration().configure().buildSessionFactory().

Paso 4: Ejemplo de inserción con Session.save()

Una vez lista la clase HibernateUtil, se abre una sesión mediante openSession(), se inicia la transacción con beginTransaction(), se instancia y rellena el objeto EmployeeEntity, y se guarda con session.save(emp) antes de confirmar la transacción:


public class TestHibernateInsert 
{

    public static void main(String[] args) 
    {
        Session session = HibernateUtil.getSessionFactory().openSession();
        session.beginTransaction();
        
        //Add new Employee object
        EmployeeEntity emp = new EmployeeEntity();
        emp.setEmail("lokesh@mail.com");
        emp.setFirstName("lokesh");
        emp.setLastName("gupta");
        
        //Save the employee in database
        session.save(emp);

        //Commit the transaction
        session.getTransaction().commit();
        HibernateUtil.shutdown();
    }
}

Diferencia entre persist() y save()

Característica persist(Object entity) save(Object entity)
Especificación Estándar JPA (presente tanto en EntityManager como en Session). Propio de la API nativa de Hibernate (deprecado en Hibernate 6 en favor de persist).
Tipo de retorno void (modifica directamente la instancia pasada por parámetro asignándole su ID). Serializable (devuelve el identificador generado para la entidad).
Comportamiento con entidades Detached Lanza una excepción PersistentObjectException si se intenta pasar una entidad que ya estaba separada. Puede llegar a insertar un registro duplicado en la base de datos.
Comparativa entre los métodos persist() de JPA y save() de Hibernate

Anotaciones de JPA usadas en la entidad

  • @Entity: Pertenece a JPA, se encuentra en javax.persistence.Entity (jakarta.persistence.Entity desde JPA 3 / Spring Boot 3). Se coloca sobre la clase e indica que se mapea a una tabla. Por defecto la tabla se llama como la clase. Requiere un constructor sin argumentos y un atributo @Id.
  • @Table: Pertenece a JPA, javax.persistence.Table. Se coloca sobre la clase. Parámetro name: nombre de la tabla (si no se indica, usa el nombre de la clase). Otros parámetros: schema y uniqueConstraints.
  • @Id: Pertenece a JPA, javax.persistence.Id. Se coloca sobre el atributo que es la clave primaria.
  • @GeneratedValue: Pertenece a JPA, javax.persistence.GeneratedValue. Se coloca junto a @Id para que la clave se genere automáticamente. Parámetro strategy (enum GenerationType):
    • IDENTITY: Usa una columna autoincremental de la base de datos (MySQL, SQL Server, PostgreSQL con SERIAL).
    • SEQUENCE: Usa una secuencia de la base de datos (Oracle, PostgreSQL); permite agrupar inserciones en lote.
    • TABLE: Usa una tabla auxiliar para simular la secuencia; es el más lento y está en desuso.
    • AUTO: Valor por defecto; el proveedor (Hibernate) elige la estrategia según el dialecto.
  • @Column: Pertenece a JPA, javax.persistence.Column. Se coloca sobre un atributo. Sin ella, la columna se llama como el atributo. Parámetros: name (nombre de columna), nullable (por defecto true), unique (por defecto false) y length (por defecto 255 en String).

¿Cuándo usar persist() / save() y cuándo NO usarlos?

  • Cuándo usarlos: Para insertar una entidad Transient nueva dentro de una transacción activa. Se prefiere persist() (estándar JPA) por ser portable.
  • Cuándo NO usarlos: Para actualizar una entidad ya existente y separada de la sesión (Detached): ahí se usa merge(). Tampoco si la entidad ya está en estado Persistent: los cambios se guardan solos por Dirty Checking.

Ejemplo y Contraejemplo al Insertar Entidades

Contraejemplo (Mala práctica): Llamar a persist() sin una transacción activa o asignando manualmente un ID autogenerado

Si una entidad tiene su clave primaria anotada con @GeneratedValue(strategy = GenerationType.IDENTITY) y le asignamos manualmente un ID antes de llamar a persist(), Hibernate creerá que la entidad ya existía en base de datos (estado Detached) y lanzará una excepción PersistentObjectException: detached entity passed to persist. Además, si olvidamos abrir y confirmar la transacción, el registro jamás se escribirá en la tabla:


// CONTRAEJEMPLO (INCORRECTO): Asignar ID manual a un campo @GeneratedValue y olvidar la transacción
try (Session session = HibernateUtil.getSessionFactory().openSession()) 
{
	EmployeeEntity emp = new EmployeeEntity();
	emp.setEmployeeId(99); // ¡Error! Al tener @GeneratedValue, Hibernate lo rechaza en persist()
	emp.setEmail("lokesh@mail.com");

	// Sin beginTransaction() ni commit(), el INSERT nunca se confirma en la base de datos
	session.persist(emp);
}

Ejemplo (Buena práctica): Dejar que la base de datos genere el @Id dentro de una transacción

Cuando el campo @Id usa @GeneratedValue, se deja a null al instanciar el objeto y se ejecuta persist() dentro de una transacción activa; tras el commit(), Hibernate rellena automáticamente el ID generado en el propio objeto:


// EJEMPLO (CORRECTO): Sin asignar el ID autogenerado y confirmando la transacción
try (Session session = HibernateUtil.getSessionFactory().openSession()) 
{
	session.beginTransaction();

	EmployeeEntity emp = new EmployeeEntity();
	emp.setEmail("lokesh@mail.com");
	emp.setFirstName("lokesh");
	emp.setLastName("gupta");

	session.persist(emp);
	session.getTransaction().commit();

	// Hibernate ya ha asignado automáticamente el ID generado por la BD
	System.out.println("ID asignado: " + emp.getEmployeeId());
}
