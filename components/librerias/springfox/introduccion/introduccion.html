SpringFox y Swagger (OpenAPI) - Introducción y Configuración

Swagger (actualmente estandarizado bajo el nombre OpenAPI Specification) es el estándar de la industria para describir, documentar y consumir APIs RESTful. Por su parte, SpringFox es la librería que se integra con Spring Boot para inspeccionar en tiempo de ejecución todos los controladores (@RestController), métodos HTTP y DTOs del proyecto y generar automáticamente tanto el descriptor JSON de la API como la interfaz gráfica web Swagger UI.

Gracias a Swagger UI, cualquier desarrollador front-end, tester o consumidor del microservicio puede consultar en el navegador todos los endpoints disponibles, qué parámetros reciben, cómo son los esquemas JSON de entrada/salida y ejecutar peticiones de prueba directamente desde el navegador sin necesidad de herramientas externas como Postman.

Evolución: SpringFox (Swagger 2) frente a SpringDoc (OpenAPI 3)

  • SpringFox (Swagger 2 / OpenAPI 3): Basado en las anotaciones clásicas del paquete io.swagger.annotations.* (como @Api, @ApiOperation, @ApiParam, @ApiModel, @ApiModelProperty). Fue el estándar de facto en proyectos Spring Boot 2.x (con javax.*).
  • SpringDoc OpenAPI (OpenAPI 3): Librería moderna basada en las anotaciones de io.swagger.v3.oas.annotations.* (como @Tag, @Operation, @Parameter, @Schema). Es la opción recomendada para proyectos nuevos en Spring Boot 3.x (basados en jakarta.* y Java 17+).

Dependencias necesarias

1. Con SpringFox 3.0.0 (Starter unificado)

En SpringFox 3.0.0 basta con añadir una única dependencia (springfox-boot-starter) que ya incluye tanto el generador de especificaciones Swagger 2 / OpenAPI 3 como la interfaz visual Swagger UI.

En Maven (pom.xml):


<dependency>
	<groupId>io.springfox</groupId>
	<artifactId>springfox-boot-starter</artifactId>
	<version>3.0.0</version>
</dependency>

En Gradle (build.gradle):


dependencies {
	implementation 'io.springfox:springfox-boot-starter:3.0.0'
}

2. Con SpringFox 2.9.2 (Artefactos separados clásicos)

En versiones anteriores de SpringFox era necesario declarar por separado el motor springfox-swagger2 y la interfaz springfox-swagger-ui:


<dependency>
	<groupId>io.springfox</groupId>
	<artifactId>springfox-swagger2</artifactId>
	<version>2.9.2</version>
</dependency>
<dependency>
	<groupId>io.springfox</groupId>
	<artifactId>springfox-swagger-ui</artifactId>
	<version>2.9.2</version>
</dependency>

3. Alternativa actual en Spring Boot 3 (SpringDoc OpenAPI)

Si el proyecto utiliza Spring Boot 3, la dependencia equivalente en Maven (pom.xml) es:


<dependency>
	<groupId>org.springdoc</groupId>
	<artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
	<version>2.2.0</version>
</dependency>

Configuración del Bean Docket en SpringFox

Para activar y personalizar la generación de documentación en SpringFox, se crea una clase de configuración de Spring anotada con @Configuration que expone un bean de tipo Docket.

Clases y Anotaciones de Configuración

  • @EnableSwagger2: Anotación perteneciente a SpringFox, ubicada en el paquete springfox.documentation.swagger2.annotations.EnableSwagger2. Habilita el soporte de Swagger 2 en el proyecto (en SpringFox 3.0 con springfox-boot-starter ya no es obligatoria o se sustituye por @EnableOpenApi).
  • Docket: Clase principal de configuración de SpringFox, ubicada en el paquete springfox.documentation.spring.web.plugins.Docket. Implementa el patrón Builder para definir qué controladores y rutas se van a documentar y qué metadatos generales tendrá la API.

    Sus métodos principales son:

    • new Docket(DocumentationType.SWAGGER_2): Inicializa el configurador indicando la versión del estándar de documentación (SWAGGER_2 o OAS_30).
    • .select(): Devuelve una instancia de ApiSelectorBuilder para filtrar qué controladores y qué rutas se expondrán en Swagger.
    • .apis(Predicate<RequestHandler>): Se utiliza junto con la clase de utilidad RequestHandlerSelectors (en springfox.documentation.builders.RequestHandlerSelectors):
      • RequestHandlerSelectors.basePackage("com.petshop.controller"): Documenta únicamente los controladores dentro de ese paquete (opción recomendada para no mostrar endpoints internos de Spring Boot como basic-error-controller).
      • RequestHandlerSelectors.any(): Documenta todos los controladores del classpath.
      • RequestHandlerSelectors.withClassAnnotation(RestController.class): Documenta solo las clases que tengan una anotación específica.
    • .paths(Predicate<String>): Se utiliza junto con la clase PathSelectors (en springfox.documentation.builders.PathSelectors) para filtrar por la URL del endpoint:
      • PathSelectors.any(): Incluye todas las rutas de los controladores seleccionados.
      • PathSelectors.ant("/petshop/**"): Incluye solo las rutas que coincidan con el patrón Ant.
      • PathSelectors.regex("/petshop/.*"): Filtra las rutas mediante una expresión regular.
    • .useDefaultResponseMessages(boolean): Si se establece a false, desactiva los códigos de estado genéricos que SpringFox añade por defecto a todos los métodos (200, 201, 401, 403, 404) para que solo se muestren los que el desarrollador haya documentado explícitamente con @ApiResponses.
    • .apiInfo(ApiInfo): Asocia la información descriptiva de cabecera de la API (título, descripción, versión, contacto y licencia) construida mediante ApiInfoBuilder.

Ejemplo completo de clase SwaggerConfig


package com.petshop.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import springfox.documentation.builders.ApiInfoBuilder;
import springfox.documentation.builders.PathSelectors;
import springfox.documentation.builders.RequestHandlerSelectors;
import springfox.documentation.service.ApiInfo;
import springfox.documentation.service.Contact;
import springfox.documentation.spi.DocumentationType;
import springfox.documentation.spring.web.plugins.Docket;
import springfox.documentation.swagger2.annotations.EnableSwagger2;

@Configuration
@EnableSwagger2
public class SwaggerConfig 
{
	@Bean
	public Docket apiDocket() 
	{
		return new Docket(DocumentationType.SWAGGER_2)
				.select()
				.apis(RequestHandlerSelectors.basePackage("com.petshop.controller"))
				.paths(PathSelectors.any())
				.build()
				.useDefaultResponseMessages(false)
				.apiInfo(getApiInfo());
	}

	private ApiInfo getApiInfo() 
	{
		return new ApiInfoBuilder()
				.title("PetShop REST API")
				.description("API REST para la gestión del catálogo de mascotas de la tienda PetShop")
				.version("1.0.0")
				.license("Apache 2.0")
				.licenseUrl("https://www.apache.org/licenses/LICENSE-2.0")
				.contact(new Contact("Equipo PetShop", "https://petshop.com", "soporte@petshop.com"))
				.build();
	}
}

Acceso a Swagger UI y al JSON de la API

Una vez arrancado el microservicio de Spring Boot (por defecto en el puerto 8080), se puede acceder a la documentación generada a través de las siguientes rutas según la versión empleada:

Librería / Versión URL de la interfaz web (Swagger UI) URL del documento JSON generado
SpringFox 2.x http://localhost:8080/swagger-ui.html http://localhost:8080/v2/api-docs
SpringFox 3.0.0 http://localhost:8080/swagger-ui/ (o /swagger-ui/index.html) http://localhost:8080/v2/api-docs (o /v3/api-docs)
SpringDoc OpenAPI http://localhost:8080/swagger-ui.html http://localhost:8080/v3/api-docs

Nota de compatibilidad en Spring Boot 2.6+ y SpringFox 3

A partir de Spring Boot 2.6, la estrategia por defecto para emparejar rutas en Spring MVC cambió de AntPathMatcher a PathPatternParser, lo que puede provocar un NullPointerException al arrancar SpringFox 3.0.0. Para solucionarlo basta con añadir la siguiente propiedad en application.properties:


spring.mvc.pathmatch.matching-strategy=ant_path_matcher

¿Cuándo usar SpringFox / Swagger y cuándo NO usarlo?

Escenario ¿Cuándo SÍ usarlo? (Recomendado) ¿Cuándo NO usarlo? (Desaconsejado / Alternativas)
Versión de Spring Boot Usar SpringFox en proyectos existentes basados en Spring Boot 2.x (javax.*) que ya emplean las anotaciones io.swagger.annotations.*. No usar SpringFox en proyectos con Spring Boot 3.x (Java 17+ / Jakarta EE), ya que SpringFox no tiene soporte para el espacio de nombres jakarta.servlet.*. En Spring Boot 3 se debe usar siempre SpringDoc OpenAPI (springdoc-openapi-starter-webmvc-ui).
Entornos de Despliegue Activar Swagger UI en entornos de desarrollo, local, integración y preproducción (QA) para facilitar las pruebas y la integración con otros equipos. No exponer Swagger UI públicamente en Producción sin autenticación: revela toda la superficie de ataque, rutas internas y estructura de datos del servidor a terceros.

Ejemplo y Contraejemplo en la configuración de Docket

Contraejemplo (Mala práctica): Usar RequestHandlerSelectors.any() y exponerlo en todos los entornos

Si en la configuración del Docket se deja RequestHandlerSelectors.any() y no se restringe el perfil de ejecución, Swagger documentará controladores internos de Spring Boot (como basic-error-controller o endpoints de Actuator) ensuciando la documentación y dejando la consola interactiva abierta en producción:


// CONTRAEJEMPLO (INCORRECTO): Expone endpoints internos de Spring y permanece activo en producción
@Configuration
@EnableSwagger2
public class BadSwaggerConfig 
{
	@Bean
	public Docket api() 
	{
		return new Docket(DocumentationType.SWAGGER_2)
				.select()
				.apis(RequestHandlerSelectors.any()) // ¡Mala práctica! Incluye basic-error-controller
				.paths(PathSelectors.any())
				.build();
	}
}

Ejemplo (Buena práctica): Filtrar por paquete base y restringir en producción con @Profile

Anotando la configuración con @Profile("!prod") (o mediante una propiedad springfox.documentation.enabled) y acotando el paquete con basePackage, nos aseguramos de publicar únicamente nuestros controladores de negocio y solo en entornos autorizados:


// EJEMPLO (CORRECTO): Solo documenta el paquete de controladores del proyecto y se desactiva en el perfil 'prod'
@Configuration
@EnableSwagger2
@Profile("!prod")
public class GoodSwaggerConfig 
{
	@Bean
	public Docket apiDocket() 
	{
		return new Docket(DocumentationType.SWAGGER_2)
				.select()
				.apis(RequestHandlerSelectors.basePackage("com.petshop.controller"))
				.paths(PathSelectors.any())
				.build()
				.useDefaultResponseMessages(false);
	}
}
