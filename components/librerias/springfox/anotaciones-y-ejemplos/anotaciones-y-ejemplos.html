Anotaciones de Swagger (SpringFox)

Aunque SpringFox es capaz de descubrir automáticamente las rutas, métodos HTTP y tipos de retorno leyendo las anotaciones nativas de Spring (@RestController, @GetMapping, @RequestParam, @RequestBody), el uso de las anotaciones de Swagger Annotations (ubicadas en el paquete io.swagger.annotations.*) permite enriquecer la documentación con descripciones funcionales, valores de ejemplo, restricciones y posibles códigos de respuesta HTTP.

1. Anotaciones para Controladores y Endpoints

  • @Api: Pertenece a Swagger Annotations (usada por SpringFox), se encuentra en el paquete io.swagger.annotations.Api y se coloca a nivel de clase sobre un controlador (@RestController). Sirve para agrupar y describir la función general del controlador dentro de Swagger UI.

    Sus parámetros más utilizados son:

    • tags: Array de Strings con el nombre o nombres de las secciones bajo las cuales se agruparán los endpoints de este controlador en Swagger UI (ej. @Api(tags = "Pet")).
    • produces / consumes: Especifica el tipo MIME que produce o consume el controlador (ej. "application/json").
  • @ApiOperation: Pertenece a Swagger Annotations, se encuentra en el paquete io.swagger.annotations.ApiOperation y se coloca sobre cada método del controlador (endpoint). Sirve para describir qué hace exactamente esa operación HTTP.

    Sus parámetros principales son:

    • value: Resumen breve de lo que hace el endpoint (aparece al lado de la ruta en la vista plegada de Swagger UI).
    • notes: Descripción detallada y extendida sobre el funcionamiento o reglas de negocio del endpoint (aparece al desplegar el endpoint).
    • response: Clase Java que representa el cuerpo de la respuesta (ej. PetDTO.class).
    • responseContainer: Si el endpoint devuelve una colección de objetos, permite indicarlo con valores como "List", "Set" o "Map".
  • @ApiResponses: Pertenece a Swagger Annotations, se encuentra en el paquete io.swagger.annotations.ApiResponses y se puede colocar tanto a nivel de clase (para respuestas comunes a todos los métodos del controlador, como los errores 400 o 500) como a nivel de método. Actúa como contenedor de un array de anotaciones @ApiResponse.
  • @ApiResponse: Pertenece a Swagger Annotations, se encuentra en el paquete io.swagger.annotations.ApiResponse y se utiliza dentro de @ApiResponses para documentar un código de estado HTTP concreto que puede devolver el endpoint.

    Sus parámetros principales son:

    • code: Número entero del código de estado HTTP (ej. 200, 201, 204, 400, 404, 500).
    • message: Explicación legible de qué significa ese código en el contexto del endpoint (ej. "OK", "Created", "Pet not found").
    • response: Clase del objeto devuelto en caso de producirse esa respuesta (ej. response = PetDTO.class o una clase de error ErrorResponseDTO.class).
    • responseContainer: Contenedor cuando la respuesta es una colección (ej. responseContainer = "List").
  • @ApiParam: Pertenece a Swagger Annotations, se encuentra en el paquete io.swagger.annotations.ApiParam y se coloca sobre los parámetros de entrada de un método del controlador (junto a @PathVariable, @RequestParam o @RequestHeader).

    Sus parámetros principales son:

    • value: Descripción del parámetro (ej. "Pet ID" o "Pet age").
    • example: Valor de ejemplo que aparecerá pre-rellenado en el formulario de Swagger UI para facilitar las pruebas (ej. example = "1").
    • required: Booleano (true / false) que indica en la documentación si el parámetro es obligatorio.
    • defaultValue: Valor por defecto si el cliente no envía el parámetro.
    • allowableValues: Restringe los valores aceptados (por ejemplo, una lista separada por comas "DOG, CAT, BIRD" o un rango "range[1, 30]").
  • @ApiIgnore: Pertenece a SpringFox, se encuentra en el paquete springfox.documentation.annotations.ApiIgnore. Se puede colocar sobre un controlador entero, un método o un parámetro concreto para que SpringFox lo ignore y no aparezca en la documentación pública de Swagger UI.

2. Anotaciones para Modelos y DTOs

Para documentar la estructura de los objetos JSON que se envían en el body de las peticiones o se reciben en las respuestas, se anotan las clases DTO (como PetDTO y PetPatchDTO) con las siguientes anotaciones:

  • @ApiModel: Se encuentra en el paquete io.swagger.annotations.ApiModel y se coloca sobre la declaración de la clase DTO. Permite darle un nombre personalizado y una descripción general al esquema JSON que aparece en la sección Models de Swagger UI.

    Sus parámetros principales son:

    • value: Nombre alternativo del modelo (por defecto toma el nombre de la clase Java, como PetDTO).
    • description: Explicación del propósito del DTO (ej. @ApiModel(description = "Pet DTO")).
  • @ApiModelProperty: Se encuentra en el paquete io.swagger.annotations.ApiModelProperty y se coloca sobre los atributos (o getters) de la clase DTO. Documenta cada propiedad individual del JSON.

    Sus parámetros principales son:

    • notes / value: Descripción funcional del campo (ej. notes = "Picture of the pet in base64").
    • example: Valor de ejemplo realista que Swagger UI utilizará para generar automáticamente el JSON de muestra en las peticiones POST, PUT y PATCH (ej. example = "Joe" o example = "1/2/2021").
    • required: Indica si el atributo es obligatorio en el JSON (true) u opcional (false).
    • allowEmptyValue: Booleano que especifica si se permite enviar el campo vacío.
    • allowableValues: Lista de valores permitidos separados por comas (ej. allowableValues = "image/jpeg, image/jpg, image/gif").
    • position: Número entero para ordenar en qué posición aparece el campo dentro del JSON de ejemplo en Swagger UI.
    • hidden: Si es true, oculta el atributo en la documentación de Swagger.

Ejemplo Completo Integrado: PetDTO y PetController

1. DTO documentado con @ApiModel y @ApiModelProperty

En PetDTO cada campo define su descripción, si es obligatorio, un ejemplo realista para el generador JSON de Swagger UI y los valores MIME permitidos para la imagen:


@ApiModel(description = "Pet DTO")
@Data
@Accessors(chain = true)
@JsonInclude(JsonInclude.Include.NON_EMPTY)
@JsonIgnoreProperties(ignoreUnknown = true)
public class PetDTO 
{   
	@ApiModelProperty(notes = "Pet ID", example = "1", required = true)
	@NotNull(message = ConstantMessages.FIELD_MANDATORY)
	@JsonProperty("petId")
	private Integer id;

	@ApiModelProperty(notes = "Pet Name", example = "Joe", required = true)
	@NotBlank(message = ConstantMessages.FIELD_MANDATORY)
	@JsonProperty("petName")
	private String name;
	
	@ApiModelProperty(notes = "Pet age", example = "1", required = true)
	@NotNull(message = ConstantMessages.FIELD_MANDATORY)
	@JsonProperty("age")
	private Short age;

	@ApiModelProperty(notes = "Date of birth", example = "1/2/2021", required = false)
	@JsonFormat(pattern = "dd/MM/yyyy", timezone = "Europe/Madrid")
	@JsonProperty("birthDate")
	private Date birthDate;

	@ApiModelProperty(notes = "Picture media type", example = "image/jpeg", required = true, allowEmptyValue = false, allowableValues = "image/jpeg, image/jpg, image/gif")
	@NotBlank(message = ConstantMessages.FIELD_MANDATORY)
	@Pattern(regexp = "^(image/jpeg|image/jpg|image/gif)$")
	@JsonProperty("pictureMediaType")
	private String pictureMediaType;
}

2. Controlador documentado con @Api, @ApiOperation, @ApiResponses y @ApiParam

En PetController se documenta tanto la cabecera de la clase como cada endpoint y sus parámetros de ruta o consulta:


@RestController
@RequestMapping("/petshop/pet")
@CrossOrigin
@Api(tags = "Pet")
@ApiResponses({
		@ApiResponse(code = 400, message = "Bad Request"),
		@ApiResponse(code = 500, message = "Internal server error")
})
public class PetController 
{
	@ApiOperation(value = "View a pet data", notes = "Retrieves a single pet from the database by its unique identifier")
	@ApiResponses({
			@ApiResponse(code = 200, message = "OK", response = PetDTO.class),
			@ApiResponse(code = 404, message = "Not found")
	})
	@GetMapping("/{id}")
	public ResponseEntity<PetDTO> get(
			@PathVariable(value = "id") 
			@ApiParam(value = "Pet Id", example = "1", required = true) final Integer pId) 
	{
		// Lógica de consulta y mapeo a PetDTO...
	}
}

¿Cuándo usar estas anotaciones y cuándo NO usarlas?

  • Cuándo usarlas: En APIs REST consumidas por otros equipos o por un front-end, para que Swagger UI muestre descripciones, ejemplos válidos y todos los códigos de respuesta posibles de cada endpoint.
  • Cuándo NO usarlas:
    • En proyectos con Spring Boot 3: allí se usan las anotaciones de OpenAPI 3 (@Tag, @Operation, @Parameter, @Schema) de SpringDoc, no las de io.swagger.annotations.*.
    • Para documentar la entidad JPA directamente: se documenta siempre el DTO.
    • Como sustituto de las validaciones: required = true solo documenta, no valida; la validación real se hace con @Valid y las constraints del DTO.

Ejemplo y Contraejemplo al documentar Endpoints y Modelos

Contraejemplo (Mala práctica): Documentar la Entidad de base de datos o usar anotaciones sin ejemplos

Un error grave al documentar un controlador es referenciar directamente la entidad JPA (response = Pet.class) o no especificar el atributo example en @ApiModelProperty. Esto provoca que Swagger UI muestre campos internos de base de datos, falle al intentar generar el esquema JSON si la entidad tiene relaciones circulares, y rellene el JSON de prueba con textos genéricos inútiles como "string" o 0 que no pasan las validaciones @Pattern:


// CONTRAEJEMPLO (INCORRECTO): Expone la entidad JPA Pet.class y no define valores 'example' válidos
@ApiOperation(value = "Get pet")
@ApiResponses({ @ApiResponse(code = 200, message = "OK", response = Pet.class) }) // ¡No usar la Entidad!
@GetMapping("/{id}")
public ResponseEntity<Pet> getBad(@PathVariable Integer id) { ... }

Ejemplo (Buena práctica): Documentar siempre con DTOs e incluir ejemplos realistas y códigos de error

Documentando el PetDTO.class con valores example que cumplan las expresiones regulares de validación y detallando tanto el código de éxito (200) como el de error (404), cualquier usuario podrá pulsar el botón "Try it out" en Swagger UI y ejecutar una petición válida al instante:


// EJEMPLO (CORRECTO): Usa PetDTO, documenta el 200 y el 404, y proporciona un ejemplo válido para el parámetro
@ApiOperation(value = "View a pet data", notes = "View a pet data")
@ApiResponses({
		@ApiResponse(code = 200, message = "OK", response = PetDTO.class),
		@ApiResponse(code = 404, message = "Not found")
})
@GetMapping("/{id}")
public ResponseEntity<PetDTO> getGood(
		@PathVariable(value = "id")
		@ApiParam(value = "pet Id", example = "1", required = true) final Integer pId) { ... }
