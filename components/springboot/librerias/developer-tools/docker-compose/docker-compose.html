Docker Compose Support: Infraestructura Automática en Desarrollo

1. ¿Qué es y para qué sirve?

Uno de los mayores dolores de cabeza para un desarrollador al clonar un nuevo repositorio es levantar manualmente toda la infraestructura auxiliar que la aplicación necesita para funcionar: la base de datos PostgreSQL, la caché Redis, el broker de RabbitMQ o el clúster de Kafka.

A partir de Spring Boot 3.1+, Spring Initializr incluye el módulo oficial Docker Compose Support (dependencia spring-boot-docker-compose):

  • Detección Automática: Al arrancar la aplicación (mvn spring-boot:run o ./gradlew bootRun), Spring Boot busca automáticamente un archivo compose.yaml o docker-compose.yml en la raíz del proyecto.
  • Gestión del Ciclo de Vida: Ejecuta automáticamente docker compose up al iniciar la aplicación y docker compose stop al detenerla.
  • Autoconfiguración Mágica de Conexiones (Connection Details): Spring Boot inspecciona los contenedores levantados por Docker Compose y autonfigura automáticamente las propiedades de conexión (URL de JDBC, puertos dinámicos, usuarios y contraseñas) de PostgreSQL, MySQL, Redis, RabbitMQ, Kafka o Zipkin sin escribir ni una sola línea en application.yml.

Analogía del mundo real

Imaginemos una autocaravana de viaje de última generación:

  • Sin Docker Compose Support, cada vez que llegas al camping tienes que tender manualmente la manguera del agua, clavar las piquetas, conectar el generador diésel con cables de cobre y configurar el regulador de gas antes de poder encender una bombilla (15 minutos de trabajo manual repetitivo).
  • Con Docker Compose Support, simplemente pulsas el botón *"Start"* en el salpicadero de la autocaravana: los gatos hidráulicos se nivelan solos, las conexiones de agua y luz se acoplan magnéticamente en 2 segundos y todo está listo para cocinar al instante.

2. Caso de Uso Real Estructurado

1. Contexto

Un equipo de 6 desarrolladores trabaja en el microservicio pet-service, que requiere PostgreSQL 16 y Redis 7 para ejecutarse localmente.

2. El Problema (Gestión manual)

Un desarrollador olvida arrancar Docker a mano y la app falla al iniciar; otro tiene un contenedor con contraseñas distintas y comitea cambios erróneos en application.yml; un nuevo fichaje tarda 2 días en configurar su entorno local.

3. La Solución (Con Docker Compose Support)

El nuevo desarrollador clona el repositorio, ejecuta ./gradlew bootRun y Spring Boot arranca PostgreSQL y Redis automáticamente en Docker, inyecta las credenciales y conecta la app en 3 segundos con cero fricción.

3. ¿Cuándo usarlo y cuándo NO usarlo?

Escenario Recomendación Motivo
Entornos de desarrollo local diario con Docker instalado en tu máquina. SIEMPRE usar Docker Compose Support Estandariza los contenedores del equipo, arranca todo con un solo clic y elimina URLs fijas.
Despliegues en producción (Kubernetes, AWS ECS) o integración continua (CI/CD). Desactivar en CI/Producción En producción la base de datos es un clúster gestionado (AWS RDS), no un contenedor Docker local efímero.

4. Dependencias Necesarias (Spring Boot 3.1+)


<!-- Starter oficial de Docker Compose en pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-docker-compose</artifactId>
    <scope>runtime</scope>
    <optional>true</optional>
</dependency>


// Gradle (build.gradle)
dependencies {
    developmentOnly 'org.springframework.boot:spring-boot-docker-compose'
}

5. Ejemplo Completo: Archivo compose.yaml en la Raíz del Proyecto

Basta con crear un archivo llamado compose.yaml en la carpeta raíz del proyecto Java: 


services:
  # 1. Base de datos PostgreSQL
  postgres:
    image: 'postgres:16-alpine'
    environment:
      - 'POSTGRES_DB=petshop_db'
      - 'POSTGRES_USER=pet_user'
      - 'POSTGRES_PASSWORD=secret_pass'
    ports:
      - '5432:5432'

  # 2. Caché en memoria Redis
  redis:
    image: 'redis:7-alpine'
    ports:
      - '6379:6379'

  # 3. Servidor de Trazabilidad Zipkin
  zipkin:
    image: 'openzipkin/zipkin:latest'
    ports:
      - '9411:9411'

6. Configuración de Comportamiento en application.yml


spring:
  docker:
    compose:
      enabled: true
      file: compose.yaml
      # Opciones de ciclo de vida:
      # start-and-stop: Arranca contenedores al iniciar y los detiene al apagar la app
      # start-only: Arranca contenedores pero los deja corriendo al apagar la app (ahorra tiempo en reinicios)
      lifecycle-management: start-and-stop
      readiness:
        tcp:
          read-timeout: 20000ms

7. Contraejemplo: Hardcodear URLs y Credenciales en application.yml


# ANTIPATRÓN: Redundancia manual innecesaria en Spring Boot 3.1+
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/petshop_db # ¡INNECESARIO!
    username: pet_user # ¡INNECESARIO!
    password: secret_pass # ¡INNECESARIO!

Solución con Docker Compose Support: Eliminar completamente las propiedades spring.datasource.url, username y password de application.yml. Spring Boot las extrae dinámicamente de las variables de entorno de compose.yaml a través del sistema unificado ConnectionDetails.
