Spring Web: Desarrollo de APIs REST y Aplicaciones Web (Spring MVC)

1. ¿Qué es y para qué sirve?

Spring Web (starter spring-boot-starter-web en Spring Initializr) es el núcleo fundamental sobre el que se construyen la inmensa mayoría de microservicios y APIs REST empresariales en Java.

Empaqueta y autoconfigura automáticamente:

  • Spring MVC: El framework web basado en el patrón Modelo-Vista-Controlador y el servlet frontal DispatcherServlet.
  • Servidor Embebido Apache Tomcat: Servidor web de producción preconfigurado que arranca en milisegundos sin requerir instalaciones externas ni despliegues en servidores de aplicaciones pesados (como WebLogic o JBoss).
  • Jackson: El motor estándar de serialización y deserialización que traduce automáticamente objetos Java a JSON y viceversa.
  • Soporte REST completo: Negociación de contenido (Content Negotiation), filtros HTTP, interceptores y conversión de parámetros.

Analogía del mundo real

Imaginemos un aeropuerto internacional moderno:

  • El Servidor Tomcat Embebido son las pistas de aterrizaje y las puertas de embarque físicas que reciben los aviones (conexiones TCP/HTTP).
  • El DispatcherServlet es la torre de control y el panel central de llegadas: cada pasajero (petición HTTP entrante) es recibido, se comprueba su billete y se le asigna la cinta transportadora o mostrador exacto que debe atenderle.
  • Los Controladores (@RestController) son los mostradores de aduanas o tiendas duty-free específicos que realizan la transacción requerida y entregan el equipaje (el payload JSON de respuesta).
  • Jackson es el traductor universal jurado que traduce el pasaporte del viajero de cualquier idioma al formato oficial estándar.

2. Caso de Uso Real Estructurado

1. Contexto

Una plataforma de telemedicina veterinaria expone endpoints REST para que aplicaciones móviles de clientes y clínicas asociadas gestionen citas, historiales médicos y prescripciones.

2. El Problema (Sin Spring Web)

Escribir Servlets puros de Java (HttpServlet) obliga a parsear manualmente cadenas de texto del BufferedReader, convertir JSON a mano con bibliotecas de bajo nivel, mapear manualmente códigos de estado HTTP y desplegar pesados archivos .war en servidores externos.

3. La Solución (Con Spring Web)

Con solo anotar una clase con @RestController, Spring resuelve rutas, valida payloads entrantes y devuelve objetos tipados como ResponseEntity<T> que se serializan automáticamente a JSON, ejecutándose como un ejecutable independiente (java -jar app.jar).

3. ¿Cuándo usarlo y cuándo NO usarlo?

Escenario Recomendación Justificación Técnica
APIs REST estándar, microservicios empresariales de propósito general y operaciones CRUD con bases de datos relacionales tradicionales. SIEMPRE usar Spring Web Es el estándar más maduro, estable, fácil de depurar y con mayor compatibilidad de librerías del ecosistema Java.
Sistemas con cientos de miles de conexiones abiertas permanentes (IoT, chats masivos en tiempo real o streaming continuo). NO usar Spring Web (Usar Spring WebFlux) Spring Web asigna un hilo por petición (modelo Tomcat bloqueante); bajo 50.000 conexiones concurrentes los hilos colapsan la memoria del sistema operativo.

5. Anotaciones Fundamentales de Spring Web

Anotación Paquete Propósito y Comportamiento
@RestController org.springframework.web.bind.annotation Anotación compuesta que une @Controller y @ResponseBody. Marca la clase como controladora REST, haciendo que cada método devuelva datos directamente al cuerpo de la respuesta HTTP en JSON.
@RequestMapping("/path") org.springframework.web.bind.annotation Define la ruta base común para todos los endpoints expuestos dentro de la clase de controlador.
@GetMapping, @PostMapping, etc. org.springframework.web.bind.annotation Atajos específicos de método HTTP (GET, POST, PUT, PATCH, DELETE).
@PathVariable org.springframework.web.bind.annotation Extrae una variable de segmento dinámico dentro de la URL (ej. /petshop/pet/{id}).
@RequestParam org.springframework.web.bind.annotation Extrae parámetros de consulta (query params) de la URL (ej. /petshop/pet?species=dog&age=3).
@RequestBody org.springframework.web.bind.annotation Indica a Jackson que deserialice el cuerpo JSON de la petición HTTP entrante hacia el objeto Java indicado.

6. Ejemplo Completo: Controlador REST Profesional con Spring Web y Lombok


package com.example.petshop.controller;

import com.example.petshop.dto.PetDTO;
import com.example.petshop.service.PetService;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.http.HttpStatus;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.servlet.support.ServletUriComponentsBuilder;

import java.net.URI;
import java.util.List;

@Slf4j
@RestController
@RequestMapping("/api/v1/pets")
@RequiredArgsConstructor
public class PetWebController {

    private final PetService petService;

    // 1. GET con parámetro de ruta (Path Variable)
    @GetMapping(value = "/{id}", produces = MediaType.APPLICATION_JSON_VALUE)
    public ResponseEntity<PetDTO> getPetById(@PathVariable Integer id) {
        log.info("Recibida petición GET para mascota con ID: {}", id);
        return ResponseEntity.ok(petService.findById(id));
    }

    // 2. GET con parámetros de consulta opcionales (Query Params)
    @GetMapping(produces = MediaType.APPLICATION_JSON_VALUE)
    public ResponseEntity<List<PetDTO>> searchPets(
            @RequestParam(required = false) String species,
            @RequestParam(defaultValue = "0") int page,
            @RequestParam(defaultValue = "10") int size) {
        
        log.info("Buscando mascotas por especie '{}', página {}, tamaño {}", species, page, size);
        return ResponseEntity.ok(petService.searchPets(species, page, size));
    }

    // 3. POST para creación de recursos con cabecera Location
    @PostMapping(consumes = MediaType.APPLICATION_JSON_VALUE, produces = MediaType.APPLICATION_JSON_VALUE)
    public ResponseEntity<PetDTO> createPet(@RequestBody PetDTO inputDto) {
        log.info("Creando nueva mascota: {}", inputDto.getName());
        PetDTO created = petService.registerPet(inputDto);

        URI location = ServletUriComponentsBuilder.fromCurrentRequest()
                .path("/{id}")
                .buildAndExpand(created.getId())
                .toUri();

        return ResponseEntity.created(location).body(created);
    }
}

7. Contraejemplo y Antipatrón Frecuente

Contraejemplo: Devolver códigos HTTP 200 OK con mensajes de error incrustados


// ANTIPATRÓN CATASTRÓFICO: Ocultar errores bajo 200 OK
@GetMapping("/bad-pet/{id}")
public ResponseEntity<String> getBadPet(@PathVariable Integer id) {
    if (id <= 0) {
        // ERROR GRAVE: Devuelve HTTP 200 OK pero con un texto de error.
        // Los balanceadores, clientes REST y sistemas de monitorización creerán que la llamada tuvo éxito.
        return ResponseEntity.ok("Error: El ID debe ser positivo"); 
    }
    return ResponseEntity.ok("Mascota encontrada");
}

Solución: Utilizar siempre el código de estado HTTP semántico adecuado (400 BAD_REQUEST, 404 NOT_FOUND, 500 INTERNAL_SERVER_ERROR) a través de excepciones gestionadas centralizadamente con @RestControllerAdvice.
