Documentación de APIs con Springdoc OpenAPI 3 y Swagger UI

1. ¿Qué es y para qué sirve?

Una API REST sin documentación viva y ejecutable es prácticamente inútil para los desarrolladores frontend, equipos móviles o microservicios que necesitan integrarse con ella.

Springdoc OpenAPI (starter springdoc-openapi-starter-webmvc-ui) es la biblioteca oficial recomendada para generar automáticamente la especificación OpenAPI 3 y la interfaz interactiva Swagger UI en aplicaciones Spring Boot 3.x, actuando como el sucesor moderno del descontinuado SpringFox.

  • Generación Automática: Analiza las anotaciones de Spring MVC (@RestController, @GetMapping, @RequestParam, @RequestBody) y las restricciones de Bean Validation (@NotNull, @Size) para deducir el contrato de la API sin esfuerzo manual.
  • Swagger UI Integrado: Proporciona una interfaz web interactiva en /swagger-ui.html donde cualquier usuario puede consultar los endpoints y probar peticiones en vivo (*"Try it out"*).
  • Especificación JSON/YAML: Expone la especificación estándar OpenAPI 3 en /v3/api-docs para importar en Postman o herramientas de integración continua.

Analogía del mundo real

Imaginemos un restaurante gourmet internacional:

  • Sin Springdoc, es como un restaurante sin carta donde el cliente debe adivinar qué platos cocina el chef, qué ingredientes llevan y cuánto cuestan preguntando uno por uno.
  • Con Springdoc OpenAPI y Swagger UI, cada mesa dispone de una tablet interactiva con la carta completa en varios idiomas, fotografías de los platos, alérgenos obligatorios señalados y un botón para pedir una muestra y probarla de inmediato.

2. Caso de Uso Real Estructurado

1. Contexto

Una API de gestión de mascotas es consumida por desarrolladores de apps móviles iOS/Android y pasarelas de pago de terceros.

2. El Problema (Documentación manual)

La documentación se mantiene a mano en un documento Word o Confluence. Tras cada despliegue, los endpoints cambian, los parámetros se renombran y el documento queda obsoleto, provocando horas de llamadas y bugs en el equipo de frontend.

3. La Solución (Con Springdoc OpenAPI)

La documentación se genera en tiempo real a partir del propio código compilado. Si un parámetro se renombra en Java, Swagger UI se actualiza al instante con total fidelidad.

3. ¿Cuándo usarlo y cuándo NO usarlo?

Escenario Recomendación Motivo
Cualquier API REST pública o interna consumida por frontends u otros equipos. SIEMPRE usar Springdoc OpenAPI Ahorra cientos de horas de soporte y asegura que la documentación nunca se desincronice.
Microservicios de procesamiento interno orientados puramente a colas (Kafka/RabbitMQ) sin puertos HTTP expuestos. NO es necesario No aportan valor visual si el microservicio no expone endpoints REST a clientes externos.

5. Anotaciones Principales de OpenAPI 3

Anotación Paquete Propósito y Uso
@Tag(name = "...", description = "...") io.swagger.v3.oas.annotations.tags Agrupa los endpoints en Swagger UI bajo una categoría temática (ej. "Mascotas", "Adopciones").
@Operation(summary = "...", description = "...") io.swagger.v3.oas.annotations Describe la acción que realiza el método REST y su comportamiento detallado.
@ApiResponse / @ApiResponses io.swagger.v3.oas.annotations.responses Documenta los códigos de respuesta HTTP posibles (200, 201, 400, 404, 500) y el esquema del cuerpo devuelto.
@Parameter(description = "...", example = "...") io.swagger.v3.oas.annotations Añade descripciones legibles y ejemplos a variables de ruta o query params.
@Schema(description = "...", example = "...") io.swagger.v3.oas.annotations.media Se coloca en los campos de los DTOs para indicar descripción, valores de ejemplo y formatos.

6. Ejemplo Completo: Controlador Documentado con Soporte de Seguridad JWT

A. Configuración Global de OpenAPI (Bean OpenAPI)


package com.example.petshop.config;

import io.swagger.v3.oas.models.Components;
import io.swagger.v3.oas.models.OpenAPI;
import io.swagger.v3.oas.models.info.Contact;
import io.swagger.v3.oas.models.info.Info;
import io.swagger.v3.oas.models.security.SecurityRequirement;
import io.swagger.v3.oas.models.security.SecurityScheme;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class OpenApiConfig {

    @Bean
    public OpenAPI customOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("PetShop Enterprise REST API")
                        .version("1.0.0")
                        .description("API REST oficial para la gestión integral de mascotas y adopciones")
                        .contact(new Contact().name("Soporte Técnico").email("soporte@petshop.com")))
                // Configuración de autenticación JWT Bearer en Swagger UI
                .addSecurityItem(new SecurityRequirement().addList("BearerAuth"))
                .components(new Components().addSecuritySchemes("BearerAuth",
                        new SecurityScheme()
                                .name("BearerAuth")
                                .type(SecurityScheme.Type.HTTP)
                                .scheme("bearer")
                                .bearerFormat("JWT")));
    }
}

B. Controlador REST Anotado con OpenAPI 3 y Lombok


package com.example.petshop.controller;

import com.example.petshop.dto.ErrorResponseDTO;
import com.example.petshop.dto.PetDTO;
import com.example.petshop.service.PetService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.media.Content;
import io.swagger.v3.oas.annotations.media.Schema;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import io.swagger.v3.oas.annotations.responses.ApiResponses;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/v1/pets")
@RequiredArgsConstructor
@Tag(name = "Mascotas", description = "Endpoints de gestión y consulta del catálogo de mascotas")
public class PetDocumentedController {

    private final PetService petService;

    @Operation(summary = "Obtener mascota por ID", description = "Devuelve los detalles de una mascota existente a partir de su identificador numérico")
    @ApiResponses(value = {
            @ApiResponse(responseCode = "200", description = "Mascota encontrada con éxito",
                    content = @Content(mediaType = "application/json", schema = @Schema(implementation = PetDTO.class))),
            @ApiResponse(responseCode = "404", description = "No existe ninguna mascota con el ID solicitado",
                    content = @Content(mediaType = "application/json", schema = @Schema(implementation = ErrorResponseDTO.class))),
            @ApiResponse(responseCode = "500", description = "Error interno no controlado en el servidor",
                    content = @Content(mediaType = "application/json", schema = @Schema(implementation = ErrorResponseDTO.class)))
    })
    @GetMapping("/{id}")
    public ResponseEntity<PetDTO> getPetById(
            @Parameter(description = "Identificador único de la mascota", example = "1", required = true)
            @PathVariable Integer id) {
        return ResponseEntity.ok(petService.findById(id));
    }
}

7. Contraejemplo y Error Común: Usar el Deprecado SpringFox en Spring Boot 3


<!-- ANTIPATRÓN: Dependencia obsoleta incompatible con Spring Boot 3 -->
<dependency>
    <groupId>io.springfox</groupId>
    <artifactId>springfox-boot-starter</artifactId>
    <version>3.0.0</version>
    <!-- FALLO DE ARRANQUE: Provoca NullPointerException y PatternParseException en Spring Boot 3 -->
</dependency>

Solución: Migrar siempre a org.springdoc:springdoc-openapi-starter-webmvc-ui, el estándar oficial para Spring Boot 3.
