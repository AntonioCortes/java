Introducción a Spring Cloud

Spring Cloud es un meta-framework y conjunto de herramientas diseñado sobre Spring Boot que proporciona patrones de arquitectura estandarizados para el desarrollo y despliegue de sistemas distribuidos y microservicios.

Al migrar de un monolito a una arquitectura distribuida, surgen desafíos inevitables de computación distribuida: cómo descubrir dinámicamente dónde se ejecutan las instancias de cada servicio, cómo coordinar la configuración común sin reiniciar aplicaciones, cómo enrutar el tráfico entrante desde un único punto perimetral y cómo evitar que la caída de un servicio secundario derribe en cascada todo el sistema. Spring Cloud proporciona soluciones probadas y nativas en Java para cada uno de estos retos.

Analogía del Mundo Real: La Red de Ciudades y Servicios de Emergencia

Imagina un pequeño pueblo donde todas las tiendas, médicos y talleres están en una misma plaza (el Monolito). Si necesitas un veterinario, simplemente cruzas la calle. Todo es directo, pero si la plaza se inunda o se corta la luz central, todo el pueblo se paraliza.

Al crecer y convertirse en una metrópoli con múltiples distritos autónomos (los Microservicios):

  • Necesitas una Guía Telefónica y Central de Registro Dinámico (Eureka Server) para saber qué ambulancia o clínica veterinaria está de guardia y en qué calle exacta se encuentra hoy.
  • Necesitas un Control Perimetral y Accesos Principales (API Gateway) en las autopistas de entrada a la ciudad para filtrar y dirigir a los visitantes al distrito correcto según su destino.
  • Necesitas una Radio y Cuadro Central de Avisos (Config Server) para cambiar los límites de velocidad o protocolos en todos los distritos a la vez sin tener que enviar un mensajero en moto a cada casa.
  • Necesitas Cortafuegos y Válvulas de Seguridad (Circuit Breakers con Resilience4j) para que si el túnel hacia el distrito financiero sufre un atasco, los autobuses tomen rutas alternativas sin bloquear la circunvalación completa.

Caso de Uso Real Estructurado

1. Contexto

La plataforma PetStore ha crecido a 8 microservicios independientes: pet-service, order-service, customer-service, billing-service, etc., desplegados en múltiples réplicas en la nube con escalado elástico.

2. El Problema (Sin Spring Cloud)

Las URLs y puertos (ej. http://10.0.1.15:8081) están escritos a fuego en archivos locales. Cuando un contenedor cambia de IP en Kubernetes o Docker, los demás microservicios fallan con errores de conexión. La caída de un servicio satura los hilos de los demás en cascada y no hay forma de trazar por qué una petición tardó 4 segundos.

3. La Solución (Con Spring Cloud)

Los microservicios se auto-registran dinámicamente en Eureka por nombre lógico. OpenFeign se comunica mediante llamadas declarativas transparentes con balanceo en cliente, el API Gateway centraliza la seguridad y los cortafuegos de Resilience4j aíslan los fallos.

¿Cuándo usarlo y cuándo NO usarlo?

Estrategia de Arquitectura ¿Cuándo usarlo? ¿Cuándo NO usarlo?
Spring Cloud (Microservicios) Aplicaciones medianas o grandes con múltiples equipos independientes, necesidades de escalado diferenciado por servicio (ej. muchas más consultas de mascotas que registros de pedidos) y despliegues desacoplados continuos. Proyectos pequeños, MVPs o equipos reducidos: la sobrecarga operacional (red, monitorización, latencia entre servicios, transacciones distribuidas) supera ampliamente los beneficios.
Monolito Modular con Spring Boot Sistemas iniciales, aplicaciones empresariales con dominio fuertemente acoplado o cuando se busca máxima simplicidad operativa y rendimiento de memoria sin latencia de red inter-proceso. Cuando diferentes módulos del sistema exigen tecnologías, escalados de hardware o ciclos de despliegue independientes.
Service Mesh (Istio / Linkerd) Ecosistemas políglotas gigantescos (mezcla de Java, Go, Python, Node.js) donde el balanceo, cifrado mTLS y trazabilidad deben residir en la infraestructura de red mediante sidecars en lugar de en librerías de aplicación. Arquitecturas centradas principalmente en Java / Spring Boot, donde Spring Cloud ofrece una integración mucho más natural, tipada y fácil de depurar en código.

Gestión de Versiones: El BOM (Release Train)

Dado que Spring Cloud está compuesto por decenas de proyectos independientes (Eureka, Gateway, OpenFeign, Config, CircuitBreaker), Spring utiliza un BOM (Bill of Materials) con nombres temáticos de hitos o versiones coordinadas (ej. Spring Cloud 2023.0.x, antes conocidas como Hoxton, Kilimanjaro, etc.) para garantizar la compatibilidad exacta entre versiones de starters:

Maven (pom.xml)


<!-- Gestión centralizada de versiones con el BOM de Spring Cloud -->
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-dependencies</artifactId>
            <version>2023.0.3</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

Gradle (build.gradle)


plugins {
    id 'io.spring.dependency-management' version '1.1.5'
}

dependencyManagement {
    imports {
        mavenBom 'org.springframework.cloud:spring-cloud-dependencies:2023.0.3'
    }
}

Spring Cloud Gateway «API Gateway reactivo» Punto único de entrada perimetral. Enruta peticiones externas, aplica seguridad, CORS y control de tasa (rate limiting).

Resilience4j «cortafuegos / circuit breaker» Aísla fallos de servicios caídos o lentos, cortando el tráfico y ejecutando métodos alternativos de respaldo (fallback).
Micrometer Tracing + Zipkin «telemetría distribuida» Inyecta identificadores globales (traceId) para rastrear el ciclo de vida y latencia de cada petición a través de todos los microservicios.

Catálogo de Módulos Principales

  • Spring Cloud Netflix Eureka: Registro y descubrimiento dinámico de instancias en tiempo real.
  • Spring Cloud OpenFeign: Generación automática de clientes REST a partir de interfaces anotadas.
  • Spring Cloud LoadBalancer: Algoritmos reactivos de reparto de carga en el lado cliente (Round-Robin, Random).
  • Spring Cloud Gateway: Enrutador perimetral de alto rendimiento basado en Spring WebFlux y Project Reactor.
  • Spring Cloud CircuitBreaker / Resilience4j: Resiliencia, reintentos inteligentes, limitación de concurrencia y tolerancia a particiones.
  • Spring Cloud Config: Servidor centralizado de configuración versionado mediante Git, Vault o base de datos.

Ejemplo vs Contraejemplo

Contraejemplo: Microservicios Rígidos con Acoplamiento por IP (Antipatrón)


// ANTIPATRÓN: Acoplar microservicios a direcciones IP y puertos estáticos sin descubrimiento ni balanceo
@Service
public class BadRemoteOrderService {

    private final RestTemplate restTemplate = new RestTemplate();

    public PetDTO getPet(Integer petId) {
        // ERROR GRAVE 1: IP y puerto fijos. Si el pod o contenedor escala o cambia de nodo, falla.
        // ERROR GRAVE 2: Sin balanceo de carga ni comprobación de salud.
        // ERROR GRAVE 3: Sin timeout ni circuit breaker. Si pet-service se congela, bloquea el hilo indefinidamente.
        String url = "http://192.168.1.150:8081/petshop/pet/" + petId;
        return restTemplate.getForObject(url, PetDTO.class);
    }
}

Ejemplo: Cliente Declarativo con Descubrimiento y Balanceo en Spring Cloud


// BUENA PRÁCTICA: Invocación por nombre de servicio registrado en Eureka con balanceo automático
@FeignClient(name = "PET-SERVICE", fallback = PetClientFallback.class)
public interface PetClient {

    @GetMapping("/petshop/pet/{id}")
    PetDTO getPetById(@PathVariable("id") Integer id);
