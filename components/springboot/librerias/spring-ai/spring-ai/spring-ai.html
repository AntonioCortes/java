Spring AI: Integración con Modelos de Lenguaje (LLMs) y Bases Vectoriales

1. ¿Qué es y para qué sirve?

Spring AI es el proyecto oficial del ecosistema Spring diseñado para aplicar los principios de diseño de Spring (portabilidad, inversión de control y abstracción de bajo acoplamiento) al desarrollo de aplicaciones con Inteligencia Artificial Generativa y Modelos de Lenguaje (LLMs).

En lugar de acoplarse rígidamente al SDK propietario de un único proveedor en Python o Java, Spring AI proporciona una capa de abstracción unificada intercambiable:

  • Abstracción Portable de Modelos (ChatModel / ChatClient): Permite escribir código una sola vez y cambiar de proveedor de LLM (OpenAI GPT-4, Anthropic Claude, Azure OpenAI, Google Vertex AI o modelos locales con Ollama como Llama 3 o Mistral) cambiando únicamente una propiedad en application.yml.
  • Salidas Fuertemente Tipadas (Structured Outputs): Mediante BeanOutputConverter<T>, Spring AI garantiza que la respuesta en lenguaje natural generada por la IA se valide y transforme automáticamente en un objeto Java tipado (DTO o Record) con validaciones de campos.
  • RAG (Retrieval-Augmented Generation) y Bases Vectoriales: Interfaz VectorStore para almacenar y buscar vectores de similitud (*embeddings*) en motores como PostgreSQL con PGVector, Redis o Chroma, permitiendo a la IA responder preguntas sobre documentos privados de la empresa.

Analogía del mundo real

Imaginemos un equipo de traductores simultáneos de la ONU:

  • Sin Spring AI, tendrías que contratar a un intérprete que solo habla un dialecto concreto de Python y reprogramar toda tu empresa cada vez que quieres probar a un traductor diferente.
  • Con Spring AI (ChatClient), tienes una cabina de traducción con auriculares estandarizados: puedes sentar en la silla a un experto de OpenAI o a un modelo privado que corre en tu propio servidor local con Ollama. El mensaje que envías y el formulario estructurado que recibes en Java son siempre idénticos.

2. Caso de Uso Real Estructurado

1. Contexto

Una tienda de mascotas online desea ofrecer un asistente virtual veterinario que recomiende alimentos y cuidados según la raza, edad y peso de la mascota.

2. El Problema (Llamadas HTTP directas a OpenAI)

El desarrollador concatena cadenas JSON enviadas con RestTemplate a la API de OpenAI. La IA a veces responde con texto libre, otras veces con Markdown o formato inválido, provocando excepciones de parseo continuas en el backend Java.

3. La Solución (Con Spring AI ChatClient)

Se utiliza ChatClient con entity(PetDietAdviceDTO.class). Spring AI instruye al modelo en el prompt para que devuelva un esquema JSON estricto y lo mapea automáticamente al DTO tipado con cero fallos de parseo.

3. ¿Cuándo usar Spring AI y cuándo NO usarlo?

Escenario Recomendación Motivo
Generación de resúmenes, extracción de datos estructurados, categorización automática de incidencias y chatbots RAG corporativos. SIEMPRE usar Spring AI Aísla el backend de cambios en APIs de terceros, soporta modelos locales privados con Ollama y ofrece salidas tipadas en Java.
Cálculos matemáticos deterministas de alta precisión (cálculo de nóminas, impuestos o saldos bancarios). NO usar LLMs Los modelos de lenguaje son probabilísticos y pueden sufrir alucinaciones; la lógica contable debe ser código Java tradicional.

        <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
    </dependency>

// Gradle (build.gradle)
dependencies {
    implementation platform('org.springframework.ai:spring-ai-bom:1.0.0-M1')
    implementation 'org.springframework.ai:spring-ai-openai-spring-boot-starter'
}

6. Ejemplo Completo: Asistente Veterinario con Salida Estructurada (ChatClient)

A. DTO de Salida Estructurada

import java.util.List;

public record PetDietAdviceDTO(
        String petName,
        String recommendedFoodType,
        int dailyPortionGrams,
        List<String> tips,
        boolean requiresVeterinaryCheck
) {}

B. Servicio con ChatClient


package com.example.petshop.service.ai;

import com.example.petshop.dto.ai.PetDietAdviceDTO;
import lombok.extern.slf4j.Slf4j;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

@Slf4j
@Service
public class PetAiAdvisoryService {

    private final ChatClient chatClient;

    public PetAiAdvisoryService(ChatClient.Builder chatClientBuilder) {
        this.chatClient = chatClientBuilder
                .defaultSystem("Eres un asistente veterinario experto. Responde siempre con profesionalidad y rigor.")
                .build();
    }

    public PetDietAdviceDTO generateDietPlan(String name, String species, int ageYears, double weightKg) {
        log.info("Generando plan nutricional con IA para {} ({} de {} años, {} kg)", 
                name, species, ageYears, weightKg);

        return chatClient.prompt()
                .user(u -> u.text("Calcula el plan dietético para la mascota con los siguientes datos: " +
                        "Nombre: {name}, Especie: {species}, Edad: {age} años, Peso: {weight} kg")
                        .param("name", name)
                        .param("species", species)
                        .param("age", ageYears)
                        .param("weight", weightKg))
                // Spring AI instruye al modelo para generar JSON y lo deserializa automáticamente
                .call()
                .entity(PetDietAdviceDTO.class);
    }
}

7. Contraejemplo: Hardcodear la API Key en el Código o en application.yml


# ANTIPATRÓN DE SEGURIDAD CRÍTICO:
spring:
  ai:
    openai:
      api-key: sk-proj-1234567890abcdef... # ¡PROHIBIDO! Fuga de credenciales en GitHub

Solución: Utilizar siempre variables de entorno inyectadas en tiempo de ejecución (api-key: ${OPENAI_API_KEY}) gestionadas mediante secretos en Docker, Kubernetes o gestores como AWS Secrets Manager.
