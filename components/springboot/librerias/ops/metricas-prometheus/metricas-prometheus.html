Prometheus y Micrometer: Métricas Operativas y Monitorización en Grafana

1. ¿Qué son y para qué sirven?

En la monitorización de microservicios, el estándar de la industria combina Prometheus (un servidor de recolección y base de datos de series temporales basada en un modelo de scraping periódico) y Grafana (la plataforma visual para dashboards y alertas en tiempo real).

Para conectar Spring Boot con este ecosistema, Spring Initializr proporciona:

  • Micrometer: La fachada de métricas de aplicación para Java (el equivalente de SLF4J pero para métricas). Permite instrumentar el código una sola vez con una API unificada neutral y exportar las métricas a cualquier destino (Prometheus, Datadog, New Relic, CloudWatch).
  • Micrometer Registry Prometheus: La extensión específica que convierte las métricas internas de la JVM y de Spring Boot al formato de texto plano y sintaxis de series temporales compatible con el raspador (*scraper*) de Prometheus a través del endpoint /actuator/prometheus.

Analogía del mundo real

Imaginemos un hospital con pacientes en la UCI:

  • Los sensores corporales (electrocardiograma, pulsioxímetro, termómetro) son Micrometer: miden constantes continuas en el paciente.
  • El registrador que pasa cada 15 segundos apuntando las constantes en la ficha del paciente es Prometheus (modelo de *scraping* periódico).
  • La pantalla táctil a color con gráficos de frecuencia cardíaca y alarmas audibles si el pulso baja de 50 es Grafana.

2. Los Cuatro Tipos Fundamentales de Métricas en Micrometer

Tipo de Métrica Comportamiento Casos de Uso Típicos
Counter (Contador) Valor que únicamente puede incrementarse (o reiniciarse a cero al arrancar la aplicación). Nunca decrece. Total de adopciones completadas, total de peticiones HTTP atendidas, número de fallos de pago bancario.
Gauge (Indicador de Nivel) Valor instantáneo que puede subir y bajar con el tiempo. Refleja una fotografía del momento presente. Conexiones activas en el pool HikariCP, memoria RAM utilizada en el Heap de la JVM, número de hilos en ejecución.
Timer (Temporizador) Mide simultáneamente la duración y la frecuencia de eventos cortos, calculando percentiles (p50, p95, p99). Tiempo de respuesta de endpoints REST, latencia de consultas SQL complejas, duración de llamadas a pasarelas externas.
DistributionSummary Mide la distribución y tamaño de eventos que no son de tiempo. Tamaño en bytes de las fotos de mascotas subidas, número de productos por cesta de la compra.

4. Configuración en Spring Boot (application.yml)


management:
  endpoints:
    web:
      exposure:
        include: health, info, prometheus # Habilita /actuator/prometheus
  metrics:
    tags:
      application: ${spring.application.name:petshop-service}
      environment: production
    distribution:
      percentiles-histogram:
        http.server.requests: true # Genera histogramas para calcular percentiles p95 y p99 en Grafana

5. Ejemplo Completo: Instrumentación Personalizada con MeterRegistry y Lombok


package com.example.petshop.service;

import io.micrometer.core.instrument.Counter;
import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.Timer;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

import java.util.concurrent.TimeUnit;

@Slf4j
@Service
public class PetAdoptionMetricsService {

    private final Counter adoptionSuccessCounter;
    private final Counter adoptionFailureCounter;
    private final Timer adoptionProcessTimer;

    // Inyectamos el MeterRegistry central de Spring Boot
    public PetAdoptionMetricsService(MeterRegistry meterRegistry) {
        // 1. Contador de adopciones exitosas con etiquetas dimensionales (tags)
        this.adoptionSuccessCounter = Counter.builder("pet.adoptions.total")
                .description("Total de adopciones completadas con éxito")
                .tag("status", "success")
                .register(meterRegistry);

        // 2. Contador de adopciones fallidas
        this.adoptionFailureCounter = Counter.builder("pet.adoptions.total")
                .description("Total de adopciones fallidas")
                .tag("status", "failure")
                .register(meterRegistry);

        // 3. Temporizador para medir el tiempo total de tramitación
        this.adoptionProcessTimer = Timer.builder("pet.adoption.duration")
                .description("Tiempo empleado en procesar una solicitud de adopción")
                .publishPercentiles(0.5, 0.95, 0.99)
                .register(meterRegistry);
    }

    public void processAdoptionWithMetrics(Runnable adoptionTask) {
        long startTime = System.currentTimeMillis();
        try {
            // Ejecutamos la tarea de adopción registrando la duración
            adoptionTask.run();
            adoptionSuccessCounter.increment();
            log.info("Adopción tramitada con éxito y métrica incrementada");
        } catch (Exception e) {
            adoptionFailureCounter.increment();
            log.error("Fallo en la adopción, registrando métrica de fallo", e);
            throw e;
        } finally {
            long duration = System.currentTimeMillis() - startTime;
            adoptionProcessTimer.record(duration, TimeUnit.MILLISECONDS);
        }
    }
}

6. Contraejemplo: Diseñar Métricas con Cardinalidad Infinita (High Cardinality)


// ANTIPATRÓN CATASTRÓFICO: Usar datos de alta cardinalidad en los tags de Micrometer
public void badMetric(String userEmail, String creditCardToken) {
    // ERROR CRÍTICO: Si añades el email o ID único de cada usuario como tag,
    // Prometheus generará 1 millón de series temporales distintas en memoria.
    // Prometheus colapsará por OutOfMemory (OOM) y saturará toda la infraestructura de monitorización.
    Counter.builder("bad.logins")
            .tag("user_email", userEmail) // ¡CARDINALIDAD INFINITA PROHIBIDA!
            .register(meterRegistry)
            .increment();
}

Regla de Oro: Los tags de las métricas deben tener valores predecibles y acotados (ej. status: success|failure, method: GET|POST, region: eu-west-1), nunca valores libres como IDs de usuario, emails, tokens o UUIDs.
