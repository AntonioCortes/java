Spring Boot Actuator: Monitorización, Salud y Métricas en Producción

1. ¿Qué es y para qué sirve?

En producción, una aplicación no es una caja negra: los equipos de operaciones (DevOps / SRE) y los orquestadores como Kubernetes necesitan saber en todo momento si la aplicación sigue viva, si está lista para recibir tráfico de red, cuánta memoria RAM consume la JVM y cuál es el estado de la conexión a la base de datos.

Spring Boot Actuator (starter spring-boot-starter-actuator en Spring Initializr) es el estándar oficial que añade funcionalidades de nivel de producción a cualquier microservicio Spring Boot sin escribir código adicional:

  • Endpoints de Salud (Health Checks): El endpoint /actuator/health comprueba automáticamente el estado de la base de datos, Redis, RabbitMQ, espacio en disco y servicios externos.
  • Sondas de Kubernetes (Probes): Soporta nativamente las sondas de vida (Liveness en /actuator/health/liveness) para reiniciar contenedores colgados, y de preparación (Readiness en /actuator/health/readiness) para no enrutar tráfico hasta que las cachés y pools estén inicializados.
  • Gestión de Logs en Caliente: Mediante /actuator/loggers se puede cambiar el nivel de log de un paquete específico (ej. de INFO a DEBUG) mediante una petición HTTP POST en tiempo de ejecución sin reiniciar la aplicación.
  • Inspección y Diagnóstico: Endpoints para volcado de hilos (/actuator/threaddump) y diagnóstico de cuellos de botella.

Analogía del mundo real

Imaginemos el cuadro de mandos y la telemetría de un coche moderno:

  • El motor y las ruedas son la lógica de negocio (los controladores y servicios).
  • Actuator es el ordenador de a bordo con los testigos luminosos: te indica la temperatura del aceite, la presión de los neumáticos, el nivel de combustible y si el sistema de frenos responde. Si el ordenador detecta que el motor se sobrecalienta (falla la base de datos), enciende el testigo rojo de emergencia de inmediato para que la grúa (Kubernetes) no mande el coche a la autopista.

2. Caso de Uso Real Estructurado

1. Contexto

Un microservicio de pagos de compras veterinarias se ejecuta en un clúster de Kubernetes con auto-escalado horizontal.

2. El Problema (Sin Actuator)

La base de datos sufre una saturación y rechaza conexiones. Kubernetes no tiene forma de saberlo (el pod sigue en estado 'Running' a nivel de contenedor de Linux) y continúa enviando peticiones de clientes que fallan con errores 500 durante 30 minutos.

3. La Solución (Con Actuator)

Kubernetes sondea /actuator/health/readiness cada 5 segundos. En cuanto la BD cae, el endpoint devuelve STATUS: DOWN (HTTP 503). Kubernetes retira el pod del balanceador automáticamente en 5 segundos, evitando que los clientes perciban el fallo.

3. ¿Cuándo usar Actuator y cuándo NO usarlo?

Escenario Recomendación Motivo
Cualquier microservicio o API REST desplegado en entornos reales (Kubernetes, AWS, Docker, On-Premise). OBLIGATORIO usar Spring Boot Actuator Sin Actuator es imposible integrar las sondas de Kubernetes, Prometheus ni monitorizar la salud operativa del sistema.
Exponer todos los endpoints (management.endpoints.web.exposure.include=*) a internet sin seguridad. PELIGRO MORTAL: NUNCA hacer esto Expone endpoints como /env o /heapdump que filtran contraseñas, variables de entorno y datos sensibles en memoria a atacantes.

4. Dependencias Necesarias (Maven y Gradle)


<!-- Starter oficial de Spring Boot Actuator en pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>


// Gradle (build.gradle)
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-actuator'
}

5. Configuración Segura en Producción (application.yml)


management:
  server:
    port: 8081 # Separar el puerto de administración del puerto de la API pública (8080)
  endpoints:
    web:
      base-path: /actuator
      exposure:
        # Exponer únicamente los endpoints imprescindibles
        include: health, info, metrics, prometheus
  endpoint:
    health:
      show-details: when_authorized # Solo muestra detalles técnicos a usuarios autenticados
      probes:
        enabled: true # Habilita las sondas nativas de Kubernetes (/liveness y /readiness)
  info:
    env:
      enabled: true
    git:
      mode: full

6. Creación de un Indicador de Salud Personalizado (Custom HealthIndicator)

Podemos crear indicadores personalizados para verificar la disponibilidad de sistemas externos propietarios (como un validador de microchips o un servicio de pasarela de vacunas): 


package com.example.petshop.health;

import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.boot.actuate.health.Health;
import org.springframework.boot.actuate.health.HealthIndicator;
import org.springframework.stereotype.Component;

@Slf4j
@Component
@RequiredArgsConstructor
public class ExternalPetRegistryHealthIndicator implements HealthIndicator {

    @Override
    public Health health() {
        boolean isRegistryUp = checkExternalRegistry();

        if (isRegistryUp) {
            return Health.up()
                    .withDetail("service", "Registro Central de Microchips")
                    .withDetail("responseTimeMs", 42)
                    .build();
        }

        return Health.down()
                .withDetail("service", "Registro Central de Microchips")
                .withDetail("error", "Timeout de conexión tras 3000 ms")
                .build();
    }

    private boolean checkExternalRegistry() {
        // Lógica de comprobación de ping HTTP o socket
        return true;
    }
}

7. Contraejemplo y Fuga de Seguridad Grave (CWE-200)


# ANTIPATRÓN CATASTRÓFICO DE SEGURIDAD EN PRODUCCIÓN:
management:
  endpoints:
    web:
      exposure:
        include: "*" # ¡PELIGRO CRÍTICO! Expone /actuator/env y /actuator/heapdump públicamente

Impacto de Seguridad: Cualquier usuario externo que navegue a /actuator/env podrá leer las claves de acceso a la base de datos, API Keys de AWS y tokens secretos de la aplicación. Mantener siempre una lista blanca estricta (health, info, prometheus) y aislar el puerto de administración.
