Spring Data: Auditoría Automática y Gestión de Transacciones (@Transactional)

1. Auditoría Automática en Persistencia

En aplicaciones reguladas o entornos de producción es imperativo auditar el ciclo de vida de los datos: saber cuándo se insertó o modificó un registro y quién fue el usuario responsable. Spring Data proporciona un framework de auditoría transparente que rellena estos campos de forma automática antes de persistir o actualizar entidades en la base de datos.

Anotaciones de Auditoría

  • @CreatedDate: Inyecta la marca de tiempo (Instant o LocalDateTime) al ejecutar la inserción inicial.
  • @LastModifiedDate: Actualiza la marca de tiempo en cada operación de guardado o actualización.
  • @CreatedBy: Inyecta el identificador o username del usuario que creó el registro.
  • @LastModifiedBy: Inyecta el identificador del usuario que realizó la última mutación.

2. Gestión de Transacciones con @Transactional

La anotación @Transactional de Spring gestiona la demarcación de transacciones automáticas mediante Proxies dinámicos de Spring AOP.

2.1. La Importancia de readOnly = true

Anotar los métodos de consulta con @Transactional(readOnly = true) en la capa de servicio:

  • En JPA / Hibernate: Desactiva el mecanismo de Dirty Checking (Hibernate no compara el estado de los objetos contra la base de datos al finalizar la transacción) y no mantiene copias en el contexto de persistencia, reduciendo sustancialmente el consumo de memoria JVM. Además, en bases de datos relacionales orientadas a réplicas, permite redirigir la consulta al nodo de solo lectura (Read Replica).
  • En MongoDB: Informa al driver para optimizar la sesión si se ejecuta dentro de un Replica Set transaccional.

2.2. Parámetros Críticos de @Transactional

  • rollbackFor = Exception.class: Por defecto, Spring únicamente revierte transacciones ante excepciones no comprobadas (RuntimeException y Error). Si el método lanza una excepción comprobada (ej. IOException o una excepción personalizada que herede de Exception), la transacción hace commit a menos que se configure explícitamente rollbackFor = Exception.class.
  • propagation = Propagation.REQUIRED (por defecto): Si ya existe una transacción activa en el hilo actual, se une a ella; si no, crea una nueva.
  • propagation = Propagation.REQUIRES_NEW: Suspende la transacción actual y crea una transacción independiente en una conexión física separada (ideal para registrar logs de auditoría que deben persistir incluso si la transacción principal falla).
---

3. Ejemplos Prácticos Completos y Simétricos

3.1. Persistencia Relacional: PostgreSQL / Oracle (Spring Data JPA)

1. Clase Base Auditable (@MappedSuperclass):


package com.example.petshop.model.relational;

import jakarta.persistence.Column;
import jakarta.persistence.EntityListeners;
import jakarta.persistence.MappedSuperclass;
import lombok.Getter;
import lombok.Setter;
import org.springframework.data.annotation.CreatedBy;
import org.springframework.data.annotation.CreatedDate;
import org.springframework.data.annotation.LastModifiedBy;
import org.springframework.data.annotation.LastModifiedDate;
import org.springframework.data.jpa.domain.support.AuditingEntityListener;

import java.time.Instant;

@Getter
@Setter
@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class AuditableEntity {

    @CreatedDate
    @Column(name = "created_date", nullable = false, updatable = false)
    private Instant createdDate;

    @LastModifiedDate
    @Column(name = "last_modified_date")
    private Instant lastModifiedDate;

    @CreatedBy
    @Column(name = "created_by", nullable = false, updatable = false, length = 50)
    private String createdBy;

    @LastModifiedBy
    @Column(name = "last_modified_by", length = 50)
    private String lastModifiedBy;
}

2. Configuración con AuditorAware:


package com.example.petshop.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.domain.AuditorAware;
import org.springframework.data.jpa.repository.config.EnableJpaAuditing;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;

import java.util.Optional;

@Configuration
@EnableJpaAuditing(auditorAwareRef = "auditorProvider")
public class JpaAuditingConfig {

    @Bean
    public AuditorAware<String> auditorProvider() {
        return () -> Optional.ofNullable(SecurityContextHolder.getContext().getAuthentication())
                .filter(Authentication::isAuthenticated)
                .map(Authentication::getName)
                .or(() -> Optional.of("SYSTEM"));
    }
}

3. Servicio Transaccional de Negocio:


package com.example.petshop.service.relational;

import com.example.petshop.model.relational.PetEntity;
import com.example.petshop.repository.relational.PetJpaRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Slf4j
@RequiredArgsConstructor
@Service
public class PetTransactionalJpaService {

    private final PetJpaRepository petRepository;

    // Consulta optimizada: Sin Dirty Checking y menor consumo de memoria
    @Transactional(readOnly = true)
    public PetEntity getPetById(Long id) {
        log.info("Consultando mascota con ID: {}", id);
        return petRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("Mascota no encontrada con id: " + id));
    }

    // Mutación con rollback ante cualquier excepción
    @Transactional(rollbackFor = Exception.class)
    public PetEntity updateVaccinationStatus(Long id, boolean vaccinated) {
        log.info("Actualizando estado de vacunación de mascota ID {} a {}", id, vaccinated);
        PetEntity pet = getPetById(id);
        pet.setVaccinated(vaccinated);
        return petRepository.save(pet);
    }
}

3.2. Persistencia Documental: MongoDB (Spring Data MongoDB)

1. Configuración de Auditoría y Transacciones en MongoDB:


package com.example.petshop.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.domain.AuditorAware;
import org.springframework.data.mongodb.MongoDatabaseFactory;
import org.springframework.data.mongodb.MongoTransactionManager;
import org.springframework.data.mongodb.config.EnableMongoAuditing;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;

import java.util.Optional;

@Configuration
@EnableMongoAuditing(auditorAwareRef = "mongoAuditorProvider")
public class MongoAuditingConfig {

    @Bean
    public AuditorAware<String> mongoAuditorProvider() {
        return () -> Optional.ofNullable(SecurityContextHolder.getContext().getAuthentication())
                .filter(Authentication::isAuthenticated)
                .map(Authentication::getName)
                .or(() -> Optional.of("SYSTEM"));
    }

    // Habilita transacciones multi-documento en MongoDB (requiere Replica Set)
    @Bean
    public MongoTransactionManager transactionManager(MongoDatabaseFactory dbFactory) {
        return new MongoTransactionManager(dbFactory);
    }
}

2. Servicio Transaccional de Negocio en MongoDB:


package com.example.petshop.service.nosql;

import com.example.petshop.model.nosql.PetDocument;
import com.example.petshop.repository.nosql.PetMongoRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Slf4j
@RequiredArgsConstructor
@Service
public class PetTransactionalMongoService {

    private final PetMongoRepository petRepository;

    @Transactional(readOnly = true)
    public PetDocument getPetById(String id) {
        log.info("Consultando documento mascota con ID: {}", id);
        return petRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("Documento no encontrado con id: " + id));
    }

    @Transactional(rollbackFor = Exception.class)
    public PetDocument updateVaccinationStatus(String id, boolean vaccinated) {
        log.info("Actualizando documento mascota ID {} a vacunada={}", id, vaccinated);
        PetDocument pet = getPetById(id);
        pet.setVaccinated(vaccinated);
        return petRepository.save(pet);
    }
}

4. Contraejemplos y Antipatrones Transaccionales

Contraejemplo 1: Autoinvocación de Métodos Transaccionales (Self-Invocation)


@Service
public class BadService {

    public void publicMethod() {
        // ANTIPATRÓN: La llamada interna 'this.transactionalMethod()' NO pasa por el Proxy de Spring
        // La anotación @Transactional será completamente IGNORADA
        transactionalMethod();
    }

    @Transactional(rollbackFor = Exception.class)
    public void transactionalMethod() {
        // operaciones en BD...
    }
}

Causa técnica: Spring AOP intercepta llamadas cuando vienen desde un bean externo inyectado. Las llamadas internas dentro del mismo objeto (this) no pasan por el proxy.

Solución: Mover el método transaccional a una clase o servicio colaborador independiente.

Contraejemplo 2: Omitir rollbackFor ante Excepciones Comprobadas


// ANTIPATRÓN: Si lanza PetValidationException (que hereda de Exception comprobada),
// Spring NO revertirá los cambios y la transacción hará COMMIT en la base de datos
@Transactional
public void saveWithCustomException(PetEntity pet) throws PetValidationException {
    petRepository.save(pet);
    if (pet.getAge() < 0) {
        throw new PetValidationException("Edad inválida"); // No hace rollback por defecto
    }
}

Solución: Anotar siempre con @Transactional(rollbackFor = Exception.class).
