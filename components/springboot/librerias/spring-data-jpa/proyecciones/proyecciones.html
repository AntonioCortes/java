Spring Data: Proyecciones y DTOs (Interface-based, Records y Dinámicas)

1. ¿Qué es una proyección y por qué es una optimización crítica?

En la mayoría de endpoints REST de consulta (GET), la vista o el cliente móvil solo necesita mostrar 2 o 3 campos básicos de una entidad (por ejemplo, el nombre y la especie de la mascota en un desplegable). Si el repositorio recupera la entidad completa (PetEntity), el motor debe traer de la base de datos decenas de columnas innecesarias, hidratar los objetos en memoria y lidiar con colecciones perezosas.

Las Proyecciones de Spring Data permiten consultar y mapear únicamente los atributos requeridos directamente desde el motor de base de datos a estructuras ligeras de Java, reduciendo drásticamente el consumo de memoria JVM y el ancho de banda de red.

---

2. Modalidades de Proyección en Spring Data

2.1. Proyecciones basadas en Interfaces (Interface-based Projections)

  • Proyección Cerrada (Closed): La interfaz define únicamente métodos de acceso (getters) cuyos nombres coinciden con las propiedades de la entidad. Spring Data optimiza la sentencia SQL/BSON solicitando exclusivamente esas columnas: 
    
        public interface PetSummaryProjection {
            String getName();
            String getSpecies();
        }
  • Proyección Abierta (Open): Utiliza la anotación @Value de Spring Framework con expresiones SpEL para calcular atributos derivados. Advertencia técnica: Al requerir SpEL, Spring Data se ve obligado a cargar la entidad completa a memoria para evaluar la expresión: 
    
        public interface PetOpenProjection {
            @Value("#{target.name + ' (' + target.species + ')'}")
            String getDisplayName();
        }

2.2. Proyecciones basadas en Clases / Records (Class-based DTOs)

A partir de Java 16/17+, el uso de Java Records es el estándar preferido de la industria para DTOs inmutables: 


public record PetSummaryDTO(String name, String species) {
}

En JPA se puede poblar mediante correspondencia automática de constructor o mediante expresiones de constructor explícitas en JPQL (SELECT new com.example.dto.PetSummaryDTO(p.name, p.species) FROM PetEntity p).

2.3. Proyecciones Dinámicas (Dynamic Projections)

Permiten reutilizar el mismo método de consulta para devolver diferentes representaciones según el caso de uso, pasando la clase de destino como parámetro (Class<T> type).

3. Ejemplos Prácticos Completos y Simétricos

Se muestra la definición de los tipos de proyección y su consumo simétrico en Spring Data JPA (PostgreSQL/Oracle) y Spring Data MongoDB.

3.1. Definición de Tipos de Proyección Compartidos


package com.example.petshop.projection;

// Interfaz cerrada
public interface PetSummaryProjection {
    String getName();
    String getSpecies();
}


package com.example.petshop.dto;

// DTO inmutable con Record de Java 17/21
public record PetSummaryDTO(String name, String species) {
}

3.2. Repositorio Relacional: PostgreSQL / Oracle (Spring Data JPA)


package com.example.petshop.repository.relational;

import com.example.petshop.dto.PetSummaryDTO;
import com.example.petshop.model.relational.PetEntity;
import com.example.petshop.projection.PetSummaryProjection;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;

import java.util.List;

@Repository
public interface PetProjectionJpaRepository extends JpaRepository<PetEntity, Long> {

    // 1. Proyección cerrada por interfaz (Genera: SELECT p.name, p.species FROM pets p WHERE p.vaccinated = true)
    List<PetSummaryProjection> findByVaccinatedTrue();

    // 2. Proyección por Record DTO mediante derivación automática
    List<PetSummaryDTO> findDtoByVaccinatedTrue();

    // 3. Proyección mediante expresión 'new' en JPQL explícito
    @Query("SELECT new com.example.petshop.dto.PetSummaryDTO(p.name, p.species) " +
           "FROM PetEntity p WHERE p.species = :species")
    List<PetSummaryDTO> findSummaryBySpecies(@Param("species") String species);

    // 4. Proyección Dinámica: Devuelve PetEntity, PetSummaryProjection o PetSummaryDTO a petición del llamador
    <T> List<T> findBySpecies(String species, Class<T> type);
}

3.3. Repositorio Documental: MongoDB (Spring Data MongoDB)


package com.example.petshop.repository.nosql;

import com.example.petshop.dto.PetSummaryDTO;
import com.example.petshop.model.nosql.PetDocument;
import com.example.petshop.projection.PetSummaryProjection;
import org.springframework.data.mongodb.repository.MongoRepository;
import org.springframework.data.mongodb.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;

import java.util.List;

@Repository
public interface PetProjectionMongoRepository extends MongoRepository<PetDocument, String> {

    // 1. Proyección cerrada por interfaz en Mongo (Genera filtro y proyección BSON automática de campos)
    List<PetSummaryProjection> findByVaccinatedTrue();

    // 2. Proyección por Record DTO mediante derivación automática
    List<PetSummaryDTO> findDtoByVaccinatedTrue();

    // 3. Proyección explícita con @Query y atributo fields
    @Query(value = "{ 'species': :#{#species} }", fields = "{ 'name': 1, 'species': 1, '_id': 0 }")
    List<PetSummaryDTO> findSummaryBySpecies(@Param("species") String species);

    // 4. Proyección Dinámica idéntica para documentos MongoDB
    <T> List<T> findBySpecies(String species, Class<T> type);
}

4. Cuándo Usar y Cuándo NO Usar Cada Proyección

Tipo de Proyección Cuándo Usarla Cuándo NO Usarla
Interface Cerrada Mapeos rápidos de solo lectura donde solo se necesitan 2-5 getters. Máxima optimización SQL automática. Cuando se requiera lógica de transformación o cuando el DTO deba serializarse a capas externas desacopladas de Spring.
Record de Java Estándar recomendado para APIs REST modernas. Inmutable, fácil de testear, serialización Jackson limpia y métodos funcionales integrados. Cuando se requiera herencia de clases complejas o mutabilidad de atributos en memoria.
Interface Abierta (SpEL) Casos puntuales donde se necesita concatenar campos antes de exponer el valor sin escribir un método Java manual. En consultas de alto rendimiento. Obliga a Hibernate a cargar la entidad entera y pierde toda optimización SQL.
Proyección Dinámica Servicios reutilizables que son invocados tanto por procesos batch (entidad completa) como por controladores REST (DTO ligero). Consultas con una única vista o caso de uso fijo.

5. Contraejemplos y Antipatrones de Proyección

Contraejemplo: Devolver Entidades JPA Completas en Endpoints REST de Consulta


// ANTIPATRÓN: Expone la entidad relacional completa al cliente HTTP
@GetMapping("/all")
public List<PetEntity> getAllPets() {
    // Si PetEntity tiene relaciones @OneToMany (citas, historial médico),
    // puede provocar LazyInitializationException o serializar megabytes de datos innecesarios
    return petRepository.findAll();
}

Solución con Proyecciones: Devolver List<PetSummaryDTO> mediante petRepository.findByVaccinatedTrue().
