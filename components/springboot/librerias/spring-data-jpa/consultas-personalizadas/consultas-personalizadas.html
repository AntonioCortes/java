Spring Data: Consultas Personalizadas con @Query (JPQL, SQL Nativo y BSON)

1. ¿Qué es la anotación @Query y cuándo utilizarla?

La anotación @Query permite tomar el control total de la consulta ejecutada por el repositorio cuando los Derived Query Methods se quedan cortos, ya sea por complejidad de operadores, necesidad de proyecciones específicas, actualización de registros en lote o por requerir optimizaciones directas del motor de persistencia.

Diferencias conceptuales entre motores

  • En Spring Data JPA: Puede ejecutar JPQL (Java Persistence Query Language), que opera sobre el modelo orientado a objetos (clases y atributos de Java, independiente del motor SQL), o SQL Nativo (activando nativeQuery = true), que se envía tal cual al motor relacional subyacente (PostgreSQL u Oracle).
  • En Spring Data MongoDB: Ejecuta fragmentos de filtros JSON/BSON nativos equivalentes al método db.collection.find(...) de la consola de Mongo, soportando operadores avanzados como $regex, $gte, $in o $elemMatch.
---

2. Parámetros Nombrados vs Posicionales

Spring Data permite dos formas de inyectar variables en las consultas:

  1. Parámetros Posicionales (?1, ?2): Se asocian por el índice ordinal del parámetro en el método. Poco recomendado: cambiar el orden de los argumentos en el método de Java rompe la consulta en tiempo de ejecución.
  2. Parámetros Nombrados (:nombre o :#{#nombre} con @Param("nombre")): Vinculan explícitamente el argumento por nombre. Recomendación obligatoria para mantener código robusto y legible.
---

3. Ejemplos Prácticos Completos y Simétricos

Implementamos exactamente los mismos tres casos de negocio en JPA Relacional y en MongoDB NoSQL:

  1. Búsqueda compleja filtrada: Mascotas de una especie con edad entre un rango mínimo y máximo, que estén vacunadas, ordenadas por fecha de admisión descendente.
  2. Proyección de campos: Traer únicamente el nombre y la especie para optimizar la transferencia de red.
  3. Actualización masiva: Marcar como vacunadas todas las mascotas de una especie determinada.

3.1. Repositorio Relacional: PostgreSQL / Oracle (Spring Data JPA)


package com.example.petshop.repository.relational;

import com.example.petshop.model.relational.PetEntity;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Modifying;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Repository
public interface PetQueryJpaRepository extends JpaRepository<PetEntity, Long> {

    // 1. Consulta JPQL: Opera sobre la entidad Java (PetEntity p) y sus atributos (p.species)
    @Query("SELECT p FROM PetEntity p " +
           "WHERE p.species = :species " +
           "AND p.age BETWEEN :minAge AND :maxAge " +
           "AND p.vaccinated = true " +
           "ORDER BY p.admissionDate DESC")
    List<PetEntity> findActiveVaccinatedPets(
        @Param("species") String species,
        @Param("minAge") int minAge,
        @Param("maxAge") int maxAge
    );

    // 2. Consulta SQL Nativa: Opera sobre la tabla física (pets) y nombres de columnas (admission_date)
    @Query(
        value = "SELECT * FROM pets p " +
                "WHERE p.species = :species " +
                "AND p.age BETWEEN :minAge AND :maxAge " +
                "AND p.vaccinated = true " +
                "ORDER BY p.admission_date DESC",
        nativeQuery = true
    )
    List<PetEntity> findActiveVaccinatedPetsNative(
        @Param("species") String species,
        @Param("minAge") int minAge,
        @Param("maxAge") int maxAge
    );

    // 3. Actualización en lote (Bulk Update) con @Modifying
    // clearAutomatically = true sincroniza la caché de primer nivel de Hibernate tras la ejecución
    @Modifying(clearAutomatically = true)
    @Transactional
    @Query("UPDATE PetEntity p SET p.vaccinated = true WHERE p.species = :species")
    int vaccinateAllBySpecies(@Param("species") String species);
}

3.2. Repositorio Documental: MongoDB (Spring Data MongoDB)


package com.example.petshop.repository.nosql;

import com.example.petshop.model.nosql.PetDocument;
import org.springframework.data.mongodb.repository.MongoRepository;
import org.springframework.data.mongodb.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;

import java.util.List;

@Repository
public interface PetQueryMongoRepository extends MongoRepository<PetDocument, String> {

    // 1. Consulta BSON con @Query: Mismo filtro exacto con ordenación inversa (-1)
    @Query(
        value = "{ 'species': :#{#species}, 'age': { '$gte': :#{#minAge}, '$lte': :#{#maxAge} }, 'vaccinated': true }",
        sort = "{ 'admissionDate': -1 }"
    )
    List<PetDocument> findActiveVaccinatedPets(
        @Param("species") String species,
        @Param("minAge") int minAge,
        @Param("maxAge") int maxAge
    );

    // 2. Proyección de campos en Mongo: Devuelve solo _id, name y species (0 excluye, 1 incluye)
    @Query(
        value = "{ 'species': :#{#species} }",
        fields = "{ 'name': 1, 'species': 1, '_id': 1 }"
    )
    List<PetDocument> findProjectedBySpecies(@Param("species") String species);

    // En MongoDB las actualizaciones en lote masivas complejas suelen gestionarse mediante MongoTemplate
    // para control fino de WriteResult y multi-update con Update.update(...)
}

4. Cuándo Usar y Cuándo NO Usar Cada Tipo de Consulta

Tipo de Consulta Cuándo Usarla Cuándo NO Usarla
JPQL estándar Consultas con 3 o más filtros lógicos, ordenación compuesta o joins explícitos entre entidades. Mantiene portabilidad entre PostgreSQL y Oracle. Consultas ultrarrápidas que necesitan funciones nativas específicas del motor (ej. operadores JSONB en Postgres).
SQL Nativo (nativeQuery = true) Cuando se requieren funciones exclusivas del dialecto (funciones de ventana, expresiones de tabla común CTEs, hints de optimización de Oracle). Consultas que deban ser portables entre distintos motores. Rompe la validación de tipos de Hibernate en el arranque.
MongoDB BSON @Query Consultas que aprovechan la riqueza del formato JSON/BSON: operadores de array ($all, $elemMatch) y proyecciones de campos (fields). Consultas muy sencillas de igualdad (en esas es preferible usar un Query Method como findByName).
---

5. Contraejemplos y Errores Habituales con @Query

Contraejemplo 1: Olvidar @Modifying en operaciones de UPDATE o DELETE en JPA


// ANTIPATRÓN: Lanzará InvalidDataAccessApiUsageException en tiempo de ejecución
public interface BrokenUpdateRepository extends JpaRepository<PetEntity, Long> {
    // Falta la anotación @Modifying y @Transactional
    @Query("UPDATE PetEntity p SET p.vaccinated = true WHERE p.species = :species")
    int badUpdate(@Param("species") String species);
}

Explicación: Por defecto, @Query asume que la sentencia es un SELECT. Para sentencias DML (UPDATE, DELETE), Spring Data requiere obligatoriamente @Modifying.

Contraejemplo 2: Desincronización de la Caché de Primer Nivel de Hibernate

Al ejecutar un UPDATE masivo mediante @Modifying, la sentencia va directa a la base de datos sin pasar por el contexto de persistencia. Si previamente se cargó una entidad en memoria, la entidad en Java conservará los valores antiguos a menos que se indique clearAutomatically = true.
