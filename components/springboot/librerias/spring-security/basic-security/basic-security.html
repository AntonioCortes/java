Spring Security: Seguridad Básica

Spring Security es el estándar indiscutible de seguridad en el ecosistema Java y Spring Boot. Proporciona un marco potente y altamente personalizable que cubre los dos pilares esenciales de la seguridad informática:

  • Autenticación (Authentication): Verificar quién es el usuario (mediante usuario/contraseña, certificados, tokens, etc.).
  • Autorización (Authorization): Determinar a qué recursos tiene permiso de acceso el usuario autenticado (roles como ROLE_ADMIN, ROLE_USER, o permisos granulares scopes).

Con la llegada de Spring Boot 3 y Spring Security 6, el framework ha experimentado una modernización total: se eliminó definitivamente la antigua clase base WebSecurityConfigurerAdapter y los encadenamientos con .and(), consolidando la configuración declarativa mediante el componente SecurityFilterChain y el uso de expresiones lambda con Customizer.

Analogía del Mundo Real: Los Torniquetes y el Guardia del Edificio

Imagina la entrada a la sede central de una clínica veterinaria u hospital:

  • En la entrada principal hay un Guardia de Seguridad y un Torniquete (la SecurityFilterChain). Nadie puede acceder a los pasillos interiores sin pasar por el torniquete.
  • El guardia te pide una identificación (la Autenticación HTTP Basic / Formulario). Muestras tu tarjeta de empleado. El guardia comprueba en el libro de registros (el UserDetailsService) que tu foto y contraseña coincidan con los datos cifrados (BCryptPasswordEncoder).
  • Una vez validada tu identidad, el guardia mira tu distintivo (la Autorización):
    • Si eres cliente general (ROLE_USER), se te permite el paso a la sala de espera (GET /petshop/pet/**).
    • Si intentas entrar al quirófano o a la caja fuerte (POST /petshop/pet o administración), el guardia comprueba si tienes la credencial dorada (ROLE_ADMIN). Si no la tienes, te deniega el acceso inmediatamente con un código 403 Forbidden.

Caso de Uso Real Estructurado

1. Contexto

La API de la tienda de mascotas (PetStore) expone endpoints de consulta pública para catálogo y endpoints privilegiados de creación y borrado para veterinarios administradores.

2. El Problema (Sin Seguridad Adecuada)

Cualquier usuario anónimo puede emitir una petición DELETE /petshop/pet/5 y borrar una mascota de la base de datos. Si se programa seguridad casera con filtros if-else en cada controlador, se cometen fallos humanos y se dejan rutas desprotegidas.

3. La Solución (Con Spring Security)

Se centralizan las reglas en un SecurityFilterChain: los métodos GET quedan públicos con permitAll(), y las mutaciones POST/PUT/DELETE exigen autenticación y rol ADMIN.

¿Cuándo usarlo y cuándo NO usarlo?

Mecanismo ¿Cuándo usarlo? ¿Cuándo NO usarlo?
HTTP Basic Authentication APIs de desarrollo, herramientas internas de administración, prototipos o comunicación directa entre servicios seguros sin navegador web de usuario final. Aplicaciones web públicas con usuarios humanos: la credencial en Base64 viaja en cada cabecera y el navegador almacena las credenciales sin posibilidad de logout limpio nativo.
Form Login (Sesión por Cookies) Aplicaciones web tradicionales monolíticas con renderizado en servidor (Thymeleaf, JSP) que mantienen una sesión HTTP con cookie JSESSIONID. APIs REST consumidas por aplicaciones móviles o SPAs (Angular, React, Vue), donde se exige arquitectura Stateless basada en Tokens JWT.
BCryptPasswordEncoder Obligatorio siempre para almacenar contraseñas en bases de datos. Incluye salt criptográfico aleatorio y es resistente a ataques por fuerza bruta o tablas rainbow. Nunca utilizar algoritmos obsoletos o rápidos como MD5, SHA-1 o texto plano (NoOpPasswordEncoder).

Diagrama de la Cadena de Filtros (SecurityFilterChain)

Toda petición entrante atraviesa una secuencia ordenada de filtros antes de alcanzar los controladores de Spring:

Figura 1: Intercepción y validación de peticiones en la SecurityFilterChain
Filtro / Componente Rol en la Cadena Comportamiento en APIs REST
CorsFilter Gestión de CORS Verifica si el origen del navegador (ej. http://localhost:3000) tiene autorización para realizar peticiones cruzadas.
CsrfFilter Protección CSRF En APIs REST sin cookies de sesión (stateless), debe deshabilitarse (csrf.disable()) para permitir peticiones POST/PUT sin token anti-falsificación.
BasicAuthenticationFilter Autenticación Lee la cabecera Authorization: Basic base64(user:pass) y valida las credenciales contra el UserDetailsService.
AuthorizationFilter Autorización por Rol Evalúa si el usuario autenticado posee los roles exigidos para la ruta solicitada (ej. hasRole('ADMIN')).

Implementación Moderna en Spring Boot 3 / Spring Security 6

Configuración Completa con DSL de Lambdas


package com.example.petstore.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.provisioning.InMemoryUserDetailsManager;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    // 1. Definición de la Cadena de Filtros de Seguridad
    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            // Desactiva CSRF para APIs REST públicas/stateless
            .csrf(AbstractHttpConfigurer::disable)
            
            // Política de sesión sin estado (Stateless)
            .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            
            // Reglas de autorización por ruta y método HTTP
            .authorizeHttpRequests(auth -> auth
                // Rutas públicas de consulta de catálogo y Swagger
                .requestMatchers(HttpMethod.GET, "/petshop/pet/**").permitAll()
                .requestMatchers("/v3/api-docs/**", "/swagger-ui/**", "/swagger-ui.html").permitAll()
                
                // Operaciones de creación, modificación y borrado restringidas a administradores
                .requestMatchers(HttpMethod.POST, "/petshop/pet/**").hasRole("ADMIN")
                .requestMatchers(HttpMethod.PUT, "/petshop/pet/**").hasRole("ADMIN")
                .requestMatchers(HttpMethod.DELETE, "/petshop/pet/**").hasRole("ADMIN")
                
                // Cualquier otra petición debe estar autenticada
                .anyRequest().authenticated()
            )
            
            // Habilita autenticación HTTP Basic estándar
            .httpBasic(Customizer.withDefaults());

        return http.build();
    }

    // 2. Codificador de contraseñas seguro con algoritmo BCrypt
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    // 3. Usuarios en memoria para desarrollo y pruebas
    @Bean
    public UserDetailsService userDetailsService(PasswordEncoder encoder) {
        UserDetails adminUser = User.builder()
                .username("admin")
                .password(encoder.encode("admin123"))
                .roles("ADMIN", "USER")
                .build();

        UserDetails regularUser = User.builder()
                .username("cliente")
                .password(encoder.encode("cliente123"))
                .roles("USER")
                .build();

        return new InMemoryUserDetailsManager(adminUser, regularUser);
    }
}

Contraejemplo: Código Obsoleto e Inseguro de Spring Security 5 (Antipatrón)


// ANTIPATRÓN: Código descontinuado en Spring Boot 3 y contraseñas en texto plano
@Configuration
public class BadSecurityConfig extends WebSecurityConfigurerAdapter { // ERROR: Eliminado en Spring Boot 3

    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http
            .csrf().disable() // ERROR: Métodos encadenados obsoletos
            .authorizeRequests() // ERROR: Reemplazado por authorizeHttpRequests
            .antMatchers("/admin/**").hasRole("ADMIN") // ERROR: Reemplazado por requestMatchers
            .and().httpBasic();
    }

    @Bean
    public PasswordEncoder badEncoder() {
        // ERROR GRAVÍSIMO: Guardar contraseñas en texto plano vulnera todas las leyes de privacidad
        return NoOpPasswordEncoder.getInstance();
    }
}

Ejemplo: Invocación de la API Protegida con cURL


# 1. Consulta pública permitida sin credenciales (Retorna 200 OK):
curl -X GET http://localhost:8080/petshop/pet/1

# 2. Intento de borrado sin credenciales (Retorna 401 Unauthorized):
curl -X DELETE http://localhost:8080/petshop/pet/1

# 3. Borrado con credenciales de usuario normal sin rol ADMIN (Retorna 403 Forbidden):
curl -X DELETE http://localhost:8080/petshop/pet/1 -u cliente:cliente123

# 4. Borrado con credenciales de administrador (Retorna 204 No Content):
curl -X DELETE http://localhost:8080/petshop/pet/1 -u admin:admin123
