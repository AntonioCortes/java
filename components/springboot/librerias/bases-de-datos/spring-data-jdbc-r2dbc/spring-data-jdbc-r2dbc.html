Spring Data JDBC y Spring Data R2DBC (Acceso Reactivo a Bases de Datos)

1. ¿Qué son y para qué sirven?

En el ecosistema de Spring Initializr, además del tradicional Spring Data JPA (basado en Hibernate y el estándar JPA), disponemos de dos alternativas modernas de persistencia relacional que resuelven problemas arquitectónicos específicos:

  • Spring Data JDBC: Un framework de persistencia relacional deliberadamente simple. A diferencia de JPA/Hibernate, no tiene caché de primer nivel (Persistence Context), no realiza dirty checking implícito, no usa proxys de Lazy Loading ni genera complejas cascadas automáticas. Cada consulta a la base de datos se traduce en SQL directo y predecible.
  • Spring Data R2DBC (Reactive Relational Database Connectivity): La implementación reactiva oficial para bases de datos SQL basada en Project Reactor (Mono y Flux). Mientras que JDBC tradicional bloquea el hilo de ejecución del sistema operativo esperando a que la base de datos devuelva los datos (modelo thread-per-request), R2DBC utiliza controladores completamente no bloqueantes sobre Netty, permitiendo gestionar miles de peticiones simultáneas con un consumo mínimo de memoria RAM y CPU.

Analogía del mundo real

Imaginemos una ventanilla de pedidos en un restaurante:

  • Spring Data JPA es como un camarero con una libreta mágica de alta tecnología que intenta recordar todo lo que has comido, predice qué vas a pedir después y reorganiza los platos a tus espaldas (muy potente, pero si se sobrecarga la libreta se producen enredos y bloqueos inesperados).
  • Spring Data JDBC es un camarero tradicional: toma la nota exacta, la lleva a la cocina, trae el plato y se olvida. No hay magia ni proxys ocultos; lo que pides es lo que se envía a cocina inmediatamente.
  • Spring Data R2DBC es una moderna cinta transportadora inteligente con beepers: el camarero jamás se queda de pie esperando a que el cocinero fría el filete; atiende a otros 100 clientes mientras la cocina trabaja, y cuando el plato está listo, un evento avisa para servirlo al cliente al milisegundo.

2. Caso de Uso Real Estructurado

1. Contexto

Un microservicio de telemetría de mascotas registra constantes vitales de collares inteligentes (frecuencia cardíaca, temperatura, GPS) recibiendo 50.000 eventos por segundo en un clúster de PostgreSQL.

2. El Problema (Con JDBC o JPA tradicional)

Cada petición HTTP bloquea un hilo en Tomcat esperando respuesta de la base de datos. El pool de 200 hilos se agota en segundos, produciendo errores HTTP 503 Service Unavailable y saturando la memoria del servidor.

3. La Solución (Con Spring Data R2DBC)

Al migrar a Spring WebFlux y Spring Data R2DBC, los flujos asíncronos y no bloqueantes procesan las 50.000 lecturas con tan solo 8 hilos del procesador sin agotar el pool de conexiones.

3. ¿Cuándo usar cada tecnología y cuándo NO usarlas?

Framework ¿Cuándo usarlo? ¿Cuándo NO usarlo?
Spring Data JPA Aplicaciones empresariales con modelos de dominio ricos, grafos complejos de entidades con relaciones @ManyToOne, @OneToMany bidireccionales y flujos CRUD tradicionales. Sistemas con arquitecturas reactivas no bloqueantes, o microservicios sencillos de alto rendimiento donde el coste del Persistence Context y el riesgo de consultas N+1 superen los beneficios.
Spring Data JDBC Microservicios donde se busque simplicidad absoluta, consultas SQL totalmente explícitas y control directo de transacciones sin complejidad de Hibernate. Sistemas que dependan fuertemente de proxys de carga perezosa (Lazy Loading) o que requieran soporte reactivo no bloqueante.
Spring Data R2DBC Microservicios de altísima concurrencia, ingesta masiva de eventos (IoT), streaming de datos en tiempo real (Server-Sent Events) y aplicaciones reactivas basadas en Spring WebFlux. Aplicaciones tradicionales construidas con Spring MVC clásico (Tomcat bloqueante), ya que mezclar código bloqueante con llamadas reactivas no aporta mejoras y añade complejidad cognitiva innecesaria.

4. Dependencias Necesarias (Maven y Gradle)

A. Dependencias para Spring Data JDBC

En Spring Initializr, se selecciona Spring Data JDBC y el driver correspondiente (por ejemplo, PostgreSQL): 


<!-- Maven: Spring Data JDBC y Driver PostgreSQL -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jdbc</artifactId>
</dependency>
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>


// Gradle (build.gradle)
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-data-jdbc'
    runtimeOnly 'org.postgresql:postgresql'
}

B. Dependencias para Spring Data R2DBC (Reactivo)

En Spring Initializr, se selecciona Spring Data R2DBC y el driver reactivo correspondiente (ej. r2dbc-postgresql): 


<!-- Maven: Spring Data R2DBC y Driver Reactivo PostgreSQL -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-r2dbc</artifactId>
</dependency>
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>r2dbc-postgresql</artifactId>
    <scope>runtime</scope>
</dependency>


// Gradle (build.gradle)
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-data-r2dbc'
    runtimeOnly 'org.postgresql:r2dbc-postgresql'
}

5. Anotaciones y Clases Principales

Elemento Paquete Propósito y Comportamiento
@Table("nombre_tabla") org.springframework.data.relational.core.mapping Mapea una clase inmutable a una tabla de la base de datos en JDBC y R2DBC (no usa jakarta.persistence.Entity).
@Id org.springframework.data.annotation Marca la clave primaria de la entidad. En R2DBC/JDBC, si el identificador es nulo, Spring asume que es una nueva inserción y genera la sentencia INSERT; si no es nulo, genera un UPDATE.
ReactiveCrudRepository<T, ID> org.springframework.data.repository.reactive Interfaz base reactiva que expone métodos como findById, save y delete devolviendo Mono<T> o Flux<T> en lugar de tipos bloqueantes.
DatabaseClient org.springframework.r2dbc.core Cliente reactivo de bajo nivel para ejecutar sentencias SQL nativas fluidas y mapear resultados asíncronamente con total control.

6. Ejemplo Completo: Persistencia Reactiva con Spring Data R2DBC y Lombok

A. Configuración de Conexión Reactiva (application.yml)


spring:
  r2dbc:
    url: r2dbc:postgresql://localhost:5432/petshop_db
    username: postgres_user
    password: secure_password
    pool:
      enabled: true
      initial-size: 10
      max-size: 50

B. Entidad Reactiva con Lombok


package com.example.petshop.model.reactive;

import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;
import lombok.ToString;
import org.springframework.data.annotation.Id;
import org.springframework.data.relational.core.mapping.Table;

import java.time.LocalDate;

@Table("pets")
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
@ToString
public class PetReactiveEntity {

    @Id
    private Long id;

    private String name;
    private String species;
    private Integer age;
    private Boolean vaccinated;
    private LocalDate admissionDate;
}

C. Repositorio Reactivo


package com.example.petshop.repository.reactive;

import com.example.petshop.model.reactive.PetReactiveEntity;
import org.springframework.data.r2dbc.repository.Query;
import org.springframework.data.repository.reactive.ReactiveCrudRepository;
import org.springframework.stereotype.Repository;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@Repository
public interface PetReactiveRepository extends ReactiveCrudRepository<PetReactiveEntity, Long> {

    // Consulta derivada reactiva: devuelve un flujo continuo asíncrono
    Flux<PetReactiveEntity> findByVaccinatedTrue();

    // Consulta personalizada reactiva con enlace de parámetros
    @Query("SELECT * FROM pets WHERE species = :species AND age <= :maxAge")
    Flux<PetReactiveEntity> findYoungPetsBySpecies(String species, int maxAge);

    Mono<Boolean> existsByName(String name);
}

D. Servicio Reactivo con Project Reactor


package com.example.petshop.service.reactive;

import com.example.petshop.model.reactive.PetReactiveEntity;
import com.example.petshop.repository.reactive.PetReactiveRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@Slf4j
@Service
@RequiredArgsConstructor
public class PetReactiveService {

    private final PetReactiveRepository petRepository;

    public Mono<PetReactiveEntity> getPetById(Long id) {
        log.info("Consultando mascota reactiva con ID: {}", id);
        return petRepository.findById(id)
                .doOnNext(pet -> log.info("Mascota encontrada: {}", pet.getName()))
                .switchIfEmpty(Mono.error(new RuntimeException("Mascota no encontrada con ID: " + id)));
    }

    public Flux<PetReactiveEntity> getAllVaccinatedPets() {
        return petRepository.findByVaccinatedTrue();
    }

    @Transactional
    public Mono<PetReactiveEntity> registerPet(PetReactiveEntity newPet) {
        return petRepository.existsByName(newPet.getName())
                .flatMap(exists -> {
                    if (exists) {
                        return Mono.error(new IllegalArgumentException("Ya existe una mascota llamada: " + newPet.getName()));
                    }
                    return petRepository.save(newPet);
                });
    }
}

7. Contraejemplo y Antipatrón Crítico

Contraejemplo: Bloquear un Flujo Reactivo con .block()


// ANTIPATRÓN CATASTRÓFICO: Usar .block() en una aplicación reactiva
@GetMapping("/bad-pet/{id}")
public PetReactiveEntity getBadPet(@PathVariable Long id) {
    // ERROR CRÍTICO: .block() secuestra el hilo no bloqueante de Netty esperando la BD.
    // Con 10 llamadas simultáneas, Netty se congela y bloquea todo el microservicio.
    return petReactiveService.getPetById(id).block(); 
}

Solución: Devolver siempre tipos reactivos (Mono<PetReactiveEntity> o Flux<PetReactiveEntity>) directamente en los controladores de Spring WebFlux, permitiendo que el framework gestione la suscripción y el streaming asíncrono sin bloquear jamás ningún hilo.
