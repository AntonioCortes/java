Tests Funcionales y Slice Tests en la Capa Web (@WebMvcTest y MockMvc)

1. ¿Qué es un Test Funcional / Web Slice Test y para qué sirve?

En aplicaciones Spring Boot modernas, los Tests Funcionales de la capa Web (también denominados Web Slice Tests) verifican el contrato HTTP de nuestros controladores REST: el enrutamiento de URLs, la serialización y deserialización de JSON con Jackson, la validación de payloads de entrada con Bean Validation (@Valid), los códigos de estado HTTP y los encabezados de respuesta (como Location o cabeceras de caché).

Analogía del mundo real

Imaginemos un simulador de vuelo de cabina completa: no quema combustible real ni despega del suelo (no arranca un servidor Tomcat real ni una base de datos), pero todos los mandos, pantallas de navegación, alarmas e indicadores responden exactamente igual que en un vuelo real. Si el piloto introduce coordenadas incorrectas, el sistema de navegación emite una alarma de error de inmediato.

¿Por qué utilizar @WebMvcTest en lugar de levantar toda la aplicación?

  • Arranque focalizado: @WebMvcTest carga únicamente los componentes de Spring MVC (controladores, manejadores de excepciones @RestControllerAdvice, filtros y configuraciones de Jackson), ignorando entidades JPA, repositorios y servicios de negocio.
  • Velocidad: Tarda solo 1 o 2 segundos en inicializarse, a diferencia de los 15-30 segundos que puede costar un @SpringBootTest completo.
  • Aislamiento total: La lógica de negocio subyacente se simula limpiamente con @MockBean, permitiendo simular fácilmente respuestas de éxito, fallos 404, colisiones de unicidad o excepciones internas.

2. Herramientas del Web Slice: MockMvc, @MockBean y @MockitoBean

Componente Paquete Propósito y Versión
@WebMvcTest(ClaseControlador.class) org.springframework.boot.test.autoconfigure.web.servlet Anota la clase de test limitando el contexto de Spring exclusivamente a los controladores especificados.
MockMvc org.springframework.test.web.servlet Punto de entrada principal para disparar peticiones HTTP virtuales (perform(get(...)), perform(post(...))) y verificar respuestas.
@MockitoBean org.springframework.test.context.bean.override.mockito Recomendado en Spring Boot 3.4+: Nueva anotación oficial de Spring Framework 6.2+ / Spring Boot 3.4+ que reemplaza a @MockBean con un ciclo de vida más predecible y soporte unificado de Bean Overrides.
@MockBean org.springframework.boot.test.mock.mockito Estándar en Spring Boot 2.x - 3.3: Registra un mock de Mockito dentro del contexto de Spring (marcada como deprecated a partir de Spring Boot 3.4 en favor de @MockitoBean).
ObjectMapper com.fasterxml.jackson.databind Serializa objetos Java a cadenas JSON para enviarlos en el cuerpo de las peticiones POST/PUT.

3. Estándar de Casos de Prueba para Controladores REST

Todo controlador REST profesional debe contar con tests que cubran rigurosamente el siguiente catálogo de situaciones:

Caso Estándar Entrada / Condición Respuesta HTTP Esperada Aserciones Críticas
1. GET Exitoso (Happy Path) ID existente en la ruta (/petshop/pet/1). 200 OK status().isOk(), jsonPath("$.name").value("Max"), jsonPath("$.species").value("Dog").
2. GET Recurso Inexistente El servicio lanza PetNotFoundException. 404 NOT_FOUND status().isNotFound(), jsonPath("$.status").value(404), mensaje de error en JSON.
3. POST Creación Exitosa Payload JSON válido con todos los campos obligatorios. 201 CREATED status().isCreated(), cabecera Location con la URI del nuevo recurso creado.
4. POST Validación Fallida (Bad Request) Payload con campos nulos o que violan restricciones @NotBlank / @Min. 400 BAD_REQUEST status().isBadRequest(), jsonPath("$.fieldErrors").isArray(), no se invoca al servicio.
5. DELETE Eliminación Exitosa ID existente. 204 NO_CONTENT status().isNoContent(), cuerpo de respuesta vacío.

4. Ejemplo Completo: Test del Controlador PetController

A continuación se presenta la suite completa de pruebas para PetController utilizando @WebMvcTest, MockMvc y BDDMockito: 


package com.example.petshop.controller;

import com.example.petshop.dto.PetDTO;
import com.example.petshop.exception.GlobalExceptionHandler;
import com.example.petshop.exception.PetNotFoundException;
import com.example.petshop.service.PetService;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.boot.test.mock.mockito.MockBean;
import org.springframework.context.annotation.Import;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;

import java.time.LocalDate;

import static org.mockito.ArgumentMatchers.any;
import static org.mockito.BDDMockito.given;
import static org.mockito.BDDMockito.then;
import static org.mockito.Mockito.never;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.*;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

@WebMvcTest(PetController.class)
@Import(GlobalExceptionHandler.class) // Importa el manejador centralizado de errores
@DisplayName("Tests Funcionales Web - PetController")
class PetControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @Autowired
    private ObjectMapper objectMapper;

    // En Spring Boot 2.x - 3.3 se usa @MockBean; en Spring Boot 3.4+ se usa @MockitoBean
    @MockBean
    private PetService petService;

    @Test
    @DisplayName("GET /petshop/pet/{id}: Debe retornar 200 OK con el JSON de la mascota si existe")
    void shouldReturn200AndPetJsonWhenPetExists() throws Exception {
        // GIVEN
        Integer petId = 1;
        PetDTO petDTO = PetDTO.builder()
                .id(petId)
                .name("Max")
                .species("Dog")
                .age((short) 4)
                .vaccinated(true)
                .admissionDate(LocalDate.of(2025, 1, 15))
                .build();

        given(petService.findById(petId)).willReturn(petDTO);

        // WHEN & THEN
        mockMvc.perform(get("/petshop/pet/{id}", petId)
                .accept(MediaType.APPLICATION_JSON))
                .andExpect(status().isOk())
                .andExpect(content().contentType(MediaType.APPLICATION_JSON))
                .andExpect(jsonPath("$.id").value(1))
                .andExpect(jsonPath("$.name").value("Max"))
                .andExpect(jsonPath("$.species").value("Dog"))
                .andExpect(jsonPath("$.vaccinated").value(true));

        then(petService).should().findById(petId);
    }

    @Test
    @DisplayName("GET /petshop/pet/{id}: Debe retornar 404 NOT FOUND si la mascota no existe")
    void shouldReturn404WhenPetDoesNotExist() throws Exception {
        // GIVEN
        Integer nonExistentId = 99;
        given(petService.findById(nonExistentId))
                .willThrow(new PetNotFoundException(nonExistentId));

        // WHEN & THEN
        mockMvc.perform(get("/petshop/pet/{id}", nonExistentId)
                .accept(MediaType.APPLICATION_JSON))
                .andExpect(status().isNotFound())
                .andExpect(jsonPath("$.status").value(404))
                .andExpect(jsonPath("$.message").value("No existe ninguna mascota con el identificador: 99"));

        then(petService).should().findById(nonExistentId);
    }

    @Test
    @DisplayName("POST /petshop/pet: Debe retornar 201 CREATED con la cabecera Location al crear una mascota válida")
    void shouldReturn201AndLocationHeaderWhenPetIsValid() throws Exception {
        // GIVEN
        PetDTO inputDto = PetDTO.builder()
                .name("Luna")
                .species("Cat")
                .age((short) 2)
                .vaccinated(true)
                .build();

        PetDTO savedDto = PetDTO.builder()
                .id(10)
                .name("Luna")
                .species("Cat")
                .age((short) 2)
                .vaccinated(true)
                .build();

        given(petService.save(any(PetDTO.class))).willReturn(savedDto);

        // WHEN & THEN
        mockMvc.perform(post("/petshop/pet")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(inputDto)))
                .andExpect(status().isCreated())
                .andExpect(header().exists("Location"))
                .andExpect(header().string("Location", org.hamcrest.Matchers.containsString("/petshop/pet/10")));

        then(petService).should().save(any(PetDTO.class));
    }

    @Test
    @DisplayName("POST /petshop/pet: Debe retornar 400 BAD REQUEST si el payload no cumple las validaciones Bean Validation")
    void shouldReturn400WhenPayloadViolatesValidationConstraints() throws Exception {
        // GIVEN: DTO con nombre en blanco y edad negativa
        PetDTO invalidDto = PetDTO.builder()
                .name("") // Viola @NotBlank
                .species("Cat")
                .age((short) -1) // Viola @Min(0)
                .build();

        // WHEN & THEN
        mockMvc.perform(post("/petshop/pet")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(invalidDto)))
                .andExpect(status().isBadRequest())
                .andExpect(jsonPath("$.status").value(400))
                .andExpect(jsonPath("$.fieldErrors").isArray());

        // El controlador rechaza la llamada antes de tocar el servicio
        then(petService).should(never()).save(any(PetDTO.class));
    }

    @Test
    @DisplayName("DELETE /petshop/pet/{id}: Debe retornar 204 NO CONTENT cuando se elimina con éxito")
    void shouldReturn204WhenPetDeletedSuccessfully() throws Exception {
        // GIVEN
        Integer petId = 1;

        // WHEN & THEN
        mockMvc.perform(delete("/petshop/pet/{id}", petId))
                .andExpect(status().isNoContent())
                .andExpect(content().string(""));

        then(petService).should().deleteById(petId);
    }
}

5. Cuándo Usar y Cuándo NO Usar @WebMvcTest

Escenario Recomendación Motivo Técnico
Validar rutas REST, códigos HTTP, serialización JSON y Bean Validation (@Valid). SIEMPRE usar @WebMvcTest Prueba el pipeline web completo de Spring MVC de forma aislada y en segundos.
Probar lógica de negocio o algoritmos de servicios. NO usar @WebMvcTest (Usar Unit Test con Mockito) No aporta nada levantar la capa web para probar una clase de servicio pura.
Probar que una transacción SQL hace rollback ante un error de controlador. NO usar @WebMvcTest (Usar @SpringBootTest con Testcontainers) @WebMvcTest no tiene base de datos ni gestor de transacciones reales configurados.

6. Contraejemplos y Errores Habituales en Tests de Controladores

Contraejemplo 1: Instanciar el Controlador con "new" Manualmente


// ANTIPATRÓN: Testear el controlador como si fuera un POJO plano
class BadControllerTest {
    @Test
    void testDirectCall() {
        PetController controller = new PetController(mockService);
        ResponseEntity<PetDTO> response = controller.get(1);
        
        // ERROR GRAVE: Este test NO prueba rutas, NO valida anotaciones @NotNull/@Valid,
        // NO prueba serialización Jackson ni comprueba filtros de seguridad.
        assertEquals(HttpStatus.OK, response.getStatusCode());
    }
}

Solución: Utilizar siempre @WebMvcTest con MockMvc para disparar la petición a través de la infraestructura web real de Spring.

7. Slice Test de Serialización JSON: @JsonTest y JacksonTester

La anotación @JsonTest configura un contexto de test ultra ligero que inicializa exclusivamente el subsistema de serialización y deserialización (Jackson, Gson o JSON-B) y utilidades auxiliares como JacksonTester<T>.

¿Para qué sirve y qué problemas previene?

  • Verifica que las anotaciones de Jackson como @JsonProperty("pet_name"), @JsonFormat, @JsonIgnore o @JsonInclude(NON_NULL) producen exactamente el payload esperado.
  • Comprueba que cadenas JSON complejas se deserializan correctamente hacia DTOs o records Java sin pérdidas de precisión ni errores de formato de fechas.
  • Se ejecuta en menos de 500 milisegundos sin levantar ningún servidor Tomcat ni servlet container.

Ejemplo Completo con JacksonTester


package com.example.petshop.json;

import com.example.petshop.dto.PetDTO;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.json.JsonTest;
import org.springframework.boot.test.json.JacksonTester;
import org.springframework.boot.test.json.JsonContent;

import java.time.LocalDate;

import static org.assertj.core.api.Assertions.assertThat;

@JsonTest
@DisplayName("Slice Test de Serialización JSON - PetDTO")
class PetJsonTest {

    @Autowired
    private JacksonTester<PetDTO> jsonTester;

    @Test
    @DisplayName("Serialización: Convierte PetDTO a JSON respetando nombres y formatos")
    void shouldSerializePetDtoToJson() throws Exception {
        // GIVEN
        PetDTO pet = PetDTO.builder()
                .id(10)
                .name("Oreo")
                .species("Cat")
                .age((short) 2)
                .vaccinated(true)
                .admissionDate(LocalDate.of(2025, 3, 20))
                .build();

        // WHEN
        JsonContent<PetDTO> result = jsonTester.write(pet);

        // THEN: Aserciones fluidas sobre rutas JSON
        assertThat(result).extractingJsonPathNumberValue("@.id").isEqualTo(10);
        assertThat(result).extractingJsonPathStringValue("@.name").isEqualTo("Oreo");
        assertThat(result).extractingJsonPathStringValue("@.species").isEqualTo("Cat");
        assertThat(result).extractingJsonPathBooleanValue("@.vaccinated").isTrue();
        assertThat(result).extractingJsonPathStringValue("@.admissionDate").isEqualTo("2025-03-20");
    }

    @Test
    @DisplayName("Deserialización: Convierte cadena JSON a objeto PetDTO fuertemente tipado")
    void shouldDeserializeJsonToPetDto() throws Exception {
        // GIVEN
        String jsonPayload = """
                {
                    "id": 10,
                    "name": "Oreo",
                    "species": "Cat",
                    "age": 2,
                    "vaccinated": true,
                    "admissionDate": "2025-03-20"
                }
                """;

        // WHEN
        PetDTO pet = jsonTester.parseObject(jsonPayload);

        // THEN
        assertThat(pet.getId()).isEqualTo(10);
        assertThat(pet.getName()).isEqualTo("Oreo");
        assertThat(pet.getSpecies()).isEqualTo("Cat");
        assertThat(pet.isVaccinated()).isTrue();
        assertThat(pet.getAdmissionDate()).isEqualTo(LocalDate.of(2025, 3, 20));
    }
}

8. Slice Test de Clientes HTTP Externos: @RestClientTest y MockRestServiceServer

Cuando nuestro microservicio se comunica con APIs externas (por ejemplo, pasarelas de pago, servicios de envíos o proveedores de vacunas veterinarias) utilizando RestClient o RestTemplate, la anotación @RestClientTest permite probar dicho cliente sin realizar llamadas de red reales.

¿Cómo funciona MockRestServiceServer?

MockRestServiceServer intercepta a nivel interno las llamadas del cliente HTTP, valida que el cliente envíe el método HTTP, la URL y las cabeceras requeridas, y responde inmediatamente con un payload simulado y un código de estado predefinido.

Ejemplo Completo con MockRestServiceServer


package com.example.petshop.client;

import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.client.RestClientTest;
import org.springframework.http.HttpMethod;
import org.springframework.http.MediaType;
import org.springframework.test.web.client.MockRestServiceServer;

import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.client.match.MockRestRequestMatchers.method;
import static org.springframework.test.web.client.match.MockRestRequestMatchers.requestTo;
import static org.springframework.test.web.client.response.MockRestResponseCreators.withSuccess;

@RestClientTest(VaccineSupplierClient.class)
@DisplayName("Slice Test de Cliente REST Externo - VaccineSupplierClient")
class VaccineSupplierClientTest {

    @Autowired
    private VaccineSupplierClient client;

    @Autowired
    private MockRestServiceServer mockServer;

    @Test
    @DisplayName("Debe consultar la disponibilidad de vacunas contra el proveedor externo vía HTTP GET")
    void shouldCheckVaccineStockFromExternalSupplier() {
        // GIVEN: Expectativa de petición hacia el proveedor externo y respuesta simulada
        String expectedUrl = "/api/v1/vaccines/rabies/stock";
        String mockResponseBody = """
                {
                    "vaccine": "rabies",
                    "availableDoses": 45,
                    "inStock": true
                }
                """;

        mockServer.expect(requestTo(expectedUrl))
                .andExpect(method(HttpMethod.GET))
                .andRespond(withSuccess(mockResponseBody, MediaType.APPLICATION_JSON));

        // WHEN: El cliente ejecuta la llamada HTTP simulada
        VaccineStockResponse response = client.checkStock("rabies");

        // THEN: Verificación de resultado y confirmación de que se cumplió el contrato
        assertThat(response).isNotNull();
        assertThat(response.isInStock()).isTrue();
        assertThat(response.getAvailableDoses()).isEqualTo(45);

        // Verifica que todas las expectativas configuradas en el servidor mock se ejecutaron
        mockServer.verify();
    }
}

6. Testing de APIs con REST-Assured (Sintaxis BDD y RestAssuredMockMvc)

Aunque MockMvc es el estándar nativo proporcionado por Spring, muchas organizaciones y proyectos empresariales (como SmartPos) prefieren REST-Assured debido a su expresividad, legibilidad y adopción del estándar BDD (Behavior-Driven Development) mediante la sintaxis fluida given() -> when() -> then().

6.1. ¿Por qué usar REST-Assured frente a MockMvc?

Criterio Spring MockMvc Estándar REST-Assured (RestAssuredMockMvc)
Estilo de Sintaxis Imperativo/Verborrágico: mezcla de perform(), andExpect(), MockMvcResultMatchers y lambdas complejas. Fluido y BDD Puro: given().contentType(...).when().post(...).then().statusCode(201). Se lee como lenguaje natural.
Validación de Payloads JSON Requiere operadores Hamcrest o conversión manual con ObjectMapper. JSONPath integrado nativo: body("species", equalTo("Canino")).body("id", notNullValue()).
Velocidad de Ejecución Ultra-rápido (ejecución en memoria contra el dispatcher servlet sin servidor HTTP real). Igual de rápido: El módulo spring-mock-mvc conecta directamente con los mocks de Spring MVC sin levantar Tomcat ni abrir puertos de red.

6.3. Ejemplo de Web Slice Test con RestAssuredMockMvc

En este ejemplo se combina la inicialización focalizada de @WebMvcTest con la elegancia sintáctica de RestAssuredMockMvc: 


package com.example.petshop.controller;

import com.example.petshop.dto.PetRequestDTO;
import com.example.petshop.dto.PetResponseDTO;
import com.example.petshop.service.PetService;
import io.restassured.http.ContentType;
import io.restassured.module.mockmvc.RestAssuredMockMvc;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.boot.test.mock.mockito.MockBean;
import org.springframework.http.HttpStatus;
import org.springframework.web.context.WebApplicationContext;

import java.time.LocalDate;

import static org.hamcrest.Matchers.equalTo;
import static org.hamcrest.Matchers.notNullValue;
import static org.mockito.ArgumentMatchers.any;
import static org.mockito.BDDMockito.given;

@WebMvcTest(PetRestController.class)
@DisplayName("Web Slice Test con REST-Assured - PetRestController")
class PetRestControllerRestAssuredTest {

    @Autowired
    private WebApplicationContext webApplicationContext;

    @MockBean
    private PetService petService;

    @BeforeEach
    void setUp() {
        // Inicializa el contexto de MockMvc dentro de REST-Assured antes de cada test
        RestAssuredMockMvc.webAppContextSetup(webApplicationContext);
    }

    @Test
    @DisplayName("Debe registrar una nueva mascota y retornar HTTP 201 con el payload JSON esperado")
    void shouldCreatePetSuccessfullyWithRestAssured() {
        // GIVEN: Preparación del mock del servicio
        PetResponseDTO mockResponse = PetResponseDTO.builder()
                .id(100L)
                .name("Max")
                .species("Canino")
                .age(2)
                .vaccinated(true)
                .admissionDate(LocalDate.now())
                .build();

        given(petService.registerPet(any(PetRequestDTO.class))).willReturn(mockResponse);

        PetRequestDTO requestDto = PetRequestDTO.builder()
                .name("Max")
                .species("Canino")
                .age(2)
                .vaccinated(true)
                .build();

        // WHEN & THEN: Petición HTTP virtual y aserciones fluidas BDD
        RestAssuredMockMvc.given()
                .contentType(ContentType.JSON)
                .body(requestDto)
        .when()
                .post("/api/v1/pets")
        .then()
                .status(HttpStatus.CREATED)
                .contentType(ContentType.JSON)
                .body("id", equalTo(100))
                .body("name", equalTo("Max"))
                .body("species", equalTo("Canino"))
                .body("vaccinated", equalTo(true));
    }
}
