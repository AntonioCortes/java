Construcción con Maven y Gradle en Spring Boot

1. Herramientas de Construcción: Maven vs Gradle

En el ecosistema de Spring Boot existen dos herramientas estándar para la compilación, gestión de dependencias y empaquetado de artefactos:

  • Apache Maven: Basado en un modelo declarativo en XML (pom.xml) y en un ciclo de vida de fases estricto y predecible. Es el estándar histórico más extendido en entornos empresariales.
  • Gradle: Basado en un motor de compilación incremental de alto rendimiento con scripts definidos mediante DSL (Groovy o Kotlin DSL). Ofrece ejecuciones sustancialmente más rápidas gracias a su caché de tareas (*Build Cache*) y demonio de ejecución (*Gradle Daemon*).
---

2. Construcción con Apache Maven

2.1. Anatomía del archivo pom.xml

En la carpeta raíz del proyecto se encuentra el documento pom.xml (Project Object Model). Dentro de la etiqueta <project> se debe indicar la versión del modelo (<modelVersion>, actualmente 4.0.0), además de los metadatos de coordenadas del proyecto:

  • Un grupo (<groupId>) es una colección de artefactos relacionados, generalmente identificados por el dominio inverso de la organización o proyecto (ej. com.example.petshop).
  • Un artefacto (<artifactId>) es la unidad de distribución de software (el nombre del archivo JAR, WAR o ZIP).
  • Una versión (<version>) identifica el ciclo de entrega (ej. 0.0.1-SNAPSHOT o 1.0.0.RELEASE).

<modelVersion> es la versión del modelo de objetos de Maven que se utiliza para definir el proyecto. La versión estándar del modelo de objetos de Maven es 4.0.0.

2.2. Ejemplo de pom.xml Generado con Spring Initializr (Spring Boot 3)


<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
	xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
	<modelVersion>4.0.0</modelVersion>

	<!-- Padre oficial de Spring Boot: gestiona automáticamente las versiones de dependencias y plugins -->
	<parent>
		<groupId>org.springframework.boot</groupId>
		<artifactId>spring-boot-starter-parent</artifactId>
		<version>3.2.4</version>
		<relativePath/> <!-- busca el padre en el repositorio central -->
	</parent>

	<groupId>com.example</groupId>
	<artifactId>petshop</artifactId>
	<version>0.0.1-SNAPSHOT</version>
	<name>petshop</name>
	<description>Demo project for Spring Boot</description>

	<properties>
		<java.version>17</java.version>
	</properties>

	<dependencies>
		<!-- Starters oficiales: No requieren indicar <version> gracias a spring-boot-starter-parent -->
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-data-jpa</artifactId>
		</dependency>
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-web</artifactId>
		</dependency>
		<dependency>
			<groupId>org.flywaydb</groupId>
			<artifactId>flyway-core</artifactId>
		</dependency>

		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-devtools</artifactId>
			<scope>runtime</scope>
			<optional>true</optional>
		</dependency>
		<dependency>
			<groupId>org.postgresql</groupId>
			<artifactId>postgresql</artifactId>
			<scope>runtime</scope>
		</dependency>
		<dependency>
			<groupId>org.projectlombok</groupId>
			<artifactId>lombok</artifactId>
			<optional>true</optional>
		</dependency>
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-test</artifactId>
			<scope>test</scope>
		</dependency>
	</dependencies>

	<build>
		<plugins>
			<!-- Plugin responsable de empaquetar el Fat-JAR ejecutable con Tomcat embebido -->
			<plugin>
				<groupId>org.springframework.boot</groupId>
				<artifactId>spring-boot-maven-plugin</artifactId>
				<configuration>
					<excludes>
						<exclude>
							<groupId>org.projectlombok</groupId>
							<artifactId>lombok</artifactId>
						</exclude>
					</excludes>
				</configuration>
			</plugin>
		</plugins>
	</build>
</project>

2.3. Proyectos Multi-módulo en Maven

Para modularizar un proyecto en diferentes subproyectos independientes (ej. capas compartidas o módulos de dominio), se crea un POM raíz o superior que define:

  • El tipo de empaquetado: <packaging>pom</packaging>.
  • La lista de sub-módulos dentro de <modules>.
  • La etiqueta <dependencyManagement> para centralizar versiones de dependencias sin forzar su descarga en los hijos a menos que estos las declaren explícitamente.

<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    
    <modelVersion>4.0.0</modelVersion>
    
    <groupId>org.company</groupId>
    <artifactId>PetShop</artifactId>
    <packaging>pom</packaging>
    <version>1.0-SNAPSHOT</version>

    <modules>
        <module>Customer</module>
        <module>Operation</module>
        <module>Pet</module>
    </modules>

    <name>petshop</name>

    <dependencyManagement>
        <dependencies>
            <!-- Importa el BOM oficial de Spring Boot para sincronizar versiones en todos los hijos -->
            <dependency>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-dependencies</artifactId>
                <version>3.2.4</version>
                <scope>import</scope>
                <type>pom</type>
            </dependency>
        </dependencies>
    </dependencyManagement>
</project>
POM raíz padre gestionando dependencias y módulos hijos

En los POM de los módulos hijos se añade la etiqueta <parent> referenciando al artefacto superior: 


<parent>
    <groupId>org.company</groupId>
    <artifactId>PetShop</artifactId>
    <version>1.0-SNAPSHOT</version>
</parent>

3. Construcción con Gradle (Groovy DSL)

3.1. Anatomía de build.gradle para Spring Boot 3

En Gradle, la configuración se expresa de forma concisa mediante código Groovy o Kotlin DSL. Los plugins oficiales gestionan la resolución automática de versiones sin necesidad de especificar números de versión en cada librería: 


plugins {
    id 'java'
    id 'org.springframework.boot' version '3.2.4'
    id 'io.spring.dependency-management' version '1.1.4'
}

group = 'com.example.petshop'
version = '0.0.1-SNAPSHOT'

java {
    sourceCompatibility = '17'
}

configurations {
    compileOnly {
        extendsFrom annotationProcessor
    }
}

repositories {
    mavenCentral()
}

dependencies {
    // Dependencias principales de compilación y ejecución
    implementation 'org.springframework.boot:spring-boot-starter-web'
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
    implementation 'org.flywaydb:flyway-core'

    // Driver de base de datos solo necesario en tiempo de ejecución
    runtimeOnly 'org.postgresql:postgresql'

    // Project Lombok: requiere compileOnly y procesador de anotaciones
    compileOnly 'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'

    // Herramientas de desarrollo
    developmentOnly 'org.springframework.boot:spring-boot-devtools'

    // Testing
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

tasks.named('test') {
    useJUnitPlatform()
}
Archivo build.gradle estándar en Groovy DSL para Spring Boot

3.2. Ámbitos de Dependencias en Gradle (Scopes)

Configuración Gradle Equivalente Maven Propósito
implementation <scope>compile</scope> Disponible en compilación y ejecución. No se expone de forma transitiva a proyectos consumidores.
runtimeOnly <scope>runtime</scope> No requerido para compilar el código Java, pero obligatorio al arrancar la app (ej. drivers JDBC).
compileOnly <scope>provided</scope> Solo necesario al compilar (no se empaqueta en el JAR final, ej. Lombok).
annotationProcessor Plugins de compilador Ejecuta generadores de código en tiempo de compilación (Lombok, MapStruct).
testImplementation <scope>test</scope> Exclusivo para la compilación y ejecución de tests unitarios y de integración.

3.3. Proyectos Multi-módulo en Gradle

En Gradle, los proyectos multi-módulo se articulan mediante dos archivos:

  1. settings.gradle (en la raíz): Registra el nombre del proyecto padre y todos sus submódulos: 
    
rootProject.name = 'petshop-multimodule'
include 'pet-model', 'pet-repository', 'pet-service', 'pet-api'
  2. build.gradle (en la raíz): Aplica configuraciones comunes a todos los submódulos mediante el bloque subprojects: 
    
subprojects {
    apply plugin: 'java'
    apply plugin: 'io.spring.dependency-management'

    group = 'com.example.petshop'
    version = '1.0.0-SNAPSHOT'

    repositories {
        mavenCentral()
    }

    dependencyManagement {
        imports {
            mavenBom "org.springframework.boot:spring-boot-dependencies:3.2.4"
        }
    }
}

4. Comandos de Terminal Habituales: Comparativa Directa

Acción Comando Apache Maven Comando Gradle
Arrancar en Desarrollo ./mvnw spring-boot:run ./gradlew bootRun
Compilar y Empaquetar JAR ./mvnw clean package ./gradlew build
Ejecutar Tests ./mvnw test ./gradlew test
Ver Árbol de Dependencias ./mvnw dependency:tree ./gradlew dependencies
Limpiar Carpeta de Salida ./mvnw clean ./gradlew clean
