Archivos de Configuración en Spring Boot

1. ¿Qué son y dónde residen los archivos de configuración?

En Spring Boot, la configuración de la aplicación se centraliza en el directorio src/main/resources/. El framework soporta de forma nativa dos formatos equivalentes:

  • YAML (application.yml): Formato jerárquico y legible basado en sangría de espacios que evita repetir prefijos. Es el estándar ampliamente preferido en arquitecturas cloud y microservicios modernos.
  • Properties (application.properties): Formato clásico basado en pares clave=valor planos (clave=valor).
---

2. Ejemplos Prácticos de Configuración

2.1. Ejemplo de application.yml (PostgreSQL, RabbitMQ, Zipkin y Eureka)


server:
  port: 8080
spring:
  application:
    name: pet-service
  datasource:
    url: jdbc:postgresql://localhost:5432/petshop_db
    username: pet_user
    password: pet_password
  jpa:
    hibernate:
      ddl-auto: update
    properties:
      hibernate:
        dialect: org.hibernate.dialect.PostgreSQLDialect
        format_sql: true
    show-sql: true
  zipkin:
    base-url: http://localhost:9411
  rabbitmq:
    addresses: localhost:5672
eureka:
  client:
    service-url:
      defaultZone: http://localhost:8761/eureka
    fetch-registry: true
    register-with-eureka: true
    enabled: false
Configuración en application.yml con base de datos, mensajería y registro en Eureka

3. Jerarquía y Precedencia de Configuración en Spring Boot

Spring Boot permite sobreescribir valores de configuración sin recompilar el código mediante una jerarquía de precedencia estricta. De menor a mayor prioridad:

  1. Valores por defecto internos de los starters.
  2. Archivo base empaquetado: application.yml dentro del JAR.
  3. Archivo de perfil específico: application-{perfil}.yml (ej. application-prod.yml).
  4. Archivo externo fuera del JAR (en la carpeta ./config/ del servidor).
  5. Variables de Entorno del Sistema Operativo: (ej. SPRING_DATASOURCE_PASSWORD=miPasswordSeguro). Sustituyen puntos y guiones por guiones bajos.
  6. Argumentos de Línea de Comandos: (ej. java -jar app.jar --server.port=9090). Tienen la máxima prioridad absoluta.

4. Gestión de Perfiles (Spring Profiles)

Los perfiles permiten segregar configuraciones según el entorno de despliegue (Desarrollo, Pruebas, Preproducción, Producción):

  • application.yml: Configuraciones comunes a todos los entornos (nombre de la aplicación, endpoints genéricos).
  • application-dev.yml: Base de datos local (PostgreSQL en Docker), show-sql: true y logs en DEBUG.
  • application-prod.yml: Clúster de base de datos cloud con pool HikariCP optimizado, logs en WARN/INFO y credenciales leídas por variables de entorno.

# Activar perfil por variable de entorno:
export SPRING_PROFILES_ACTIVE=prod
java -jar target/pet-service.jar

# Activar perfil por argumento de terminal:
java -jar target/pet-service.jar --spring.profiles.active=dev

5. Lectura Tipada con @ConfigurationProperties

Aunque la anotación @Value("${clave}") es útil para inyectar una propiedad individual, la mejor práctica en Spring Boot es agrupar propiedades relacionadas mediante @ConfigurationProperties, aportando tipado fuerte, validación y autocompletado en el IDE: 


# application.yml
app:
  petshop:
    max-pets-per-owner: 5
    enable-sms-notifications: true
    support-email: soporte@petshop.com


package com.example.petshop.config;

import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import lombok.Getter;
import lombok.Setter;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.context.annotation.Configuration;
import org.springframework.validation.annotation.Validated;

@Getter
@Setter
@Validated
@Configuration
@ConfigurationProperties(prefix = "app.petshop")
public class PetShopProperties {

    @Min(value = 1, message = "El límite de mascotas debe ser al menos 1")
    private int maxPetsPerOwner;

    private boolean enableSmsNotifications;

    @NotBlank
    @Email
    private String supportEmail;
}
Mapeo de propiedades tipadas y validadas con @ConfigurationProperties y Lombok ---

6. Cuándo Usar @Value frente a @ConfigurationProperties

Criterio @Value @ConfigurationProperties
Tipo de Uso Propiedades aisladas, flags simples o constantes rápidas. Configuraciones estructuradas, jerárquicas o con múltiples atributos.
Validación con Bean Validation No soportada. Soportada con @Validated (falla en el arranque si los valores son inválidos).
Soporte de Expresiones SpEL Sí (@Value("#{systemProperties['user.home']}")) No.
Autocompletado en IDE No disponible. Sí (generando metadatos con spring-boot-configuration-processor).

7. Contraejemplos de Seguridad en Configuración

Contraejemplo: Credenciales Secretas Hardcodeadas en el Repositorio Git


# ANTIPATRÓN CRÍTICO DE SEGURIDAD: Contraseñas en texto plano versionadas en Git
spring:
  datasource:
    url: jdbc:postgresql://servidor-produccion.com:5432/db
    username: superadmin
    password: PasswordSecreta1234! # Expuesta en el repositorio de código

Solución Segura: Utilizar referencias a variables de entorno con valores por defecto para local: 


# BUENA PRÁCTICA: Inyección de secretos por variables de entorno
spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/petshop}
    username: ${DB_USERNAME:petuser}
    password: ${DB_PASSWORD} # Obligatorio inyectar en producción (AWS Secrets Manager, Vault o K8s Secrets)
