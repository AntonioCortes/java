Crear un Microservicio con Spring Boot

1. ¿Qué es un Microservicio y por qué Spring Boot es el estándar?

Una arquitectura de microservicios descompone una aplicación empresarial compleja en un conjunto de servicios autónomos, pequeños y débilmente acoplados, donde cada servicio gestiona su propio dominio de negocio, su propio almacén de persistencia y se comunica mediante protocolos estándar y ligeros (como HTTP/REST o mensajería asíncrona con RabbitMQ/Kafka).

Analogía del mundo real

Pensemos en un restaurante tradicional monolítico donde una sola persona atiende mesas, cocina, friega los platos y cobra en caja: si esa persona enferma, todo el restaurante se detiene por completo. En una cocina por estaciones (microservicios), existe un puesto independiente para ensaladas, otro para carnes y otro para postres. Cada cocinero trabaja con sus propios utensilios a su propio ritmo; si el puesto de ensaladas recibe una avalancha de comandas, se refuerza únicamente esa partida sin alterar el resto de la cocina.

2. Spring Initializr: Generación del Proyecto Base

Spring Initializr (accesible en start.spring.io) es la herramienta web oficial proporcionada por VMware/Spring que permite a los desarrolladores configurar, seleccionar dependencias y descargar proyectos de Spring Boot personalizados y listos para compilar.

3. Generación Alternativa desde Terminal (cURL / Spring CLI)

En pipelines de automatización o entornos de terminal es posible generar el proyecto directamente mediante una petición curl a la API de Spring Initializr: 


# Generar y descomprimir proyecto Spring Boot con Web, Lombok y JPA para Java 21
curl https://start.spring.io/starter.tgz \
  -d dependencies=web,lombok,data-jpa,postgresql \
  -d type=maven-project \
  -d language=java \
  -d bootVersion=3.2.4 \
  -d groupId=com.example.petshop \
  -d artifactId=pet-service \
  -d name=pet-service \
  -d packageName=com.example.petshop \
  -d javaVersion=21 | tar -xzvf -
---

4. Anatomía de la Clase de Arranque (@SpringBootApplication)

Todo microservicio Spring Boot contiene una clase principal con el método main estándar de Java. La anotación @SpringBootApplication es en realidad una meta-anotación que combina tres anotaciones esenciales:

  1. @SpringBootConfiguration: Especialización de @Configuration que marca la clase como fuente de definición de Beans.
  2. @EnableAutoConfiguration: Activa el motor de autoconfiguración condicional de Spring Boot basado en los starters del classpath.
  3. @ComponentScan: Habilita el escaneo automático de componentes (@Component, @Service, @Repository, @RestController) en el paquete donde se encuentra la clase y en todos sus subpaquetes hijos de forma recursiva.

package com.example.petshop;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class PetServiceApplication {

    public static void main(String[] args) {
        // Inicializa el contexto IoC, arranca el servidor web embebido y ejecuta los listeners
        SpringApplication.run(PetServiceApplication.class, args);
    }
}

5. Compilación, Empaquetado y Ejecución

5.1. Ejecución en Modo Desarrollo (Wrappers)

Los proyectos generados incluyen los wrappers de Maven (mvnw) o Gradle (gradlew), lo que permite compilar y ejecutar el proyecto sin necesidad de tener Maven o Gradle instalados previamente en el sistema operativo: 


# En proyectos Maven:
./mvnw spring-boot:run

# En proyectos Gradle:
./gradlew bootRun

5.2. Generación del JAR Ejecutable para Producción

El plugin de Spring Boot empaqueta todas las dependencias compiladas y el servidor Tomcat embebido en un único archivo Fat-JAR (o Uber-JAR) autosuficiente: 


# 1. Compilar y empaquetar el microservicio omitiendo tests si fuera necesario
./mvnw clean package -DskipTests

# 2. Ejecutar el JAR generado de forma independiente
java -jar target/pet-service-0.0.1-SNAPSHOT.jar

# 3. Modificar el puerto o perfil activo en tiempo de ejecución por línea de comandos
java -jar target/pet-service-0.0.1-SNAPSHOT.jar --server.port=8085 --spring.profiles.active=prod

6. Verificación de Salud con Spring Boot Actuator

Al añadir la dependencia spring-boot-starter-actuator, Spring Boot expone automáticamente endpoints de observabilidad listos para su integración con Kubernetes, Docker o sistemas de monitorización: 


# Comprobar el estado del microservicio
curl -i http://localhost:8080/actuator/health

# Respuesta HTTP 200 OK generada:
# { "status": "UP" }
---

7. ¿Cuándo Usar Microservicios y Cuándo NO Usarlos?

Criterio Cuándo Usar Microservicios Cuándo NO Usar Microservicios (Usar Monolito Modular)
Tamaño del Equipo Múltiples equipos autónomos (más de 15-20 ingenieros) trabajando en dominios desacoplados. Equipos pequeños o startups (1 a 5 desarrolladores) que necesitan iterar rápidamente.
Escalabilidad Componentes con requerimientos asimétricos (ej. el servicio de cobros recibe 100 veces más tráfico que el catálogo). Cargas de trabajo homogéneas y previsibles donde escalar toda la aplicación conjuntamente es económico y sencillo.
Complejidad Operacional La organización cuenta con infraestructura cloud, Docker, Kubernetes, CI/CD maduro y trazas distribuidas. Organizaciones sin cultura DevOps automatizada: el coste de monitorizar 20 microservicios superará con creces sus beneficios.
