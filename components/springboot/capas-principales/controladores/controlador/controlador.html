Controlador Tradicional (@Controller) y Renderizado en Servidor

En el framework Spring MVC, un Controlador Tradicional (@Controller) es el componente de la capa web encargado de recibir las peticiones HTTP del navegador, coordinar la lógica con la capa de servicio y devolver una vista HTML renderizada en el servidor (usando motores de plantillas como Thymeleaf o JSP) o redirigir el navegador hacia otra URL mediante el prefijo redirect:.

Analogía del Mundo Real: El Maître del Restaurante

Imagina que entras en un restaurante clásico:

  • El Maître (@Controller tradicional) te recibe en la puerta, comprueba tu reserva en el libro de reservas (el modelo de datos Model), te acompaña personalmente a una mesa decorada con mantel, vajilla y cubiertos físicos (renderiza la página HTML completa con Thymeleaf) o te indica que el comedor principal está lleno y debes pasar a la terraza (hace una redirección con redirect:/terraza).
  • En cambio, una ventanilla de comida rápida para llevar (@RestController) no te pone mesa ni decoración: solo te entrega la comida empaquetada en una bolsa con un ticket de datos planos (el payload JSON puro).

Anotaciones y Objetos Clave de Spring MVC

Elemento / Anotación Paquete / Origen Propósito y Comportamiento
@Controller org.springframework.stereotype.Controller Registra la clase como bean de Spring MVC. Las cadenas devueltas por los métodos se interpretan como nombres de plantillas lógicas (ej. "pets/list" → src/main/resources/templates/pets/list.html).
Model / ModelMap org.springframework.ui.Model Contenedor de datos clave-valor accesible desde la vista. Spring inyecta la instancia en el método y los atributos añadidos con addAttribute("clave", valor) quedan disponibles en las expresiones ${clave} de Thymeleaf.
RedirectAttributes org.springframework.web.servlet.mvc.support.RedirectAttributes Permite transferir atributos tras una redirección HTTP (Patrón Post-Redirect-Get). Los atributos addFlashAttribute(...) se almacenan temporalmente en la sesión del usuario y sobreviven exactamente a la siguiente petición GET.
@ModelAttribute org.springframework.web.bind.annotation.ModelAttribute Vincula un objeto de formulario completo enviado por POST con un JavaBean del modelo o puebla atributos globales compartidos por todos los métodos del controlador.
BindingResult org.springframework.validation.BindingResult Debe colocarse inmediatamente después del objeto validado con @Valid. Almacena los errores de validación sin lanzar excepción, permitiendo devolver al usuario al formulario para mostrar los mensajes de error en rojo.

Ejemplo Completo: Gestión Web de Mascotas con Validación y Subida de Foto

El siguiente ejemplo implementa el flujo canónico de la tienda de mascotas: muestra el formulario, procesa la subida de imagen (MultipartFile), valida los datos con BindingResult y aplica el patrón Post-Redirect-Get con mensajes Flash:


package com.example.petshop.controller;

import com.example.petshop.dto.PetDTO;
import com.example.petshop.service.PetService;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.validation.BindingResult;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.multipart.MultipartFile;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.nio.file.StandardCopyOption;
import java.util.UUID;

@Slf4j
@RequiredArgsConstructor
@Controller
@RequestMapping("/pets")
public class PetWebController {

    private final PetService petService;
    private static final String UPLOAD_DIR = "uploads/pets";

    /**
     * Muestra el listado visual completo de mascotas.
     */
    @GetMapping
    public String listarMascotas(Model model) {
        log.info("Petición GET /pets: cargando vista de listado");
        model.addAttribute("pets", petService.findAll());
        return "pets/list"; // Resuelve a src/main/resources/templates/pets/list.html
    }

    /**
     * Muestra el formulario vacío para registrar una nueva mascota.
     */
    @GetMapping("/new")
    public String mostrarFormularioCreacion(Model model) {
        log.info("Petición GET /pets/new: mostrando formulario");
        model.addAttribute("petDTO", new PetDTO());
        return "pets/form";
    }

    /**
     * Procesa el envío del formulario con validación y subida de archivo.
     */
    @PostMapping("/save")
    public String guardarMascota(
            @Valid @ModelAttribute("petDTO") PetDTO petDTO,
            BindingResult bindingResult,
            @RequestParam(value = "foto", required = false) MultipartFile foto,
            RedirectAttributes redirectAttributes,
            Model model) {

        log.info("Petición POST /pets/save para mascota: {}", petDTO.getName());

        // 1. Si hay errores de validación de Bean Validation, regresar al formulario
        if (bindingResult.hasErrors()) {
            log.warn("Errores de validación detectados: {}", bindingResult.getAllErrors());
            return "pets/form";
        }

        // 2. Procesamiento opcional de la foto subida
        if (foto != null && !foto.isEmpty()) {
            try {
                Path directorioDestino = Paths.get(UPLOAD_DIR);
                if (!Files.exists(directorioDestino)) {
                    Files.createDirectories(directorioDestino);
                }

                String nombreFichero = UUID.randomUUID() + "_" + foto.getOriginalFilename();
                Path rutaCompleta = directorioDestino.resolve(nombreFichero);
                Files.copy(foto.getInputStream(), rutaCompleta, StandardCopyOption.REPLACE_EXISTING);

                petDTO.setPhotoUrl("/" + UPLOAD_DIR + "/" + nombreFichero);
                log.info("Foto guardada correctamente en: {}", rutaCompleta);
            } catch (IOException e) {
                log.error("Fallo al almacenar el archivo multimedia", e);
                model.addAttribute("errorSubida", "No se pudo almacenar la imagen adjunta");
                return "pets/form";
            }
        }

        // 3. Persistir mascota en la capa de servicio
        petService.save(petDTO);

        // 4. Patrón Post-Redirect-Get: mensaje flash temporal para el listado
        redirectAttributes.addFlashAttribute("mensajeExito", "Mascota '" + petDTO.getName() + "' guardada con éxito.");
        return "redirect:/pets";
    }
}

El Patrón Post-Redirect-Get (PRG)

Uno de los errores más graves en aplicaciones web tradicionales es devolver directamente una vista HTML (return "pets/list";) tras procesar un POST. Si el usuario pulsa la tecla F5 (Recargar) en su navegador, este reenviará el formulario completo, provocando inserciones duplicadas en base de datos o cobros dobles con tarjeta.

La solución universal es el Patrón Post-Redirect-Get (PRG):

  1. El usuario envía el formulario mediante POST /pets/save.
  2. El servidor guarda los datos y responde con un código HTTP 302 Found / 303 See Other y la cabecera Location: /pets (mediante return "redirect:/pets";).
  3. El navegador recibe la orden y emite automáticamente una petición limpia GET /pets. Si el usuario pulsa F5, solo recargará el listado GET sin reenviar datos.

¿Cuándo Usar @Controller y Cuándo @RestController?

Criterio @Controller Tradicional @RestController
Tipo de Salida Vistas HTML completas (Thymeleaf, JSP) renderizadas en el servidor. Cuerpos de respuesta estructurados (JSON, XML) serializados con Jackson.
Cliente Destino Navegadores web clásicos navegando entre páginas mediante enlaces y formularios. SPAs (React, Angular, Vue), aplicaciones móviles iOS/Android o microservicios externos.
Transición de Pantallas Redirecciones HTTP de servidor (return "redirect:/ruta" o "forward:/ruta"). El cliente front-end gestiona el enrutamiento interno mediante React Router, Angular Router, etc.
Sobrecarga de Red El servidor envía todo el árbol DOM con cada click (HTML + CSS + datos). El servidor solo transmite los datos en bruto; la UI se renderiza en el cliente.

Contraejemplo (Mala Práctica): Devolver objetos de negocio sin @ResponseBody en @Controller


// ¡ERROR CLÁSICO! Intentar responder JSON usando @Controller sin @ResponseBody
@Controller
@RequestMapping("/api/pets")
public class BrokenPetController {

    @GetMapping("/{id}")
    public PetDTO getPet(@PathVariable Integer id) {
        // ERROR GRAVE: Spring MVC asume que PetDTO es el nombre de una plantilla HTML.
        // Buscará un archivo "PetDTO.html" en templates/, provocando un error HTTP 404
        // o la excepción: "javax.servlet.ServletException: Circular view path [pet]"
        return PetDTO.builder().id(id).name("Bobby").build();
    }
}
Antipatrón: usar @Controller para endpoints que deben devolver JSON

Solución: Si la clase está pensada para una API REST, sustituir @Controller por @RestController. Si es un método aislado dentro de un controlador web híbrido, añadir explícitamente la anotación @ResponseBody sobre el método.
