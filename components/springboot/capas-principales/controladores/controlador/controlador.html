Controlador Tradicional (@Controller)

En el framework Spring MVC, un Controlador (@Controller) es el componente de la capa web encargado de recibir las peticiones HTTP del navegador, coordinar la lógica con la capa de servicio y devolver una vista HTML renderizada en el servidor (usando motores de plantillas como Thymeleaf o JSP) o redirigir el navegador hacia otra URL (mediante redirect:).

Analogía del Mundo Real: El Maître del Restaurante

Imagina que entras en un restaurante clásico:

  • El Maître (@Controller tradicional) te recibe en la puerta, comprueba tu reserva en el libro de reservas (el modelo de datos), te acompaña personalmente a una mesa decorada con mantel y cubiertos físicos (renderiza la página HTML completa) o te indica que el comedor principal está lleno y debes pasar a la terraza (hace una redirección con redirect:/terraza).
  • En cambio, una ventanilla de comida rápida para llevar (@RestController) no te pone mesa ni decoración: solo te entrega la comida empaquetada en una bolsa con un ticket de datos planos (el JSON puro).

Anotaciones de Spring Framework para Controladores Web

  • @Controller: Pertenece a Spring Framework, se encuentra en el paquete org.springframework.stereotype.Controller y sirve para registrar la clase como un Spring Bean dentro del contexto de Spring MVC. A diferencia de @RestController, los métodos de una clase @Controller interpretan las cadenas de texto devueltas (String) como el nombre de una plantilla HTML que el motor de vistas debe resolver y renderizar.
  • @ResponseBody: Pertenece a Spring Framework (paquete org.springframework.web.bind.annotation.ResponseBody). Le indica a Spring que el valor devuelto por un método específico NO debe interpretarse como el nombre de una vista HTML, sino que debe serializarse directamente en el cuerpo de la respuesta HTTP (habitualmente como JSON o XML).
  • @RequestMapping: Pertenece a Spring Framework (paquete org.springframework.web.bind.annotation.RequestMapping). Se coloca a nivel de clase o método para mapear la ruta URL base y los métodos HTTP admitidos por el controlador.

Ejemplo: Gestión de Películas con Subida de Archivos y Redirección

El siguiente ejemplo muestra un controlador web tradicional que procesa un formulario con subida de imagen de portada (MultipartFile), persiste el archivo en el disco del servidor, almacena la película y redirige al listado visual:


@RequiredArgsConstructor
@Controller
@RequestMapping("/film")
public class FilmController {
	
	private final FilmService filmService;
	
	@Secured({"ROLE_USER","ROLE_ADMIN"})
	@PostMapping("/save")
	public String saveFilm(Film film, BindingResult result, @RequestParam("cover") MultipartFile cover, Model model)
	{
		if (!cover.isEmpty()) {

			Path directorioRecursos = Paths.get("src/main/resources/static/uploads");
			String rootPath = directorioRecursos.toFile().getAbsolutePath();

			try {
				byte[] bytes = cover.getBytes();
				Path rutaCompleta = Paths.get(rootPath + "/" + cover.getOriginalFilename());
				Files.write(rutaCompleta, bytes);
				film.setCover(cover.getOriginalFilename());
			} catch (IOException e) {
				e.printStackTrace();
			}
		}
		
		if(film.getCover() == null && film.getId() != null) {
			film.setCover((filmService.readFilmById(film.getId())).getCover());
		}
		filmService.saveFilm(film);
		model.addAttribute("listOfFilms", filmService.readAllFilms());
		return "redirect:/film/list";
	}
}

BindingResult result Validación Web Captura posibles errores de conversión o validación del formulario sin lanzar una excepción abrupta.

¿Cuándo Usar @Controller y Cuándo @RestController?

Criterio @Controller Tradicional @RestController
Tipo de Salida Vistas HTML completas (Thymeleaf, JSP) renderizadas en el servidor. Datos estructurados crudos (JSON o XML) en el cuerpo de la respuesta.
Cliente Destino Navegadores web clásicos con formularios HTML tradicionales. SPAs (React, Angular, Vue), aplicaciones móviles iOS/Android o microservicios externos.
Redirecciones Uso frecuente de return "redirect:/..." o "forward:/...". Se devuelven cabeceras HTTP como Location con códigos 201 Created o 302 Found.

Contraejemplo (Mala Práctica): Devolver objetos sin @ResponseBody en @Controller

Si defines una clase con @Controller y devuelves un objeto Java o una cadena esperando que el cliente reciba un JSON, Spring asumirá que el texto devuelto es el nombre de una plantilla HTML:


// ¡ERROR COMÚN! Usar @Controller para una API REST
@Controller
@RequestMapping("/api/pets")
public class BrokenPetController {

    @GetMapping("/{id}")
    public PetDTO getPet(@PathVariable Integer id) {
        // ERROR: Spring MVC intentará buscar una plantilla llamada "PetDTO.html"
        // Provoca error HTTP 404 Not Found o "Circular view path [pet]"
        return new PetDTO().setId(id);
    }
}
Antipatrón: Olvidar @ResponseBody o usar @Controller en lugar de @RestController para APIs
