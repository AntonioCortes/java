Capa de Servicio (@Service)

La Capa de Servicio (@Service) es el corazón y el cerebro de una aplicación Spring Boot. En ella reside toda la lógica de negocio, las reglas de validación complejas, los cálculos, la coordinación de transacciones de base de datos (con @Transactional) y la comunicación con recursos externos (bases de datos a través de repositorios, otros microservicios REST o colas de mensajería como Apache Kafka o RabbitMQ).

Analogía del Mundo Real: El Director de Orquesta

Imagina una orquesta sinfónica:

  • El Controlador (@RestController) es el taquillero que recibe al público y revisa las entradas.
  • El Servicio (@Service) es el Director de Orquesta: no toca todos los instrumentos por sí mismo, pero conoce la partitura completa (las reglas de negocio). Le indica al violinista cuándo entrar (llama a PetRepository para persistir los datos en base de datos), le da la señal al trompetista (llama a PetKafkaService para avisar a otros microservicios por la cola de eventos) y coordina el ritmo para que todo suene de forma armoniosa y consistente.
  • Si un músico se equivoca gravemente a mitad del concierto, el director detiene la actuación y reinicia el compás (hace un rollback de la transacción con @Transactional).

Responsabilidades y Separación de Recursos Externos

La capa de servicio se encarga de conectar con todos los recursos que se encuentren fuera del microservicio (bases de datos, otros microservicios, colas Kafka, buckets en la nube S3, etc.).

Principio de Responsabilidad Única (SRP): Debe crearse un servicio especializado para cada recurso externo. Por ejemplo, no es adecuado que un único servicio contenga a la vez el código de base de datos y la configuración del productor de Kafka: deben ser dos servicios independientes (ej. PetService y PetKafkaService), donde el servicio principal orquestador inyecta y utiliza al servicio secundario especializado.

Anotaciones Fundamentales de la Capa de Servicio

  • @Service: Pertenece a Spring Framework (paquete org.springframework.stereotype.Service). Es una especialización de @Component que marca la clase como un bean de servicio dentro del contenedor de Inyección de Dependencias, permitiendo su descubrimiento automático mediante escaneo de componentes (component scanning).
  • @Transactional: Pertenece a Spring Framework (paquete org.springframework.transaction.annotation.Transactional). Delimita el inicio y fin de una transacción de base de datos. Si el método finaliza sin errores, Spring hace commit; si salta una RuntimeException o excepción configurada en rollbackFor = Exception.class, Spring revierte automáticamente (rollback) todos los cambios realizados en la base de datos durante ese método.
  • @Primary: Pertenece a Spring Framework (paquete org.springframework.context.annotation.Primary). Se coloca sobre una clase que implementa una interfaz cuando existen múltiples implementaciones de esa misma interfaz registradas como beans (por ejemplo, PetServiceImpl y PetServiceMockImpl). Indica a Spring que esta implementación tiene preferencia por defecto al inyectar con @Autowired a menos que el cliente use explícitamente @Qualifier.

Ejemplo 1: Servicio Orquestador con Persistencia y Kafka

El siguiente ejemplo muestra cómo PetServiceImpl implementa el contrato PetService e interactúa tanto con la base de datos relacional (PetRepository) como con el bus de eventos distribuido (PetKafkaService):


@RequiredArgsConstructor
@Service
public class PetServiceImpl implements PetService 
{
    private final PetKafkaService petKafkaService;
    private final PetRepository petRepository;

    @Override
    public Optional<Pet> findById(Integer pId) 
    {
        return petRepository.findById(pId);
    }

    @Override
    public Pet save(Pet pPet)
    {
        Pet savedPet = petRepository.save(pPet);
        petKafkaService.sendKafkaMessage(savedPet, KafkaAction.INSERT.value);
        return savedPet;
    } 

    @Override
    public void delete(Pet pPet) 
    {
        petRepository.delete(pPet);
        petKafkaService.sendKafkaMessage(pPet, KafkaAction.DELETE.value);
    }
}

Ejemplo 2: Servicio para Llamar a Otro Microservicio (Consumo REST)

En arquitecturas de microservicios distribuidos, un servicio de negocio frecuentemente necesita consultar información alojada en otro microservicio. El siguiente ejemplo muestra StoreServiceImpl, que utiliza RestTemplate y URIBuilder para invocar endpoints remotos, gestionar códigos de estado HTTP y transformar respuestas dinámicas con control exhaustivo de excepciones:


@Slf4j
@RequiredArgsConstructor
@Service
public class StoreServiceImpl implements StoreService {

    private static final String ERROR_REST_SERVICE_STORES_MSG = "Error calling stores service";
    
    private static final String ERROR_REST_SERVICE_STORES_LOG_MSG = "Error calling store: {}, status code {}, body {}";
    
    private static final String ERROR_REST_SERVICE_STORES_LOG_EXCEPTION = "Error calling store: {}, error {}";
    
    private static final String SLASH = "/";
    
    private static final String QUESTION = "?";
    
    private static final String EQUALS = "=";
    
    private static final String FIND = "find";

    private final CommunicationConfiguration commConfig;
    private final RestTemplate restTemplate;

    private String makeStoreURL(String pRegion, String pProvince, String pBusiness,
            String pStoreType) {
        URIBuilder url = new URIBuilder();
        try {
            url = new URIBuilder(commConfig.getStoresUrl());
            if (StringUtils.isNotBlank(pRegion)) {
                url.addParameter(Constants.REGION_PARAM, pRegion);
            }
            if (StringUtils.isNotBlank(pProvince)) {
                url.addParameter(Constants.PROVINCE_PARAM, pProvince);
            }
            if (StringUtils.isNotBlank(pBusiness)) {
                url.addParameter(Constants.BUSINESS_PARAM, pBusiness);
            }
            if (StringUtils.isNotBlank(pStoreType)) {
                url.addParameter(Constants.STORE_TYPE_PARAM, pStoreType);
            }
            return url.build().toString();
        } catch (URISyntaxException e) {
            LOGGER.error("URL {}, error:{}", commConfig.getStoresUrl(), e);
        }
        return null;
    }

    private String makeStoreURL(Integer pStoreId) {
        StringBuilder url = new StringBuilder(commConfig.getStoresUrl());
        url.append(SLASH);
        url.append(pStoreId);
        return url.toString();
    }

    @SuppressWarnings({ "unchecked", "rawtypes" })
    @Override
    public String getStoreWerks(Integer idStore) {
        String storesMicroServiceURL = makeStoreURL(idStore);

        try {
            ResponseEntity<LinkedHashMap> storeResponse = restTemplate.getForEntity(storesMicroServiceURL, LinkedHashMap.class);
            if (storeResponse.getStatusCode().equals(HttpStatus.OK)) {
                LinkedHashMap<Object, Object> store = (LinkedHashMap<Object, Object>) storeResponse.getBody();
                return (String) store.get(Constants.WERKS);
            } else {
                LOGGER.error(ERROR_REST_SERVICE_STORES_LOG_MSG, storesMicroServiceURL, storeResponse.getStatusCode(), storeResponse.getBody());
                throw new RestDependencyException(ERROR_REST_SERVICE_STORES_MSG);
            }
        } catch (RestClientException e) {
            LOGGER.error(ERROR_REST_SERVICE_STORES_LOG_EXCEPTION, storesMicroServiceURL, e);
            throw new RestDependencyException(ERROR_REST_SERVICE_STORES_MSG, e);
        }
    }

    @SuppressWarnings({ "rawtypes", "unchecked" })
    @Override
    public List<Integer> getStoreIds(String pRegion, String pProvince, String pBusiness,
            String pStoreType) {
        String storesMicroServiceURL = makeStoreURL(pRegion, pProvince, pBusiness, pStoreType);
        try {
            ResponseEntity<List> storeResponse = restTemplate.getForEntity(storesMicroServiceURL, List.class);
            if (storeResponse.getStatusCode().equals(HttpStatus.OK)) {
                return processResponse(storeResponse.getBody());
            } else {
                LOGGER.error(ERROR_REST_SERVICE_STORES_LOG_MSG, storesMicroServiceURL,
                        storeResponse.getStatusCode(), storeResponse.getBody());
                throw new RestDependencyException(ERROR_REST_SERVICE_STORES_MSG);
            }
        } catch (RestClientException e) {
            LOGGER.error(ERROR_REST_SERVICE_STORES_LOG_EXCEPTION, storesMicroServiceURL, e);
            throw new RestDependencyException(ERROR_REST_SERVICE_STORES_MSG, e);
        }
    }

    private List<Integer> processResponse(List<LinkedHashMap<Object, Object>> pResponse) {
        List<LinkedHashMap<Object, Object>> remoteStoreList = pResponse;
        List<Integer> remoteStoreIdList = new ArrayList<>();

        if (remoteStoreList != null) {
            Integer idStore;
            for (LinkedHashMap<Object, Object> store : remoteStoreList) {
                idStore = (Integer) store.get(Constants.ID_STORE);
                remoteStoreIdList.add(idStore);
            }
        }

        return remoteStoreIdList;
    }
    
    private String makeFindStoreURL(String werks) {
        StringBuilder url = new StringBuilder(commConfig.getStoresUrl());
        url.append(SLASH);
        url.append(FIND);
        url.append(QUESTION);
        url.append(Constants.WERKS);
        url.append(EQUALS);
        url.append(werks);
        return url.toString();
    }
    
    @SuppressWarnings({ "unchecked", "rawtypes" })
    @Override
    public Integer getStoreId(String werks) {
        String storesMicroServiceURL = makeFindStoreURL(werks);

        try {
            ResponseEntity<LinkedHashMap> storeResponse = restTemplate.getForEntity(storesMicroServiceURL, LinkedHashMap.class);
            if (storeResponse.getStatusCode().equals(HttpStatus.OK)) {
                LinkedHashMap<Object, Object> store = (LinkedHashMap<Object, Object>) storeResponse.getBody();
                return (Integer) store.get(Constants.ID_STORE);
            } else {
                LOGGER.error(ERROR_REST_SERVICE_STORES_LOG_MSG, storesMicroServiceURL, storeResponse.getStatusCode(), storeResponse.getBody());
                throw new RestDependencyException(ERROR_REST_SERVICE_STORES_MSG);
            }
        } catch (RestClientException e) {
            LOGGER.error(ERROR_REST_SERVICE_STORES_LOG_EXCEPTION, storesMicroServiceURL, e);
            throw new RestDependencyException(ERROR_REST_SERVICE_STORES_MSG, e);
        }
    }
}

¿Cuándo Usar la Capa de Servicio y Cuándo NO?

Escenario Recomendación Buenas Prácticas
Validaciones de negocio y transformaciones DTO ↔ Entidad SIEMPRE en el @Service Mantiene los controladores limpios y delgados (Skinny Controllers).
Transacciones que tocan varias tablas o publican eventos Usar @Transactional Garantiza la consistencia atómica: si falla la inserción, no se envía el evento o se revierte la transacción.
Validaciones de formato simple (campos no nulos, emails válidos) NO en el servicio Hacerlo en el DTO con anotaciones Bean Validation (@NotNull, @Email) para rechazar en la puerta de entrada.
Consultas SQL y queries directas a la base de datos NO en el servicio Delegar en la capa de Repositorio (Spring Data JPA) mediante métodos o @Query.

Contraejemplo (Mala Práctica): El Antipatrón "Fat Controller"

Colocar lógica de negocio, cálculos de comisiones o llamadas directas a Kafka dentro de un método de controlador REST rompe la arquitectura por capas, imposibilita la reutilización de la lógica en otros controladores y hace inviables los tests unitarios aislados:


// ¡ANTIPATRÓN FAT CONTROLLER! El controlador hace de todo
@RestController
@RequestMapping("/pets")
public class BadFatPetController {

    @Autowired
    private PetRepository petRepository;
    
    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;

    @PostMapping
    public ResponseEntity<?> create(@RequestBody Pet pet) {
        // ERROR: Lógica de negocio y persistencia mezcladas en la capa web
        if (pet.getAge() < 0) {
            return ResponseEntity.badRequest().body("Edad inválida");
        }
        petRepository.save(pet);
        kafkaTemplate.send("pet-topic", "Pet created: " + pet.getId());
        return ResponseEntity.ok(pet);
    }
}
