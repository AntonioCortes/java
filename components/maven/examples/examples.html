Ejemplos Reales de POMs Explicados Línea por Línea

Para consolidar todo lo aprendido sobre Maven, analizamos a continuación la arquitectura real de un sistema de microservicios en producción (PetStore): un POM Superior (Padre Agregador) que coordina 7 microservicios, y un POM Hijo (Módulo Customer) que hereda la configuración común e implementa su propia persistencia (PostgreSQL + Spring Data JPA), mensajería asíncrona (RabbitMQ AMQP), descubrimiento (Eureka) y contenedorización automática (Jib).

1. POM Superior Agregador (petstoreservices/pom.xml)

Este archivo se ubica en la raíz del repositorio. Su objetivo es orquestar la compilación multi-módulo con <modules>, fijar versiones compatibles mediante <dependencyManagement> y centralizar plugins en <pluginManagement>:


<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0" 
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 
         http://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.petStore</groupId>
    <artifactId>petstoreservices</artifactId>
    <packaging>pom</packaging>
    <version>1.0-SNAPSHOT</version>

    <!-- Submódulos que componen la arquitectura de microservicios -->
    <modules>
        <module>customer</module>
        <module>fraud</module>
        <module>eureka-server</module>
        <module>clients</module>
        <module>notification</module>
        <module>apigw</module>
        <module>amqp</module>
    </modules>

    <name>petstoreservices</name>
    <url>https://www.petStore.com</url>

    <properties>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
        <spring.boot.maven.plugin.version>2.7.14</spring.boot.maven.plugin.version>
        <spring.boot.dependencies.version>2.7.14</spring.boot.dependencies.version>
        <spring.cloud-version>2021.0.8</spring.cloud-version>
        <image>petStore/${project.artifactId}:${project.version}</image>
    </properties>

    <!-- Catálogo central de versiones para todos los microservicios hijos -->
    <dependencyManagement>
        <dependencies>
            <!-- BOM oficial de Spring Boot -->
            <dependency>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-dependencies</artifactId>
                <version>${spring.boot.dependencies.version}</version>
                <scope>import</scope>
                <type>pom</type>
            </dependency>
            <!-- BOM oficial de Spring Cloud (Eureka, Gateway, Sleuth) -->
            <dependency>
                <groupId>org.springframework.cloud</groupId>
                <artifactId>spring-cloud-dependencies</artifactId>
                <version>${spring.cloud-version}</version>
                <type>pom</type>
                <scope>import</scope>
            </dependency>
        </dependencies>
    </dependencyManagement>

    <!-- Dependencias comunes que heredarán TODOS los submódulos -->
    <dependencies>
        <dependency>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok</artifactId>
            <scope>provided</scope>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <pluginManagement>
            <plugins>
                <plugin>
                    <groupId>org.springframework.boot</groupId>
                    <artifactId>spring-boot-maven-plugin</artifactId>
                    <version>${spring.boot.maven.plugin.version}</version>
                    <executions>
                        <execution>
                            <goals>
                                <goal>repackage</goal>
                            </goals>
                        </execution>
                    </executions>
                </plugin>
                <!-- Plugin Jib para generar imágenes Docker sin necesidad de demonio Docker local -->
                <plugin>
                    <groupId>com.google.cloud.tools</groupId>
                    <artifactId>jib-maven-plugin</artifactId>
                    <version>3.3.2</version>
                    <configuration>
                        <from>
                            <image>eclipse-temurin:17-jre-focal</image>
                        </from>
                        <to>
                            <image>${image}</image>
                        </to>
                    </configuration>
                </plugin>
            </plugins>
        </pluginManagement>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.10.1</version>
                <configuration>
                    <source>17</source>
                    <target>17</target>
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>
POM Padre que centraliza versiones y empaquetado Docker con Jib

2. POM Hijo: Microservicio de Clientes (customer/pom.xml)

Este POM hereda del padre anterior. Observa cómo ninguna librería de Spring Boot o Spring Cloud necesita llevar número de versión:


<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 
         http://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>com.petStore</groupId>
        <artifactId>petstoreservices</artifactId>
        <version>1.0-SNAPSHOT</version>
    </parent>

    <artifactId>customer</artifactId>
    <packaging>jar</packaging>

    <dependencies>
        <!-- Capa Web REST -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
        <!-- Persistencia JPA y Driver PostgreSQL -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-data-jpa</artifactId>
        </dependency>
        <dependency>
            <groupId>org.postgresql</groupId>
            <artifactId>postgresql</artifactId>
            <scope>runtime</scope>
        </dependency>
        <!-- Descubrimiento con Eureka y Trazabilidad distribuida con Sleuth + Zipkin -->
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-starter-netflix-eureka-client</artifactId>
        </dependency>
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-starter-sleuth</artifactId>
        </dependency>
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-sleuth-zipkin</artifactId>
        </dependency>
        <!-- Mensajería Asíncrona con RabbitMQ y módulos hermanos -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-amqp</artifactId>
        </dependency>
        <dependency>
            <groupId>com.petStore</groupId>
            <artifactId>amqp</artifactId>
            <version>1.0-SNAPSHOT</version>
        </dependency>
        <dependency>
            <groupId>com.petStore</groupId>
            <artifactId>clients</artifactId>
            <version>1.0-SNAPSHOT</version>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>

    <!-- Perfil para construir la imagen Docker en pipelines de CI/CD -->
    <profiles>
        <profile>
            <id>build-docker-image</id>
            <build>
                <plugins>
                    <plugin>
                        <groupId>com.google.cloud.tools</groupId>
                        <artifactId>jib-maven-plugin</artifactId>
                        <executions>
                            <execution>
                                <phase>package</phase>
                                <goals>
                                    <goal>dockerBuild</goal>
                                </goals>
                            </execution>
                        </executions>
                    </plugin>
                </plugins>
            </build>
        </profile>
    </profiles>
</project>

¿Cuándo Usar Perfiles de Maven (<profiles>) y Cuándo NO?

Escenario Recomendación Buenas Prácticas
Tareas costosas en tiempo (ej. crear imágenes Docker con Jib o escaneo SonarQube) SÍ usar <profile> Aislar en un perfil para que el desarrollador local no sufra esperas al ejecutar mvn test.
Configuraciones de entornos (dev, pro, test) NO usar perfiles Maven Preferir perfiles de Spring Boot (application-dev.yml, application-pro.yml) para no recompilar el artefacto para cada entorno (principio Twelve-Factor App).

Ejemplo y Contraejemplo en la Invocación del Proyecto

Ejemplo (Buena Práctica): Compilar todos los microservicios desde la raíz


# Desde la raíz donde reside el POM Padre:
mvn clean install

# Maven calcula automáticamente el orden topológico y compila primero amqp y clients antes que customer
Compilación coordinada de todo el ecosistema de microservicios

Contraejemplo (Mala Práctica): Compilar un hijo sin haber instalado sus dependencias locales

Si entras directamente a la carpeta customer/ y ejecutas mvn compile sin haber ejecutado mvn install previamente en la raíz, Maven buscará el módulo amqp:1.0-SNAPSHOT en Maven Central. Al no encontrarlo en internet, fallará con Could not resolve dependencies.
