Estructura Estándar de Directorios en Maven

Una de las mayores fortalezas de Apache Maven es la estandarización universal de su estructura de archivos. Gracias al principio de Convención sobre Configuración, Maven asume por defecto dónde se encuentra el código Java, dónde residen los recursos de configuración y dónde deben generarse los binarios sin necesidad de escribir cientos de rutas en el pom.xml.

Figura 1: Árbol canónico de directorios según el Standard Directory Layout de Maven
Ruta del Directorio Rol y Contenido ¿Se empaqueta en el JAR final?
src/main/java Paquetes y clases Java reales de la aplicación (producción). SÍ: Se compila a .class y forma el núcleo del paquete.
src/main/resources Archivos de configuración (application.properties, .yml, esquemas SQL). SÍ: Se copian directamente a la raíz del .jar (classpath).
src/main/webapp Vistas JSP, CSS, JS e imágenes para aplicaciones Web clásicas empaquetadas en .war. SÍ: Solo en proyectos con <packaging>war</packaging>.
src/test/java Clases de pruebas unitarias y de integración (JUnit, Mockito). NO: Solo se usan al ejecutar mvn test; nunca viajan al cliente.
src/test/resources Archivos de configuración exclusivos para tests (ej. BD en memoria H2). NO: Se aíslan exclusivamente para la fase de pruebas.
target/ Directorio de salida: clases compiladas, reportes y el archivo .jar o .war final. NO: Se borra por completo al ejecutar mvn clean (excluir de Git).
pom.xml Descriptor del Proyecto (Project Object Model): librerías, plugins y configuración. SÍ: Se incluye dentro de META-INF/maven/ para trazabilidad.

¿Cuándo Modificar la Estructura Estándar y Cuándo NO?

Situación Recomendación Explicación
Proyectos nuevos o microservicios modernos NUNCA alterar Respetar src/main/java permite compilar sin configurar ninguna etiqueta <sourceDirectory>.
Proyectos heredados (Legacy) con carpetas antiguas SÍ redefinir en <build> Maven permite anular rutas con <sourceDirectory> o <testSourceDirectory> si no es posible mover archivos.
Generación automática de código (Avro, OpenAPI, WSDL) Usar target/generated-sources/ Los plugins deben depositar el código generado en target/generated-sources/ para que mvn clean pueda regenerarlo limpiamente sin ensuciar src/.

Ejemplo y Contraejemplo en el Control de Versiones (.gitignore)

Ejemplo (Buena Práctica): Ignorar siempre la carpeta target/

La carpeta target/ contiene binarios transitorios específicos de la compilación y nunca debe subirse al repositorio de código:


# .gitignore para proyectos Maven
target/
*.class
*.jar
*.war
.idea/
*.iml
.project
.classpath
.settings/
Reglas indispensables en .gitignore para proyectos Maven

Contraejemplo (Mala Práctica): Mezclar recursos de configuración dentro de src/main/java


# ¡ERROR COMÚN!
src/main/java/com/petshop/application.properties

Por defecto, el compilador de Maven (maven-compiler-plugin) solo copia archivos que terminan en .java dentro de src/main/java. Si colocas un archivo .properties, .xml o .json dentro de src/main/java, Maven lo ignorará y no lo copiará a target/classes, provocando un error FileNotFoundException al arrancar tu aplicación en producción.
