El Archivo build.gradle, settings.gradle y gradle.properties

El archivo build.gradle es el cerebro de tu proyecto. Si solo sabías que ahí se ponían las librerías, en esta sección vas a entender para qué sirve cada uno de sus bloques y cómo se relaciona con settings.gradle y gradle.properties.

Un archivo build.gradle Completo y Limpio Explicado por Bloques

Veamos primero cómo luce un archivo build.gradle estándar para un proyecto Java moderno y analicemos cada uno de sus 5 bloques numerados:


// BLOQUE 1: Plugins (Qué tipo de proyecto es y qué herramientas activa)
plugins {
    id 'java'
    id 'application'
}

// BLOQUE 2: Metadatos del Proyecto y Versión de Java
group = 'com.miempresa.facturacion'
version = '1.0.0-SNAPSHOT'

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

// BLOQUE 3: Repositorios (De qué servidores de internet descargamos las librerías)
repositories {
    mavenCentral()
}

// BLOQUE 4: Dependencias (Qué librerías externas necesita nuestro código)
dependencies {
    implementation 'com.google.code.gson:gson:2.11.0'
    compileOnly 'org.projectlombok:lombok:1.18.34'
    annotationProcessor 'org.projectlombok:lombok:1.18.34'
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.2'
}

// BLOQUE 5: Configuración de Tareas y de la Aplicación
application {
    mainClass = 'com.miempresa.facturacion.Main'
}

tasks.named('test') {
    useJUnitPlatform()
}

Desglose Detallado de Cada Bloque

  • Bloque 1 — plugins { ... }:

    Por sí solo, Gradle es un motor genérico que no sabe ni siquiera qué es un archivo .java. Al poner id 'java', le dices a Gradle: "Este es un proyecto Java: activa la compilación de src/main/java, los tests y la creación de archivos .jar". Y al añadir id 'application', le permites ejecutar tu método main directamente con el comando ./gradlew run.

  • Bloque 2 — Metadatos (group, version y java):

    group identifica a tu organización o paquete raíz (por ejemplo, 'com.miempresa') y version da nombre al archivo generado (por ejemplo, mi-proyecto-1.0.0-SNAPSHOT.jar). El bloque java { toolchain { ... } } es la forma moderna de indicar qué versión de JDK usar (por ejemplo, Java 17 o Java 21). En proyectos antiguos también verás escrito sourceCompatibility = '17'.

  • Bloque 3 — repositories { ... }:

    Cuando pides una librería en el bloque de dependencias, Gradle necesita saber a qué servidor web acudir para descargarla. Existen cuatro opciones principales:

Declaración en repositories ¿De dónde descarga los archivos .jar?
mavenCentral() El repositorio público oficial más grande del mundo Java. Es el que debes poner siempre por defecto.
google() Repositorio oficial de Google (imprescindible si desarrollas para Android).
mavenLocal() Busca en la carpeta local de Maven de tu propio ordenador (~/.m2/repository). Útil si estás desarrollando dos proyectos a la vez en tu PC.
maven { url "https://..." } Un servidor privado de tu empresa (como Nexus o JFrog Artifactory) donde se alojan las librerías internas de tu compañía.
flatDir { dirs 'libs' } Busca archivos .jar sueltos que hayas copiado manualmente dentro de una carpeta local llamada libs/ en tu proyecto.

¿Para qué sirve el archivo settings.gradle?

Mientras que build.gradle define cómo se compila el proyecto, settings.gradle define cómo se llama el proyecto y qué subcarpetas lo componen:


// En un proyecto simple (de un solo módulo), solo tiene esta línea:
rootProject.name = 'sistema-reservas'

// Si tu proyecto es grande (Multimódulo) y está dividido en 3 subcarpetas, las incluyes aquí:
include('modulo-dominio')
include('modulo-base-datos')
include('modulo-api-rest')

¿Para qué sirve el archivo gradle.properties?

Es un archivo opcional de clave=valor muy útil por dos motivos: acelerar Gradle y guardar versiones de librerías en un solo sitio para no repetirlas en build.gradle:


# 1. Opciones de rendimiento del motor de Gradle
org.gradle.daemon=true
org.gradle.parallel=true
org.gradle.caching=true
org.gradle.jvmargs=-Xmx2048m -Dfile.encoding=UTF-8

# 2. Variables propias que luego podemos usar en build.gradle con ${lombokVersion}
lombokVersion=1.18.34
springBootVersion=3.3.4
