Estructura de un Proyecto Gradle y el Gradle Wrapper

Cuando creas o descargas un proyecto que usa Gradle, verás una serie de carpetas y archivos en la raíz del proyecto. Entender qué hace cada uno te quitará el miedo a tocar la configuración desde el primer día.

├── src/
│   ├── main/
│   │   ├── java/                    # AQUÍ escribes el código Java de tu aplicación
│   │   └── resources/               # Archivos de configuración (application.yml, SQL, imágenes)

│       ├── java/                    # AQUÍ escribes tus tests unitarios (JUnit, Mockito)
│       └── resources/               # Configuración exclusiva para las pruebas

├── settings.gradle                  # Define el nombre del proyecto y sus submódulos
├── gradle.properties                # (Opcional) Variables globales y memoria de Gradle

└── gradlew.bat                      # Script para ejecutar Gradle en Windows
Estructura estándar de directorios de un proyecto Java con Gradle
Archivo / Carpeta ¿Se sube a Git? Explicación para Principiantes
src/main/java Sí (Obligatorio) Contiene todos los paquetes y clases .java reales de tu programa.
src/main/resources Sí (Obligatorio) Todo lo que pongas aquí (como application.properties o plantillas HTML) se copiará automáticamente dentro de la raíz de tu archivo .jar final.
src/test/java Sí (Obligatorio) Contiene las clases de prueba. Gradle las usa cuando ejecutas ./gradlew test, pero nunca las mete dentro del .jar de producción para no ensuciar tu aplicación.
build/ NO (Añadir a .gitignore) Es el equivalente a la carpeta target/ de Maven. Aquí deposita Gradle el resultado de compilar y empaquetar. Si ejecutas ./gradlew clean, esta carpeta se borra por completo.
build.gradle Sí (Obligatorio) Es la "receta" de tu proyecto (equivalente al pom.xml de Maven). Aquí añades tus librerías, plugins y versión de Java.
settings.gradle Sí (Obligatorio) Define el nombre raíz del proyecto (rootProject.name) y, si tu proyecto está dividido en varios submódulos, enumera qué carpetas forman parte de él.
gradlew / gradlew.bat Sí (Muy recomendado) Son los scripts del Gradle Wrapper. Permiten que cualquier persona compile el proyecto sin tener que instalar Gradle previamente en su ordenador.

¿Qué es el Gradle Wrapper (./gradlew) y por qué es tan importante?

Una de las primeras dudas de cualquier principiante es: "¿Por qué en todos los tutoriales ejecutan ./gradlew build con una w al final en vez de escribir gradle build?"

La w significa Wrapper (Envoltorio), y es una de las mejores invenciones de Gradle:

  • El problema sin Wrapper: Imagina que creas un proyecto usando Gradle 8.10. Seis meses después, un compañero descarga tu proyecto pero él tiene instalado en su Windows el antiguo Gradle 6.5. Al intentar compilar, todo falla con errores extraños porque las versiones son incompatibles.
  • La solución con el Wrapper (./gradlew): Dentro de la carpeta gradle/wrapper/gradle-wrapper.properties queda grabada la dirección exacta de la versión de Gradle con la que nació el proyecto:

distributionBase=GRADLE_USER_HOME
distributionPath=wrapper/dists
distributionUrl=https\://services.gradle.org/distributions/gradle-8.10.2-bin.zip
zipStoreBase=GRADLE_USER_HOME
zipStorePath=wrapper/dists
Contenido del archivo gradle/wrapper/gradle-wrapper.properties

Cuando tu compañero descarga el repositorio y escribe en su terminal:

  • En Linux o macOS: ./gradlew build
  • En Windows (CMD o PowerShell): .\gradlew.bat build

El script comprueba si en su ordenador ya está descargado Gradle 8.10.2. Si no lo tiene, lo descarga él solo en segundo plano dentro de la carpeta ~/.gradle/wrapper/dists y compila el proyecto usando exactamente esa versión. ¡Nadie del equipo tiene que instalar Gradle manualmente nunca más!

Groovy DSL (build.gradle) vs Kotlin DSL (build.gradle.kts)

Cuando crees un proyecto nuevo (por ejemplo, en Spring Initializr o en IntelliJ IDEA), te preguntará qué lenguaje quieres usar para los archivos de Gradle:

  • Groovy (build.gradle): Es el formato clásico y el que encontrarás en el 80% de los proyectos de empresa y respuestas de StackOverflow. Permite omitir paréntesis y usar comillas simples '...' o dobles "...".
  • Kotlin (build.gradle.kts): Es el formato más reciente con tipado estático. Ofrece mejor autocompletado en IntelliJ IDEA, pero exige usar siempre paréntesis implementation("...") y comillas dobles.

// 1. Sintaxis en Groovy DSL (Archivo: build.gradle)
plugins {
    id 'java'
}
dependencies {
    implementation 'com.google.guava:guava:33.0.0-jre'
}

// 2. Sintaxis equivalente en Kotlin DSL (Archivo: build.gradle.kts)
