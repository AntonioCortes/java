Ciclo de Vida de Gradle y Tareas (Tasks)

Para dejar de ver a Gradle como una "caja negra mágica" y dominarlo de verdad, necesitas comprender dos conceptos fundamentales: las 3 fases de su ciclo de vida y qué es el Grafo de Tareas (DAG).

Figura 1: Las 3 fases internas de Gradle y el Grafo Acíclico Dirigido (DAG) de tareas del plugin Java

1. Las 3 Fases Internas que Ocurren cada vez que Ejecutas un Comando

Cada vez que escribes en la terminal un comando como ./gradlew build, Gradle ejecuta internamente tres fases en estricto orden:

  1. Fase 1: Inicialización (Initialization):

    Gradle lee primero el archivo settings.gradle para descubrir el nombre del proyecto y comprobar si se trata de un único proyecto o de una estructura con múltiples submódulos.

  2. Fase 2: Configuración (Configuration):

    Gradle lee tu archivo build.gradle de arriba abajo, registra los plugins y construye en memoria el mapa de qué tareas dependen de cuáles (el Grafo Acíclico Dirigido o DAG). ¡Ojo! En esta fase todavía no se ha compilado ni ejecutado ninguna tarea real.

  3. Fase 3: Ejecución (Execution):

    Una vez trazado el plan de ruta en la fase anterior, Gradle ejecuta una por una solo las tareas necesarias para cumplir el comando que le has pedido.

2. Las Tareas Principales de un Proyecto Java

Cuando añades id 'java' en tu build.gradle, Gradle crea automáticamente por ti las siguientes tareas listas para usar:

Tarea (./gradlew <tarea>) ¿De qué tareas depende antes? ¿Qué hace exactamente?
compileJava Ninguna Compila todos tus archivos .java de src/main/java y deja los .class en build/classes/.
processResources Ninguna Copia tus archivos de configuración desde src/main/resources hacia la carpeta build/resources/.
classes compileJava + processResources Agrupa el código compilado y los recursos listos para empaquetar.
jar / assemble classes Empaqueta tu aplicación en un archivo .jar dentro de build/libs/ sin ejecutar los tests.
test classes + compileTestJava Compila y ejecuta todos los tests unitarios de src/test/java.
check test (+ plugins de calidad) Ejecuta todas las verificaciones de calidad del proyecto (tests, cobertura JaCoCo, linters).
build assemble + check La tarea reina: compila todo, pasa todos los tests y genera el archivo .jar final.
clean Ninguna Borra por completo la carpeta build/ para empezar una compilación limpia desde cero.

3. Cómo Crear Tus Propias Tareas Personalizadas en build.gradle

Una de las mayores ventajas de Gradle frente a Maven es lo fácil que resulta crear tus propias tareas automatizadas (por ejemplo, imprimir información, copiar archivos, generar un ZIP o ejecutar un test de integración especial).

¡Regla de Oro para Principiantes! (doLast vs Configuración): Dentro de una tarea, las acciones que quieras que ocurran cuando alguien invoque esa tarea deben ir siempre dentro de un bloque doLast { ... } (al final de la tarea) o doFirst { ... } (al principio de la tarea). Si escribes un println suelto fuera de doLast, se ejecutará siempre en la Fase de Configuración aunque no hayas llamado a esa tarea.


// Ejemplo 1: Crear una tarea personalizada sencilla
tasks.register('saludarEquipo') {
    group = 'Mi Empresa'
    description = 'Muestra un mensaje de estado del proyecto por consola'

    doLast {
        println '========================================='
        println 'Proyecto: ' + project.name
        println 'Versión actual: ' + project.version
        println '¡Todo listo para desplegar!'
        println '========================================='
    }
}

// Ejemplo 2: Tarea para copiar archivos o hacer una copia de seguridad automática
tasks.register('copiarConfiguracion', Copy) {
    group = 'Utilidades'
    description = 'Copia los archivos de configuración a la carpeta de distribución'
    from 'src/main/resources'
    into "${layout.buildDirectory.get()}/config-backup"
    include '*.yml', '*.properties'
}

// Ejemplo 3: Hacer que una tarea dependa de otra (dependsOn)
tasks.register('prepararEntrega') {
    group = 'Mi Empresa'
    description = 'Genera el JAR y además copia la configuración'
    dependsOn 'jar', 'copiarConfiguracion'

    doLast {
        println 'Entrega generada correctamente en la carpeta build/'
    }
}
Creación de tareas propias, tareas de tipo Copy y encadenamiento con dependsOn

Para ejecutar cualquiera de las tareas que acabas de crear en tu terminal, simplemente escribes su nombre:
